# StepUp 지갑 · 구현 지시서

## 1. 목표와 범위

내 정보의 `지갑`에서 **얼마나 보유했는지, 어떤 내역이 남았는지**를 바로 확인하게 한다. 러닝 패스와 같은 남색 카드와 큰 숫자를 사용하고, 목록은 카드 여러 개로 감싸지 않는다. WEB3 설명은 짧은 연결 행과 눌렀을 때 나오는 모달로 정리한다.

이번 산출물은 시안과 구현 안내다. 생성 과정에서는 Android 소스를 수정하지 않았다. 실제 대상 앱의 공통 컴포넌트와 내비게이션을 사용한다. 별도 웹페이지를 만들거나 전체 PNG를 앱 화면으로 붙이지 않는다.

기준: `01-screens`의 16개 PNG와 같은 이름의 SVG. 대표 비교는 `02-boards/01-wallet-and-detail.png`. 분리 부품은 `03-components`에 있다.

## 2. 현재 코드에서 확인한 내용

이번에 읽은 소스는 `stepup-stage9`다. 적용 작업장의 코드가 달라졌으면 다음 대응 지점을 다시 확인한다.

| 위치 | 현재 역할 |
| --- | --- |
| `ui/screens/rewards/RewardsScreen.kt` | `WalletScreen`, 잔액, 누적 적립·사용, 원장 목록, GIWA 준비 안내 |
| `ui/screens/rewards/RewardsViewModel.kt` | `totals`, `ledger`를 nullable StateFlow로 제공 |
| `data/repo/RewardRepository.kt` | 잔액/누계, `ledger(limit = 100)` |
| `data/local/Daos.kt` | `observeTotals()`, `observeLedger(limit)` |
| `data/local/Entities.kt` | `RewardEntity(id, timestamp, type, amount, description)`, `RewardType` |
| `ui/StepUpRoot.kt` | `Routes.WALLET`, 기존 뒤로 가기 연결 |
| `ui/AppChromePolicy.kt` | 지갑을 내 정보 하위 상세로 분류 |
| `ui/screens/settings/ConnectedAccountsScreen.kt` | 확인한 버전에서는 지갑 연결이 준비 상태 |

위 경로에는 `app/src/main/java/com/stepup/android/`가 앞에 붙는다.

**원장에서 확인한 집계 규칙**:

- 잔액: 전체 `amount` 합계.
- 누적 적립: 양수 `amount` 합계.
- 누적 사용: 음수 `amount`의 절댓값 합계.
- 정렬: `timestamp DESC, id DESC`.
- 기존 적립 합계에는 거래·반환 등 양수 기록도 포함될 수 있다. 이를 전부 `러닝으로 번 SUP`로 바꾸지 않는다.

현재 코드는 첫 목록을 최대 100건 조회한다. 이번 필터·전체 내역 탐색·행 상세·명시적 실패 상태는 UI와 조회 연결을 보완해야 하는 항목이다. 문서에 있다고 구현되어 있는 것으로 간주하지 않는다.

```text

보유 SUP

누적 적립 103.07             누적 사용 20.00

WEB3 지갑                           >
연결 상태에 맞는 짧은 문구

이용 내역                           최근순
[전체] [적립] [사용]

걷기·러닝 적립                    +3.50

기존 공통 하단 메뉴 · 내 정보 선택
```

화면 전체 본문은 세로 스크롤한다. 상단 제목과 공통 하단 메뉴는 기존 앱 정책을 따른다. 16번은 같은 목록을 아래로 읽은 상태이며 별도의 `이전 내역` 페이지를 만들지 않는다.

잔액·누계는 필터를 바꿔도 같은 전체 기준을 유지한다. `최근순`은 설명이며 이번 시안에서 정렬 메뉴가 아니다. 원장에 없는 달별 합계나 출금 가능한 금액을 새로 추정하지 않는다.

| 장면 | 조건과 동작 |
| --- | --- |
| 01 연결 전 | 실제 연결 기능을 제공할 수 있고 연결되지 않은 상태. 연결 행 → 기존 혜택 안내 |
| 02 연결 완료 | 실제 유효한 연결이 확인됨. 행 → 14 연결 상태 모달 |

적립 내역만 없는 경우는 08과 같은 빈 상태 부품에 `적립 내역이 없어요`를 사용한다. 예시 외 새 화면을 임의로 추가하지 않는다. `확인`, X, 시트 바깥, 시스템 뒤로 가기는 열린 모달만 닫고 기존 필터와 스크롤 위치로 돌아간다.

## 5. 내역 데이터와 필터

- 필터는 **전체 원장을 기준으로** 적용한다. 처음 읽은 100건에 사용 내역이 없다는 이유만으로 `사용 내역이 없어요`를 확정하지 않는다.
- 로컬 원장이 기준이면 DAO에서 필터와 페이지 조건을 적용하거나 전체 조회 범위를 명확하게 확보한다. 서비스가 별도 페이지 API를 제공한다면 같은 필터와 커서 기준을 사용한다.
- 페이지를 추가할 때 `timestamp`와 `id`를 함께 정렬 기준으로 사용해 동일 시각 기록이 중복·누락되지 않게 한다. 추가 조회가 끝나기 전까지 더 오래된 기록의 존재 여부를 단정하지 않는다.
- 원장 ID를 안정된 목록 키로 사용한다. 필터 변경과 재시도 때문에 기록을 새로 적립하거나 차감하지 않는다.
- 양수는 `+`, 음수는 `−`, 정확히 0인 항목은 `0.00`으로 표시한다. 0인 항목이 실제로 있다면 전체에서만 보이고 적립/사용으로 분류하지 않는다.
- 숫자 표시는 기존 정밀도와 반올림 정책을 따른다. 예시는 소수점 두 자리이며 합계를 화면 문자열로 다시 계산하지 않는다. `-0.00` 같은 표시를 피한다.
- 일시는 저장된 timestamp를 사용자 시간대로 표시한다. 전체 일시는 상세에서 연도까지 보여준다. 오래된 연도의 목록 행도 연도를 생략해 혼동시키지 않는다.
- 종류 이름은 기존 `RewardType` 매핑을 재사용한다. 모르는 유형은 `기타 내역`으로 보이고 실제 설명을 상세에서 읽을 수 있게 한다.
- 같은 유형의 걷기·러닝을 구분할 근거가 없으면 `걷기·러닝 적립`으로 표시한다. 원장에 없는 km·페이스·보상 배율을 붙이지 않는다.

필터와 목록 조회는 누계 조회와 구분해 상태를 가진다. 새 데이터 조회에 실패했지만 기존 값이 남아 있는 경우, 마지막 값임을 알 수 있게 작은 `이전 확인 내역` 안내를 붙이고 값을 현재 성공 응답처럼 보이지 않게 한다. 11번은 누계가 정상 조회된 예시다.

## 6. 상세 모달

모달은 선택한 `RewardEntity`를 기준으로 한다. 큰 금액, 종류, 구분, 날짜·시간, `description`만 표시한다. 잔액 변화 전후나 트랜잭션 해시, 블록체인 확정 상태, 연결된 러닝 상세 링크를 현재 모델에 있는 것처럼 만들지 않는다.

설명이 비어 있으면 `내용` 행을 생략한다. 긴 설명은 줄바꿈하며 모달 내용을 스크롤한다. 짧은 설명 때문에 모달 높이를 반드시 동일하게 유지할 필요는 없지만 버튼은 화면 안에 있어야 한다. 행을 누른 뒤 목록이 갱신돼도 다른 원장 ID의 내용이 섞이지 않게 한다.

시안의 `신발 강화 −20.00`은 기존 `SPEND_UPGRADE` 유형의 **과거 기록 예시**다. 강화 화면을 새로 만들거나 강화 가격을 20 SUP로 정하지 않는다. 기존 마켓·기타 사용 이력 역시 표시용 데이터로 보존하고 해당 기능의 재도입 버튼을 붙이지 않는다.

## 7. WEB3 연결: 실제 제공 상태에 맞게

현재 확인한 코드에서는 GIWA 연결과 출금이 지원되지 않는 안내를 표시한다. **그 상태라면 12번을 구현한다.** 목표 시안의 연결 전/후 화면을 보여주려고 로컬 boolean, 가짜 주소, 성공 타이머, 가짜 QR을 넣지 않는다.

적용 대상 앱에 실제 연결 기능이 준비되어 있다면 그 서비스의 상태로 01/02/15를 사용한다. 연결 기능이 없다는 이유로 SUP 잔액과 원장 UI 작업 전체를 멈출 필요는 없다. 연결 기능 신규 구현은 디자인 적용과 구분해서 보고한다.

| 서비스 상태 | 표시 |
| --- | --- |
| 연결 기능 미제공 | 12 준비 중, 클릭 없음 |
| 연결 상태 확인 중 | 09의 연결 행 문구 재사용, 연결 여부 단정 안 함 |
| 미연결·연결 가능 | 01 |
| 실제 유효 연결 | 02 |
| 기존 연결 재승인 필요 | 15 |
| 연결 상태 조회 실패 | 행의 보조 문구 `연결 상태를 확인하지 못했어요`, `다시 확인` 텍스트 동작 |

SUP 잔액/원장, 지갑 세션, 뽑기 기회는 서로 다른 상태다. 연결 취소나 만료로 SUP를 0으로 만들거나 원장을 비우지 않는다. 앱 로그인과 WEB3 연결을 동일시해 로그아웃시키지 않는다.

주소·체인·지갑 제공자가 이번 시안에 보이지 않는 것은 현재 확정되지 않은 연동 정보를 만들어내지 않기 위해서다. 실제 계정 확인/승인 UI는 기존 SDK나 지갑 앱에서 제공한다. 앱이 이미 지원하는 계정 관리 기능을 삭제할 근거로 이 시안을 사용하지 않는다.

## 8. 기존 연결 모달 재사용과 복귀 위치

`04-reused-connection`은 이전 신발 뽑기 디자인에서 가져온 참조다. 화면 이미지의 배경은 신발 뽑기다. **지갑에서 열 때는 현재 지갑 화면 위에 분리 모달을 올린다.** 재사용 참조 전체 PNG를 그대로 화면에 붙이지 않는다.

| 지갑에서 누르는 동작 | 재사용 자료와 결과 |
| --- | --- |
| 01 WEB3 지갑 | `06-wallet-benefit-sheet` / `sheet-wallet-benefit` |
| 연결하기 | 실제 SDK → `07-wallet-connecting` / `sheet-wallet-waiting` |
| 사용자가 연결 취소 | 원래 지갑 01로 복귀. 오류를 억지로 표시하지 않음 |
| 실제 연결 실패 | `09-wallet-connect-failed` / `sheet-wallet-failed` → 다시 연결 |
| 최초 연결 + 선물 지급 확인 | `08-wallet-connected` / `sheet-wallet-success` |
| 연결 성공, 선물 지급 미확인 | `25-wallet-reward-pending` / `sheet-grant-pending` |
| 15 재연결 | 대기·실패 모달 재사용. 최초 선물 재지급 없음 |

호출 위치를 `wallet`로 유지한다. 성공 모달의 `뽑기 화면으로` 등 명시적인 버튼은 기존 신발 뽑기로 이동한다. X·바깥·뒤로 닫기는 지갑으로 돌아와 실제 연결 상태만 갱신한다. `상급으로 1회 뽑기`가 있는 재사용 성공 모달에서는 기존 뽑기 요청 흐름으로 한 번만 이동한다. 연결이 성공했다는 이유로 자동으로 뽑지 않는다.

`24-wallet-reconnect`는 기존 연결 해제 상태 참고 화면이다. 지갑 첫 화면에서는 새 15번 배치를 쓰고, 재연결 처리와 기존 기회 보존 규칙을 가져온다.

## 9. 뽑기 정책과 SUP의 구분

사용자가 정한 규칙을 그대로 유지한다.

- 첫 가입: 무료 뽑기 10회.
- 매일: 무료 뽑기 3회.
- WEB3 지갑 연결: 추가 상급 뽑기 10회.
- 연결된 회원: 인정된 러닝 1km당 상급 뽑기 1회.

상급 뽑기 기회를 SUP 원장에 `+10 SUP`로 기록하지 않는다. 뽑을 때 SUP를 차감하거나 SUP 구매·충전 화면을 붙이지 않는다. 지갑 연결 성공과 선물 지급 성공은 따로 확인한다. 연결 선물의 중복 방지와 기존 뽑기 패키지의 지급 확인/재시도 규칙을 그대로 사용한다.

지급 기준 시각, 거리 인정·반올림, 이월·소멸 등은 실제 서비스 규칙을 따른다. 이번 지갑 디자인으로 새 값을 정하지 않는다. 출금·송금·교환·현금 가치·1:1 전환·가격 차트는 추가하지 않는다.

| 연결 행 | 카드 아래 16dp 이상, 작은 아이콘과 두 줄 설명 |
| 이용 내역 제목 | 18sp / 600 |
| 필터 | 35dp 시각 높이, 48dp 이상 터치 영역. 선택된 것만 밝은 면 |
| 목록 행 | 기준 80dp, 제목 16sp / 600, 날짜 12.5sp |
| 금액 | 19sp / 600, 오른쪽 정렬. 양수 `#A3BFFE`, 음수 밝은 중립색 |
| 상세 모달 | 표면 `#111D2E`, 상단 반경 27dp |
| 주 버튼 | 높이 54dp, 반경 17dp, 흰색 면과 짙은 글자 |

카드 배경은 `balance-background.svg`를 재사용할 수 있다. 카드 오른쪽 선은 장식이며 금융 차트나 지도 기능을 연결하지 않는다. 그래픽은 모서리 안에서 잘린다. 숫자·단위·누계는 네이티브 텍스트다.

큰 금액은 단위를 다음 줄로 보내거나 카드 높이를 늘린다. 장식을 줄일 수 있지만 숫자를 잘라 숨기지 않는다. 긴 내역 제목과 큰 글자에서는 행 높이가 늘어나고 금액과 제목 영역이 겹치지 않게 한다. 공통 하단 메뉴·상단바를 화면별로 새로 구현하지 않는다.

## 11. 상태와 접근성

원장 조회 자체는 적립·차감 작업이 아니다. 재시도에 쓰기나 보상 지급을 연결하지 않는다. nullable 초기 상태, 실제 빈 목록, 예외, 연결 미제공을 구분한다. 로컬 데이터 조회 실패를 무조건 인터넷 오류로 안내하지 않는다.

빈 화면에서도 뒤로 가기와 하단 메뉴는 사용할 수 있다. 오류 상태에서 모달을 닫아도 오류 안내와 재시도 진입점이 사라지지 않는다. 페이지 오류는 기존 목록을 지우지 않는다.

행 전체와 작은 아이콘은 최소 48dp 터치 영역으로 제공한다. 필터는 선택 상태를 접근성 속성으로 알린다. 금액 부호와 구분 텍스트로도 적립/사용을 구분하며 색만 의존하지 않는다. 스크린리더는 종류 → 일시 → 금액 순으로 읽는다.

모달이 열리면 배경 탐색을 막고 제목으로 초점을 이동한다. 닫으면 실행한 행/버튼으로 돌아간다. 회전·글자 확대·작은 화면에서도 내용과 버튼은 스크롤로 접근 가능해야 한다. 지속적인 숫자 카운트업, 반짝임, 가짜 진행률은 넣지 않는다.

## 12. 검수 기준

1. 내 정보 → 지갑 → 내역 상세 → 닫기 → 기존 스크롤 복귀.
2. 전체/적립/사용 필터가 누적 잔액을 바꾸지 않으며 100건 바깥의 내역도 정확히 처리.
3. 같은 timestamp의 기록 순서, 다음 페이지 중복·누락, 필터 전환 중 응답 순서 확인.
4. 빈 원장, 사용 내역만 없음, 누계만 성공, 전체 실패, 다음 페이지 실패를 구분.
5. 재시도나 지갑 연결 때문에 SUP 원장을 쓰거나 재보상을 지급하지 않음.
6. 실제 연결 미제공이면 12 사용. 연결 성공·실패·취소·재연결·선물 확인 지연은 실제 서비스 상태에 맞게 표시.
7. 기존 무료 뽑기와 상급 기회 정책 유지. SUP 잔액과 뽑기 횟수는 별도 상태.
8. 기존 과거 거래/사용 기록과 계정·저장소 식별자 보존.
9. 큰 숫자, 긴 설명, 다른 연도, 글자 확대, 화면 읽기 확인.
10. 시안의 원장은 `103.07 − 20.00 = 83.07`이며 예시일 뿐 운영 데이터로 삽입하지 않음.
