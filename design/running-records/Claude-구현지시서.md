# StepUp 내 러닝 기록 / 지난 러닝 상세 — 구현 지시서

첨부 PNG와 SVG를 기준으로, 기존 앱의 내 정보 → 내 러닝 기록 흐름을 구현한다. 첫 화면 ‘러닝 패스’에서 선택한 색상과 글꼴을 이어받는다. 새 웹페이지나 새로운 디자인 변형을 만들지 않는다.

## 2. 시각 기준

기준 크기 390 × 844, 좌우 여백 24. 배경 `#050912`, 흰색 `#F2F4FC`, 보조 글자 `#98A8C0`, 파란 강조 `#A3BFFE`. Pretendard 400/600 사용.

- 머리글 21sp/600. 뒤로 버튼과 우상단 통계는 최소 48dp 터치 영역을 가진다.
- 기간 행 19sp/600. 아이콘·월·화살표·기간 선택 문구가 하나의 접근 가능한 버튼이다.
- 러닝 패스 카드 342 × 134, 모서리 약 23. 선택한 기간의 거리 51sp/600, 단위 20sp, 횟수 13sp.
- 기록 행 썸네일 80 × 80, 모서리 15. 날짜 14sp, 거리 28sp/600, 단위 16sp, 시간·페이스 12.5sp. 행 간 간격 116 기준이며 큰 글자에서는 높이를 늘린다.
- 날짜 행에는 예시의 처음 세 기록만 하드코딩하지 않는다. 실제 목록을 스크롤해서 계속 볼 수 있어야 한다.
- 통계 선택 버튼 342 × 42, 선택 면은 `#273B58`. 실제 터치 영역은 최소 48dp로 넓힌다.
- 통계의 합계 49sp/600. 막대 색은 `#ACCAFF → #527EBD`; 선택하지 않은 막대는 `#304765`.
- 주 버튼 높이 54, 모서리 17, `#F7F8FF → #E8EDFA`, 글자 `#081223` 16sp/600.
- 기간 시트 모서리 28, 삭제 시트 27, 표면 `#101B2C`. 작은 기기/큰 글자에서는 시트 내용을 스크롤한다.
- 로딩 시 카드와 행 자리를 유지한다. 강한 반짝임이나 경로 점의 무한 애니메이션을 추가하지 않는다.

상태 표시줄과 시스템 홈 바는 OS가 관리한다. 공통 내비게이션은 앱의 최신 공통 컴포넌트를 재사용한다. 이번 그림은 목록/통계에는 ‘내 정보’ 탭을, 상세/지도에는 뒤로 가기를 중심으로 보여준다. 실제 구현은 공통 화면 표시 정책에서 일관되게 처리하고 화면마다 별도 하단 바를 복제하지 않는다.

## 3. 데이터 기준 — 기존 통계 화면과의 중요한 차이

현재 확인한 소스:

- `app/src/main/java/com/stepup/android/ui/screens/profile/AnalyticsScreen.kt`
- `app/src/main/java/com/stepup/android/ui/screens/profile/HistoryMapScreen.kt`
- 같은 폴더의 `ProfileScreen.kt`, `ProfileViewModel.kt`

현재 AnalyticsViewModel은 최근 세션 20개/200개와 걸음 수 기반 주간·90일 자료를 사용한다. 이번 화면은 **저장된 러닝 세션의 거리·시간·횟수**를 보여주므로 이 자료를 그대로 월 합계나 전체 기록이라고 표시하면 안 된다.

구현 시 실제 저장 구조를 확인한 뒤 다음을 맞춘다.

1. 목록은 계정과 날짜 범위로 조회하고 최신순으로 보여준다. 최근 20/200개 제한을 전체 기록처럼 사용하지 않는다. 페이징 또는 충분한 조회 API가 필요하다.
2. 기간 합계는 화면에 로드된 한 페이지의 합이 아니라 해당 기간 전체 집계다. 목록·요약·차트에 같은 기간/계정/삭제 기준을 적용한다.
3. 러닝 횟수는 저장이 완료되어 현재 기록 목록에 포함되는 세션 수다. 진행 중·저장 실패 세션을 완료 기록으로 세지 않는다.
4. 날짜는 앱에서 사용하는 사용자 시간대 기준으로 일관되게 계산한다. 월 범위는 월 시작 이상~다음 월 시작 미만이며, 주간은 월요일~일요일을 기준으로 한다. 예시는 한국 시간이다.
5. 거리 합계는 유효한 러닝 거리의 합, 운동 시간은 포함된 세션 시간의 합이다. 만보기 걸음 수로 대신 계산하지 않는다.
6. 평균 페이스는 거리와 시간이 모두 유효한 세션들의 시간 합 ÷ 거리 합이다. 각 기록의 페이스를 단순 평균하지 않는다. 거리 없는 시간 전용 기록은 러닝 횟수·총 운동 시간에 포함될 수 있지만 페이스 계산에서는 제외한다.
7. 기록이 있음에도 거리 전체가 미확인이라면 합계를 0km로 단정하지 않는다. `—`와 거리 기록 없음 안내로 표현한다. 기록이 아예 없는 경우에만 0회를 표시한다.
8. 주간 막대는 각 날짜의 러닝 거리다. 월간 막대는 1–7일, 8–14일, 15–21일, 22–28일, 29일~월말의 날짜 구간별 합계다. 이를 달력 주간이라고 잘못 표시하지 않는다.
9. 아직 오지 않은 날짜는 기록 없음/0km로 그리지 않는다. 월간 예시의 29–30일은 미래라 막대가 없고 글자가 흐리다.
10. 예시의 전체 기간과 9월 합계가 같은 이유는 예시 기록 8개가 모두 9월이기 때문이다. 실서비스의 두 합계를 같게 고정하지 않는다.

## 4. 상세와 지도

목록에서 선택한 세션 ID를 상세와 확대 지도로 전달한다. 현재 `onOpenHistoryMap: () -> Unit` 같은 계정 전체 지도 진입점만 있다면, 해당 세션을 식별할 수 있는 기존 경로/데이터 연결을 확인하고 필요한 방식으로 확장한다. 다른 기록의 지도나 전체 합산 경로로 바뀌면 안 된다.

목록 썸네일·상세 지도·확대 지도는 같은 GPS 데이터를 써야 한다. 확대 시 가로·세로를 따로 늘려 경로 모양이나 원형 마커를 찌그러뜨리지 않는다. 초기 지도 화면은 경로 전체가 보이게 맞추고, 아래 기록 요약에 경로가 가리지 않게 여백을 둔다.

첨부 지도는 기존 커뮤니티 시안의 참고 이미지와 예시 경로다. 실제 사용자의 위치도, 지도 서비스 연동도 아니다. 배포 화면은 기존 지도 공급자의 지도와 해당 러닝의 저장 좌표를 사용하고, 공급자가 요구하는 출처 표기를 유지한다. 이 과거 경로를 보기 위해 사용자의 현재 위치 권한을 새로 요구하지 않는다.

13번은 거리와 GPS 없이 운동 시간만 저장된 예외 예시다. 거리·페이스에는 `—`를 표시한다. GPS가 없더라도 다른 유효한 거리 데이터가 저장된 경우에는 해당 데이터의 실제 의미에 맞게 보여주되 GPS 측정값처럼 오인시키지 않는다.

지도 타일을 불러오지 못한 상황과 애초에 좌표가 없는 상황도 구분한다. 전자는 기록 수치와 재시도 경로를 유지하고, 후자는 13번 안내를 사용한다.

## 5. 기록 삭제와 복귀

삭제는 시안 이미지와 무관하게 실제 저장소/API의 결과로 확정한다. 처리 중에는 같은 삭제 요청을 반복하지 않게 하며, 실패하면 기록을 보존하고 16번 안내를 보여준다. 성공 후 남은 기록이 없으면 선택 기간에 따라 07 또는 08로 이동한다.

러닝 기록을 지우는 행동을 SUP 지급 취소, 뽑기 기회 환수, 보상 원장 삭제에 임의로 연결하지 않는다. 기존 서비스의 삭제 계약을 먼저 확인하고 기존 보상 정책을 보존한다. 삭제로 집계 제외되는 기준이 프로필·목록·통계에서 같아야 한다.

## 6. 상태와 접근성

- 최초 로딩, 조회 실패, 계정에 기록이 없음, 선택한 기간만 비어 있음은 다른 상태다. 각 장면 07~10과 연결한다.
- 이전 정상 자료가 있는 상태의 재조회 실패라면 기존 기록을 유지하고 재시도 안내를 덧붙인다. 새 정상 결과가 오기 전 수치를 덮어쓰지 않는다.
- 글자 확대 시 날짜/단위/페이스를 자르지 않는다. 거리 숫자 크기와 행 높이를 조절하고, 장식 면적을 먼저 줄인다.
- 막대 그래프는 가는 막대 자체만 누르게 하지 않고 날짜 칸 전체가 반응하게 한다. 좁은 7열 화면에서는 별도의 이전/다음 날짜 선택 접근성 동작도 제공한다. 날짜와 값을 읽을 수 있어야 한다.
- 기간 시트는 임시 선택과 적용 상태를 분리한다. 뒤로 가기나 외부 누름으로 기간이 바뀌지 않는다.
- 화면과 모달에서 뒤로 가기는 가장 위의 열린 단계를 먼저 닫고 이전 기간/스크롤/선택을 복원한다.

## 7. 완료 확인

첨부된 16개 장면을 기준으로 실제 앱 캡처를 비교한다. 새 기록 저장 후 목록 반영, 여러 페이지 조회, 월 경계, 0회, 거리 없는 기록, 긴 이름/큰 숫자, 확대 글꼴, 조회 및 삭제 실패, 뒤로 복귀를 확인한다. 프로젝트의 기존 필수 검사와 관련 빌드를 실행하고, 같은 수정본의 실제 앱 캡처로 결과를 제출한다.

이번 전달본은 디자인 제안이다. 시안 PNG를 실제 동작 결과로 제출하거나, 지시서의 예시 데이터를 실제 사용자 데이터로 저장하지 않는다.
