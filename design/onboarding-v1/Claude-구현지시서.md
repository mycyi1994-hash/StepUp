# StepUp 시작·로그인·첫 사용 구현 지시서

작성일: 2026-09-28. 이 전달본은 **20개 장면의 디자인·동작 명세**이며 앱 적용본이 아니다. 기존 러닝 연결 화면 4개는 참고 SVG로 별도 포함했다. 실제 앱 소스는 변경하지 않았다.

## 1. 의도

Google 로그인으로 시작하고, 처음 쓰는 사람에게는 러닝·신발·내 정보만 한 장에서 설명한다. 실제 러닝을 시작할 때 필요한 권한을 안내한다. 이미 로그인한 사람은 매번 소개 화면을 거치지 않는다.

기존 강변 이미지, 아치형 이미지 영역, 짙은 남색과 흰색 버튼을 유지한다. 큰 문구 하나와 명확한 행동 하나에 집중한다. 튜토리얼을 위해 탭을 연속으로 자동 전환하거나 화려한 테두리를 점멸하지 않는다.

첫 사용 안내는 기존 3단계 GuideTour를 대체하는 제안이다. 한 장에 세 가지 기능을 설명하고 `러닝 시작` 또는 `먼저 둘러보기`로 끝낸다. 새로운 회원가입 단계나 프로필 입력을 추가하지 않는다.

## 3. 실제 소스와 변경 경계

경로는 프로젝트의 `stepup-stage9/`를 기준으로 한다. 적용 전에 대상 브랜치의 최신 코드를 다시 확인한다.

| 위치 | 확인한 현재 동작 | 적용 방향 |
| --- | --- | --- |
| `app/src/main/java/com/stepup/android/ui/StepUpRoot.kt` | 초기화·loginMethod·실제 세션·guideSeen으로 진입 분기. 첫 가이드 자동 실행 | 진입 조건 보존. 첫 가이드만 한 장으로 단축. 직접 링크 진입은 먼저 처리하고 가이드로 가리지 않기 |
| `ui/screens/splash/SplashScreen.kt` | 실제 준비 작업과 14초 제한, 재시도. ensureStarter·구매 복구·기존 데이터 정리 | 화면 교체만으로 준비 작업을 제거하거나 성공으로 간주하지 않기 |
| `ui/screens/login/LoginScreen.kt` | Google 하나. 취소·계정 없음·실패·연결 오류 구분 | 화면 01, 05~10의 구조와 문구로 표현. 로그인 콜백·취소 처리는 보존 |

| `data/remote/SupabaseAuth.kt` | 서버가 확인한 실제 세션 | 계정 선택 완료와 앱 로그인 성공을 구분 |

| `ui/StepPermissions.kt` | 활동·알림·위치 권한 확인. 대략적 위치 허용을 존중 | API 수준과 기존 허용 상태를 존중. 선택 권한 거절을 러닝 전체 실패로 취급하지 않기 |
| `ui/screens/settings/SupportScreen.kt`, Root의 `onOpenGuide` | 도움말에서 기존 가이드 재실행 | 화면 20 진입으로 연결하고 뒤로 가면 도움말로 복귀 |

로고·공통 배경·하단 메뉴·상태 표시를 화면별로 복제하지 않는다. 실제 구현은 공통 Wordmark/디자인 시스템과 AppChromePolicy를 사용한다. 자료 속 상태바와 홈 인디케이터는 시안 비교용이며 앱 콘텐츠에 그리지 않는다.

## 4. 앱 진입과 로그인

1. 실제 준비 중에는 03. 준비 실패·시간 초과는 04. `다시 시도`는 기존 초기화 과정을 재시도한다. 장식용 최소 대기 시간을 추가하지 않는다.
2. 로그인 정보가 없으면 01. 로그인 유지 및 실제 세션이 유효하면 로그인 화면을 건너뛴다.
3. `Google로 계속하기`를 누르면 중복 요청을 막고 실제 시스템 계정 선택창을 연다. 시스템 창이 전면에 있는 동안 앱이 별도 모달을 띄우지 않는다.
4. 계정 선택 뒤 서버 확인 동안 05. 로딩 중 버튼을 비활성화하고 진행 상태를 스크린리더에 알린다.
5. 서버 TokenResult.Ok 이후에만 loginMethod 저장 및 홈 진입. 기존 Analytics.login, pushRegistrar.syncInBackground, SessionUploadWorker.schedule 호출을 보존한다. 요청 취소 및 실패 시 로딩은 반드시 해제한다.
6. GoogleIdResult.Cancelled는 01로 조용히 돌아온다. 오류 토스트·로그인 완료·홈 진입을 표시하지 않는다. 별도 취소 화면을 만들지 않는다.
7. TokenResult.Unavailable는 06의 중립적 연결 실패 안내. 단순 통신 오류를 계정 만료로 단정하거나 저장 기록을 초기화하지 않는다. 서버 거절·기타 실패는 07. NoAccount는 08.
8. 09는 실제로 다시 로그인이 필요한 경우에만 사용한다. 재인증임을 구분할 수 있는 이유 값이 없다면 01을 사용하고 추정 만료 안내를 만들지 않는다. 다른 계정으로 로그인한 데이터를 이전 계정과 섞지 않는다.
9. 재로그인이 끝났고 가이드가 이미 완료되었으면 가이드 생략. 알림·초대·댓글 등에서 재인증한 경우 저장된 목적지로 복귀한다. 초대 수락, 글 게시, 뽑기 등을 자동 실행하지 않는다.

### 약관 링크

기존 주소를 유지한다: `https://stepupcrew.com/terms.html`, `https://stepupcrew.com/privacy.html`. 시안의 문구는 현재 앱의 안내를 유지한 것이며 법률 문서를 새로 작성한 것이 아니다. 문서 내용·현재 접근 가능 여부는 이번 디자인 작업에서 확인하지 않았다.

기존 외부 브라우저 열기를 사용하고 돌아오면 로그인 상태와 레이아웃을 보존한다. URL 열기 자체가 실패한 경우만 10의 안내를 앱 안에 표시한다. 외부 브라우저 내부의 로딩 결과를 관측하지 못하는 상황에서 앱이 성공·실패를 추정하지 않는다. 문서를 임의로 요약한 동의 화면, 필수 마케팅 체크, 가짜 약관 본문을 추가하지 않는다.

## 5. 첫 사용 안내와 홈

첫 로그인 + guideSeen=false + 정상 홈 진입이면 02를 한 번 표시한다.

| 행동 | 결과 |
| --- | --- |
| 러닝 시작 | 안내 완료를 저장하고 12의 러닝 방법 선택으로 이동. 아직 운동 기록은 시작하지 않음 |
| 먼저 둘러보기 | 안내 완료 저장 후 홈 |
| X·뒤로·바깥 영역·아래로 닫기 | 먼저 둘러보기와 같음. 다시 열림 반복 방지 |
| 앱 종료·강제 중단 | 완료되지 않은 안내를 완료로 쓰지 않음 |
| 도움말 → 앱 사용 안내 | 화면 20. 기존 guideSeen을 초기화하지 않음 |

소개 행은 설명이며 개별 버튼으로 보이도록 화살표를 붙이지 않는다. 외부 링크 목적지가 있으면 그 목적지 처리를 먼저 하고 자동 가이드는 다음 안전한 홈 진입으로 미룬다. 사용자가 보고 있는 글이나 초대를 가이드 때문에 다른 탭으로 이동시키지 않는다.

11은 **새 사용자이며 아직 걸음 권한이 없는 홈 상태**만 정의한다. 기존 사용자 전체 홈을 이 문구로 덮어쓰지 않는다. 데이터가 로딩 중이면 숫자 0을 대신 넣지 않으며, 이전에 기록이 있는 사람에게 ‘첫 러닝’이라고 쓰지 않는다. 홈의 위치·걸음·잔액은 실제 값이 준비될 때 기존 홈 디자인으로 표시한다.

12의 메뉴는 기존 확정안을 연결한 장면이다: `자유 러닝 / 러닝 챌린지 / 추천 코스 / 다이어트 모드`. 10분 러닝 항목, 키·몸무게 필수 가입 단계, 강제 크루 생성, 지갑 연결 필수 단계는 없다. 자유 러닝은 목표 입력 없이 시작하며, 필요한 권한 안내는 최초 또는 실제 권한 변경 때만 거친다.

## 6. 러닝 권한 순서

기존 WalkScreen은 여러 권한을 한 번에 요청할 수 있다. 이번 시안은 이를 **활동 → 위치 → 알림** 순서로 설명하는 제안이다. 이미 허용했거나 사용자가 이전에 선택한 선택 권한 안내는 건너뛴다. 허용된 사용자에게 매번 3장의 모달을 보여주지 않는다.

### 신체 활동

- Android 29 미만 등 런타임 요청이 필요 없는 경우 13을 생략한다.
- 자유 러닝을 선택했고 활동 권한이 없을 때 13. `권한 허용하기`만 실제 시스템 권한 요청을 실행한다.
- `나중에`, X, 바깥 영역, 뒤로는 아직 시작하지 않은 러닝 의도를 취소하고 메뉴로 복귀. 서비스와 타이머는 시작하지 않는다.
- 일반 거절은 14. 다시 허용은 재요청, 홈으로 돌아가기는 홈으로 복귀하고 pendingRun을 해제한다.
- 다시 요청할 수 없는 상태에서 15. `설정 열기`는 앱의 시스템 설정을 연다. 최초 미요청도 shouldShowRequestPermissionRationale=false일 수 있으므로 **실제 요청 이력과 결과를 함께** 판단한다. 최초 요청 전부터 설정으로 보내지 않는다.
- 설정 복귀 시 권한을 재조회한다. 허용되었다면 사용자가 선택했던 러닝 준비를 이어간다. 거절 상태는 그대로 보여준다. 다른 화면으로 이동하여 pendingRun이 취소된 경우에는 자동 러닝 시작 금지.

### 위치

- 16은 **자유 러닝의 경로 기록**용이다. 추천 코스 진입의 ‘내 위치에서 코스를 찾아요’ 안내는 기존 코스 패키지 L01을 유지한다. 추천 코스를 위치 없이 찾았다고 표시하지 않는다.
- `위치 허용하기`는 현재 OS에 맞는 위치 요청을 연다. Android 12+에서는 정확한 위치 단독 요청 문제를 피하도록 실제 권한 API 구성을 확인한다.
- 위치가 허용되어도 실제 GPS fix를 받기 전에는 경로가 준비되었다고 표시하지 않는다. GPS 확인 화면은 기존 L03으로 연결한다.
- 대략적 위치만 허용한 사용자는 17에서 그 상태를 안내하고 그대로 계속 가능. 매 러닝마다 정확한 위치로 바꾸도록 요구하지 않는다.
- 위치 요청을 거절했다면 18. `경로 없이 계속`은 선택적인 알림 단계 또는 기존 자유 러닝 흐름으로 이동. `위치 설정 열기`는 설정으로 이동.
- 16에서 직접 `경로 없이 계속`을 눌렀다면 이미 의도가 명확하므로 18을 다시 보여주지 않는다.
- 앱 밖의 설정에서 돌아오면 재조회하고 허용 상태에 맞춰 이어간다. 거절·설정 열기 실패·상태 변화 없음도 처리 가능해야 한다.
- 기존 R02_TIME의 **시간 중심 표시**를 재사용한다. 측정되지 않은 GPS 거리와 페이스를 정확한 값처럼 표시하지 않는다. 센서 추정 값의 저장/계산 정책은 이번 디자인에서 변경하지 않는다.

### 알림

- Android 33 미만 또는 OS 알림 권한이 이미 있으면 19를 생략한다.
- `알림 허용하기`만 실제 OS 알림 요청을 실행한다. 허용 또는 거절 결과 이후에는 진행 중이던 러닝 시작 흐름을 계속한다. 거절은 별도 오류 모달이 아니다.
- `나중에`는 권한 요청 없이 러닝 시작으로 진행. 이 선택을 매번 다시 묻지 않는다. 나중에는 설정에서 변경한다.
- 앱 내부 알림 선호와 OS 권한은 별개다. OS 허용을 받았다고 사용자가 끈 앱 내부 선택 값을 모두 켜지 않는다.
- 이 시트의 X/바깥 영역/뒤로는 **준비 흐름 취소 후 메뉴 복귀**로 처리한다. `나중에`의 계속 진행과 구분한다. 닫기를 눌렀는데 러닝이 갑자기 시작되지 않게 한다.

모든 권한 단계에서 화면 회전, 앱 복귀, 콜백 중복, 재구성으로 세션을 두 번 시작하지 않도록 한 번의 run intent를 사용한다. 최종 진행은 기존 R01 → R02/R02_TIME으로 이어진다. 운동 서비스 시작 시점은 기존 러닝 카운트다운/타이머 정책과 하나로 묶고, 안내 진입만으로 서비스를 시작하지 않는다.

## 7. 스타일·모션·접근성

390×844는 기준 캔버스다. 가로 여백 24, 본문 14~16, 화면 제목 19, 큰 제목 28~35, 기본 버튼 54/모서리 17, 시트 상단 모서리 27을 사용한다. 시트 본문은 내용 기반 높이와 스크롤로 구현한다. 작은 화면/큰 글자에서 제목과 닫기 버튼이 겹치지 않게 제목 영역 오른쪽에 여유를 둔다.

흰색 Google 버튼은 현재 앱의 공식 G 자산을 그대로 사용하며 변형·새 로고 제작을 하지 않는다. 제공된 Pretendard는 앱 문구 편집용이고 실제 Google 버튼의 브랜드 스타일과 공식 자산 요구사항은 구현 시 유지한다. 기존 패키지의 흰 StepUp 로고를 사용하되 공통 Wordmark에서 관리한다.

권한 아이콘은 의미를 돕고 상태는 글자로 설명한다. 아이콘만으로 실패/허용 상태를 구별하지 않는다. 닫기·약관·보조 행동의 실제 터치 영역은 최소 48dp. 스크린리더는 화면 제목 → 설명 → 주 행동 → 보조 행동 순으로 읽는다. 모달 뒤 화면은 읽거나 누를 수 없고 모달이 닫히면 원래 진입 버튼으로 포커스가 돌아간다.

모션은 앱 진입 불투명도 180ms, 시트 220ms 내외, 버튼 피드백 정도로 제한한다. 로딩은 실제 대기 중에만 표시한다. 동작 줄이기는 이동을 끄고 즉시 표시 또는 짧은 불투명도 변화로 대체한다. **이 패키지는 정적 시안이며 실행 가능한 애니메이션 파일은 포함하지 않는다.**

## 8. 보존할 기능과 구현 범위

기존 계정·DataStore·세션 ID·기록·보유 신발·SUP를 초기화하지 않는다. 초기화 시 ensureStarter 등 기존 작업을 재로그인마다 새 선물 지급처럼 실행하지 않는다. 첫 로그인 화면에서 무료 10회를 ‘이미 지급’했다고 표시하지 않는다. 무료/상급 뽑기 정책과 WEB3 연결 상태는 기존 뽑기 전달서에서 처리한다.

OAuth 클라이언트 ID, nonce, 토큰, 서버 세션, 업로드 큐를 디자인 편의로 바꾸지 않는다. 인증 토큰을 로그나 디자인 검수 이미지에 노출하지 않는다. 공통 레이아웃 정책에서 로그인/시작 화면에는 하단 탭을 숨기고, 홈에는 러닝 탭, 도움말 가이드는 설정의 부모 경로를 지정한다.

신규 필요한 상태는 기존 guideSeen과 충돌 없이 설계한다: 미요청/요청 이력, 선택 권한 안내를 나중에로 넘김, pendingRun, 로그인 복귀 목적지. 영구 권한 허용 값을 앱 자체 플래그로 대신하지 않고 OS에서 재조회한다. 단순 렌더러의 예시 상태를 운영 데이터로 저장하지 않는다.

## 9. 적용 후 확인할 기준

- 새 설치: 초기화 → Google 로그인 → 한 장 안내 → 홈/러닝 메뉴. 홈 보기만으로 권한창이 뜨지 않음.
- 기존 사용자: 세션 유효 시 로그인·첫 안내 생략. 재인증 후 기록과 원래 목적지 보존.
- 로그인 취소/실패/오프라인/계정 없음/중복 탭/화면 회전: 로그인 완료로 오인하지 않고 버튼이 복구됨.
- 약관 양쪽 링크: 열기와 복귀, 열기 자체 실패 처리. 승인되지 않은 로그인 생략 경로 없음.
- 첫 안내의 모든 닫기 경로: 홈 복귀, guideSeen 보존. 도움말에서 다시 보기 가능.
- 활동 권한: 최초, 재요청 가능 거절, 재요청 불가 거절, OS 설정 복귀 모두 정확히 분기.
- 위치: 정확/대략/거절/GPS 대기 구분. 선택 권한 거절로 자유 러닝 전체가 막히지 않음.
- 알림: 허용/거절/나중에 이후 한 번만 러닝 시작. 닫으면 시작하지 않음.
- 회전/백그라운드/복귀/뒤로를 반복해도 세션 이중 생성이나 guide 자동 재실행 없음.
- 320~430dp 폭, 큰 글자, 스크린리더, 동작 줄이기에서 중요한 버튼과 약관 링크가 접근 가능.
- 대상 프로젝트 AGENTS.md에 따른 디자인 계약·문자열/리소스 검사와 관련 테스트 및 실제 기기 캡처 수행. 시안 렌더링을 앱 검증으로 대체하지 않음.

## 10. 편집 자료의 범위

SVG는 텍스트와 도형을 편집할 수 있다. 사진·로고·Google G는 포함된 원본 비트맵이다. `03-components`는 버튼·안내 시트가 분리되어 있다. Figma에 SVG를 가져올 수 있지만 **네이티브 Auto Layout/Variant/프로토타입 링크가 만들어진 Figma 파일은 아니다.** SVG를 화면 전체 이미지로 앱에 넣지 말고 실제 버튼·텍스트·모달로 구현한다.
