# StepUp 설정 구현 지시서

작성일: 2026-09-28. 이번 전달 범위는 **디자인 시안 28개와 구현 기준**입니다. 이 패키지 제작 과정에서는 앱 소스를 수정하지 않았습니다.

## 1. 목표와 구성

러닝 패스에서 이어지는 설정을 간결한 목록으로 만듭니다. 카드와 장식을 늘리는 대신 항목 이름·현재 값·눌러야 할 곳을 분명히 표시합니다. 세부 설명과 위험한 작업의 확인은 진입한 화면에서 제공합니다.

설정 첫 화면의 순서는 다음과 같습니다.

| 그룹 | 항목 | 동작 |
| --- | --- | --- |
| 러닝과 알림 | 하루 걸음 목표 | 목표 조절 바텀시트. 현재 걸음 수 표시 |
| 러닝과 알림 | 알림 | 기존 네 가지 알림 설정 |
| 러닝과 알림 | 개인정보·앱 권한 | 권한 상태, 저장 정보 안내, 로컬 알림 기록 정리 |
| 앱 사용 | 언어 | 현재 언어 표시, 선택 즉시 적용 |
| 앱 사용 | 화면 테마 | 현재 모드 표시, 선택 즉시 적용 |
| 앱 사용 | 소리·진동·동작 | 효과음·환경음·진동·동작 줄이기 |
| 계정과 도움말 | 연결된 계정 | 로그인·외부 연결 상태와 계정 삭제 |
| 계정과 도움말 | 도움말·문의 | FAQ·기존 앱 가이드·문의 방법 |

프로필 수정과 지갑은 기존 러닝 패스 진입점을 유지합니다. 이 목록에 다시 중복 배치하지 않습니다. 마켓·도감·강제 크루 생성·등급 배지를 추가하지 않습니다.

확인한 코드의 설정은 프로필 내부 탭에 흩어져 있습니다. 독립적인 첫 목록 경로가 필요하면 기존 라우팅 방식으로 추가하고 AppChromePolicy·화면 목록도 함께 갱신합니다. 기존 하위 경로를 활용합니다. 공통 상단·하단 메뉴를 화면마다 중복 구현하지 않습니다. 선택된 상위 탭은 ‘내 정보’입니다. 각 하위 화면에서 뒤로 가면 설정 목록의 이전 위치로 돌아갑니다.

새로 다듬는 동작은 설정 첫 목록, 목표의 ±500 버튼, 로컬 알림 삭제 확인, 문의 메일/주소 복사, 공통 오류 표현입니다. 기존 기본값·보상 계산·계정 정책을 바꾸는 작업이 아닙니다.

## 3. 알림과 저장 상태

`NotifyPrefs`의 push / goalReminder / partyInvite / eventNews를 그대로 대응시킵니다. 기본값은 기존 값을 유지합니다. 시안의 이벤트 소식 OFF는 예시 사용자 상태입니다. push를 다른 세 항목을 함께 끄는 새 마스터 스위치로 해석하지 않습니다. ‘러닝 초대’는 기존 크루·파티 초대 설정의 표시 이름입니다.

설정은 바꾸면 즉시 저장합니다. 별도 저장 버튼을 추가하지 않습니다.

1. 로컬 저장에 성공한 뒤 ‘이 휴대폰에 저장했어요’라고 알립니다.
2. 기존 `pushRegistrar.syncPrefsInBackground()`로 서버 반영을 이어갑니다.
3. 서버 반영을 확인하지 못하면 04 안내를 유지합니다. 새 로컬 값은 보존하고 서버 성공으로 표시하지 않습니다. ‘다시 반영하기’는 동기화 재시도입니다.
4. 로컬 저장 자체가 실패하면 05처럼 직전 저장값을 유지/복원합니다. 토글이 바뀐 채 성공처럼 남지 않게 합니다.
5. 저장·동기화 중 연타가 중복 요청이나 오래된 값의 덮어쓰기를 만들지 않게 순서를 관리합니다. 작업 취소 예외는 정상 오류와 분리합니다.

`storedPrefs == null`일 때는 25 로딩을 사용합니다. 임시 기본 토글을 실제 저장값처럼 보여주지 않습니다. 조회 실패는 26과 재시도를 사용합니다. 전체 데이터가 없을 때와 서버 동기화만 지연된 상태를 구분합니다.

OS 알림 허용 여부는 NotificationManagerCompat로 별도 확인합니다. 앱의 push가 켜져 있어도 OS에서 차단되면 03 안내와 휴대폰 설정 열기를 제공합니다. 앱 토글을 임의로 OFF로 바꾸지 않습니다. OS 설정에서 돌아오면 ON_RESUME에 다시 조회합니다. OS 권한 승인 여부를 앱 설정 저장 성공으로 간주하지 않습니다.

## 4. 개인정보·앱 권한

활동 인식, 위치, 알림의 실제 상태를 읽습니다. 위치는 정확한 위치 / 대략적인 위치 / 허용 안 됨을 구분합니다. 상태 행은 앱 내부 토글이 아닙니다. 변경은 기존 ExternalIntents의 휴대폰 앱 설정 열기로 이어갑니다. 복귀 후 갱신합니다.

08 ‘저장하는 정보’는 보관 범위의 짧은 설명입니다. 기존 개인정보 처리방침이나 동의 화면을 대체하는 새 정책이 아닙니다. 기존 상세 안내와 정책 진입이 있으면 보존합니다. 데이터 보유 기간이나 수집 항목을 시안으로 새로 정하지 않습니다.

09 ‘알림 기록 지우기’의 대상은 `notificationRepository.clearAll()`로 지우는 **이 휴대폰의 일반 알림 내역**입니다. 기존 clearExceptPendingActions처럼 미처리 CREW_INVITE·PARTY_INVITE·EVENT_REWARD는 남기며, 남은 알림의 읽음 표시는 기존 저장소 동작을 따릅니다. 이름이 비슷해도 markAllRead는 삭제를 수행하지 않는 별도 동작입니다. 러닝·SUP·신발·서버 계정·OS 권한을 지우지 않습니다. 처리 중에는 버튼에 ‘지우는 중…’을 표시하고 중복 요청을 막습니다. 성공한 뒤에만 10 토스트를 표시합니다. 실패하면 27에서 다시 시도하거나 닫을 수 있게 합니다. 삭제 범위를 넓히지 않습니다.

## 5. 연결된 계정과 계정 삭제

`sessionHolder.isSignedIn()`이 확인한 상태만 표시합니다. 조회 중에는 확인 중으로 표시하고 삭제 메뉴는 숨깁니다. 로그인 전 상태는 12를 사용합니다. 데이터에 없는 로그인 제공자·이메일을 만들어 표시하지 않습니다.

현재 소스의 GIWA 및 Health Connect는 사용 불가 상태입니다. 시안의 WEB3 지갑과 건강 데이터도 실제 제공 여부에 맞춰 ‘준비 중’을 유지합니다. 단순 탭으로 연결 완료 상태를 만들지 않습니다. 실제 연결 기능이 제공되는 경우 이전 지갑/뽑기 연결 전달본의 흐름을 재사용합니다.

13에서 서버에 삭제되는 정보를 먼저 설명합니다. 기존 `server.deleteAccount()`의 account_delete 결과를 따릅니다. 서버 러닝·GPS·SUP 원장·글/댓글·코스·땅 표시 삭제 범위와 되돌릴 수 없음을 보존합니다. 크루장 사용자에게는 기존 정책의 ‘가장 오래된 크루원에게 크루장이 넘어감’ 안내를 조건부로 표시합니다. 휴대폰에 남는 기록과 서버 삭제를 혼동하지 않습니다.

14는 삭제 요청 처리 중입니다. 중복 요청을 막고 요청 결과를 기다립니다. 실제 ServerResult.Ok 이후에만 기존 signOut·loginMethod 초기화·로그인 전 화면 이동을 수행합니다. 성공 도착 화면은 기존 진입/로그인 화면을 재사용합니다.

응답이 끊겨 처리 결과를 알 수 없으면 15를 사용합니다. 실패 또는 완료로 단정하거나 파괴적 요청을 자동 반복하지 않습니다. 로그인/로컬 기록을 임의로 초기화하지 않습니다. 권위 있는 결과 확인 방법이 실제로 있을 때만 그것을 사용합니다. 현재 코드에 없는 조회 API를 있다고 가정하지 않습니다. 결과를 확인할 수 없으면 문의/닫기 경로를 제공합니다. 서버가 처리하지 않았음을 명확히 확인한 실패는 기존 확인 창에 오류 문구와 재시도를 제공할 수 있습니다.

## 6. 테마와 언어

테마 SYSTEM / DARK / LIGHT의 기존 키를 유지합니다. 시안의 순서 변경은 데이터 값 변경이 아닙니다. AppTheme.change로 즉시 반영하고 기존처럼 UI 생명주기와 독립적인 저장을 사용합니다. 테마 변경 때문에 Activity를 불필요하게 재생성하지 않습니다. 미리보기 숫자는 고정 예시로, 실제 기록처럼 취급하지 않습니다.

언어는 SYSTEM / en / ko / zh / ja를 유지합니다. ‘휴대폰 설정 따르기’, English, 한국어, 中文, 日本語를 표시합니다. AppLocale.change와 필요한 Activity 재생성, Android의 앱별 언어 설정 대응을 보존합니다. 언어 변경 때문에 저장이 취소되거나 이전 선택으로 돌아가지 않도록 합니다. 게시물·이름 같은 사용자 작성 내용은 자동 번역하지 않습니다.

16~19는 실제 선택 후 모습을 비교하는 시안입니다. 별도 확인 창이나 저장 버튼을 추가하지 않습니다. 영구 저장이 실패한 경우 적용 중인 값과 저장된 값의 불일치를 방치하지 말고 직전 저장값 복원 및 공통 오류 안내를 제공합니다.

## 7. 소리·진동·동작

ExperiencePreferences의 sounds / ambience / haptics / reducedMotion과 기존 저장 메서드를 유지합니다. 실제 저장값을 읽은 뒤 스위치를 보여줍니다. 시안의 선택값으로 기존 기본값을 덮어쓰지 않습니다.

미리 듣기는 기존 FeedbackCue.Reward를 활용합니다. sounds 또는 haptics가 켜진 경우에만 작동하며 ambience만 켜졌다고 활성화하지 않습니다. 이 버튼은 보상을 지급하지 않습니다. 시스템 음소거·방해금지·진동 제한과 동작 줄이기 설정을 존중합니다. 미리 듣기 때문에 실제 러닝이나 뽑기가 실행되지 않아야 합니다.

## 8. 도움말·문의·걸음 목표

FAQ는 하나씩 펼칩니다. `FAQ-문구.md`를 참고하되 최신 서버/앱 규칙과 일치시킵니다. 과거 SUP 출금 조건·세션 전용 적립·유료 뽑기 문구를 다시 가져오지 않습니다. 앱 가이드는 기존 StepUpRoot의 홈 이동 → GuideTour.start 진입을 보존합니다. 가이드 자체의 새 디자인은 후속 첫 사용 단계입니다.

문의 시트는 메일 앱 열기와 주소 복사를 제공합니다. 시안 주소 `support@stepupcrew.com`은 기존 한국어 계정 삭제 오류 리소스에 있는 주소입니다. 운영 수신 가능 여부를 확인한 것은 아니므로 실제 배포에는 서비스가 확인한 문의 주소 설정을 사용합니다. 메일 앱 열기는 ACTION_SENDTO mailto 등 사용자 작성창으로 연결합니다. 자동 발송하거나 민감한 GPS/계정 정보·로그를 자동 첨부하지 않습니다. 앱 열기 성공은 문의 접수 성공이 아닙니다. 메일 앱을 열 수 없으면 28과 주소 복사를 제공합니다. 복사는 실제 성공 후에만 안내합니다.

24의 하루 목표는 기존 UserPrefs의 3,000~20,000걸음, 500걸음 단위입니다. 슬라이더를 큰 −500 / +500 버튼으로 바꿉니다. 양 끝에서 범위 밖 버튼을 비활성화합니다. 변경 즉시 기존 경로로 저장하고 닫기는 닫기만 수행합니다. 빠른 연타에서도 마지막 값이 저장되게 합니다. 실패하면 실제 저장값과 오류 안내를 보여줍니다.

예시 8,000걸음의 예상 거리 6.1km는 STRIDE_METERS 0.762, 기본 보너스 20.0 SUP는 GOAL_BONUS_PER_1K 2.5의 기존 계산에 따른 것입니다. 구현에는 기존 공식/서버 정책을 사용하고 숫자를 하드코딩하지 않습니다. 목표를 바꾸는 행위 자체로 SUP를 지급하지 않습니다.

## 9. 디자인과 접근성

- `design-tokens.json` 기준. 기본 배경 #050912, 본문 #F2F4FC, 보조 글자 #98A8C0, 파란 강조 #A3BFFE. 밝은 테마도 동일 구조를 유지합니다.
- 390 × 844는 시안 기준입니다. 화면 높이를 고정하지 말고 목록과 시트 본문을 스크롤 가능하게 만듭니다. 시스템 상태·하단 안전 영역을 반영합니다.
- 본문 좌우 24, 목록 주 제목 17, 보조 설명 13, 기본 행 높이 58, 설명 있는 행은 76~88을 시작값으로 사용합니다. 긴 번역이나 큰 글씨에는 행 높이가 늘어나야 합니다.
- 모든 실제 터치 영역은 최소 48dp. 작은 화살표·스위치·문의 시트의 보조 버튼도 이 기준을 확보합니다. 아이콘이나 시각적 버튼 높이가 더 작아도 클릭 범위는 줄이지 않습니다.
- 스위치에는 이름과 현재 상태, 선택 행에는 선택됨 의미, 오류에는 설명을 제공합니다. 색만으로 상태를 전달하지 않습니다. 중복된 행+스위치 포커스를 피합니다.
- 시트가 열리면 배경 탐색을 막고 초점을 시트로 옮깁니다. 닫으면 원래 실행 버튼으로 돌려줍니다. 취소 가능한 시트는 뒤로 가기로 닫습니다. 파괴적 요청 처리 중 중복 실행을 막되 무기한 회전 표시로 결과 미확인을 숨기지 않습니다.
- 모션은 짧은 페이드·시트 전환 정도로 제한합니다. 동작 줄이기를 적용하면 이동 애니메이션을 생략합니다. 장식용 반복 애니메이션은 추가하지 않습니다.
- SVG의 Pretendard 텍스트는 편집 가능합니다. Figma 가져오기 후 Auto Layout·컴포넌트 변형·프로토타입 연결은 별도로 구성합니다. 이 파일 자체를 이미 완성된 Figma 네이티브 라이브러리라고 보고하지 않습니다.

## 10. 구현 후 확인

저장 데이터/서버 호출을 변경하는 부분에는 해당 동작을 검증하는 테스트를 추가합니다. 단순 색·간격 변경만을 확인하는 형식적인 테스트는 만들지 않습니다. 기존 저장소의 필수 검사와 관련 테스트를 수행하고 실제 수행 결과를 보고합니다.

확인할 주요 시나리오는 다음과 같습니다.

1. 처음 진입의 로딩·조회 오류, 저장 성공·실패, 재진입 후 값 유지.
2. 알림 로컬 저장은 성공하지만 서버 반영은 실패한 경우; 재시도 후 안내 해제.
3. OS 알림 차단/허용, 대략적 위치/정확한 위치 변경 후 복귀 시 갱신.
4. 로컬 알림 기록 삭제 확인·취소·성공·실패. 러닝/SUP/신발 데이터 보존.
5. 로그인 전/후/확인 중 계정 메뉴, 외부 연결 준비 상태. 계정 삭제 중복 차단·확정 성공·확정 실패·결과 미확인.
6. 테마/언어 즉시 변경과 다시 시작한 후 유지. 영어·중국어·일본어, 큰 글씨에서도 잘림 없음.
7. 소리/진동 미리 듣기의 활성 조건과 시스템 제한, 동작 줄이기.
8. 목표 최솟값/최댓값, 빠른 연속 변경, 저장 실패. 목표 변경에 따른 보상 지급 없음.
9. 메일 앱 미설치, 주소 복사, 사용자 취소. 열기만 했는데 문의 접수 완료 표시 없음.
10. 작은 화면·큰 글씨·키보드/스크린리더·안전 영역과 공통 내 정보 탭 유지.

이번 전달본은 모든 비교 보드의 시각적 확인과 SVG/PNG 파일 검사를 마쳤습니다. 실제 앱 런타임·서버·메일 전송·권한 요청 검증을 수행했다는 뜻은 아닙니다.
