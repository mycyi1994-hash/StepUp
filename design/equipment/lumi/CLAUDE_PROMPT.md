# StepUP 루미 장비 시스템 구현 요청

첨부한 이미지 5장과 equipment-catalog.json을 읽고, 현재 StepUP 프로젝트의 홈·프로필·인벤토리에 루미의 의상/신발 장착 기능을 구현해 주세요. 먼저 프로젝트 구조와 기존 아바타 렌더링·상태·저장 방식을 확인하고 그 구조에 맞춰 작업하세요. 설명만 하지 말고 구현 가능한 부분은 실제 코드에 반영하고 검증해 주세요.

## 목표와 캐릭터 규칙

- 루미(LUMI)는 무료 기본 여성 캐릭터입니다. 캐릭터 자체를 NFT로 판매하지 않습니다.
- 의상과 신발만 별도 장착 아이템입니다. 이번 신규 디자인은 의상 5종, 기존 신발 52종입니다.
- 큰 둥근 머리, 높게 묶은 검은 포니테일과 옆머리, UP 모자, 청록빛 세로 눈 두 개, 귀여운 3D 비율을 유지합니다. 코·입을 추가하지 않습니다.
- 얼굴·귀·손·팔·다리의 노출 부위는 모두 같은 짙은 남색 피부입니다. 살색으로 바꾸지 않습니다.
- 눈·얼굴·체형·포니테일과 모자 형태는 고정합니다. 모자색은 선택한 의상에 따라 함께 변경합니다. 신발 변경은 의상이나 모자색에 영향을 주지 않습니다.
- 불·물·번개·바람은 시각적 컬렉션 분류입니다. 전투 능력치, 상성, 보상 배율 등 새로운 시스템을 추가하지 않습니다.

## 첨부 이미지 해석

1. 01_LUMI_FIRE_13.png: FIR-001~013 신발 단독 디자인과 루미 착용 참고.
2. 02_LUMI_WATER_13.png: WAT-001~013.
3. 03_LUMI_LIGHTNING_13.png: LIT-001~013.
4. 04_LUMI_WIND_13.png: WND-001~013.
5. 05_LUMI_WARDROBE_05.png: 신규 의상 LUM-CLO-001~005. 상단은 의상 단독 앞·뒤, 중단은 착용 전면, 하단은 착용 후면.

신발 시트의 13개 셀은 왼쪽에서 오른쪽, 위에서 아래 순서입니다. 마지막 행의 HOME/PROFILE은 동기화 예시이며 추가 아이템이 아닙니다. 시트의 HOME/PROFILE 각도 차이는 필수 UI 사양이 아닙니다. 두 화면에서 같은 장비가 보이는 것이 핵심입니다.

신발 시트는 추천 조합입니다: FIR은 LUM-CLO-002, WAT은 LUM-CLO-003, LIT은 LUM-CLO-004, WND는 LUM-CLO-005를 착용합니다. 이 조합을 강제하지 않습니다. 무료 기본 의상은 OUTFIT-BASE이며 새 LUM-CLO-001과 구분합니다. 의상 시트에 보이는 파란 기본 신발은 SHOES-BASE이며 WAT 아이템으로 대체 해석하지 않습니다.

이 5장은 디자인 참고 시트입니다. 투명 레이어·리깅된 모델·완성된 스프라이트 아틀라스가 아닙니다. 생성된 그림의 작은 로고·봉제선 등은 원본과 다를 수 있습니다. 신발 세부 형상과 이름·등급은 별도 제공한 기존 신발 원본 52개와 JSON을 우선합니다. 시트의 글자를 OCR해 상품 데이터를 새로 만들지 않습니다.

## 의상 목록

| ID | 이름 | 구성과 특징 |
|---|---|---|
| LUM-CLO-001 | 코어 집 / CORE ZIP | 남색 집업 후드·반바지, 코발트 대각선 패널과 청록 파이핑 |
| LUM-CLO-002 | 엠버 셸 / EMBER SHELL | 검정 기술형 재킷·반바지, 주황 불꽃형 패널 |
| LUM-CLO-003 | 타이드 아노락 / TIDE ANORAK | 흰색·로열블루 반집업 아노락, 남색 반바지, 물결 패널 |
| LUM-CLO-004 | 볼트 저지 / VOLT JERSEY | 차콜 반팔 저지·반바지, 노랑 번개와 연보라 파이핑 |
| LUM-CLO-005 | 에어로 윈드브레이커 / AERO WINDBREAKER | 흰색 바람막이·연회색 반바지, 민트 곡선 패널 |

각 의상은 상의+반바지+연동되는 모자 외형이 한 아이템인 세트입니다. 모자는 별도 슬롯이나 별도 NFT로 판매하지 않습니다. 상의/하의 슬롯을 별도로 만들지 않습니다. 신규 의상의 등급·가격·발행량·토큰 주소는 미정이므로 임의로 확정하지 않습니다. 추천 색 조합은 있어도 의상과 신발을 강제 묶지 않습니다. 5×52=260 조합을 허용하며 기본 무료 장비 조합도 지원합니다.

## 장착 상태와 화면 연동

- 공통 상태는 avatarId='LUMI', equippedOutfitId, equippedShoeId로 관리합니다. 초기 상태는 OUTFIT-BASE / SHOES-BASE입니다.
- HomeAvatar와 ProfileAvatar는 같은 AvatarRenderer와 같은 장착 상태를 사용합니다. 화면마다 별도 장착 값을 저장하지 않습니다.
- 인벤토리에서 미리보기 → 장착을 누르면 해당 슬롯만 변경합니다. 신발 변경은 의상과 모자를 보존하고, 의상 변경은 모자색까지 함께 바꾸되 신발을 보존합니다. 취소는 기존 상태를 유지합니다. 해제하면 해당 슬롯의 기본 장비로 돌아갑니다.
- 장착 직후 홈·프로필에서 같은 디자인이 보여야 합니다. 라우트 이동·새로고침 후에도 유지합니다.
- 기존 계정 저장 API가 있으면 사용하고, 없으면 개발용 localStorage 어댑터를 분리해 구현합니다. 추후 서버 교체가 쉬워야 합니다. 저장 실패 시 오류 표시와 이전 상태 복원 또는 재시도를 제공합니다.
- 아이템 정의 ID와 실제 소유 인스턴스/NFT token ID를 구분합니다. 같은 디자인을 여러 개 소유할 수 있으므로 디자인 ID를 토큰 ID로 쓰지 않습니다.
- 기존 소유권 검증이 있으면 재사용합니다. 없으면 명확한 개발용 보유 목록으로 시연하고 실제 NFT 검증이라고 표시하지 않습니다. 보유하지 않은 항목은 미리보기만 가능합니다.

## 이미지와 렌더링 자산 전략

현재 프로젝트에 3D 아바타가 있으면 동일 리그의 의상·신발 메시를 교체하는 방식을 우선합니다. 2D 프로젝트라면 고정된 동일 카메라·포즈·캔버스·발 위치를 갖는 투명 레이어 합성 방식으로 구현합니다. 5장 시트를 배경 이미지로 통째로 표시하는 것을 장착 구현이라고 처리하지 마세요.

2D의 경우 권장 자산 계약은 baseBody + outfitLayers[outfitId] + capLayers[outfitId] + shoeLayers[shoeId]입니다. 동일 캔버스와 정규화 좌표를 사용하고 가림 순서를 명시합니다. 반팔 LUM-CLO-004는 팔을 덮는 긴 소매가 남지 않도록 기본 몸체와 의상 영역을 분리합니다. 신발은 좌우 한 쌍이 필요하며 단독 상품 측면 PNG를 그대로 발 위에 얹는 것으로 완료하지 않습니다. 홈·프로필이 같은 포즈를 사용하면 하나의 레이어 세트를 공유할 수 있습니다.

상품 이미지와 착용 자산 경로를 분리합니다. catalog의 productSourceFilename은 기존 상품 원본을 찾기 위한 이름이고, runtimeAssets의 null은 아직 없는 실제 착용 레이어를 뜻합니다. 파일이 존재하고 시각 검수가 끝난 경우에만 해당 경로와 상태를 채웁니다. 경로를 임의로 만들어 로딩에 성공한 것처럼 보고하지 않습니다.

260개 전체 조합 이미지를 미리 만드는 대신 정렬된 레이어 1개 기본 몸체+5개 의상+5개 모자+52개 신발 쌍을 공유하는 방식을 목표로 합니다. 이것은 추가 자산 제작이 필요한 구현 방식이며 현재 첨부에 해당 레이어가 완성되어 있다는 뜻은 아닙니다. 포즈를 늘리면 포즈별 자산도 필요합니다.

이미지 편집/생성 기능이 있다면 시트를 바탕으로 필요한 투명 레이어를 실제 제작하고 경계·맞춤·가림을 검수하세요. 기능이 없거나 품질 확보가 안 되면 공통 상태, 인벤토리, 저장, 렌더러, 자산 검증까지 구현하고 missing-assets 목록을 정확히 출력하세요. 준비되지 않은 조합은 시각 자산 준비 중임을 보여주고, 다른 아이템의 그림을 대신 보여주며 장착 완료라고 속이지 마세요. 장착 적용 전에 필요한 자산을 확인하고 누락 시 기존 모습을 유지하세요.

단순 hue-rotate/CSS 색상 필터로 52종을 흉내 내지 않습니다. 신발마다 어퍼·끈·뒤축·밑창·트레일 러그·발광 부위가 다릅니다. 일반 등급에 레전더리 발광을 일괄 추가하지 않습니다. 앱 실행 때마다 생성 AI로 이미지를 새로 만드는 방식도 사용하지 않습니다.

## 검증과 완료 보고

1. JSON의 신발 ID가 정확히 52개이고 각 계열 13개인지 확인합니다. 의상 ID는 정확히 5개여야 합니다. '희귀'와 '레어'는 원본의 별도 등급 표기를 유지합니다.
2. 신발만 변경했을 때 의상·모자가 유지되고, 의상 변경 시 모자색이 함께 변경되면서 신발이 유지되는지 검증합니다.
3. 홈→프로필→새로고침 뒤 같은 장비인지 확인합니다. 변경된 이미지는 읽기 가능한 대체 텍스트를 제공합니다.
4. 미보유 장착 차단, 미리보기 취소, 기본 장비 복귀, 저장 오류, 이미지 로딩 실패, 잘못된 저장 ID를 확인합니다.
5. 대표 혼합 조합 LUM-CLO-002+WND-008, LUM-CLO-004+WAT-004, LUM-CLO-005+FIR-001도 확인합니다. 같은 색 계열만 허용하는 버그를 만들지 않습니다.
6. 260 조합의 자산 경로 해석 가능 여부를 검사하고, 밝은 옷·어두운 신발·반팔·두꺼운 트레일 밑창을 대표 시각 검수합니다.
7. 변경 파일, 실행 방법, 검증 결과, 실제 준비된 착용 자산 개수, 남은 자산을 구분하여 보고하세요. 디자인 시트만 존재하는 상태를 모든 조합 구현 완료라고 보고하지 마세요.


## 의상–모자 세부 기준
첨부 CAP_RULES.md의 색상 매핑과 원자적 적용 규칙을 따르세요. 기존 루노는 보존하고 루미 렌더링 자산과 상태를 avatarId 기준으로 구분하세요. 루미 의상 ID는 LUM-CLO-001~005이며 신발 디자인 ID는 기존 52종과 공유합니다. 같은 신발이라도 캐릭터별 착용 레이어는 구분할 수 있어야 합니다.
