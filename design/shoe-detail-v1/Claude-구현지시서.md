# StepUp 보유 신발 상세 구현 지시서

작성일: 2026-09-28. 시안 18개, 비교 보드 9개, 분리 부품 12개. 실제 앱 코드는 이번 제작에서 변경하지 않았습니다.

## 1. 디자인 결정

기존 신발 일러스트와 신발 전시 구도를 유지합니다. 상세에서만 이미지 크기를 조금 줄여 주요 정보와 착용 버튼을 한 화면에 놓습니다. 신발 뒤에 색이 채워진 사각형을 추가하지 않습니다. 낮은 받침, 접촉 그림자, 배경에 스며드는 조명을 별도 레이어로 사용합니다.

배경 #050912, 본문 #F2F4FC, 보조 글자 #98A8C0, 강조 #A3BFFE, 표면 #0E192A, 구분선 #1D2B3F를 사용합니다. Pretendard Regular/Semibold로 제목·숫자·본문을 구분합니다. 신발만 시각적 중심으로 두고 정보는 정렬된 글자로 표현합니다. 레이더 차트, 장식용 수치 막대, 왕관·훈장·광택 배지는 넣지 않습니다.

신발 이미지는 중앙 정렬, 두 주요 능력치는 두 열 왼쪽 정렬, 정보 목록의 값은 오른쪽 정렬합니다. 주 버튼은 흰색 ‘이 신발 신기’ 하나입니다. 착용 중에는 비활성 ‘지금 신고 있어요’를 표시합니다. 기존 상세의 ‘착용 중이면 강화 버튼으로 바뀜’ 동작을 이 새 버튼에 가져오지 않습니다.

이 문서는 보유 신발 보기와 착용 변경의 디자인입니다. 강화·판매·도감·중복 신발 합성 정책은 이번 범위 밖입니다. 새 화면에 해당 메뉴를 다시 넣지 않습니다. 동시에 기존 저장소의 다른 진입점·저장 데이터·도메인 로직을 이 이유로 삭제하지 않습니다. 별도 레거시 경로는 이번 범위 밖으로 명시합니다.

## 2. 기존 코드와의 대응

기준 루트: `stepup-stage9/app/src/main/java/com/stepup/android/`. 구현 작업장의 최신 소스도 함께 확인합니다.

| 소스 | 적용 기준 |
| --- | --- |
| `ui/StepUpRoot.kt`의 `sneaker/{id}` | 실제 소유 신발 ID로 상세 진입. 기존 부모 신발 탭 정책 유지 |
| `ui/screens/items/SneakerDetailScreen.kt` | 새 상세와 능력치·정보 시트 |
| `ui/screens/items/ItemsViewModel.kt` | 선택 목록, 실제 착용 상태, 개별 ID, 변경 중·결과 |
| `data/repo/SneakerRepository.kt` | 기존 `equip(id)` 사용 |
| `data/local/Daos.kt`의 `equipExclusively(id)` | 없는 ID가 현재 착용을 해제하지 않는 원자적 변경 보존 |
| `domain/Sneaker.kt` | 실제 번호·이름·레벨·속성·등급·능력치·획득 시각 |
| `data/repo/RewardRepository.kt` | 착용 신발에 따른 기존 적립·에너지 계산 보존 |
| `ui/components/SneakerImage.kt`, `SneakerArt.kt` | 소유 신발과 연결된 실제 아트 선택 경로 확인 |

화면의 숫자·라벨·버튼은 네이티브 UI로 구현합니다. 화면 SVG 전체를 하나의 클릭 이미지로 붙이지 않습니다. 공통 헤더·하단 메뉴는 기존 디자인 시스템과 AppChromePolicy를 사용합니다. 신발 탭 선택은 상위 경로 정책에서 관리합니다. 새 경로가 필요하면 공통 정책과 화면 목록에 함께 등록합니다.

## 3. 목록에서 상세로

01의 기존 보유 신발 썸네일을 누르면 큰 전시에 해당 신발을 보여줍니다. 파란 밑줄은 선택, 작은 체크는 실제 착용입니다. 탭만으로 equip를 호출하지 않습니다.

‘신발 자세히 보기’는 선택된 소유 ID의 상세로 이동합니다. 큰 신발을 눌러도 같은 상세로 갈 수 있지만 명시적인 텍스트 버튼을 유지합니다. 받은 신발을 보여주는 기존 뽑기 복귀 화면도 같은 선택/착용 규칙을 따릅니다.

예시는 세 모델·네 켤레입니다. 새벽 강변 아래 ‘2켤레 보기’는 07 선택 시트를 엽니다. 행을 누르면 해당 ID의 상세로 이동합니다. ‘보는 중’은 선택 상태만 뜻합니다. 실제 착용한 사본에는 별도의 ‘신고 있음’ 텍스트/체크를 표시합니다. 표시만을 위해 다른 사본의 ID를 덮어쓰지 않습니다.

기존 ItemsViewModel의 그룹 키는 속성×등급×변형입니다. 그룹 대표는 착용 중 사본, 없으면 기존 대표 선택 로직을 활용합니다. 상세는 그룹 키가 아닌 개별 소유 ID가 대상입니다. 레벨·착화감·날짜가 다른 같은 모델을 하나로 합쳐 보여주지 않습니다.

보유 개수는 켤레 수이며 모델 종류 수가 아닙니다. 실제 사용자 목록을 가로 스크롤하고 선택·목록 위치를 복귀 시 유지합니다. 변경 후에는 동일한 ID를 기준으로 선택을 유지합니다. 실제 그룹 정렬이 달라져도 예전 인덱스의 다른 신발을 선택하지 않습니다.

## 4. 상세 정보와 능력치

02는 다른 신발을 구경하는 기본 상세, 03은 이미 신고 있는 신발, 08은 같은 모델의 다른 켤레, 17은 보유 신발은 있지만 착용이 없는 경우입니다.

| 화면 표시 | 실제 데이터/계산 |
| --- | --- |
| 이름 | 기존 현지화 모델 이름/표시 함수. 샘플 이름으로 DB 수정 금지 |
| 신발 번호 | `mintNumber`. DB `id`나 체인 토큰 ID와 혼동하지 않음 |
| Lv. | `level` |
| 보유 중/지금 신고 있어요 | 실제 소유 및 `equipped`/equipped ID |
| SUP 적립 보너스 | `boostPercent`, 백분율로 표시 |
| 에너지 절감 | `(1 - energyEfficiency) * 100` |
| 행운·착화감·내구도 | `luck`, `comfort`, `durability` |
| 등급·속성 | 기존 현지화 rarity/faction 라벨 |
| 받은 날짜 | `acquiredAt`, 사용자 지역 날짜로 표시 |

주 화면의 보너스는 배율 1.0045와 혼동하지 않도록 ‘+0.45%’ 형식입니다. 0.45% 예시를 ‘45%’나 ‘0.45 SUP’로 바꾸지 않습니다. 내구도는 100 기준을 유지합니다. 값이 없는 경우 0으로 만들어 표시하지 말고 조회/오류 상태로 처리합니다.

04는 다섯 능력치, 05는 설명, 06은 기본 정보입니다. 04에서 05로 전환할 때 시트를 중첩하지 말고 같은 시트 내용을 바꿉니다. 05의 ‘능력치로 돌아가기’와 시스템 뒤로 가기는 04로 돌아갑니다. X/바깥 누르기는 시트 전체를 닫아 상세로 돌아갑니다. 04와 06의 확인/X/뒤로 가기는 해당 시트를 닫습니다. 본문 스크롤 위치를 필요에 따라 보존합니다.

현재 코드의 보너스는 design.boostPercent + (level−1)×0.5입니다. 에너지 절감은 착화감 기준 계산과 최대 15% 제한을 따릅니다. 이 계산을 UI에서 별도로 재정의하지 않습니다. `sample-inventory.json`의 에너지 값은 해당 공식과 맞췄지만 실제 도감의 새 상품 정의는 아닙니다.

기존 유료 민팅의 행운 효과를 새 무료/상급 뽑기의 확정 정책이라고 안내하지 않습니다. 새 무료 뽑기의 등급 확률·행운 적용 여부는 이 문서에서 정하지 않습니다. 내구도 감소·수리 비용·레벨 강화 비용도 새로 제안하지 않습니다.

신발 일러스트는 이전 전달본 원본 3종입니다. ‘시티 스프린트/새벽 강변/나이트 트랙’은 승인된 시안에서 쓰던 일러스트 이름입니다. 이 일러스트와 기존 52종 카탈로그의 특정 slotKey 간 대응이 확정됐다는 뜻이 아닙니다. 실제 적용은 확정된 아트 매핑을 사용하고, 매핑이 없다면 기존 소유 데이터 식별자는 유지하며 미확정 부분을 보고합니다. 그림 색만 보고 속성·등급을 자동 추정하지 않습니다.

## 5. 착용 버튼과 피드백

착용 변경은 무료이고 되돌릴 수 있으므로 반복 확인 창을 추가하지 않습니다. ‘이 신발 신기’를 누르면 기존 equip 경로를 한 번 호출합니다. 선택만 하거나 상세/모달을 여는 일은 저장 동작이 아닙니다.

1. 누르면 09처럼 버튼을 ‘신발 바꾸는 중…’으로 바꾸고 중복 입력을 막습니다. 실제 변경 전에는 착용 체크를 옮기지 않습니다.
2. 기존 ItemsViewModel의 equipping 상태와 실패/성공 메시지를 사용합니다. 성공 신호뿐 아니라 갱신된 소유 데이터의 실제 착용 ID를 일치시킵니다.
3. 성공하면 10의 상태 문구와 약 2초의 완료 토스트를 표시합니다. 토스트는 버튼/정보를 가리지 않는 위쪽 여백에 놓고 한 번만 읽어줍니다. 기존 FeedbackCue.Equip을 사용하되 설정의 소리·진동·동작 줄이기를 존중합니다.
4. 뒤로 가면 12처럼 보유 목록에도 체크가 같은 ID로 옮겨집니다. 시안의 #0002로 매번 초기화하지 않습니다.
5. 저장 실패는 11입니다. 기존 실제 착용을 조회해서 유지하며 다시 시도하거나 닫을 수 있게 합니다. 시안의 ‘시티 스프린트를 계속 신고 있어요’는 이전 착용이 그 신발임을 확인한 예시입니다. 이전 착용이 없으면 ‘아직 신고 있는 신발이 없어요’로 표시합니다. 상태를 확인할 수 없다면 단정하지 말고 재조회 안내를 사용합니다.

기존 equipExclusively는 대상이 존재할 때 하나의 원자적 UPDATE로 착용을 바꿉니다. `clearEquipped()` 후 별도 업데이트로 바꿔 실패 시 맨발이 되는 회귀를 만들지 않습니다. 없는 대상 ID로 업데이트가 0건이면 15로 안내할 수 있습니다. 새 신발을 만들어 성공 처리하지 않습니다.

화면을 떠났다가 돌아오거나 앱이 재시작돼도 영구 저장값으로 표시합니다. 이미 처리한 요청을 재생하거나 완료 토스트를 재진입마다 표시하지 않습니다. 장시간 대기는 최신 상태 재조회로 정리하며 무조건 실패나 성공으로 타이머 전환하지 않습니다.

현재 소스에는 이 화면에서 러닝 중 착용 변경을 막는 확정 정책이 없습니다. ‘러닝 중 변경 불가’나 ‘다음 러닝부터 적용’ 같은 새 규칙을 임의로 추가하지 않습니다. 기존 적립/에너지 정산 시점의 동작을 유지하고 실제 제품 정책이 따로 있다면 그것을 반영합니다. 착용 변경으로 과거 러닝 기록이나 획득 보상을 다시 계산하지 않습니다.

## 6. 조회·예외 상태

- 13: 소유 데이터를 확인하는 중. 기존 `selectionInventory == null` 의미를 활용합니다. `inventory` 초기값 emptyList를 실제 빈 목록으로 오해하지 않습니다.
- 14: 데이터 조회 실패. 다시 불러오기/보유 목록 복귀. 예외를 잡아 빈 목록으로 치환하지 않습니다.
- 15: 로딩이 끝난 최신 목록에 대상 ID가 없음. 보유 목록 복귀. 이미지 오류와 구분합니다.
- 16: 신발 데이터는 있지만 이미지 로딩만 실패함. 이름·능력치·착용 기능은 유지하고 이미지 재시도만 합니다. 임의의 다른 신발 그림을 넣지 않습니다.
- 17: 실제 보유는 있으나 착용 없음. 같은 버튼으로 처음 착용합니다.
- 18: 실제 조회가 끝났고 보유가 비어 있음. 기존 무료 뽑기 메인으로 연결합니다. 스타터 지급 대기/동기화 중을 빈 상태로 먼저 보여주지 않습니다.

확인한 기존 `ensureStarter()`는 초기 스타터를 제공할 수 있으므로 18은 일반 신규 가입의 고정 첫 화면을 뜻하지 않습니다. 무료 뽑기 화면의 횟수·지갑 조건은 이전 `stepup-draw-complete` 전달서를 그대로 따릅니다. 새 무료 버튼에 기존 SUP 유료 `mint()`를 연결하지 않습니다. 이 화면 진입만으로 보상·신발·SUP를 생성하지 않습니다.

## 7. 레이어·크기·접근성

- 본문 좌우 여백 24. 주 버튼 높이 54, 모서리 17. 시트 상단 모서리 27. 기본 기준은 `design-tokens.json`입니다.
- 원본 신발 PNG의 투명 여백이 서로 다릅니다. 전체 파일 사각형 대신 보이는 신발 범위와 바닥선을 기준으로 맞춥니다. 원본을 늘리거나 자르지 않습니다. 기준 bounds는 토큰 파일에 있습니다.
- 신발 이미지·받침·조명·접촉 그림자·글자·버튼은 각각 독립 요소입니다. `shoe-stage`는 전시 배경, `hero-river`는 배치 참고용 조합입니다. 앱에는 독립 요소로 조립합니다.
- 390 × 844는 시안 크기입니다. 작은 화면에서는 본문이 스크롤되고 버튼은 공통 내비게이션/안전 영역 위에 놓입니다. 긴 이름은 최대 두 줄, 정보 값·날짜는 필요한 만큼 줄바꿈합니다. 숫자·단위를 분리해서 잘라 표시하지 않습니다.
- 링크·정보 아이콘·2켤레 보기·닫기를 포함해 실제 터치 영역 최소 48dp. 행 전체를 누를 수 있게 하며 아이콘만 작은 클릭 영역으로 만들지 않습니다.
- 선택과 착용을 색만으로 구분하지 않습니다. 스크린리더에는 이름·신발 번호·선택/착용 상태를 함께 제공합니다. 장식용 조명/받침은 읽지 않습니다.
- 시트 열림 시 배경 탐색을 막고 포커스를 옮기며 닫으면 실행한 버튼으로 돌아갑니다. 설명 시트 전환 때 겹친 모달을 누적하지 않습니다.
- 밝은 테마에서는 기존 설정 전달본의 의미별 색상을 적용합니다. 이 전달본의 대표 시안은 사용자가 선택한 어두운 톤입니다. 밝은 테마를 강제로 어두운 색으로 덮어쓰지 않습니다.

## 8. 모션 기준

신발을 고르면 기존 전시 위치에서 교체합니다. 상시 회전·떠오름·스파클을 넣지 않습니다. 필요한 경우 이미지 준비 후 120ms 정도의 짧은 페이드로 교체하되 실제 신발이 바뀌기 전에 이름만 앞서 바뀌지 않게 합니다. 동작 줄이기는 즉시 교체합니다.

시트는 기존 공통 전환을 재사용합니다. 새로 구성한다면 약 220ms, 끝에서 느려지는 이동으로 한 번만 열고 닫습니다. 동작 줄이기는 이동 없이 짧은 페이드 또는 즉시 전환합니다. 착용 완료는 텍스트·체크·짧은 피드백만 제공합니다. 뽑기 애니메이션을 착용 변경에 재생하지 않습니다.

이 패키지는 정적 상태 시안입니다. 새로운 실행형 모션 파일을 제작했다는 뜻이 아닙니다. 신발 뽑기 모션은 기존 전달본을 재사용합니다.

## 9. 구현 후 검증

저장소 필수 검사를 수행하고 변경한 동작에 필요한 검증을 추가합니다. 단순 도형·색상을 그대로 따라 쓰는 테스트는 추가하지 않습니다.

1. 썸네일 선택/상세 열기/사본 선택만으로 착용이 바뀌지 않음.
2. 같은 모델의 다른 소유 ID 선택 시 해당 수치와 날짜가 표시됨.
3. 실제 착용은 항상 한 켤레이며 기존 원자적 업데이트 보존. 없는 ID 요청에 기존 착용 유지.
4. 변경 중 연타 차단, 저장 성공/실패, 뒤로 가기·재진입·재시작 후 일치.
5. 목록 조회 중/빈 목록/오류/대상 없음/아트 오류의 분리.
6. 수치 포맷과 기존 에너지 계산 일치. SUP 차감·보상 지급 없음.
7. 큰 글씨·긴 이름·좁은 화면·시트 스크롤·스크린리더·소리/진동 설정.
8. 공통 신발 탭·상단/하단 바 중복 없음. 뽑기 진입은 무료 정책 전달본으로 연결.
