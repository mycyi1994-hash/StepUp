# StepUp 프로필 수정 · 구현 지시서

## 목표

기존 내 정보의 `프로필 수정`을 누르면 사진과 닉네임을 편집하는 화면을 연다. 선택한 **러닝 패스**의 짙은 남색, 밝은 글자, 흰색 주요 버튼을 그대로 이어간다. 사진 변경은 보조 동작, 닉네임 저장은 화면 아래의 주요 동작이다.

이 문서는 디자인 구현을 위한 전달서다. 패키지를 만든 단계에서는 Android 코드를 수정하지 않았다. 기존 프로젝트에서 구현하며 별도 웹페이지를 만들지 않는다.

## 기준과 범위

- `01-screens/*.png`: 장면별 시각 기준. 1170 × 2532px, 390 × 844의 3배.
- 같은 이름의 SVG: 편집 가능한 텍스트·벡터 원본. Pretendard 사용.
- `03-components`: 분리된 버튼·입력창·모달. 화면 이미지를 통째로 앱에 붙이지 않는다.
- `12-saved-profile`: 기존 러닝 패스 첫 화면에 새 이름과 짧은 저장 완료 안내를 반영한 예시.
- 지갑·설정 등 다른 메뉴 화면은 이번 범위에 포함하지 않는다.

현재 작은 다이얼로그를 **전체 높이의 편집 화면**으로 바꾸는 것은 이번 시안의 의도된 변경이다. 기존 내 정보의 진입 동작은 유지하되, 이 화면에서는 공통 하단 탭을 표시하지 않는다. 뒤로 가면 내 정보로 돌아온다.

## 기존 코드에서 확인한 규칙

확인한 파일:

- `app/src/main/java/com/stepup/android/ui/screens/profile/ProfileScreen.kt`
- `app/src/main/java/com/stepup/android/ui/screens/profile/ProfileViewModel.kt`
- `app/src/main/java/com/stepup/android/data/prefs/UserPrefs.kt`
- `app/src/main/java/com/stepup/android/ui/components/Components.kt`

위 경로는 이번에 확인한 `stepup-stage9` 프로젝트 기준이다. 적용 대상 브랜치가 달라졌다면 대응하는 실제 구현을 먼저 확인한다.

| 항목 | 확인한 현재 동작 | 이번 적용 |
| --- | --- | --- |
| 닉네임 길이 | `UserPrefs.NICKNAME_MAX = 16` | 같은 상수를 사용 |
| 저장 전 처리 | `trim().take(NICKNAME_MAX)` | 동일한 정규화 사용 |
| 빈 닉네임 | 저장 가능, 화면에서 기본 호칭 사용 | 필수 입력 오류를 만들지 않음 |
| 닉네임 저장 | 확인을 눌러 저장 | 아래 `저장` 버튼으로 유지 |
| 사진 선택 | `PickVisualMedia` → `setCustomAvatar(uri)` | OS 선택기 사용, 선택 후 즉시 저장 유지 |
| 기본 이미지 | `AvatarEmojis` 16개, 인덱스로 저장 | 기존 순서와 ID 유지, 보조 시트로 이동 |
| 사용자 사진 | `AVATAR_CUSTOM = -2`, `avatarRev`로 갱신 | 식별자·기존 사진 보존 |
| 사진 처리 | 최대 변 512px, JPEG 90으로 내부 저장 | 기존 크기/품질 정책 유지 |

새 최소 글자 수, 중복 이름 검사, 변경 비용, 변경 대기 기간, 계정 아이디 변경 기능을 추가하지 않는다. 이름은 표시용 닉네임이며 로그인 계정 식별자가 아니다.

현재 ViewModel의 저장 함수는 호출 결과를 UI에 충분히 전달하지 않는다. **진행·성공·실패 상태와 성공 확인 후 닫기는 이번 구현에서 보완할 부분**이다. 시안에 있다고 이미 동작하는 기능으로 간주하지 않는다.

## 화면 순서와 버튼 연결

| ID | 장면 | 동작 |
| --- | --- | --- |
| 01 | 프로필 수정 진입 | 저장된 닉네임을 복사해 편집 시작. 변경 전 `저장` 비활성 |
| 02 | 이름 변경 | 정규화한 값이 저장된 값과 달라지면 `저장` 활성 |
| 03 | 사진 변경 메뉴 | `사진 변경` → 시트. 앨범 또는 기본 이미지 선택 |
| 04 | 기본 이미지 선택 | 기존 16개 중 선택 → 저장 → 편집 화면의 이미지 갱신 |
| 05 | 빈 닉네임 | 빈 문자열로 저장 가능. 원래도 비어 있었다면 변경 없음 |
| 06 | 16자 입력 | 기존 최대 길이를 안내. 추가 입력 때문에 기존 입력을 지우지 않음 |
| 07 | 사진 저장 중 | 원형 사진 안 진행 표시. 중복 사진 선택과 닉네임 저장 잠시 비활성 |
| 08 | 사진 저장 실패 | 이전 사진 유지. `다시 선택` → OS 사진 선택기 |
| 09 | 닉네임 수정 중 나가기 | `계속 수정` 또는 `닉네임 버리고 나가기` |
| 10 | 닉네임 저장 중 | 버튼 `저장 중…`, 중복 요청 방지 |
| 11 | 닉네임 저장 실패 | 초안 보존, `다시 저장`으로 동일 값 재시도 |
| 12 | 저장 완료 | 내 정보로 복귀, 실제 저장된 새 이름 표시, 짧은 안내 |

기본 이미지 선택 시트의 `닫기`, 시스템 뒤로 가기, 시트 밖 터치는 시트만 닫는다. 닉네임 초안은 그대로 남는다. 기본 이미지 저장 성공 후에는 편집 화면으로 돌아간다. 같은 이미지를 다시 누르면 불필요한 저장을 하지 않는다. 실패하면 시트를 유지하고 선택 표시를 이전 값으로 되돌리며, 같은 오류 컴포넌트로 `이미지를 저장하지 못했어요. 다시 선택해 주세요.`를 표시한다.

시안 04의 선택 체크는 기존 기본 이미지 0번이 저장된 경우의 예시다. 사용자 사진을 사용 중이면 기본 이미지에는 선택 체크가 없다. 저장이 성공하기 전 새 선택을 확정 표시하지 않는다.

OS 앨범 선택에서 취소하면 사진·닉네임 초안 모두 바뀌지 않는다. OS 사진 선택기 자체는 새로 디자인하거나 가짜 목록으로 구현하지 않는다. 기존 선택 방식에 필요하지 않은 광범위한 사진 접근 권한이나 카메라 권한을 추가하지 않는다.

## 사진과 닉네임의 저장 범위

두 데이터의 기존 저장 시점을 유지한다.

1. 사진 또는 기본 이미지는 선택한 직후 독립적으로 저장한다.
2. 닉네임은 사용자가 `저장`을 눌러야 저장한다.
3. 사진 아래와 사진 메뉴에 즉시 저장 문구를 보여준다.
4. 이름을 수정하지 않고 사진만 바꾼 경우 뒤로 가면 바로 내 정보로 돌아간다. 이미 저장된 사진을 취소하지 않는다.
5. 이름 초안이 달라졌을 때만 09 확인 시트를 띄운다. `닉네임 버리고 나가기`는 이름 초안만 버린다.
6. 사진을 이번 세션에서 실제로 변경했다면 `이미 바꾼 사진은 유지돼요.`를 표시한다. 변경하지 않았다면 이 줄을 생략해도 된다.

프로필 편집의 임시 상태는 `storedNickname`, `draftNickname`, `nameSaveState`, `photoSaveState`처럼 구분한다. 초안 변경 여부는 저장 때와 같은 정규화 규칙으로 비교한다. 두 작업의 오류 메시지와 저장 상태를 서로 덮어쓰지 않는다.

사진 저장 중에도 이름 입력은 가능하지만 이름 저장은 잠시 비활성이다. 뒤로 가기를 누른 경우 사진 작업이 기존 ViewModel 범위에서 완료되도록 하고, 변경된 이름 초안에 대해서만 나가기 확인을 한다. 화면 재진입 시 실제 저장 상태를 다시 읽는다. 작업 상태를 잃어 완료 안내를 중복 표시하지 않는다.

닉네임 저장 중에는 입력과 사진 변경, 저장 요청을 일시적으로 막는다. 시스템 뒤로 가기는 앱의 일반 내비게이션에 맞게 처리하되 저장 성공 여부를 왜곡하지 않는다. 저장 작업은 ViewModel에서 완료되고, 편집 화면이 보이지 않을 때 임의로 화면을 다시 열지 않는다. 저장 실패로 돌아왔을 때 초안을 복원할 수 있게 관리한다.

## 사진 실패 시 기존 이미지 보존

시안의 `기존 사진을 유지했어요.`는 실제로 보장되어야 한다. 현재 원본 파일을 직접 덮어쓰는 구현만으로는 부족할 수 있다.

- 입력 스트림 읽기·디코딩·방향 보정·기존 크기/품질 처리를 별도 임시 파일에 수행한다.
- 저장 결과가 유효한지 확인한 후 기존 파일과 교체한다. 실패 시 기존 이미지 파일, 아바타 ID, 리비전을 보존한다.
- 파일 교체와 설정 갱신 사이에서 실패해도 기존 사진을 복원할 수 있게 구현한다. 부분 실패를 성공으로 안내하지 않는다.
- 성공한 뒤에만 `AVATAR_CUSTOM` 및 리비전을 반영한다. 실패한 임시 파일은 정리한다.
- 이미지가 커도 UI 스레드에서 디코딩하지 않는다. 사진을 별도 외부 서버에 올리는 기능은 추가하지 않는다.
- 사용자가 지정한 기존 아바타가 있다면 사람 아이콘으로 덮어쓰지 않는다. 시안의 사람 아이콘은 사진 자리의 대체 그림일 뿐이다.

## 입력과 키보드

- 필드는 한 줄, 18sp. 이름이 길면 입력 커서가 보이도록 가로 스크롤한다. 글씨를 임의로 축소하거나 편집 중 말줄임하지 않는다.
- 지우기 아이콘은 입력이 있을 때만 표시한다. 접근성 이름은 `닉네임 지우기`, 터치 영역은 48dp 이상이다.
- 한국어 조합 중 글자를 잘라 깨뜨리지 않는다. 기존 최대 길이와 카운팅의 일관성을 유지하고 한글 입력·붙여넣기를 확인한다.
- 오른쪽의 `현재 길이 / 16`은 저장 데이터와 동일한 길이 기준이다. 정규화 전 공백도 입력 상태에 맞춰 센다.
- 키보드가 열리면 저장 버튼을 키보드 위에 둔다. 본문은 스크롤 가능하며 입력창·안내·버튼이 겹치지 않는다.
- 최초 진입에는 자동으로 키보드를 띄우지 않는다. 필드를 누르면 입력한다. 키보드 완료 키는 키보드를 닫고 아래 저장 버튼으로 마무리한다.
- 사진 메뉴를 열 때 키보드를 닫되 이름 초안을 보존한다.
- 16자 상태 자체는 오류가 아니다. 버튼은 저장 가능한 상태를 유지한다.

포커스된 입력창에는 얇은 `#A3BFFE` 강조선을 적용한다. 일반 상태의 두꺼운 테두리, 게임식 육각형 레벨, 배지, 보상, 크루 정보는 추가하지 않는다. 기본 이미지 16개는 기존 옵션 보존 목적이며 첫 화면에 펼쳐 놓지 않는다. 기존 시스템 이모지를 그대로 사용하고 별도 동물·기호 에셋을 새로 제작하지 않는다.

## 전환과 접근성

- 시트는 앱의 기존 네이티브 전환을 사용한다. 별도 화려한 등장 효과를 추가하지 않는다.
- 사진 처리 중 원형 진행 표시만 사용하고 종료 시 즉시 멈춘다. 수치 없는 작업에 가짜 진행률을 만들지 않는다.
- 저장 안내는 저장 성공 후 한 번만 표시하고 자동 사라짐에 의존하는 필수 정보를 넣지 않는다. 변경된 이름은 본문에 계속 남는다.
- 스크린리더에 진행/실패/성공을 알린다. 사진 설명과 기본 이미지별 구분 가능한 이름을 제공한다.
- 시트가 열리면 시트 안으로 포커스를 이동하고, 닫으면 실행 버튼으로 돌린다. 배경 컨트롤은 접근성 탐색에서 제외한다.
- 큰 글자에서 메시지와 버튼 높이는 늘어날 수 있다. 시각 크기가 48dp보다 작은 보조 버튼에도 48dp 이상 터치 영역을 확보한다.

## 완료 확인

1. 선택한 러닝 패스 화면 → 수정 → 저장 후 복귀가 연결되는지 확인한다.
2. 이름 미변경, 수정, 다시 원래 이름, 빈 이름, 공백만 입력, 16자, 17자 붙여넣기, 한글 조합을 확인한다.
3. 사진 선택 취소, 성공, 읽기 실패, 저장 실패에서 이전 사진과 이름 초안을 확인한다.
4. 기본 이미지 16개의 ID가 유지되고 기존 선택이 정확히 표시되는지 확인한다.
5. 이름 저장 실패·재시도·중복 터치, 사진 저장 중 이름 입력과 뒤로 가기를 확인한다.
