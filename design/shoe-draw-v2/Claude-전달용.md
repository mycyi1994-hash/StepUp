# StepUp 신발 뽑기 구현 전달서

## 작업 범위와 최종 방향

기존 StepUp 신발 탭의 `신발 뽑기` 버튼 이후 영역을 이 시안으로 바꾼다. 내 신발 화면의 보유 신발 목록은 유지한다. 무료/상급을 전환하는 상단 탭은 없앤다. 메인 화면에 `무료 뽑기`와 `상급 뽑기` 두 칸을 위아래로 놓는다.

이 전달본에는 28개 상태, 버튼·모달의 분리 원본, 연결표와 모션이 있다. 웹페이지를 새로 만들지 않고 기존 앱 화면과 서비스 흐름에 적용한다. 메인 카드 배경을 누르는 동작은 없다. 각 칸의 명시적인 버튼과 내역 링크를 누르는 방식이다.

기본 모양은 `02-boards/01-two-compartments.png`, 정확한 화면별 기준은 `01-screens`의 PNG다. 대응하는 SVG는 편집 가능한 텍스트와 도형, 포함된 이미지를 갖는다. 실제 앱에 맞는 네이티브 컴포넌트로 구현한다. SVG 전체를 한 장의 이미지로 붙여 앱을 만들지 않는다.

## 사용자가 정한 지급 규칙

| 종류 | 조건 | 지급 |
| --- | --- | --- |
| 무료 뽑기 | 첫 가입 | 10회 |
| 무료 뽑기 | 매일 | 3회 |
| 상급 뽑기 | WEB3 지갑 연결 | 추가 10회 |
| 상급 뽑기 | WEB3 지갑이 연결된 회원의 러닝 | 1km당 1회 |

모든 뽑기는 무료다. SUP 가격·잔액, 구매·충전·비용 확인창, 나올 수 있는 신발 목록을 넣지 않는다. 무료와 상급의 횟수를 합치거나 서로의 횟수로 사용하지 않는다. 일반 무료 뽑기에는 지갑 연결이 필요 없다.

이 시안은 첫날 가입 10회와 당일 3회를 함께 지급해 총 13회로 표현했다. 연결 선물은 첫 연결 1회성으로 해석했다. 지갑을 다시 연결해도 가입/연결 선물을 반복 지급하지 않는다. 운영 정책이 달라지면 화면 문구와 계산을 함께 바꾼다.

## 메인 두 칸

무료 칸에는 제목, 지급 조건, 남은 횟수, 기회 내역 링크, `무료로 1회 뽑기` 버튼을 둔다. 상급 칸에는 연결 상태에 맞는 행동을 보여준다.

| 회원 상태 | 상급 칸 | 주 버튼 |
| --- | --- | --- |
| 연결 전 | 처음 연결 시 +10회 안내 | 지갑 연결하고 10회 받기 |
| 연결 완료·기회 있음 | 남은 상급 횟수, 다음 기회까지 거리 | 상급으로 1회 뽑기 |
| 연결 완료·기회 없음 | 0회, 다음 기회까지 거리 | 러닝하고 기회 받기 |
| 기존 회원의 연결 해제 | 기존 상급 횟수를 유지해 표시 | 지갑 다시 연결하기 |
| 연결 성공·선물 지급 미확인 | 연결 선물 확인 중 | 지급 상태 확인 |
| 진행 중 뽑기의 결과 미확인 | 결과 확인 중 표시 | 결과 확인 |

무료 0회에서는 `무료 기회 안내`로 바뀐다. 횟수를 불러오는 중에는 임의로 0회를 표시하지 않는다. 네트워크 실패와 기회 소진을 같은 상태로 표현하지 않는다.

03/04 내역 모달의 뽑기 버튼도 해당 종류의 1회를 바로 사용한다. 내역 모달을 여는 일이나 닫는 일은 기회를 사용하지 않는다. 모든 모달의 X·배경·뒤로가기는 모달만 닫고 실제로 열린 배경 상태로 돌아간다. 23의 닫기는 로딩 화면에 갇히지 않게 오류 설명과 재시도 진입점을 유지한다. 25를 닫아도 지급 확인 상태는 유지된다.

첫 화면으로 돌아갈 때 시안의 13회/10회로 초기화하지 않는다. 모든 횟수, 소진 상태, 연결 상태, 진행 거리는 실제 최신 데이터로 표현한다. 내역의 지급 출처별 숫자는 남은 사용 가능 횟수이며 최초 지급량이나 평생 누적량과 섞지 않는다.

## 지갑 연결 영역의 범위

StepUp 내부의 혜택 안내·대기·성공·실패·재연결·선물 지급 지연을 디자인했다. 외부 지갑 앱의 선택, 계정 승인, 서명 UI는 기존 연결 SDK나 지갑 앱이 제공하는 실제 화면을 사용한다. 지원 지갑이나 체인이 현재 코드에서 확정되지 않았으므로 가짜 지갑 목록, 주소, QR, 연결 성공을 만들지 않는다.

지갑 연결 성공과 회원 선물 지급 성공은 별도 확인한다. 지갑을 연결했다고 즉시 클라이언트에서 10회를 더하지 않는다. 기존 회원 재연결에서는 보유 기회를 유지하고 최초 연결 선물을 중복 지급하지 않는다.

## 뽑기와 오류 처리

뽑기 종류와 요청 식별자를 유지하며 중복 누르기를 막는다. 서버가 결과·기회 차감·보유 신발 지급을 확인한 뒤 연출한다. 확인되지 않은 결과를 클라이언트에서 정하거나, 닫기·재시도·연출 건너뛰기 때문에 기회가 다시 차감되는 동작을 만들지 않는다.

`19`는 서비스가 뽑기를 시작하지 않았고 기회도 사용하지 않았다고 확인한 경우에만 쓴다. 응답을 받지 못해 처리 여부가 불명확하면 `20`을 쓴다. 결과 조회 중에는 새 뽑기를 막고 `26`에서 결과 확인으로 복귀할 수 있게 한다. 기다리는 화면에서 뒤로가거나 앱을 다시 열어도 진행 중인 요청을 복구한다.

결과의 `한 번 더 뽑기`는 새 요청이다. 남은 횟수가 없거나 상태가 갱신 중이면 진행시키지 않는다. 모션의 건너뛰기는 이미 확정된 결과로만 이동한다.

## 보유 신발과 예시 데이터

예시 회원은 새벽 강변과 나이트 트랙 2켤레를 갖고 있고 새벽 강변을 착용 중이다. 시티 스프린트를 받으면 3켤레가 된다. 결과에서 내 신발로 돌아오면 새 신발을 선택해 크게 보여주되 착용 신발은 바꾸지 않는다. 썸네일의 체크는 기존 새벽 강변에 유지된다.

무료와 상급 결과에 같은 그림을 쓴 것은 결과 화면의 공통 형식을 설명하기 위해서다. 같은 지급 목록이나 확률이라는 뜻이 아니다. 실제 보상으로 이미지·이름·개수·보유 내역을 채운다. 중복 신발 정책은 아직 정하지 않았으므로 임의의 합성, 환전, 재화 보상을 추가하지 않는다.

## 모션

`04-motion/free-draw-flow-60fps.mp4`는 9초짜리 사용 흐름 데모다. 영상의 대기 시간은 서비스 응답 시간 보장이 아니다. 실제 앱에서는 결과를 받는 즉시 연출을 진행한다.

- 버튼 누름: 120ms, scale 0.98 및 약한 opacity 변화, ease-out `(0.23,1,0.32,1)`.
- 모달: 240ms, 아래에서 진입, `(0.32,0.72,0,1)`. 닫을 때 같은 경로로 복귀한다.
- 화면 전환: 200ms opacity. 결과 숫자나 읽는 중인 본문은 불필요하게 움직이지 않는다.
- 상자 열기: 동봉한 390×420, 60fps Lottie를 재사용한다. 약 2초. 뚜껑이 먼저 비켜나고 신발이 나와 받침에 놓인다.
- 모션 줄이기: `unboxing-reduced.json` 사용. 상자·신발의 이동 대신 약 0.2초 opacity 전환. 모달도 이동 없이 opacity로 바꾼다.
- 결과 그림: `img_4`가 예시 시티 스프린트다. 실서비스에서는 확정된 신발을 같은 표시 영역에 맞춰 사용한다.

실기기의 Lottie 성능과 접근성 동작은 앱에 연결한 뒤 확인해야 한다. 이번 산출물은 이미지·모션 전달본이며 앱에 직접 통합한 결과는 아니다.

## 편집과 접근성

기준 크기는 390×844다. 메인 칸은 x24, 폭342, 높이282이며 y134와 y434에 놓인다. 칸 내부 버튼은 x44, 폭302, 높이50이다. 배경은 #050912, 흰색 버튼과 차분한 남색 표면을 사용한다. 상급에 금색 상자, 등급 보석, 폭죽을 추가하지 않는다.

`03-components`에는 버튼 4상태, 뽑기 칸 5상태, 거리 진행, 토스트, 모달 12종이 분리되어 있다. 분리된 모달 PNG는 배경이 투명하다. 전체 화면 PNG에서 덮개와 배경 어두워짐을 확인할 수 있다. SVG의 텍스트는 Pretendard로 편집 가능하다. 폰트 파일과 라이선스는 `05-assets/fonts`에 포함했다. Figma에서 가져온 뒤 필요한 Auto Layout과 프로토타입 연결을 설정한다.

글자 확대와 작은 화면에서는 본문을 스크롤한다. 중요한 버튼을 화면 밖에 고정시키지 않는다. 뒤로가기, X, 내역 링크, 텍스트 버튼은 최소 44×44의 누르는 영역을 둔다. 모달을 열면 초점을 모달로 옮기고 닫으면 시작 버튼으로 돌린다. 화면 읽기는 제목 → 횟수 → 행동 순서로 제공하며 결과·오류·지급 완료는 알려준다.

## 아직 정하지 않은 운영값

일일 3회 갱신 시간·시간대, 미사용분 이월/소멸, 첫날 당일 3회의 동시 지급 여부, 러닝 거리의 누적·소수점·검증 기준·보상 상한, 연결 전 러닝의 소급 여부, 지급 출처의 차감 순서, 신발별 지급 목록·확률·중복 정책은 기존 서비스 규칙이나 후속 결정을 따른다. 이 시안 때문에 임의의 자정 타이머, 소멸 문구, 10회 일괄 뽑기나 확률 수치를 만들지 않는다.
