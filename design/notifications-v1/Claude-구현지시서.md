# StepUp 알림·공지 구현 지시서

작성일: 2026-09-28. 신규 시안 23개, 비교 보드 12개, 분리 부품 12개입니다. 이번 작업에서는 앱 코드·사용자 데이터·운영 공지를 수정하지 않았습니다.

## 1. 화면 구조

알림 화면 안에 ‘내 알림 / 공지’ 두 항목을 놓습니다. 내 알림은 오늘·어제·이전 날짜로 묶는 단순 목록, 공지는 제목과 게시일 중심의 목록입니다. 선택한 항목의 밑줄과 글자 굵기로 위치를 구분합니다. 검색·카테고리 칩·추가 배너는 넣지 않습니다.

상단 ‘설정’은 기존 알림 설정으로 이동합니다. 뒤로 가면 실제 이전 화면으로 돌아갑니다. 새 알림 때문에 목록이 갑자기 맨 위로 움직이지 않게 하며 항목별 스크롤 위치를 기억합니다. 공지 상세에서 돌아오면 공지 목록의 위치와 선택을 복원합니다.

개인 알림은 작은 아이콘, 최대 두 줄 기본 제목, 시간, 읽지 않은 점으로 표시합니다. 더 긴 제목과 큰 글씨는 행 높이를 늘립니다. 공지에는 임의의 ‘중요’ 배지·프로모션 그림을 넣지 않습니다. 기존 내 정보의 짧은 구성을 유지하며 중복된 새 메인 메뉴를 추가하지 않습니다. 기존 알림 진입 버튼을 이 화면에 연결합니다.

기존 초대형 알림은 실제로 수신된 경우의 기능 보존 시안입니다. 이 패키지는 강제 크루 생성·가입, 새 크루 추천, 가짜 초대 발송을 제안하지 않습니다.

NewsViewModel/NewsRepository의 과거 설명 주석만 보고 앱 공지가 구현돼 있다고 판단하지 않습니다. 최신 NewsScreen은 RunningFeedViewModel의 실제 외부 피드를 사용합니다. 공지와 외부 뉴스의 자료·경로를 구분하고 기존 외부 피드를 보존합니다.

## 3. 읽음 처리

01에서 파란 점은 read=false입니다. 단순 화면 진입은 전체 읽음으로 처리하지 않습니다. 사용자가 알림을 열어 해당 내용 시트나 유효한 대상 화면이 준비되면 해당 ID만 읽음 처리합니다. 원본이 삭제돼 14의 안내를 본 경우에도 그 알림 내용을 열어 본 것으로 처리할 수 있습니다. 서버 접속 실패로 내용 자체를 못 연 경우는 자동으로 읽음 처리하지 않습니다.

개별 읽음은 read만 바꿉니다. actioned를 바꾸거나 알림을 삭제하지 않습니다. 저장에 실패해도 내용 확인 자체를 막지는 않되 read 표시를 성공으로 남기지 않고 13의 오류 패턴으로 안내합니다. 알림별/모두 읽음 쓰기 실패를 구분할 수 있게 메시지를 맞춥니다.

‘모두 읽음’은 별도 확인 창 없이 실행합니다. 요청 중 중복 입력을 막고 성공 후 02처럼 점과 개수를 갱신합니다. 알림 행은 그대로 남습니다. 새 알림 0이면 버튼을 숨기고 모두 읽었다는 상태를 표시합니다. 요청 중 새로 도착한 알림이 이미 읽은 것으로 사라지지 않게 적용 범위를 일관되게 관리합니다. 실패하면 13처럼 기존 저장 상태를 유지합니다.

알림 전체 수와 unreadCount는 실제 저장소를 기준으로 합니다. notifications 기본 조회 한도는 100개이므로 화면에 보이는 100개만 세어 전체 미확인 개수라고 단정하지 않습니다. 시안의 3개는 예시입니다. 날짜 그룹은 사용자 시간대로 계산하며 화면 복귀·날짜 변경 때 상대 시간을 갱신합니다. 현재 remember로 고정된 now를 장시간 그대로 유지하지 않습니다.

읽음(read), 초대 응답(actioned), 실제 가입/참가/보상 지급은 서로 다른 상태입니다. 모두 읽음을 눌렀다고 아직 답하지 않은 초대 버튼이 사라지면 안 됩니다.

03은 2,400걸음과 2.40 SUP라는 시안 예시입니다. 보상 계산 공식이나 현재 사용자 지급 증거가 아닙니다. 금액은 해당 NotificationEntity의 인자로 표시하고 현재 잔액으로 덮어쓰지 않습니다. ‘지갑 보기’는 전체 지갑 화면이며 이 알림에 대응하는 정확한 원장 ID가 확인되지 않았다면 거래 상세를 임의로 선택하지 않습니다.

신발 알림의 argText는 소유 ID가 아닌 모델 slotKey일 수 있습니다. 같은 모델을 여러 켤레 가졌다고 임의의 신발 상세를 골라 열지 않습니다. 04의 ‘보유 신발 보기’로 가서 실제 보유 상태를 확인합니다. 알림을 열었다고 신발을 지급·선택 착용하지 않습니다.

댓글 대상의 실제 삭제/접근 불가를 확인한 경우 14를 사용합니다. 단순 네트워크 오류는 삭제로 단정하지 말고 재시도 안내로 바꿉니다. 원본 댓글 화면의 디자인은 기존 커뮤니티 전달본을 재사용합니다. 링크가 깨진 알림의 원문이나 이전 적립 기록을 임의로 삭제하지 않습니다.

## 5. 기존 초대 기능 보존

크루 이름과 대상 ID는 실제 알림/서버 값입니다. ‘여의도 러너스’는 예시입니다. 시트 열기·크루 보기·닫기만으로 초대를 수락하지 않습니다.

- 초대 수락은 기존 acceptCrewInvitation → crewRepository.join 결과를 따릅니다. ID별 busy 상태로 중복 요청을 막습니다. 처리 중 버튼은 ‘확인 중…’으로 바꾸고 수락/거절을 함께 비활성화합니다.
- Joined는 가입 완료, Requested는 06의 가입 신청 완료입니다. Requested를 가입 완료로 표현하지 않습니다. 표시할 상태는 실제 서버의 현재 membership 결과로 확인합니다. 기존 actioned=true만으로 두 상태를 구분할 수 없으면 서버 확인이나 상태 모델 보강이 필요합니다.
- 거절은 21 확인 뒤 해당 초대 알림만 삭제합니다. 현재 크루 탈퇴가 아닙니다. 성공 후 목록으로 돌아가고 짧게 ‘초대를 거절했어요’라고 안내합니다. 실패하면 초대가 남은 상태로 재시도/닫기를 제공합니다.
- 확정된 미처리 실패는 07입니다. 응답 유실처럼 결과를 모르면 ‘응답 상태를 확인하지 못했어요’로 바꾸고 기존 가입 상태를 먼저 확인합니다. ‘처리되지 않았어요’를 단정하거나 수락 요청을 무조건 반복하지 않습니다.
- 로그인 필요는 22입니다. 취소해도 초대를 보존합니다. 로그인 후 원래 초대를 다시 보여주고 사용자가 다시 응답하게 합니다. 로그인 복귀만으로 자동 수락하지 않습니다.
- legacy 가짜 초대 정리(purgeLegacyInvites)를 되돌리거나 예시 초대를 DB에 넣지 않습니다.

파티 초대의 기존 acceptPartyInvite는 로컬 actioned 표시이며 실제 대기실 참가 완료 API가 아닙니다. ‘수락하고 보기’는 이 기존 표시 후 유효한 argExtra의 대기실로 이동합니다. 실제 참가/실행 상태는 대기실에서 확인합니다. ‘대기실 보기’만 누르면 수락 처리하지 않습니다. 실패·종료·대상 없음은 실제 로비 상태로 안내하고 참가 완료·러닝 시작으로 꾸미지 않습니다. 기존 코드에서 부족한 busy/예외 처리는 이 경로에도 적용합니다.

EVENT_REWARD의 이전 주석에는 ‘누르면 SUP 적립’이 남아 있으나 최신 화면은 챌린지를 열어 자격을 확인하도록 바뀌어 있습니다. 이 시안도 알림 클릭이나 읽음 처리로 보상을 지급하지 않습니다. 실제 수령은 기존 챌린지 서버 동작에 맡깁니다.

## 6. 공지 목록과 본문

15~20, 23은 앱 공지의 새 표시 구조입니다. 기존 external news 라우트를 재사용해 덮어쓰지 않습니다. 예를 들어 알림 화면에 공지 선택 상태를 두고 별도의 notice/{id} 상세를 연결할 수 있습니다. 새 상세는 공통 부모 내 정보 정책과 화면 목록에 등록합니다. 명칭은 저장소 규칙에 맞게 정하되 외부 기사와 혼동하지 않습니다.

확인한 현재 코드에는 이 디자인에 필요한 앱 공지 데이터 계약이 없습니다. **공지 자료 제공·저장·상세 조회는 구현 시 연결이 필요한 부분**입니다. 공급원이 없으면 실제 서비스에서는 준비/빈 상태를 정확하게 표시하고 예시를 운영 글처럼 넣지 않습니다. `sample-content.json`은 프리뷰/테스트용으로만 사용합니다.

최소 데이터는 안정적인 id, 현지화 가능한 title/body, 실제 publishedAt, 공개 여부입니다. 필요한 경우 관련 화면 action을 허용된 내부 경로 목록으로 제한합니다. 관련 화면이 없으면 주 버튼 없이 본문과 뒤로 가기만 제공합니다. 상세 본문은 서비스가 제공하는 실제 내용을 렌더링하며 앱 리소스 번호나 날짜를 영구 게시물 ID로 사용하지 않습니다.

16의 본문은 사용자가 확정한 무료 뽑기 규칙을 설명하는 예시입니다. 첫 가입 10회, 매일 3회, WEB3 지갑 연결 추가 상급 10회, 연결 회원의 1km 러닝당 상급 1회를 유지합니다. 갱신 시각·만료·누적 한도·거리 소급 등 미정 정책을 새로 쓰지 않습니다. 현재 연결 기능이 준비 중인 경우의 안내를 포함했으며, 실제 기능이 제공되면 서비스 상태에 맞게 갱신합니다. ‘신발 뽑기 보기’는 기존 무료/상급 두 칸 화면으로 가고 기회를 사용하지 않습니다.

공지 제목·게시일은 시안용 예시입니다. 실제 게시 사실을 의미하지 않습니다. 공지 등록·푸시 발송·외부 사이트 게시를 이번 적용 작업에 포함하지 않습니다. 새 뉴스 수집기나 광고/특가 기능도 추가하지 않습니다.

20 조회 중, 17 조회 성공 후 빈 목록, 18 캐시도 없는 조회 실패를 구분합니다. 이미 받아 둔 유효한 자료가 있고 새로 고침만 실패하면 23처럼 캐시를 유지합니다. 운영 측에서 철회/비공개로 바꾼 자료임을 확인하면 캐시보다 그 상태가 우선입니다. 실제 볼 수 없는 공지는 19로 표시하며 일시적 통신 실패를 폐기된 공지로 처리하지 않습니다. 해당 서버가 캐시/공개 상태를 아직 제공하지 않는다면 없는 기능이 완료됐다고 보고하지 않습니다.

## 7. 알림 설정과 기록 정리의 구분

설정은 `settings/notifications`와 이전 설정 전달본으로 연결합니다. OS 푸시 허용과 앱 내부 알림 내역은 같은 상태가 아닙니다. 푸시가 차단됐다고 알림함 데이터를 삭제하거나 빈 목록으로 표시하지 않습니다.

`markAllRead()`는 read를 바꾸고 행을 남깁니다. `clearAll()`은 별개로 clearExceptPendingActions를 호출해 일반 알림을 지우되 actioned=false인 CREW_INVITE/PARTY_INVITE/EVENT_REWARD는 보존하고 남은 행의 read를 갱신합니다. 이름이나 과거 주석만 보고 두 메서드를 바꿔 쓰지 않습니다. 미응답 초대가 모두 읽음 때문에 삭제되거나 수락되는 일이 없어야 합니다.

이 동작에 맞춰 기존 설정 전달본의 삭제 확인 문구도 보정했습니다. 답하지 않은 초대·미확인 보상 알림이 남는다는 설명을 유지합니다. 신규 일괄 삭제 버튼을 알림 첫 화면에 추가하지 않습니다.

## 8. 디자인·편집·접근성

배경 #050912, 본문 #F2F4FC, 보조 #98A8C0, 강조 #A3BFFE, 구분선 #1D2B3F. 폰트는 Pretendard Regular/Semibold, 목록 주 글자 16.5~18, 보조 12.5~14, 좌우 여백 24가 기준입니다. `design-tokens.json`의 값은 고정 화면 크기 강제가 아니라 시작값입니다.

SVG 텍스트·도형과 12개 분리 부품을 활용해 네이티브 UI로 만듭니다. Figma에서 가져온 SVG에 Auto Layout과 컴포넌트 상태는 별도로 구성합니다. 큰 이미지 한 장에 클릭 좌표만 덧씌우지 않습니다.

목록과 시트 본문은 작은 화면·큰 글씨에 맞춰 스크롤합니다. 버튼과 안전 영역은 겹치지 않습니다. 모든 터치 영역은 최소 48dp이며 점·화살표는 장식이고 행 전체를 누를 수 있어야 합니다. 새 알림은 색뿐 아니라 읽지 않음 의미를 스크린리더로 제공합니다. 읽은 제목도 충분한 대비를 유지합니다.

시트는 배경 초점을 막고 닫으면 원래 행으로 포커스를 돌립니다. 초대 거절 확인은 초대 시트 위에 계속 중첩하지 말고 내용 전환으로 제공합니다. 처리 중에는 중복 입력을 막되 종료할 수 없는 무기한 화면으로 만들지 않습니다. 공통 200ms 안팎의 절제된 전환을 사용하고 동작 줄이기를 존중합니다. 별도 반복 모션·보상 폭죽은 넣지 않습니다.

## 9. 구현 후 확인

기존 저장소의 필수 검사와 변경 동작의 테스트를 수행합니다. 읽음·응답·데이터 연결 변경에는 실제 상태를 검증하는 테스트가 필요합니다. 단순 색상/도형을 그대로 복제하는 테스트는 만들지 않습니다.

1. 첫 진입 미읽음 유지, 개별 읽음, 모두 읽음, 쓰기 실패, 요청 중 새 알림 도착, 재시작 후 상태.
2. 읽음 처리로 알림 삭제/actioned/가입/보상 지급이 발생하지 않음.
3. 정보형 알림의 지갑/신발 진입. slotKey를 임의의 소유 ID로 변환하지 않음.
4. 댓글 대상 이동·삭제·권한 없음·네트워크 오류. 목록 복귀 위치 유지.
5. 크루 Joined/Requested/확정 실패/결과 미확인/로그인 필요·취소. 중복 입력 방지.
6. 파티 초대 표시와 실제 참가의 분리. 거절 성공/실패·미처리 초대 보존.
7. 보상 알림에서 챌린지 확인만 수행하며 로컬 재지급 없음.
8. 공지 공급원·id·게시일·본문·허용된 내부 동작, 빈/오류/철회/유효 캐시·갱신 실패.
9. 외부 러닝 뉴스·대회 기능 보존. 새 공지가 기존 뉴스 저장소를 임의로 덮어쓰지 않음.
10. 큰 글씨·긴 제목·날짜 변경·작은 화면·스크린리더·공통 하단 바와 뒤로 가기.

이 패키지의 검수는 정적 시안과 파일에 한정됩니다. 실제 앱 실행·운영 서버·공지 게시·초대 처리 테스트 완료를 의미하지 않습니다.
