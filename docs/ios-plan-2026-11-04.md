# 아이폰 앱 계획 (2026-11-04)

사용자: "앱스토어 제출용 파일을 만들어야 하는데 자꾸 오류" → 저장소에 아이폰 앱이 없다(안드로이드 Kotlin 만) → "아이폰 앱 만드는 계획 짜줘" →
"추천대로 KMP로 시작해"(방식 결정). 개발자 계정 · 첫 판 범위 · 번들 ID 는 아직 정하지 않았다.

## 진행

### 1단계 ① 공용 모듈 · 규칙 코드 옮기기 (2026-11-04)

- `shared/` 모듈(Kotlin Multiplatform — 안드로이드 · iosArm64 · iosSimulatorArm64). 앱은 `implementation(project(":shared"))`. 패키지는 그대로 `com.stepup.android.domain`.
- `domain/` 50 파일을 모두 옮겼다. **공용(commonMain) 37 파일**, **아직 안드로이드 쪽(androidMain) 13 파일**:
  날짜에 `java.time` 을 쓰는 8개(RunRecords · CrewHome · CrewChat · CrewRunPool · Leaderboard · StoryRuns · coaching/CoachingPlans · coaching/CoachingWeeks)와
  그것을 쓰는 5개(Community · CrewCards · Stories · FeaturedMeetup · coaching/CoachingAi). 다음 차례에 kotlinx-datetime 으로 바꿔 공용으로 옮긴다.
- Java 함수 자리는 `Platform.kt`(expect) — 안드로이드는 예전 Java 함수를 그대로 부른다(`Platform.android.kt`, 안드로이드 동작 그대로).
  아이폰은 같은 글자를 내는 순수 Kotlin(`JavaFormat.kt` — `%d` · `%f` 포맷 · BigDecimal 반올림 · URL 인코딩)을 쓰고,
  `PlatformTwinTest`(안드로이드 단위 테스트)가 수천 개 값으로 Java 와 맞대어 본다. `PlatformCommonTest` 는 두 쪽 모두에서 돈다.
- 다른 모듈의 값은 자동 형변환(smart cast)이 안 돼서 앱 화면 8 파일의 19 줄에 `!!` 를 붙였다(바로 앞에서 null 을 확인한 자리, 동작 그대로).
- 아이폰 컴파일 · 시뮬레이터 검사는 `.github/workflows/ios-shared.yml`(Mac 러너 — shared · 빌드 설정이 바뀔 때만).
- 규칙 파일 경로를 읽던 스크립트(`scripts/check-coaching-twin.py` · `check-fakes.py` · `tools/gen_shoe_catalog.py` · `tools/build_design_asset_inventory.py`)와
  `test-sql.yml` 경로를 새 위치로.

## 방식: Kotlin Multiplatform + Compose Multiplatform (추천)

- 지금 코드 약 127,000줄이 모두 Kotlin · Compose 다. 공용 모듈(`shared`)로 옮기면 안드로이드 · 아이폰이 같은 화면 · 같은 규칙을 쓴다.
- Swift 로 새로 만들면 화면 189개 · 규칙 전부를 두 번 만들고, 그 뒤로 고칠 때마다 두 곳을 고쳐야 한다(서버 규칙과 어긋날 위험이 두 배).
- 아이폰에만 있는 부분(잠금 화면 Live Activity 등)은 Swift 로 쓴다 — 멀티플랫폼에서도 그 부분은 원래 그렇다.
- 이 작업 환경(리눅스)에서는 아이폰 빌드를 못 돌린다. 아이폰 빌드 · 검사는 GitHub Actions 의 Mac 러너가 하고, 결과는 TestFlight 로 받아 폰에서 본다.

## 단계

안드로이드 앱은 단계마다 지금처럼 Build APK 를 통과해야 한다(기능 · 화면 변화 없음). `strideup.db` · `strideup_prefs` 이름은 그대로.

1. **공용 모듈 만들기** — Kotlin 2.0 → 2.2, `shared` 모듈, `domain/` 을 먼저 옮긴다(테스트도 같이). 안드로이드는 이 모듈을 가져다 쓴다.
2. **서버 · 폰 저장 공용화** — 통신을 Ktor 로, Room 을 멀티플랫폼 판으로(같은 DB 이름 · 판 · 옮기기 그대로), 설정은 DataStore 그대로.
3. **아이폰 앱 뼈대 + 빌드** — Xcode 프로젝트 `iosApp/`, GitHub Actions Mac 빌드 → TestFlight 올리기. **첫 목표: 아이폰에서 로그인 · 홈 화면이 열린다.**
4. **화면 옮기기** — `ui/` 를 공용으로. Context · Intent · Toast · 클립보드 · 공유 · 링크 열기를 공용 틀(안드로이드 / 아이폰 구현) 뒤로.
5. **아이폰 전용 기능**
   - 러닝: 위치 `CLLocationManager`(백그라운드 위치), 걸음 `CMPedometer`. 안드로이드의 전경 서비스 대신 백그라운드 위치로 앱이 깨어 있다.
   - 잠금 화면 · 다이내믹 아일랜드: Live Activity(SwiftUI 위젯) — 안드로이드의 러닝 알림 · `LockRunPanel` 자리.
   - 푸시: APNs 키를 Firebase 에 넣고 FCM 아이폰 SDK. 크루 출발 알림 · 링크 열기 같은 길.
   - 로그인: 구글 + **애플로 로그인**(애플 심사 규칙 4.8 — 구글 로그인을 두면 애플 로그인도 있어야 한다). 서버 Supabase 에 Apple 공급자를 켠다.
   - 러닝 올리기: WorkManager 대신 앱이 앞으로 올 때 · 러닝이 끝날 때 바로 + `BGTaskScheduler`.
   - 링크: `web/.well-known/apple-app-site-association`(Universal Links — `assetlinks.json` 의 아이폰 짝).
   - 테스트 APK 스스로 업데이트는 없다(TestFlight 가 대신).
6. **심사 준비 · 제출** — 개인정보 매니페스트(`PrivacyInfo.xcprivacy`) · App Privacy 답 · 위치 사용 까닭 글 · 스크린샷 · 연령 등급 ·
   심사 메모에 접속 코드(비공개 베타 동안). 계정 삭제(5.1.1)와 뽑기 확률 표시(3.1.1)는 이미 앱에 있다.

## 애플 심사에서 조심할 것

- **SUP · 지갑 · 거래소**: 안드로이드 스토어 판처럼 블록체인 기능은 뺀다(`WEB3 = false`). 지갑 주소 연결도 첫 판에서 뺄지는 사용자 결정.
  SUP 가 돈으로 바뀌는 길(출금)이 아이폰 판에 보이면 안 된다.
- **애플로 로그인**이 없으면 거절된다.
- **백그라운드 위치**: 러닝 중에만 쓰는 까닭을 화면 · 글로 분명히(항상 위치 권한은 요청하지 않는다 — 러닝 중 "사용하는 동안" + 백그라운드 모드).
- **접속 코드로만 들어오는 앱**: 심사자에게 코드를 주면 된다. 베타는 원래 TestFlight 로 돌리는 것이 자연스럽다.
