# 점검 — 함께 뛰기(크루 러닝 · 번개러닝) (2026-11-18)

사용자 "함께뛰기쪽 버그없는지 다시 테스트해보고 많은 케이스 상정해서 샅샅히 뒤져봐" → "심각성별로 봐봐".
같은 날 사용자 "전부수정해" — **모두 고쳤다**(맨 아래 "모두 고쳤다", 서버 0117 · 새 판 29 · 1.20.1).

- 서버: 실제 규칙(`supabase/setup.sql`, 0116 까지)을 로컬 Postgres 에 올리고 가짜 사용자 여럿이 앱이 부르는 함수를 그대로 불렀다 —
  `tools/together_sim/run.sh`(장면 아홉, 끝나면 되돌린다). 숫자는 운을 끈 값(보상 · 닳음 × 1).
- 앱: 대기실 쪽 · 달리는 중 · 결과 쪽을 서버 함수 본문과 맞대어 읽었다(기기에서 돌려 보지는 못했다). 큰 것은 코드를 다시 열어 확인했다.

"고치는 곳"의 **서버** 는 배포만으로 예전 스토어 판(1.17.1) · 1.20.0 모두에 바로 듣는다. **앱** 은 새 판이 필요하다.

## 🔴 심각

### 1. 상태 알림(5초마다) 없이 달리면 크루 체력을 쓰지 않는다 — 크루 러닝에는 다른 상한이 없다

- 크루 체력은 `crew_run_beat` 가 부르는 `economy.crew_pool_settle` 로만 줄고, 정산(`record_session`)은 그 기록(`crew_pool_empty` 구간)만 본다.
  알림이 한 번도 안 오면 0 이던 구간이 없어 러닝 전체가 적립된다. 크루 러닝은 하루 금액 상한 · 경로 없는 러닝 상한 · 올린 날 상한 · 개인 에너지 · 내구도를 모두 건너뛴다(0070 · 2026-10-21 "일단 무제한").
- 재현(`02-offline-both` · `09-nobeat-nogps-6h`): 둘이 출발하고 인터넷을 끈 채 3시간 28,000보 → **485 SUP**(같은 신발 혼자 77) · 효율 +600% 신발이면 **2,428 SUP** ·
  경로 없이 걸음만 6시간 80,000보 → **1,388 SUP**(혼자 러닝이면 경로 없는 러닝은 하루 96).
- 같은 뿌리: 출발 명단에 들고 폰은 출발하지 않은 사람이 10분 안에 혼자 러닝을 하면 크루 러닝으로 정산(체력 3 · 크루 보상 · 에너지 · 내구도 없음, `03` 나).
- 고치는 곳 — **서버**: 정산 때 서버가 세지 못한 시간(러닝 시간 − `active_sec`)만큼 그때 풀에서 빼고, 모자라면 그만큼 적립을 줄인다
  (지하철 같은 진짜 끊김도 공정하다). 경로 없는 크루 러닝에는 혼자 러닝과 같은 상한.

## 🟠 높음

### 2. 둘이 뛰다 한 명이 "종료"를 누르면 남은 사람의 러닝이 5초 안에 소리 없이 멈춘다

- 서버 `economy.crew_run_close` 는 남은 사람이 하나면 바로 `LAST_PARTICIPANT_END` 로 끝낸다(여유 `crew_alone_grace_sec` 60 은 만들어 두고 아무 데서도 안 쓴다).
  앱은 다음 알림 답에서 `endedAlone` 을 보면 러닝을 멈추고 저장한다(`CrewRunRepository.kt` · `ServiceLocator.kt` `stopRun`) — 소리 · 진동 · 알림 없이, 러닝 화면을 보고 있을 때만 시트가 뜬다.
- 종료 창은 "다른 러너는 계속 달려요"(`run_crew_end_member_note`) · "다른 사람은 각자 폰에서 계속 기록해요"라고 안내한다 — 남은 사람이 하나면 사실이 아니다.
- 결과: 폰을 주머니에 넣은 사람은 기록 없이 계속 뛰고 그날 크루 러닝도 끝난다. 출발 몇 초 만에 상대가 끝내면 내 기회도 몇 초 만에. 모르고 30분을 더 뛰어 올리면 4,850보 중 213보(3.7 SUP, `07` 나).
- 고치는 곳 — **서버**: 마지막 한 사람을 바로 끝내지 않거나 60초 여유를 쓴다(예전 앱도 서버 답으로 멈추므로 같이 낫는다). **앱**: 둘 남았을 때 종료 창에 "○○ 님의 크루 러닝도 끝나요", 멈출 때 소리 · 진동 알림.

### 3. 출발 순간 폰이 러닝을 켜지 못하면 그날 크루 러닝 기회가 사라진다

- `PartyRunStartHost` 는 방을 "처리함"으로 적은 뒤 `WalkSessionService.start` 를 부르고 러닝 화면으로 간다 — 서비스가 거절해도(과속 멈춤 뒤 10분 · 정리 안 된 앞 러닝 · 전경 거절 · 정확한 위치를 거뒀음)
  안내 한 줄뿐이고 `startRefusals` 를 보지 않는다. "처리함"이라 `missedStart()`(→ `crew_run_release`)가 다시 돌지 않는다.
- 결과: 서버에는 오늘 크루 러닝을 한 사람, 다른 사람 인원에도 들어간다. 앱은 그 방을 "달리는 중"으로 쥔 채 5초마다 묻고, 다음 혼자 러닝 지도에 크루원을 그린다.
  대기실 "준비"는 과속 금지 시간을 보지 않는다(혼자 러닝 시작은 본다).
- 고치는 곳 — **앱**: 금지 시간 · 남은 앞 러닝이면 준비를 막고, 출발 뒤 거절이 오면 `missedStart()` 처럼 돌려받고 나간다.

### 4. 카운트다운 중 "나가기"를 누르면 그날 기회가 사라진다 — 나가기 창은 "아직 출발 전이라 오늘 기회를 쓰지 않아요"

- 출발을 누르는 순간 서버가 `crew_runs` 를 만든다. 앱 `leaveLobby()` 는 `party_leave` 만 보내고 `crew_run_release` 를 부르지 않는다(방 바꾸기도 같다). 나가기 창은 카운트다운 동안에도 열려 있다.
- 서버 검사(`06` 가): `crew_run_release` 를 부르면 돌려받는다 — 앱이 안 부를 뿐.
- 고치는 곳 — **서버**: `party_leave` 가 달리지 않은 오늘 크루 러닝을 함께 푼다(예전 앱도 낫는다). **앱**: 카운트다운이면 나가기 창을 닫는다.

### 5. 대기실에서 폰을 잠그거나 다른 앱으로 가면 출발에서 빠지고, 돌아오면 "진행자가 내보냈어요"

- 서버 `party_start` 는 15초 넘게 대기실을 묻지 않은 준비 인원을 뺀다(0087 유령 막기 — 그대로 둘 규칙). 앱은 대기실을 앱 범위 코루틴으로 묻지만 잠금 · 다른 앱이면 폰이 재워 멈춘다(전경 서비스 · 깨우기 없음).
  화면 켜 두기는 준비한 사람만, 앱이 보일 때만. 출발 푸시는 없다(push-send 에 방 열림만) — `CrewStartAlert` 는 앱이 깨어 있을 때만 뜬다.
- 빠진 사람은 다음 물음에서 42501 → 앱이 모두 `REMOVED`("진행자가 내보냈거나 들어갈 수 없는 대기실")로 보인다. 번개는 "다시 시도"가 그 사람을 진행자로 한 **새 대기실**을 연다.
- 진행자가 준비 전이면 화면이 꺼지고 30초 뒤 진행자가 말없이 다른 사람에게 넘어간다.
- 고치는 곳 — **서버**: 출발 때 명단에 푸시(+ push-send 다시 올리기). **앱**: 거절을 가려 "출발했어요 — 대기실을 보고 있지 않아 함께 못 했어요"로, 진행자도 화면 켜 두기.

### 6. 번개 글 하나로 인원 보너스를 몇 번이고 받는다

- 방을 닫고 같은 글로 다시 열면 매번 새 방이라 +30 ~ 50% 가 다시 붙는다. 모임 시각이 이틀 지난 글로도 열린다(앱만 `Post.lobbyOpen` 으로 막는다).
  출발만 누르고 뛰지 않은 사람도 인원이다("무조건 다 보너스" 결정대로) — 넷이 출발하고 한 명만 뛰어도 4명 보너스(`05`).
- 혼자 러닝의 하루 상한 안이라 끝없지는 않지만 상한까지 빨리 찬다.
- 고치는 곳 — **서버**: 번개 글 하나에 출발은 한 번, 대기실은 모임 시각 앞뒤로만.

## 🟡 보통

7. **출발을 놓친 뒤 기회를 돌려받는 동작이 한 번뿐** — `missedStart()` 의 `crew_run_release` 는 8초 한 번, 실패하면 다시 안 한다. 화면에서 뒤로 가면 취소되고 `party_leave` 도 안 간다.
   앱을 껐다 켜면 아예 돌지 않는다. **앱**: 다시 시도 · 방 목록 · 오늘 크루 러닝에 "달리지 않은 내 방"이 보이면 그때도 돌려받기.
8. **크루 러닝 결과의 "예상 보상"이 혼자 러닝 식** — 개인 에너지 · 신은 신발 내구도 · 번개 배수로 센다. 체력이 중간에 바닥난 러닝은 약 2배, 개인 에너지가 0 이면 0 으로 보인다("예상" 표시는 있다). 달리는 중 예상의 체력 0 구간 기록은 화면 상태에 있어 화면이 꺼져 있으면 놓친다. **앱**.
9. **크루 출발 10분 안 혼자 러닝을 서버가 크루 러닝으로 짝지을 수 있다** — `economy.party_for` 가 시각만 본다(±10분). 올리는 순서에 따라 혼자 러닝이 크루 자리를 가져가 거의 0, 진짜 크루 러닝은 개인 러닝으로.
   **서버**: 창을 출발 −10초 ~ +2분 15초로(앱은 2분 넘게 늦은 출발을 안 켠다). **앱**: 크루 러닝은 0초 · 무효여도 올리고 먼저 올린다.
10. **달리는 중 크루 해산 · 진행자 계정 삭제(드묾)** — 방(`parties`)이 cascade 로 지워져 같이 뛰던 모두가 혼자 러닝으로 정산(에너지 · 내구도), 오늘 기회는 쓴 채(`04` 가 · 다). **서버**: 달리는 중 해산 막기, 계정 삭제 때 진행자 넘기기.
11. **정해 둔 출발 시각이 폰 시계 차이만큼 밀려 보인다** — `planAtLocal = planAt − (서버 − 폰)`. 시계가 조금만 늦어도 "19:00" 방이 "18:59". 카운트다운에만 빼야 한다. **앱**.

## 🟢 낮음

12. 0 SUP 로 정산된 크루 러닝은 까닭 줄(체력 바닥 · 서버가 끝냄 · 크루 러닝 아님)이 안 보인다 — `confirmed` 가 `points > 0` 을 요구. **앱**.
13. 체력 0/0(신발 없이 출발) · 끊겨서 화면에서 0 이 돼도 "체력 바닥"이 안 뜬다 — `exhausted` 는 총량 > 0 일 때만. **앱**.
14. 크루 러닝 중 과속 멈춤 벌칙(남은 내구도 절반)이 크루에서 고른 신발이 아니라 신은 신발로. **앱**.
15. 번개 대기실 정원이 글의 정원과 상관없이 20(`party_capacity` — 번개 방은 `capacity` 가 비어 있다). 정원 30 글에 22명이면 22/20. **서버**.
16. 준비 · 준비 취소를 빨리 누르면 서버에 순서가 뒤집혀 들어갈 수 있다(누를 때마다 따로 보냄). **앱**.
17. 문구: 이미 오늘 뛴 사람의 준비 거절이 "다시 눌러 주세요" · 코스 바뀜 출발 거절도 같은 글 · 크루원이 아닌 방 링크에 "내보냈어요" · 번개인데 "크루 러닝이 출발했어요" 알림 ·
    번개 대기실 내보내기 확인 없음 · 출발 순간에 알림 권한 창(늦게 출발). **앱**.
18. 달리는 사람이 모두 10분 넘게 끊기면 다른 크루원이 방 목록을 여는 순간 방이 닫혀 거리 공유가 말없이 멈춘다(보상 영향 없음, `06` 나). **서버**.
19. 종료 알림이 1분 안에 서버에 못 닿으면 올릴 때까지 서버에 "달리는 중"으로 남는다 · 알림 간격이 폰 시계라 시계를 뒤로 돌리면 멈춘다 · 크루 함수 응답 대기가 20 + 20초. **앱**.
