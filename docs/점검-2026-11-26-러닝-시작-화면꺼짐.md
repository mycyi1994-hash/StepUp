# 점검 2026-11-26 — 화면을 끄면 측정이 안 됨 · 3·2·1 뒤에야 측정 · 다른 러닝 앱과 겹침

테스터 피드백(사용자가 전달): "화면을 띄운 상태에서 껐더니 측정이 안 됐다 · 백그라운드 설정 문제 같다(신발은 37분짜리)" ·
"1·2·3 하고 start 해야 측정된다 — 누르자마자 측정되게" · "다른 러닝 앱이랑 겹쳐서 안 된다". 사용자 "전부 확인해 봐".

## 찾은 것

1. **기록은 3·2·1 연출이 끝나야 시작했다.** 자유 러닝은 "이 신발로 출발"을 누르면 3 · 2 · 1 · 0 → StepUP! 를 보이고 3.76초 뒤(지도 펼침)에
   러닝 서비스를 켰다(`FreeRunStartSequence`). 연출 시계는 앱이 화면에 있을 때만 나아간다 — 앱이 뒤에 있을 때 전경 서비스를 켜면
   안드로이드 12+ 가 막기 때문이다. 그래서 **누르고 바로 화면을 끄거나 · 주머니에 넣어 화면이 꺼지거나 · 다른 러닝 앱으로 넘어가면 연출이 멈춰
   기록이 아예 시작되지 않았다**(돌아와 화면을 켜야 이어서 시작). 챌린지 · 코스 · 다이어트의 3-2-1(`RunCountdown`)도 같다.
   - 세 피드백이 모두 이것으로 설명된다 — "화면을 띄운 채 껐다", "1·2·3 뒤에 start 해야 측정", "다른 러닝 앱과 같이 쓰면 안 된다"
     (다른 앱을 켜러 넘어간 사이 StepUp 연출이 멈춤).
2. **배터리 절전 안내가 없었다.** 러닝 서비스는 전경 서비스(health · location) · CPU 깨우기(12시간) · 구글 위치(높은 정확도 2.5초)라
   화면이 꺼져도 돌도록 돼 있다. 다만 삼성 · 샤오미 등은 앱 배터리 설정이 "최적화" · "절전"이면 화면이 꺼진 뒤 위치 · 걸음을 늦추거나
   앱을 재운다 — 앱에 그 안내가 어디에도 없었다.
3. **다른 러닝 앱과 겹치는 자원은 없다.** GPS(구글 위치 · LocationManager) · 걸음 센서(TYPE_STEP_COUNTER)는 여러 앱이 함께 받는다.
   소리 포커스(audio focus)를 잡지 않고, 가짜 위치 표시(isMock)는 가짜 GPS 앱의 위치만 거른다. 겹침 문제는 1 의 연출 멈춤이다.

## 고친 것

- 자유 러닝: **누른 순간 기록을 켠다**(앱이 확실히 앞에 있는 때). 3 · 2 · 1 · 0 숫자는 빼고 StepUP! → 지도 펼침만(약 1초,
  `FreeRunStartMotion.QUICK_START_AT`) — 연출은 그대로 앱이 보일 때만 나아가지만 기록은 이미 돌고 있다. 숫자 묶음은 다 빠진 뒤로 그리지 않는다
  (화면 읽기가 투명한 "0"을 읽지 않게). 시작한 뒤 뒤로 가기는 취소가 아니다(러닝 화면 규칙).
- 챌린지 · 코스 · 다이어트: 3-2-1 없이 바로 시작(`RunCountdown` 은 남겨 두었고 쓰지 않는다).
- 출발 전 신발 확인에 배터리 한 줄 — 앱이 배터리 최적화 대상이면 "화면을 꺼도 기록이 끊기지 않게 배터리 사용을 「제한 없음」으로" +
  "설정 열기"(앱 정보). 돌아오면 다시 읽어 바꿨으면 사라진다. 출발을 막지 않는다. 예외 요청 권한(REQUEST_IGNORE_BATTERY_OPTIMIZATIONS)은
  Play 정책상 쓰지 않는다.
- 크루 러닝 출발은 그대로(서버 시각에 맞춰 출발 — 앱이 뒤에 있으면 `CrewStartAlert` 알림, 2026-11-04).

## 확인하지 못한 것

- 실제 폰(특히 삼성 "사용하지 않는 앱 절전 · 딥 슬립")에서 화면을 끈 채 30분 넘게 달려 보는 확인 — 이 세션엔 폰 · 에뮬레이터가 없다.
  테스터에게 새 테스트 APK 로 "누르고 바로 화면 끄기"와 "배터리 제한 없음" 두 경우를 부탁한다.
