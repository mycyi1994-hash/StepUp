## 1. 정식 출시의 정의 (Definition of Done)

아래 항목이 **전부** 체크돼야 "정식 출시"라고 부른다. 하나라도 비면 베타다.

### 제품
- [ ] Google Play **프로덕션 트랙**에 공개, 서명은 Play App Signing
- [ ] 실제 Google 로그인 + 게스트 → 계정 승격 (기기 바꿔도 데이터 유지)
- [ ] 커뮤니티·크루·랭킹·코스 공유가 **서버 데이터**로 동작 (시드 데이터 제거)
- [ ] 크래시 프리 세션 ≥ 99.5%, ANR < 0.3% (Play Vitals 기준)
- [ ] 4개 언어 전부 실기기 QA 통과

### 포인트 (온체인 아님)
- [ ] SUP 잔고·원장이 **서버에** 있어 기기를 바꿔도 유지됨
- [ ] 앱 어디에도 "곧 토큰으로 바꿔 드립니다"라는 **약속이 없다** (§8 주의)
- [ ] 이용약관에 SUP가 현금 가치 없는 인앱 포인트임이 명시 — [작성 완료](../web/terms.html)

### 신뢰·안전
- [ ] 서버 측 GPS·케이던스 검증이 실제 부정 세션을 걸러낸 베타 데이터
- [ ] 개인정보처리방침·이용약관 게시, 앱 내 링크
- [ ] 위치정보사업 신고 필요 여부 확인 (§8)

### 운영
- [ ] 크래시(Firebase Crashlytics)·서버 로그 모니터링, 알림 채널

## 4. 핵심 설계 결정 (ADR)

### D1. 지갑 — 임베디드 지갑을 기본으로, 외부 지갑은 선택
- **선택:** 첫 실행 시 앱이 조용히 키를 생성해 Android Keystore로 암호화 저장. 사용자는 "지갑"이라는 단어를 출금 화면에서 처음 본다. 백업은 Google Drive 앱 데이터에 암호화 저장(로그인 계정 기준). 원할 때 시드 문구 내보내기 / WalletConnect v2로 MetaMask 등 외부 지갑을 출금 주소로 연결.
- **대안:** WalletConnect만 지원 → 첫 러닝 전에 지갑 설치를 요구하게 되어 README가 약속한 "지갑 없이 시작"이 깨진다.
- **라이브러리:** `org.web3j:core`(Android 호환 빌드) 또는 KEthereum. 키 생성·EIP-712 서명·ERC-20 approve·`mintWithAuth` 호출만 필요하므로 가벼운 쪽을 고른다.

### D2. 정산 모델 — 세션 종료 즉시 어테스트, 출금은 배치 청구
`RewardDistributor`는 **세션 단위**로만 지급하고(`sessionHash` 재사용 방지), **7일 청구 창**(`CLAIM_WINDOW_DAYS`)이 있다. 그래서:

1. **러닝 종료 시** 앱이 `{runner, startedAt, endedAt, steps, boostBps, partySize, track}` + Play Integrity 토큰을 백엔드에 업로드(오프라인이면 큐에 넣고 WorkManager로 재시도, 7일 안에).
2. 백엔드가 기기 증명을 확인하고 어테스터에 전달 → **서명된 Claim을 백엔드에 보관**, 인앱 SUP 원장에 적립.
3. 인앱 SUP는 지금처럼 민팅·강화·부스트에 **오프체인으로** 쓴다(토크노믹스 §7.1 그대로).
4. **출금 요청 시** 릴레이어가 미청구 세션 서명을 **오래된 순(FIFO)** 으로 `claim()` 제출. 출금 가능액 = `min(인앱 잔고, 미청구 세션 합)`.
5. 인앱에서 이미 써버린 만큼의 세션은 청구하지 않고 만료시킨다. **청구되지 않은 세션 = 발행되지 않은 SUP** — 인앱 소각과 온체인 공급이 자연스럽게 맞는다.

- **대안(전부 온체인):** 적립·소비 모두 체인 tx. 매 러닝·매 민팅이 tx가 되어 가스와 UX 비용이 커진다. 메인넷 안정화 후 검토.
- **주의:** 서명은 `deadline`이 있으니 백엔드는 세션 어테스트 후 7일 내 미출금 세션의 "출금 가능액"이 줄어든다는 점을 UI에 표시해야 한다. 간단한 해법은 **출금 가능액을 매일 자동 청구**(유저 개입 없이 릴레이어가 매일 밤 미청구 세션을 전부 claim → 지갑 잔고가 진짜 잔고, 인앱 소비는 온체인 `burnFrom`). 이 경우 인앱 원장이 사라져 더 단순하지만 민팅·강화가 유저 tx가 된다. **베타에서 두 방식 중 하나를 확정**한다. 기본 권장은 ①~⑤(오프체인 원장 유지).

### D3. 가스 — 유저는 가스를 모른다
- `claim()`은 누가 호출해도 SUP는 `c.runner`에게 가므로(`RewardDistributor.sol:168`) **릴레이어가 제출**한다. 유저 가스 0.
- 민팅·강화·전송은 유저 지갑이 `msg.sender`여야 한다(`mintWithAuth`: `a.to == msg.sender`). GIWA는 OP Stack L2라 가스가 매우 싸므로 **신규 지갑에 1회 가스 드립**(예: 0.0005 ETH, 계정당 1회, Play Integrity 통과 시)을 릴레이어가 보낸다.
- 장기: ERC-4337 페이마스터 또는 컨트랙트에 ERC-2771 포워더 추가(메인넷 배포 전 결정 — 배포 후엔 못 바꾼다).

### D4. 백엔드 — Supabase, 어테스터·릴레이어는 Cloudflare로 분리
§3 참고. 서명 키(`ATTESTER_PRIVATE_KEY`, 릴레이어 키)는 **절대 백엔드에 두지 않는다.**

### D5. 인증 — 진짜 Google 로그인 + 게스트 승격
- Android Credential Manager로 Google ID 토큰 획득 → Supabase Auth로 교환.
- 게스트로 쌓은 Room 데이터는 로그인 시 **한 번 업로드해 서버 원장으로 승격**(`RUNNER_UID`를 서버 UID에 매핑). 이후 서버가 진실, Room은 캐시.
- 이 마이그레이션이 Phase 1의 가장 까다로운 부분이다. 기존 APK 사용자의 잔고·스니커즈가 사라지면 안 된다.

### D6. 기기 증명 — Play Integrity를 청구의 전제 조건으로
- 앱이 세션 업로드마다 Integrity 토큰을 첨부, 백엔드가 Google API로 검증.
- 실패해도 **플레이는 된다**(인앱 SUP 적립). **청구·출금만 막는다.** 토크노믹스 §8-3 그대로.

### D7. NFT 메타데이터 — 44종 IPFS 고정
- 앱에 있는 44개 스니커즈 디자인을 PNG/SVG로 내보내 Pinata에 고정, `{faction}/{rarity}/{variant}.json` 구조. 메인넷 `SneakerNFT` 배포 시 실제 CID를 `baseURI`로 넣는다(`setBaseURI`로 나중에 바꿀 수도 있음).

### D8. 메인넷은 재배포, 테스트넷 데이터는 이관하지 않는다
- 컨트랙트가 업그레이드 불가(의도적)이므로 메인넷은 **새 주소**. Sepolia 잔고·NFT는 테스트용이었음을 앱과 문서에 명시.
- 메인넷 배포 전 **반드시** 결정: ERC-2771/4337 지원 여부(D3), 트레저리·팀·생태계 지갑 주소(멀티시그), `attester`·`roller`·`recorder` 주소 분리, 초기 풀 펀딩액.
- 감사: 코드가 작으므로(4개 컨트랙트, OZ 기반) 소규모 감사 업체 또는 공개 리뷰 + 버그바운티. **감사 없이 메인넷 풀에 실물 가치를 넣지 않는다.**

### D9. 릴리즈 서명·배포 — Play App Signing, 3단계 트랙
- 업로드 키 생성 → GitHub Secrets → CI가 `bundleRelease`(AAB) 생성. debug 키스토어는 사이드로딩 테스트용으로 유지.
- 내부 테스트(팀) → 비공개 테스트(베타 100~500명) → 프로덕션.
- R8/ProGuard 켜기(`isMinifyEnabled = true`), web3 라이브러리 keep 규칙 추가.

## 9.5 v2 — 온체인화 (v1 지표를 보고 판단)

v1을 내고 **실제로 쓰는 사람이 있는지 확인한 뒤에** 시작한다. 이미 만들어 둔
것들이 잠들어 있으므로, 깨우는 일부터다.

**시작 판단 기준 (예시 — 실제 수치는 v1 데이터를 보고 정한다)**

- D7 리텐션이 의미 있는 수준인가
- 하루에 실제로 러닝 세션이 얼마나 쌓이는가
- 온체인 없이도 사람들이 남아 있는가 — 남지 않는다면 토큰을 붙여도 남지 않는다

**깨울 것 (이미 있음)**

| 이미 만들어 둔 것 | 상태 |
|---|---|
| GPS 경로 저장 | 동작 중 — 세션마다 시각이 붙은 경로가 쌓인다 |
| 세션 업로드 대기열 | 동작 중 — 서버 주소가 비어 있어 잠들어 있다 |
| 어테스터 (서명 서비스) | 코드·테스트 완료, 미배포 |
| 컨트랙트 4종 | GIWA Sepolia 배포 완료 |

**새로 할 것**

| 할 일 | 비고 |
|---|---|
| 임베디드 지갑(D1) | 생성·Keystore·백업·복원 |
| 어테스터 배포 + 컨트랙트에 등록 | `setAttester` |
| 릴레이어(§6) + 가스 드립(D3) | 유저 가스 0 |
| 오프체인 포인트 → 온체인 SUP 전환 정책 | **가장 어려운 결정.** 그동안 쌓인 포인트를 어떻게 다룰지 |
| NFT 메타데이터 IPFS 고정(D7) | `setBaseURI` |
| Play Integrity(D6) | 청구 자격 검사 |
| 메인넷 배포 전 결정(D8) + 키 역할 분리 + 감사 | 트레저리·소유자는 멀티시그 |
| 법률 재검토 | 출금이 생기는 순간 §8이 전부 되살아난다 |

> ⚠️ **전환 정책을 v1 단계에서 약속하지 않는다.** "나중에 토큰으로 바꿔 드립니다"는
> 그 자체로 기대를 만들고, 기대는 법적 성격을 띤다. v1 이용약관은 "온체인 전환을
> 개발 중이나 시점·조건·지역을 약속하지 않는다"로 이미 적혀 있다 —
> [이용약관 §3-3](../web/terms.html).

## 11. 리스크와 대응

| 리스크 | 가능성 | 대응 |
|---|---|---|
| 국내 P2E 규제로 출금 불가 | 높음 | 투트랙(§8): 출금 없는 국내 빌드 + 허용 국가부터 온체인. 앱은 이미 오프체인으로 완결 |
| 게스트 → 계정 마이그레이션에서 데이터 손실 | 중 | 승격 전 로컬 스냅샷 내보내기, 서버 검증 후 커밋, 롤백 경로 |
| 어테스터 규칙 오탐으로 정상 유저 반발 | 중 | 베타에서 VOID 세션 리뷰·이의신청 채널, 규칙은 서버에서 즉시 조정 |
| 릴레이어 키·가스 고갈 | 중 | 잔고 알림, 자동 충전 상한, 실패 큐 재시도 |

| 1인 개발 병목 | 높음 | Phase마다 "끝까지 한 바퀴" 우선, 기능 추가보다 통합 먼저 |
| Play 정책 거절 | 중 | 내부 트랙에서 정책 선언 먼저 제출해 피드백 확보 |

## 12. 지금 당장 (이번 주)

1. **출시 국가·출금 정책 질문을 던진다** (§8) — 법률 검토 착수. 답이 늦어도 Phase 0·1은 진행 가능.
2. **Phase 0 기술 항목**: 문서 최신화 → 소스 검증 → 어테스터 배포 → CI 브랜치 → Play Console 내부 트랙.
3. **Phase 1 첫 삽**: Supabase 프로젝트 생성, 스키마 초안, 앱에 `data/remote` 뼈대 + 진짜 Google 로그인.

이 순서로 가면 4~6주 뒤 "계정이 있고 서버가 있는 앱", 그로부터 4~6주 뒤 "테스트넷에서 러닝→출금이 한 바퀴 도는 앱", 다시 4~6주 베타를 거쳐 메인넷·스토어 공개 순이다.
