# 인터넷이 중간에 끊겼을 때 — 점검과 고침 (2026-10-17)

사용자: "지금 인터넷이 중간에 끊어졌을 때의 대처들을 확인해 보고, 맞는지 파악해 봐. 이상한 게 있으면 고쳐 봐."

다섯 갈래로 나눠 코드를 읽고 점검했다. 다섯 갈래는 러닝 끝(저장 · 정산 · 올리기), 크루 · 번개 달리기, 값이 오가는 일(뽑기 · 수리 · 강화 · 거래소 · 보상),
커뮤니티 · 채팅, 로그인 · 앱 시작이다. 각 흐름에서 세 가지 경우를 따라갔다.

1. 누르기 전에 이미 끊겨 있다.
2. 보낸 뒤 응답만 잃었다 — 서버는 했을 수도, 안 했을 수도 있다.
3. 다시 연결됐다.

## 잘 되고 있던 것

- 러닝 기록 · 저장은 폰 안에서 끝난다. 러닝을 잃거나 두 번 정산하는 길은 없었다.
- 서버가 확인하기 전에 "적립 완료"를 보이는 곳도 없었다.
- 올리기 일꾼(WorkManager)은 연결을 기다렸다가 같은 러닝을 한 번만 올린다(서버가 사용자 · 시작 시각으로 거른다).
- 뽑기 · 강화 · 포인트는 요청 번호 · 결과 확인이 갖춰져 있다.
- 채팅은 메시지마다 번호가 있고, 끊기면 "전송 대기" → 다시 연결되면 번호로 확인한다.
- 네트워크 오류로 로그아웃되거나 세션이 지워지는 길은 없었다. 연결 오류로 앱이 죽는 길도 찾지 못했다.

## 고친 것

| 영역 | 문제 | 고침 |
|---|---|---|
| 로그인 · 러닝 | 느린 연결에서 출입증 갱신(최대 40초)이 잠금을 쥔 동안 러닝 시작 · 저장 · 되살리기가 함께 멈췄다(시작 화면은 5초 뒤 포기 → 러닝이 늦게 몰래 시작). 줄 선 요청마다 갱신을 다시 해 그 곱만큼 막혔다 | 기록 주인 읽기는 잠금 없이(`SessionHolder.recordingOwner`). 연결 문제로 갱신하지 못하면 20초 동안 다시 두드리지 않는다 |
| 러닝 올리기 | 다시 로그인해야 올릴 수 있을 때 일꾼이 조용히 물러나 결과가 "정산 대기"에 머물렀다(7일 지나면 서버가 받지 않음) | 결과 화면의 "다시 로그인"이 보이게 알린다(`EconomySync.markSignedOut`) |
| 러닝 올리기 | 몇 번 끊긴 뒤엔 다시 하기 간격이 두 배씩 늘어 몇 시간까지 "정산 대기" | 실패마다 30초씩 늘린다(LINEAR) |
| 다시 연결 | 연결이 돌아와도 잔고 · 푸시 주소 · 올리기를 앱을 다시 켤 때까지 아무도 다시 하지 않았다 | 인터넷이 다시 되면(VALIDATED) 한 번 다시 한다(`core/NetworkWatch.kt`) |
| 잔고 맞추기 | 다 받아 온 뒤 계정 확인에 출입증을 다시 받아(네트워크) 느린 연결에서 받은 사본을 버렸다 | 저장된 세션으로 확인한다 |
| 거래소 | 구매 입찰을 응답만 잃고 다시 누르면 같은 값을 두 번 묶거나 신발을 두 번 샀다. 즉시 구매 · 판매 · 내놓기는 된 일을 "이미 끝난 매물"로 보였다 | 요청 번호(서버 0062 · 0057 영수증) — 다시 보내면 처음 결과. 끊기면 "결과를 확인하지 못했어요"와 함께 다시 맞춘다 |
| 글 · 댓글 | 게시판 · 번개 글과 댓글이 다시 누르면 두 번 올라갔다(번개는 모임이 둘) | 요청 키(서버 0062 `post_create` · `comment_create` `p_client_key`) |
| 좋아요 | 응답을 잃고 다시 누르면 거꾸로 취소됐다 | 바라는 상태를 보낸다(서버 0062 `post_set_like`) |
| 지우기 | 지운 응답을 잃고 "다시 삭제"를 누르면 몇 번을 눌러도 "내가 쓴 글만…" | 이미 없으면 된 것으로(서버 0062) |
| 크루 대기실 | 진행자가 끊긴 채 나가면(나가기가 서버에 안 닿음) 진행자로 남아 나머지가 출발할 수 없었다 | 30초 넘게 안 보이는 진행자는 지금 보이는 사람에게 넘긴다(서버 0063) |
| 러닝 위치 | 구글 위치 서비스가 러닝 중간에 조용해지면(끊겼다 돌아온 뒤 등) 러닝이 끝날 때까지 위치가 멈췄다 — 휴대폰 위치로 넘기는 것은 켠 뒤 처음 15초에만 있었다 | 언제든 15초 조용하면 휴대폰 위치도 듣고, 30초면 요청을 다시 건다(`WalkSessionService`) |
| 지도 | 끊긴 동안 못 받은 타일을 보이는 범위가 바뀔 때까지 다시 받지 않았다 — 빈 칸 격자는 화면에 붙어 있어 "아무리 움직여도 그 자리"로 보였다 | 다시 연결되면 바로 · 빈 칸은 15초마다 다시 받는다. 격자는 지도와 함께 흐른다(`MapTiles` · `StepUpMap`) |
| 지도의 내 점 | 흐린 위치만 오는 동안 경로 끝에서 100m 넘게 멀어지면 내 점이 옛 경로 끝에 묶였다 | 경로 끝이 20초 넘게 그대로면 받은 위치로 옮긴다(`RunTrack.liveHead`) |
| 크루 달리기 | 끊김을 늦게(40초 ~ 2분) 알았고, "다시 연결"이 걸린 요청을 기다렸다. 뒤처진 사람을 "나갔다"고 알렸다 | 15초면 끊김 표시 · "다시 연결"은 바로 새로 묻는다. 나간 알림은 명단에서 빠졌을 때만 |

앱 쪽(거래소 · 수리 · 이벤트 보상, 글 · 댓글 · 좋아요, 크루 달리기 연결 표시 · 알림)의 세부는 같은 PR 설명에 적는다.

## 같은 날 사용자 신고 — 러닝 화면 (2026-10-17)

사용자: "1. 천천히 걸었는데 페이스가 15.30? 2. 지도가 너무 부정확하다 … 지도가 더 밝아야 한다. 네이버지도처럼. 3. 내구도는 왜 안 닳는가? …
1분마다 5씩 닳는 것으로 수정해라. 4. 중간에 인터넷이 끊긴 후 다시 연결했을 때 내 위치를 못 잡는다. 아무리 움직여도 그냥 그 자리다."

1. 페이스 15'30"은 1km 에 15분 30초(시속 3.9km)다 — 천천히 걷는 빠르기와 맞고, 같은 화면의 속도 칸과 같은 값이다. 바꾸지 않았다.
2. 러닝 · 크루 달리기 지도를 밝은 거리 지도로 바꿨다(`BrightMapFilter` — 땅 흰 회색 · 흰 길 · 초록 공원 · 파란 물, 두 테마 모두).
   위치가 틀어져 보이던 것은 아래 4번(멈춘 위치 · 옛 경로 끝에 묶인 내 점)과 같은 까닭이 컸다.
   지도 엔진(네이버 지도 SDK)으로 바꾸는 것은 네이버 클라우드 키가 필요해 하지 않았다.
3. 닳는 양을 달린 1분마다 5로 바꿨다(서버 0064, 멈춘 시간 빼고). 달리는 중 화면의 %도 같은 규칙으로 줄어든다.
4. 위 표의 러닝 위치 · 지도 · 지도의 내 점 세 줄.
