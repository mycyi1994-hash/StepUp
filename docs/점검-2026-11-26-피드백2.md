## 1. 잠금 상태에서 카운트다운이 멈춤(아디다스처럼 바로 시작 · 잠가도 이어서)

이미 고쳤다(첫 점검) — "이 신발로 출발"을 누른 순간 기록을 켜고 3·2·1 은 뺐다. 테스터는 그 전 판을 썼다(작업 브랜치가 main 에 합쳐져야
테스트 APK 가 바뀐다). 아디다스처럼 카운트다운을 다시 넣는다면 서비스 안에서 세고(앱이 앞에 있을 때 서비스를 먼저 켠다) "바로 시작"을 둔다 —
기록 시작을 연출 뒤로 미루지 않는다(CLAUDE.md).

## 2. 잠금화면 내구도 막대 · 20% / 10% 알림음

- 출발할 때 신은 신발의 남은 · 최대 내구도 · 1분마다 닳는 양을 적어 두고(`WalkSessionState.shoeWear` — `domain/ShoeLowAlert.kt` `ShoeWearSnapshot`)
  달린 시간으로 지금 남은 %를 센다(`shoePercent` — 신발 칸과 같은 규칙: 다 채운 1분마다 5 × 효율 포인트 배수).
- 잠금 화면 가운데 현황(`LockRunPanel`)에 "신발 내구도" 막대 · %(20% 아래 주황, 다 쓰면 빨강, 테스트 이름 `lock-run-shoe`). 러닝 알림의 상태 줄은
  "N걸음 · 신발 N%".
- 20% · 10% 를 지나는 순간 한 번씩, 다 쓰면 한 번 — 소리 · 진동 알림(채널 `run_shoe_alert`, `service/ShoeDurabilityAlerts.kt`). 화면을 꺼도 들린다.
  출발할 때 이미 지난 기준은 알리지 않는다(15% 출발 → 10% 만). 한 번에 둘을 지나면 낮은 것 하나. 알림 권한이 없으면 다 씀만 화면 소리(예전 그대로).
- 크루 러닝은 개인 신발이 닳지 않아 없다. 최대 내구도를 모르는 신발도 없다.

## 3. 백그라운드에서 GPS 가 잘못 그려짐 · 정확성

**찾은 것**: 러닝 서비스는 위치를 **받은** 순간의 폰 시계로 점 사이 시간을 쟀다. 화면이 꺼지면 휴대폰(절전 설정)이 위치를 모아 한꺼번에 넘기는데,
그러면 1분 동안 잰 점들이 같은 순간에 와 점 사이 시간이 0초가 된다 — 0초 구간은 거리로 세지 않아(`MIN_SEGMENT_SEC`) **화면을 끈 동안의 거리가 거의
빠지고**, 경로 점 시각이 모두 같아 서버의 경로 확인(점 사이 시각)도 흔들렸다. 지도는 묶음 사이가 곧은 줄로 보였다.

**고친 것**: 위치마다 **잰** 시각(`Location.elapsedRealtimeNanos` — 부팅 뒤 시계)을 폰 시계로 옮겨 쓴다(`domain/FixClock.kt`, `FixClockTest`).
기준점보다 먼저 잰 위치(다른 공급원이 늦게 넘긴 것)는 버린다. 10분 넘게 오래된 · 미래 시각은 받은 시각 그대로.

남은 것: 배터리 「제한 없음」 안내(첫 점검)는 그대로. 실제 폰에서 화면을 끈 채 달린 경로를 다시 보는 확인은 테스터에게(새 테스트 APK).

## 4. 앱을 켜지 않으면 하루 걸음이 안 잡힘

**찾은 것**: 걸음 센서(TYPE_STEP_COUNTER)는 앱이 살아 있을 때만 읽혔다. 어제 잰 적이 없으면 오늘 앱을 열기 전 걸음은 넘겨받지 않아(`StepTracker`
— 며칠 치가 오늘로 쏟아지지 않게) 통째로 빠지고, 앱을 연 적 없는 날은 기록이 없었다. "한 번이라도 켜면 그날은 트래킹"과 같다.

**고친 것**:
- 구글 Play 서비스의 걸음 기록(Recording API — `play-services-fitness` 21.2.0, 기기 안에만 남고 계정 · 서버 없음, 열흘)을 켠다(`sensor/StepHistory.kt`).
- 걸음 일꾼(`sensor/DailyStepsWorker.kt`, 한 시간마다 · 배터리 낮으면 쉼)과 앱 시작이 날마다 합을 읽어 폰 기록에 채운다(`StepRepository.mergeHistory` — 큰 값만).
  오늘 값이면 걸음 센서가 그 값부터 이어 센다(`StepTracker.raiseFloor` — 기준점을 내린다).
- 로그인했으면 어제 · 오늘을 서버에 올린다(steps_sync — 예전엔 앱을 켜야만 올렸다).
- 걸음 권한이 없거나 Play 서비스가 낡았으면 아무것도 하지 않는다(센서 셈 그대로). 러닝 보상 · 목표 · 연속은 이 걸음으로 정하지 않는다(0118 그대로).

## 5. 안 달려도 쌓이는 보상 · 앱테크 걸음 보상(아이디어)

정한 것(사용자 "묻지 말고" — 앞서 추천한 대로): **SUP 는 주지 않는다**(하루 에너지 상한 · 인플레이션 0122 A — 자동 적립 1/100 안은 그대로 버림).
대신 **하루 걸음 상자**(서버 0128): 그날(한국 날짜) 올린 하루 걸음이 `step_box_steps`(6,000)를 넘으면 일반 상자 하나(`box_grant 'STEPS:<날>' FREE`), 하루 한 번.
- 하루 걸음은 폰이 센 값이라 서버가 확인하지 못한다 — 그래서 상자 하나만(출석과 같은 무게). 러닝 상자 · 목표 · 연속 셈에는 들지 않는다.
- 가입하고 24시간 뒤부터(`step_box_min_account_hours`). 끄기 `update public.economy_settings set value = '"OFF"' where key = 'step_box_rule';`
- 앱: 걸음 일꾼 · 동기화가 하루 걸음을 올린 뒤 `step_box_claim()` — 처음 받았으면 알림 "걸음 상자를 받았어요"(채널 `daily_rewards`). 서버에 0128 이 없으면 조용히.
- 서버 검사 "걸음 상자(0128)" 다섯.
