## 2. 빈 곳

1. **가입 전·첫 러닝 전 단계가 안 보인다** — 앱 첫 실행 → 로그인 화면 → 가이드 완료 → 권한 허용 →
   러닝 시작 사이에 이벤트가 없다. 어디서 빠지는지 모른다.
   - `login` 은 재로그인에도 찍혀 "가입"이 아니다.
   - `run_finish` 는 보상 걸음이 0 이면 안 찍힌다.
2. **앱 열기 재방문은 서버에 기록이 없다** — `push_tokens.updated_at` 은 마지막 값만 남는다.
3. **테스트 기기가 실제 사용자와 섞인다** — 배포 테스트 APK 가 debug 빌드이고, CI 에뮬레이터(QA·스크린 갤러리)도
   같은 Firebase 프로젝트(`stepup-16d6e`)로 보낸다. **지금 Firebase 숫자는 증빙으로 못 쓴다.**
4. **동의·끄기가 없다** — Firebase 가 로그인 화면 이전부터 수집한다. 앱 안 개인정보 화면(`privacy_data_body`)에
   Firebase Analytics 언급이 없다. 끄는 스위치도 없다.
5. **탈퇴하면 코호트에서 사라진다** — `account_delete()` 가 연쇄 삭제. 가입 수를 따로 스냅샷하지 않으면
   재방문율이 실제보다 좋아 보인다.
6. **크래시 지표가 없다** — LAUNCH-PLAN 은 크래시 없는 비율 ≥99% 를 목표로 하지만 Crashlytics 가 없다.
   (Play Console Vitals 로 대신 가능 — 출시 트랙에 올라간 뒤부터.)

## 3. 설계

### 3-1. 정본은 서버, Firebase 는 보조

심사 증빙은 **서버 숫자**로 낸다. 이유: 로그인·업로드·판정을 거친 실제 러닝이라 테스트 기기와 봇을 걸러 낼 수
있고, 재계산할 수 있다. Firebase 는 가입 전 단계(깔대기 앞부분)만 본다.

### 3-2. 서버 — 관리자 전용 집계 함수 1개 + 활동 표 1개

- `user_activity(user_id, day)` 표 — 하루 한 줄. 이미 앱 시작 때마다 부르는 `push_register` 안에서
  `insert ... on conflict do nothing`. 앱 변경 없음. → 앱 열기 D1/D7/D30.
- `metrics_snapshot(day, signups, ...)` 표 — 하루 한 번 크론으로 누적 가입 수 등을 적어 둠(탈퇴 보정).
- `admin_metrics(from, to)` 함수 — `security definer` + 기존 `admin_guard()`. **집계 숫자만** 돌려준다
  (개인별 행 없음). 앱·어드민 페이지 어디서든 관리자 계정으로만.
  - 가입 · 첫 러닝 · 첫 CLEAN 러닝 · 크루 가입 전환율
  - 주간 활성 러너, 러닝 D1/D7/D30, 앱 열기 D1/D7/D30
  - 러닝 수·거리·판정 비율·파티/크루 비율
- **테스트 계정 제외**: `metrics_excluded(user_id)` 표 — 팀·QA 계정을 넣어 두고 모든 집계에서 뺀다.
- 서비스 롤 키는 앱에 넣지 않는다(CLAUDE.md). 조회는 SQL Editor 또는 관리자 로그인.

### 3-3. 앱 — 이벤트 5개 추가 + 테스트 빌드 분리

| 추가 이벤트 | 위치 | 파라미터 |
|---|---|---|
| `sign_up` | 로그인 성공 중 서버가 새 사용자라고 알려 줄 때 | method |
| `tutorial_complete` | 가이드 끝(`setGuideSeen`) | — |
| `permission_result` | 활동·위치 권한 응답 | perm, granted |
| `run_start` | `WalkSessionService` 시작 | mode(solo/party/course) |
| `run_upload` | 업로드 성공 | verdict |

- 개인정보 없음(거리는 소수 1자리까지만, 위치·이름·이메일 안 보냄). Firebase `setUserId` 는 **쓰지 않는다**
  — 쓰면 개인정보처리방침·Play 데이터 안전 항목 변경이 필요해진다.
- **테스트 빌드 분리**: debug·CI 빌드는 `setAnalyticsCollectionEnabled(false)` 또는 `build_type` 사용자 속성으로
  걸러 냄. (가장 싼 방법은 속성 — Firebase 콘솔에서 비교 제외.) 단, 지금은 사용자에게 **debug APK 를 배포**하므로
  수집을 끄면 실사용자도 빠진다 → 배포 APK 를 release 빌드로 바꾸는 것이 먼저(서명 키 필요, `docs/RELEASE-SIGNING.md`).

### 3-4. 동의·개인정보

- 내 정보 › 설정 › 개인정보 에 **"사용 통계 보내기" 스위치**(기본 켜짐, 끄면 `setAnalyticsCollectionEnabled(false)`).
- 앱 안 `privacy_data_body`(4개 언어)에 Firebase Analytics 한 줄 추가 — 이미 `web/privacy.html` 에는 있다.
- `web/privacy.html` 57/147행 이벤트 목록에 새 이벤트를 "등" 범위 안에서 명시. `user_activity`(하루 접속 여부)는
  서비스 운영 기록으로 §2 에 한 줄 추가.
- Play 데이터 안전(`docs/PLAY-STORE.md:72-81`) — 항목 변화 없음(앱 상호작용·기기 ID, 분석 목적).
- 베타 모집 때 "테스트 참여 = 사용 통계 수집 동의" 문구를 모집 글에 넣는다.
