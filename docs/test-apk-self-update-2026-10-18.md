# 테스트 APK 스스로 업데이트 — 다시 만듦 (2026-10-18)

사용자: "원격 업데이트 안 되는데" → "제대로 되게 근본적으로 해결을 해". 코드는 `core/TestUpdates.kt` · `TestUpdateWorker.kt` ·
`TestUpdateReceiver.kt` · `ui/components/TestUpdatePrompt.kt`, 매니페스트는 `src/debug/AndroidManifest.xml`(debug · qa 만).

## 무엇이 안 됐나

릴리스 파일 · 서명은 문제가 없었다. `test-apk` 의 `StepUp-test.json` · `StepUp-test.apk` 는 main 마다 바르게 올라갔고
(a7b05ed, versionCode 19025), 서명도 늘 같은 키(공개 debug 키 — `TEST_APK_SIGNING_KEY` 를 아직 넣지 않았다)였다.
문제는 앱 쪽 흐름이었다.

1. **앱을 켤 때 한 번만** 물었다 — 켜 둔 앱은 새 빌드를 몰랐다.
2. 받은 APK 로 **안드로이드 설치 화면을 "열기만"** 했다. 그 순간 창을 "나중에"로 바꿔, 설치를 취소했거나 "출처를 알 수 없는 앱"
   허용 화면에서 돌아왔거나 안드로이드가 막아도 **같은 빌드는 다시 묻지 않았다**. 왜 안 됐는지도 보이지 않았다.
3. 앱이 꺼져 있으면 아무 일도 없었다.

## 이제

- **묻기**: 앱을 켤 때 · 앱으로 돌아올 때(5분에 한 번까지) · 설정 › 테스트 빌드 업데이트, 그리고 **앱이 꺼져 있어도 1시간마다**(WorkManager 일꾼, 인터넷 있을 때).
- **깔기**: 안드로이드 설치 세션(PackageInstaller)에 직접 넣는다. 결과(성공 · 취소 · 실패 까닭)를 받는다.
  - **안드로이드 12 이상은 확인 화면 없이** 깔린다 — 앱이 자기 자신을 업데이트할 때(`UPDATE_PACKAGES_WITHOUT_USER_ACTION`,
    `setRequireUserAction(NOT_REQUIRED)`). 앱이 잠깐 닫히고 새 버전이 깔리면 "새 버전으로 업데이트했어요 · 눌러서 열기" 알림이 뜬다(`MY_PACKAGE_REPLACED`).
  - 안드로이드 11 이하는 안드로이드 확인 화면에서 "업데이트"를 한 번 더 누른다.
  - 앱을 쓰지 않을 때(화면이 하나도 안 보일 때)는 일꾼이 받아서 그대로 깐다. 확인이 필요한 폰이면 "새 버전이 있어요 — 눌러서 업데이트" 알림만(빌드마다 한 번).
- **"출처를 알 수 없는 앱 설치" 허용이 없으면** 그 설정의 StepUp 칸을 바로 열고, 허용하고 돌아오면 이어서 깐다.
- **깔기 전에 맞대어 본다**: 패키지 이름, 판(versionCode — 데이터베이스가 더 옛 빌드면 막는다), 서명(이 폰의 앱을 지금 서명한 키가 새 APK 의 서명 · 서명 이력에 있어야 한다).
  안 맞으면 까닭을 글로 보인다 — 서명이 다르면 "지우고 받는 곳에서 다시 설치".
- **취소는 "나중에"가 아니다** — 같은 창이 다시 떠 바로 다시 누를 수 있다. 받아 둔 파일은 같은 빌드면 다시 받지 않는다.
- **러닝 중 · 러닝 저장 중에는 깔지 않는다**(창도 숨는다) — 깔면 앱이 다시 켜지며 러닝 서비스가 끊긴다.
- 스토어 빌드(release)에는 권한 · 받는 쪽 · 일꾼이 없다(`SELF_UPDATE = false`). 계측 테스트 중에도 끈다.
