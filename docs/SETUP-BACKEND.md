# 계정 · 서버 연동 — 직접 하실 일

**약 40분 · 전부 무료 · 순서대로 하시면 됩니다**

## 왜 필요한가

지금 앱은 모든 걸 폰 안에만 저장합니다. **기기를 바꾸면 그동안 모은 SUP와
스니커즈가 전부 사라집니다.** 온체인으로 가지 않기로 했으니, 서버가 유일한
보관처입니다. 그래서 계정과 서버가 v1에서 가장 중요합니다.

## 🔐 먼저 — 보내도 되는 것과 안 되는 것

| 값 | 저에게 | 이유 |
|---|:--:|---|
| Supabase **Project URL** | ✅ | 앱에 그대로 박히는 공개 주소 |
| Supabase **anon public** 키 | ✅ | **공개용으로 설계된 키**입니다. 앱에 넣으라고 주는 값이고, 이것만으로는 권한 규칙(RLS)을 못 넘습니다 |
| Google **웹 클라이언트 ID** | ✅ | 공개 값 |
| SHA-1 지문 | ✅ | 공개 값 |
| Supabase **service_role** 키 | ❌ | **절대 금지.** 모든 권한을 무시하는 마스터 키입니다 |
| Google **클라이언트 보안 비밀** | ❌ | Supabase 화면에만 붙여넣으세요 |
| 지갑 개인키 · 시드 문구 | ❌ | 이 작업에는 아예 필요 없습니다 |

> 헷갈리시면 **아무것도 안 보내고 화면 캡처만** 주셔도 됩니다. 제가 어느 값인지
> 짚어 드리겠습니다. 단, 캡처에 `service_role`이 보이면 가려 주세요.

# 1단계 · Supabase 프로젝트 만들기

데이터베이스 + 로그인 + 실시간 동기화를 한 번에 주는 서비스입니다. 무료 등급으로
충분합니다.

1. `supabase.com` 접속 → **Start your project**
2. **Sign in with GitHub** (이미 GitHub 쓰시니 가장 빠릅니다)
3. **New project** 클릭
4. 입력합니다.

| 항목 | 값 |
|---|---|
| **Name** | `stepup` |
| **Database Password** | 자동 생성 버튼을 누르고 **비밀번호 관리자에 저장**하세요. 다시 볼 수 없습니다 |
| **Region** | **Northeast Asia (Seoul)** — 사용자가 한국이면 응답이 가장 빠릅니다 |
| **Plan** | Free |

5. **Create new project** → 프로비저닝에 1~2분 걸립니다.

### 값 찾기

프로젝트가 만들어지면 왼쪽 아래 **⚙ Project Settings → API** 로 갑니다.

| 화면에 보이는 것 | 저에게 보낼 것 |
|---|:--:|
| **Project URL** (`https://xxxxx.supabase.co`) | ✅ |
| **Project API keys → `anon` `public`** | ✅ |
| **Project API keys → `service_role` `secret`** | ❌ 보내지 마세요 |

✅ **확인:** Project URL과 anon 키 두 개를 복사해 두셨으면 1단계 끝입니다.

# 2단계 · Google 로그인 등록

## 먼저 — 왜 이걸 해야 하나요?

앱에 "Google로 로그인" 버튼을 넣으려면, **구글에 미리 신고를 해야 합니다.**
"com.stepup.android 이라는 앱이 구글 로그인을 쓸 겁니다"라고요.

신고하지 않으면 구글이 로그인 요청을 거절합니다. 그래서 필요한 작업입니다.

신고할 때 구글이 묻는 것은 결국 두 가지입니다.

| 구글의 질문 | 우리 답 |
|---|---|
| "어떤 앱인가요?" | `com.stepup.android` · 지문 `34:ED:...` |
| "로그인 결과를 어디로 보낼까요?" | Supabase 주소 |

그래서 **등록을 두 번** 합니다. 하나는 앱용, 하나는 Supabase용입니다.
번거롭지만 둘 다 있어야 동작합니다.

---

## 2-1. 구글 클라우드에 프로젝트 만들기

> "클라우드"라는 말에 겁먹지 마세요. 그냥 **구글에 우리 앱을 등록하는 서랍**을
> 하나 만드는 겁니다. 서버를 빌리거나 돈을 내는 게 아닙니다. 무료입니다.

1. `console.cloud.google.com` 접속 (평소 쓰시는 구글 계정으로)
2. 처음이면 약관 동의 화면이 나옵니다 → 동의
3. **화면 맨 위 파란 띠**를 보세요. 왼쪽에 `Google Cloud` 로고가 있고,
   그 오른쪽에 **프로젝트 선택 드롭다운**이 있습니다
   (`프로젝트 선택` 또는 이미 만들어진 프로젝트 이름)
4. 그 드롭다운 클릭 → 팝업이 뜨면 오른쪽 위 **새 프로젝트**
5. **프로젝트 이름**에 `StepUp` 입력 → 나머지는 그대로 → **만들기**
6. 10~20초 기다리면 알림이 뜹니다 → **프로젝트 선택** 을 눌러 방금 만든
   프로젝트로 들어갑니다

✅ **확인:** 맨 위 드롭다운에 `StepUp` 이 보이면 됩니다.
**이게 중요합니다** — 다른 프로젝트가 선택된 채로 진행하면 엉뚱한 곳에 등록됩니다.

---

## 2-2. "이 앱이 누구인지" 알리기 (동의 화면)

구글 로그인을 누르면 "StepUp이 내 구글 계정 정보를 봐도 될까요?" 라는 화면이
뜹니다. 거기 뭐라고 쓸지를 미리 정하는 단계입니다.

1. **왼쪽 메뉴**(햄버거 ☰ 를 눌러야 나올 수 있습니다) → **API 및 서비스** →
   **OAuth 동의 화면**
   - 안 보이면 위쪽 검색창에 `OAuth 동의 화면` 이라고 치세요
2. **User Type** 에서 **외부(External)** 선택 → **만들기**
   - 회사 계정이 아니면 "내부"는 선택 자체가 안 됩니다. 정상입니다.
3. 3칸만 채웁니다. 나머지는 비워도 됩니다.

| 칸 | 넣을 값 |
|---|---|
| 앱 이름 | `StepUp` |
| 사용자 지원 이메일 | 본인 이메일 (드롭다운에서 고르면 됩니다) |
| 개발자 연락처 정보 | 본인 이메일 (직접 타이핑) |

4. **저장 후 계속**
5. **범위(Scopes)** 화면 → 아무것도 하지 말고 **저장 후 계속**
6. **테스트 사용자** 화면 → 아무것도 하지 말고 **저장 후 계속**
7. **요약** 화면 → **대시보드로 돌아가기**

> 나중에 "게시" 심사를 받아야 하지만 **지금은 안 해도 됩니다.**
> 테스트 상태에서도 본인 계정으로는 로그인이 됩니다.

✅ **확인:** 게시 상태가 `테스트` 로 보이면 이 단계 끝입니다.

---

## 2-3. 등록 ① — Supabase용 (웹)

로그인이 끝나면 구글이 결과를 Supabase로 보냅니다. **그 주소를 미리 알려주는**
등록입니다.

1. **왼쪽 메뉴 → API 및 서비스 → 사용자 인증 정보**
2. 위쪽 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
3. **애플리케이션 유형** → **웹 애플리케이션** 선택
4. **이름** 칸에 `StepUp Web` (아무 이름이나 괜찮습니다. 본인만 봅니다)
5. 아래로 스크롤 → **승인된 리디렉션 URI** 항목의 **+ URI 추가** 클릭
6. 나타난 칸에 **아래 주소를 그대로** 붙여넣기

```
https://pupjzcmybuoyhzfwrsdf.supabase.co/auth/v1/callback
```

> ⚠️ 이 주소는 **한 글자도 틀리면 안 됩니다.** 끝의 `/auth/v1/callback` 까지
> 포함입니다. 마지막에 슬래시(`/`)를 더 붙이면 안 됩니다.

7. **만들기**
8. **팝업이 뜹니다.** 여기에 값 두 개가 있습니다. **창을 닫기 전에 복사하세요.**

| 팝업에 보이는 것 | 어디에 쓰나 |
|---|---|
| **클라이언트 ID** (`숫자-문자.apps.googleusercontent.com`) | 3단계 + 저에게 전달 |
| **클라이언트 보안 비밀번호** (`GOCSPX-...`) | 3단계에만. **저에게 보내지 마세요** |

> 창을 닫아도 괜찮습니다. **사용자 인증 정보** 목록에서 `StepUp Web` 을 다시
> 클릭하면 언제든 볼 수 있습니다.

---

## 2-4. 등록 ② — 앱용 (Android)

"이 폰에 깔린 이 앱이 진짜 StepUp이 맞다"를 구글이 확인할 수 있게 하는 등록입니다.

1. 같은 화면에서 다시 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
2. **애플리케이션 유형** → **Android**
3. 세 칸을 채웁니다.

| 칸 | 넣을 값 |
|---|---|
| 이름 | `StepUp Android` |
| **패키지 이름** | `com.stepup.android` |
| **SHA-1 인증서 디지털 지문** | 아래 값 |

```
34:ED:A6:73:DF:C6:27:FD:AF:D1:06:C0:A0:05:91:1C:AF:59:8A:EC
```

4. **만들기**

> **SHA-1 이 뭔가요?** 앱마다 붙는 지문입니다. 다른 사람이 `com.stepup.android`
> 라는 이름으로 가짜 앱을 만들어도, 지문이 달라서 구글 로그인을 못 씁니다.
>
> 위 값은 저장소에 들어 있는 **개발용 키**의 지문이라 공개해도 안전합니다.
> 나중에 Play 스토어에 올릴 때는 구글이 주는 **다른 지문**을 하나 더 등록해야
> 하는데, 그건 Play Console 등록이 끝난 뒤에 알려드리겠습니다.

✅ **확인:** 사용자 인증 정보 목록에 `StepUp Web` 과 `StepUp Android` **두 개**가
보이면 2단계 끝입니다.

# 3단계 · Supabase에 구글 연결

구글 쪽 등록이 끝났으니, 이제 Supabase에 "구글 로그인 쓸 거야"라고 알려줍니다.

1. Supabase 대시보드 → 왼쪽 **Authentication** (자물쇠 아이콘)
2. 그 안에서 **Sign In / Providers** (또는 **Providers**)
3. 목록에서 **Google** 을 찾아 클릭 → 맨 위 스위치를 **켭니다**
4. 칸 두 개를 채웁니다 — **2-3에서 복사한 값**입니다

| Supabase 칸 | 넣을 값 |
|---|---|
| **Client IDs** | 웹 클라이언트 ID (`...apps.googleusercontent.com`) |
| **Client Secret** | 웹 클라이언트 보안 비밀번호 (`GOCSPX-...`) |

5. 맨 아래 **Save**

> ⚠️ 여기 넣는 건 **웹** 쪽 값입니다. Android 쪽 클라이언트 ID가 아닙니다.
> Android 것은 구글에 등록만 해두면 되고 어디에 붙여넣지 않습니다.

✅ **확인:** Google 항목에 **Enabled** 표시가 뜨면 3단계 끝입니다.

---

# 4단계 · 저에게 전달

Supabase 주소와 공개 키는 이미 받았습니다. **하나만 더 주시면 됩니다.**

```
Google 웹 클라이언트 ID : 000000000000-xxxxxxxx.apps.googleusercontent.com
```

2-3 에서 만든 **웹** 쪽 클라이언트 ID 입니다. 앱에 그대로 들어가는 **공개
값**이라 보내셔도 안전합니다.

> ❌ **클라이언트 보안 비밀번호**(`GOCSPX-...`)는 보내지 마세요.
> Supabase 화면에만 붙여넣는 값입니다.

받으면 로그인 버튼을 실제로 동작하게 만들고, 폰에서
**로그인 → 러닝 → 서버 저장**까지 한 바퀴 같이 확인하겠습니다.

---

# 5단계 · 서버 표 올리기 (표가 늘어날 때마다)

1. Supabase 대시보드 → 왼쪽 **SQL Editor** → **New query**
2. 저장소의 [`supabase/setup.sql`](../supabase/setup.sql) **전체**를 복사해 붙여넣기
3. **Run**

**이미 한 번 올리셨어도 그냥 다시 하시면 됩니다.** 몇 번을 다시 붙여넣어도
안전하게 만들어 두었습니다 — 이미 있는 표는 건너뛰고 새로 생긴 것만
들어갑니다. **쌓인 기록은 지워지지 않습니다.**

끝나면 아래쪽에 만들어진 표 목록이 나옵니다. 지금 기준으로 14개입니다
(프로필·걸음·러닝 세션·SUP 원장 + 크루·게시판·댓글·코스·차단·신고).

> 표가 늘어날 때마다 이 단계를 한 번 더 하시게 됩니다. 제가 스키마를 고치면
> 알려 드리겠습니다. 무엇이 왜 들어 있는지는 [`supabase/README.md`](../supabase/README.md)
> 에 적어 두었습니다.

# ❓ 막혔을 때

| 증상 | 해결 |
|---|---|
| Supabase 프로젝트 생성이 계속 돌아감 | 1~2분 걸립니다. 5분 넘으면 새로고침 |
| 리디렉션 URI 형식 오류 | `https://` 로 시작하고 끝에 `/auth/v1/callback` 이 붙었는지 확인. 슬래시 하나 차이로 거절됩니다 |
| OAuth 동의 화면에서 막힘 | 범위·테스트 사용자는 전부 건너뛰어도 됩니다. "저장 후 계속"만 누르세요 |
| 어떤 키를 보내야 할지 모르겠음 | 화면 캡처를 주세요 (단, `service_role` 부분은 가려서) |
| 값이 틀렸는지 확인하고 싶음 | 일단 보내 주세요. 형식이 틀리면 제가 바로 알 수 있습니다 |

**막히시면 어느 단계에서 뭐가 안 되는지만 알려 주세요.**
