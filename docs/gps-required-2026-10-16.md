# 러닝은 GPS 가 잡혀야 시작한다 (2026-10-16)

사용자 결정: "GPS 안 되면 못 하는 거야. 그렇게 해 놔. 권한에 위치 다 해 놨어. 근데도 안 된다니까?"

- 위치 없이 시간 · 걸음만 기록하는 시작 길을 없앴다.
- 시작 전에 실제 GPS 신호를 기다리고, 무엇 때문에 안 잡히는지 화면에 보인다.
- 권한을 허용했는데도 GPS 를 못 잡던 버그를 고쳤다.

## 시작 차례

```
러닝 고르기 → 권한(걸음 · 정확한 위치 · 알림) → 위치 기능 켜짐? → GPS 대기 → 3-2-1 → 러닝
```

### 권한

[`domain/Onboarding.kt`](../app/src/main/java/com/stepup/android/domain/Onboarding.kt) `RunPermissionRules.next`

- 위치는 꼭 필요하고, **정확한 위치**여야 한다.
  - 위치 권한이 없으면 매번 시스템 창부터 띄운다(16).
  - 시스템 창이 다시 뜨지 않으면 그 결과로 "위치를 허용해야 달릴 수 있어요"(18)를 보인다. 주 버튼은 설정이다.
  - 대략적인 위치만 있으면 "위치 정확도를 확인해주세요"(17)를 보인다. 주 버튼은 설정이다(‘정확한 위치 사용’).
- 세 장면의 보조 버튼은 모두 **취소**다. 예전의 "나중에 할게요(경로 없이 계속)" · "이대로 계속" · "위치 없이 시간만 기록"은 없다.
- 예전에 "나중에"를 골라 둔 기록(`runLocationChosen`)은 더 읽지 않는다. 그 사람도 다음 러닝에서 위치부터 묻는다.
- 알림은 예전처럼 거절해도 러닝을 막지 않는다.

### 위치 기능 꺼짐 (E07)

[`RunStartOverlays.kt`](../app/src/main/java/com/stepup/android/ui/screens/walk/RunStartOverlays.kt) `RunLocationOffContent`

- "위치 설정 열기" 하나만 남았다. 그만두려면 뒤로 간다.
- 설정에서 켜고 돌아오면 GPS 대기로 간다.

### GPS 대기 (새 화면)

[`RunGpsGate.kt`](../app/src/main/java/com/stepup/android/ui/screens/walk/RunGpsGate.kt) · 판단은 [`domain/GpsReadiness.kt`](../app/src/main/java/com/stepup/android/domain/GpsReadiness.kt)

화면에 보이는 것:

- 위성: "n개 사용 · m개 수신". 휴대폰이 알려 준 값 그대로다(GNSS 상태).
- 정확도 "±m". 아래에 "50m 안이면 시작해요"가 붙는다.
- 기다린 시간.
- 아래에 취소 하나. 주 버튼은 없다. 잡히면 저절로 3-2-1 로 간다.

"잡혔다"로 보는 위치(`GpsFixRule`):

- GPS 에서 왔다. 기지국 · 와이파이 위치는 세지 않는다.
- 가짜(모의 위치 앱)가 아니다.
- 30초 안의 것이다. 휴대폰이 이미 알던 새 GPS 위치가 있으면 기다리지 않는다.
- 정확도가 50m 안이다. 정확도를 알려 주지 않는 기기는 받는다.

알림(`gpsHintOf`)은 두 가지로 나뉜다.

막는 까닭은 바로 알린다. 기다려도 소용없기 때문이다.

| 까닭 | 알림 |
|---|---|
| GPS 가 없는 휴대폰 | "이 휴대폰에는 GPS가 없어요" |
| 위치 기능이 꺼짐 | E07 로 간다 |
| GPS 가 꺼짐(Android 8 이하 절전 방식) | "위치 방식을 ‘높은 정확도’로" + 위치 설정 열기 |
| 가짜 위치만 들어옴 | "개발자 옵션의 ‘모의 위치 앱’을 끄면…" |

기다림의 까닭은 20초 뒤에 알린다.

| 까닭 | 알림 |
|---|---|
| 신호를 받는 위성이 0 | "실내 · 지하에서는 GPS가 잡히지 않아요. 밖으로" |
| 위치는 오는데 50m 밖 | "높은 건물 · 나무에서 조금 떨어져 주세요" |
| 위성은 보이는데 첫 위치가 늦음 | "유심이 없거나 오래 안 쓴 휴대폰은 처음에 오래 걸려요. 와이파이에 연결하고 밖에서" |

기다리는 동안:

- 위치 기능을 끄면 E07 로 간다.
- 권한을 거두면 권한 안내부터 다시 한다.
- 3-2-1 동안에도 GPS 를 켜 둔다. 러닝 서비스가 이어서 켤 때 처음부터 찾지 않게 하려는 것이다.

### 크루 · 번개 대기실

[`PartyLobbyScreen.kt`](../app/src/main/java/com/stepup/android/ui/screens/community/PartyLobbyScreen.kt)

- "준비"는 걸음 권한과 정확한 위치를 확인한다.
- 그다음 GPS 확인 시트(같은 위성 · 정확도 · 알림)가 뜬다. 잡히면 준비 완료로 바뀌고 시트가 닫힌다.
- 시트를 닫으면 준비 전으로 남는다.
- 진행자도 준비해야 출발할 수 있으니(`canStart = isHost && myReady`) 진행자도 같은 확인을 거친다.
- 대략적인 위치만 허용했으면 정확한 위치를 다시 묻는다(Android 12+ 바꾸기 창). 그래도 안 되면 "설정 › 권한 › 위치에서…"라고 알린다.
- 출발 순간에 정확한 위치가 없으면(준비한 뒤 권한을 거둔 경우) 출발하지 않고 까닭을 알린다.

## 고친 버그 — "권한 다 했는데 GPS 를 못 잡는다"

1. **달리는 중에 위치 권한을 허용해도 GPS 가 켜지지 않았다.**
   - 러닝 서비스는 위치를 시작할 때 한 번만 켰다(`beginTracking` → `startLocation`).
   - 그래서 위치 없이 시작한 러닝("위치 없이 기록해요" 화면)에서 설정으로 가 권한을 켜고 돌아와도, 그 러닝 내내 "GPS 찾는 중"이었다.
   - 이제는 5초마다 확인한다. 권한이 생겼으면 GPS 를 켜고, 전경 서비스에 위치 종류도 더한다. 더하지 못하면(앱이 뒤에 있을 때) 다음에 다시 해 본다.
   - 새 시작 차례에서는 이런 러닝이 생기지 않는다. 그래도 되살린 러닝 · 대기실 출발 같은 다른 길을 위해 남겨 둔다.
2. **Android 10 이하에서 위치를 켜고 끌 때 앱이 죽을 수 있었다**(`CurrentLocation.kt`).
   - 위치 리스너가 `onProviderEnabled` · `onProviderDisabled` · `onStatusChanged` 를 구현하지 않았다.
   - API 29 이하에서는 이것들이 추상 메서드라 AbstractMethodError 가 난다. 이제 모두 구현했다.

### 서브폰에서 안 잡히던 까닭 (짐작)

위 1번이 가장 그럴듯하다. 처음에 위치 없이 시작했고, 그 뒤 권한을 켰지만 그 러닝에는 GPS 가 켜지지 않았다.

그 밖의 까닭:

- 정확한 위치가 꺼져 있었다(대략적인 위치만 허용).
- 실내였다.
- 유심이 없어 첫 위치가 오래 걸렸다.

새 GPS 대기 화면이 위성 수 · 정확도로 어느 쪽인지 보여 준다.

## 그대로 둔 것

- **달리는 중에 GPS 가 끊기는 것**(터널 · 지하도)은 러닝을 멈추지 않는다.
  - 예전처럼 끊긴 구간의 거리는 더하지 않는다.
  - L04 시트의 버튼 이름만 "시간만 기록하며 계속"에서 **"계속 달리기"**로 바꿨다.
- **달리는 중에 위치를 끄거나 권한을 거두면** 러닝은 이어진다.
  - 화면은 "위치 꺼짐"과 "위치를 받을 수 없어요 — 켜면 바로 GPS 로 이어서 기록해요"를 보인다.
  - 다시 켜면 GPS 가 이어진다(위 1번 · 기존 `onProviderEnabled`).
- **서버 정산 규칙은 바꾸지 않았다**(`no_gps_daily_cap` 60 SUP · `gps_check_min_m` 300m).
  - 시작은 GPS 로 막았다. 하지만 달리다 위치를 끈 러닝은 서버에서 예전처럼 "GPS 부족" 규칙을 따른다.
  - 위치 없는 적립을 아예 없애려면 `no_gps_daily_cap` 을 0 으로 바꾸면 된다. 사용자 결정이 필요하다.
