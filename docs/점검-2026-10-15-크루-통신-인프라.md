- 같은 러닝이 두 번 적립되거나 다른 계정에 적립되는 길은 없다(영수증 · 서버 재시도 응답 · 계정 확인).
- 크루 채팅 · 크루 · 대기실 서버 함수 이름 · 인자 · JSON 필드는 앱과 모두 맞는다. setup.sql 은 마이그레이션과 같다.
- 뉴스는 `news_articles`(0009)를 읽는다 — 옛 `news_items` 경로는 화면이 쓰지 않는다.

1. **테스트 APK 서명 키** — 저장소 밖의 새 키로 서명하고 서명 이력(옛 키 → 새 키, v3 키 회전)을 붙인다. 깔린 테스트 앱 위에 그대로
   덮어 설치되고, 새 키로 올라간 폰에는 옛 공개 키 APK 가 더는 깔리지 않는다. 키는 main 에서만 쓰는 GitHub 환경 `test-apk` 의 비밀에 둔다.
   사용자가 할 일(구글 지문 등록 · 비밀 넣기)은 [TEST-APK-SIGNING.md](TEST-APK-SIGNING.md). 넣기 전까지는 전처럼 옛 키로 올린다.
   `apk-dist`(README 의 옛 링크)도 같은 테스트 APK 를 받는다 — 공개 키로 서명한 디버그 빌드를 더는 내보내지 않는다.
2. **attester-logs** — 손으로 돌릴 때만, main 의 코드로만 돈다(`claude/**` 푸시 트리거와 요청 파일을 뺐다). Claude 는 GitHub 도구로 main 에서 돌린다.
3. **Build APK 쓰기 권한** — 빌드 작업은 읽기 권한만. 테스트 APK 를 올리는 `publish` 작업이 main 에서만 쓰기 권한(과 서명 키)을 받는다.
4. **멈춘 원격 브랜치 4개** — 모두 main 에 합쳐진 상태(앞선 커밋 0, 열린 PR 없음)를 확인했다. 이 세션은 다른 브랜치를 지울 권한이 없어(403)
   사용자가 GitHub 브랜치 화면에서 지운다. 되살릴 때 쓸 커밋: `codex/release-readiness` 006c489 · `claude/quirky-rubin-dwm6yv` 60cf8d8 ·
   `codex/screen-captures-20260924` cf3b263 · `codex/stepup-cohesive-redesign` e31ccf9.
5. **같은 versionCode** — 테스트 · 개발 빌드(debug · qa)의 versionCode = 데이터베이스 판 × 1000 + 스토어 versionCode(지금 17025).
   데이터베이스가 더 새 빌드 위에 더 옛 빌드를 깔면 안드로이드가 설치 단계에서 막는다(앱이 죽지도, 기록이 지워지지도 않는다).
   앱의 새 버전 알림도 더 낮은 versionCode 는 알리지 않는다(StepUp-test.json 의 versionCode). 스토어 빌드는 손으로 올린 값 그대로.
6. **계정 삭제 시 채팅** — 메시지 · 사진 · 공지를 남기고 작성자만 비운다(0058). 앱은 "탈퇴한 사용자"로 보이고, 다른 폰도 다음 따라오기에서 바뀐다.
   계정 삭제 안내 · 개인정보 처리방침(시행일 2026-10-16) · 삭제 안내 페이지에 남는 것으로 적었다.

## 사용자 결정이 필요했던 것(위에서 반영 — 기록으로 남긴다)

- **테스트 APK 서명 키가 공개 레포에 있다**(`app/debug.keystore`). 누구나 테스트 앱 위에 덮어 설치되는 앱을 만들 수 있다. 바꾸면 이미 깔린 테스트 앱 위에 설치되지 않고 구글 로그인 등록 지문도 바뀐다 — 비공개 키를 Secrets 에 두는 결정이 필요하다.
- **attester-logs 워크플로**는 `claude/**` 브랜치 푸시마다 브랜치 코드(npm)로 Cloudflare 토큰을 쓴다 — main 에서만 돌리거나 환경 제한이 필요하다.
- **Build APK 쓰기 권한**: 빌드와 게시가 한 작업이라 PR 에서도 쓰기 권한이 열린다 — 게시를 따로 떼는 구조 변경이 필요하다.
- **멈춘 원격 브랜치 4개**(`codex/release-readiness` · `claude/quirky-rubin-dwm6yv` · `codex/screen-captures-20260924` · `codex/stepup-cohesive-redesign`)는 각자 옛 워크플로를 가지고 있어 푸시되면 QA 캡처를 덮을 수 있다 — 지울지 결정.
- **같은 versionCode(25)**: 데이터베이스 판이 높은 브랜치 APK 위에 main APK 를 깔면 앱이 시작하자마자 멈춘다. 지우고 다시 만드는 방식은 기록이 사라져 쓰지 않았다.
- **계정 삭제 시 채팅**: 지운 계정의 메시지가 다른 폰에는 다시 받기 전까지 남는다 — 지우는 대신 "탈퇴한 사용자"로 바꾸는 스키마 결정이 필요하다.
- 보내지 못한 채팅 메시지는 메모리에만 있어 앱이 죽으면 사라진다(기능 추가 범위).
- 배포 중 잡은 표 잠금은 커밋까지 유지된다(배포 5~6분). 한 번에 보내거나 DB 가까이서 돌리는 개선은 따로.

## 남은 것
