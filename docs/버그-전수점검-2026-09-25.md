## 2차 점검 — 1차 수정의 회귀와 새로 찾은 것

### 1차 수정에서 나온 회귀(바로 고침)

- 답글 정책의 `parent_id` 가 안쪽 표를 가리켜, 모든 직접 답글을 거절하고 있었다.
- 이벤트 몫을 컨트랙트마다 따로 줘서 한 번에 60개까지 보낼 수 있었다. 세 컨트랙트가 몫을 나눠 쓰고, 시작 컨트랙트를 매분 돌리게 했다.
- 기기 시계가 빠르면 웹 지갑이 2단계 인증을 끝없이 다시 물었다. 토큰 발급 시각을 넘지 않게 보도록 했다.
- 대략 위치 권한만 있는 폰(API 30 이하)은 GPS 등록이 거절되면서 기지국 위치까지 못 받았다. 두 등록을 따로 한다.
- 저장을 재시도할 때 뒤따르는 일(코스 완주 등)을 건너뛰었다. 되살린 SETTLING 러닝일 때만 건너뛴다.

### 서버 — 돈 · 신발 흐름

SUP 를 새로 찍어 내거나 두 번 환불하거나 잔고를 음수로 만드는 경로는 없었다. 두 세션을 동시에 돌려 경쟁까지 확인했다.

| 심각도 | 문제 | 고친 것 |
|---|---|---|
| 중간 | 신은 신발이 없으면 내구도 100 · 닳지 않음으로 전액 적립됐다. 닳은 신발을 신고 수리비를 내는 것보다 나았다(신발을 꺼내면 이렇게 됐다) | 신은 신발이 없으면 첫 신발을 신긴다. 꺼낼 때도 첫 신발로 갈아 신긴다 |
| 낮음~중간 | 만료 뒤 체인에서 늦게 확정된 신발 작업이 있으면 같은 신발이 앱(팔기 · 신기 가능)과 체인에 둘 다 있었다 | 앱 쪽을 "체인에 있음"으로 돌리고 매물을 내린다 |
| 낮음 | 옛 신발 올리기(`market_import`)가 동시 요청으로 30켤레 상한을 넘을 수 있었다. 다시 올리면 폰 값으로 내구도가 새것처럼 돌아갔다 | 같은 사람의 요청을 한 줄로 세우고, 내구도는 서버 값을 둔다 |
| 낮음 | 적립할 걸음이 없는 경로 러닝은 보류 중에도 잠금 거리 · 꺼내기 조건 거리를 받았다 | 보류는 늘 적용한다. 걸음 0 이면 경로 100m 여유를 주지 않는다 |
