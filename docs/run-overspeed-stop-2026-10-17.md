# 러닝 중 과속 — 경고 · 30초면 멈춤 · 패널티 (2026-10-17)

사용자 질문: "지금 속도가 시속 100km 이렇게 나오면 문제 없어?" → 결정: "빼는게 아니라 애초에 경고가 뜨고 그렇게 유지되면
강제로 멈추고 패널티를 주는 방식을 넣어야해".

고른 값(사용자):

| 항목 | 정한 것 |
|---|---|
| 경고 기준 | 25km/h(기존 `RunIntegrity.MAX_SPEED_KMH` 그대로) |
| 멈추기까지 | 과속이 **30초** 이어지면 |
| 패널티 | 신은 신발의 **남은 내구도 50% 차감** + **10분 러닝 금지**(제시한 30분 대신 10분) |
| 멈춘 러닝의 보상 | 바꾸지 않았다 — "그 러닝 보상 0"은 고르지 않았다. 기존 판정 그대로이고 서버 판정에 까닭만 남는다 |

## 기획

| 항목 | 정한 것 |
|---|---|
| 경고 | 25km/h 를 넘는 구간이 들어오는 즉시. 자유 · 크루: 지도 위 띠 "속도가 너무 빨라요 · N초 뒤 러닝이 멈춰요"(1초마다 줄어든다). 챌린지 · 코스 · 다이어트: 같은 제목 + 패널티 설명 안내 띠 |
| 소리 · 진동 | 과속이 시작될 때 한 번(앱 설정을 따른다) |
| 이어진다는 뜻 | 과속 구간이 끊기지 않고 들어온다. 사람 속도로 움직인 구간(5m · 1초 이상)이 오면 경고가 풀린다. 과속 구간 사이가 **10초**를 넘으면 처음부터 다시 센다 — 서 있는 러너의 GPS 튐 두 번이 30초 떨어져 와도 멈추지 않게. 제자리 노이즈(5m 아래)는 풀지도 늘리지도 않는다 |
| 멈춤 | 과속 구간끼리 30초를 채우면 서비스가 평소 "마치기"와 같이 저장한다(크루 · 번개면 방도 평소처럼 닫는다). 결과 화면 맨 위에 "과속이 30초 이어져 러닝을 멈췄어요 · 신발 내구도 절반 · 10분 러닝 금지" |
| 일시정지 | 일시정지하면 과속을 세지 않는다(기록도 멈춘다) |
| 띠 차례(자유 · 크루) | **과속** > 위치 꺼짐 > 측정 무효 > 속도 오류 > 멈춰 있음 > 신호 약함 > 대략적 위치 > 일시정지 |
| 러닝 금지 | 멈춘 때부터 10분. 시작 버튼(점검창 · 3-2-1 전)과 서비스 시작이 모두 거절하고 "N분 뒤에 다시 달릴 수 있어요"를 알린다. 앱이 꺼져도 남는다(설정 저장소) |
| 내구도 | 서버가 깎는다 — 신은 신발의 남은 내구도를 절반으로(소수 버림). 앱은 서버가 받은 뒤 다시 받아 온다 |

하지 않는 것:

- 25km/h 를 넘는 구간은 예전처럼 거리 · 경로에 넣지 않는다(지도에도 그리지 않는다). 경고 · 멈춤이 더해졌을 뿐이다.
- 멈춘 러닝을 무효로 만들지 않는다(사용자가 고르지 않았다). 무효 판정은 예전 규칙(튄 구간 3번 이상 · 절반 이상) 그대로다.

## 서버 — `supabase/migrations/0065_overspeed_stop.sql`

- `public.run_penalties` — (사용자, 러닝 시작 시각)마다 한 줄. 앱은 읽기만(자기 것).
- `public.report_overspeed_stop(p_started_at, p_stopped_at)` — 앱이 멈춘 뒤 부른다.
  - 신은 신발 `dur_now` 를 절반으로, `banned_until = 멈춘 때 + 10분`(`economy.overspeed_ban_min()`).
  - 같은 러닝을 다시 보내도 한 번만(응답을 잃은 재시도). 미래 · 시작 전 · 7일 지난 신고는 거절한다.
- `record_session` — 0064 본문 그대로 + 둘:
  - 금지 시간(멈춘 때 ~ +10분)에 시작한 러닝은 `VOID` "과속으로 멈춘 뒤 러닝 금지 시간에 시작한 러닝입니다" — 앱을 지웠다 깔아도.
  - 멈춘 러닝 자체는 무효가 아니면 `FLAGGED` + "과속이 이어져 러닝이 멈췄습니다"(적립 · 닳기 규칙은 그대로).
- 한계: 튄 점은 경로에 남기지 않으므로 서버가 경로로 과속을 다시 볼 수 없다 — 앱의 신고를 받는다. 앱을 고쳐 신고하지 않으면
  패널티도 없다(예전처럼 그 구간 거리는 빠지고, 서버의 튐 비율 · 걸음 대비 거리 검사는 그대로 돈다).

## 앱

- 규칙: [`domain/RunOverspeed.kt`](../app/src/main/java/com/stepup/android/domain/RunOverspeed.kt) — `STOP_MS 30초` · `GAP_MS 10초` · `BAN_MS 10분`.
- 서비스: [`WalkSessionService`](../app/src/main/java/com/stepup/android/service/WalkSessionService.kt)
  - `WalkSessionState.overspeed`(화면 표시용, 저장본에 남기지 않는다) — 과속 구간마다 이어 세고, 사람 속도 구간이면 거둔다. 1초 타이머가 10초 넘게 끊긴 것을 거둔다.
  - `stopForOverspeed` — 금지 시간과 서버 신고를 먼저 폰에 적고(`UserPrefs.raiseRunBanUntil` · `addPendingOverspeedStop`) 평소처럼 저장한다.
  - 시작할 때 금지 시간이면 거절(`startRefusals`) — 자유 · 챌린지 · 코스 · 크루 · 번개 모두.
- 서버 신고: [`OverspeedReporter`](../app/src/main/java/com/stepup/android/data/repo/OverspeedReporter.kt) — 올리기 일꾼(`SessionUploadWorker`)이 러닝보다 **먼저** 보낸다.
  끊기면 러닝도 올리지 않고 다시 시도한다(금지 시간을 서버가 먼저 알게). 무효로 끝나 올라가지 않는 러닝의 신고도 간다.
- 화면: `FreeBand.Overspeed`(자유 · 크루 띠), 챌린지 · 코스 · 다이어트 안내 띠, 결과(자유: 판 위 한 줄 · 그 밖: 보상 줄 맨 앞), 시작 버튼 토스트.
- 글: `run_overspeed_band` · `run_overspeed_body` · `run_overspeed_result` · `run_overspeed_ban`(복수형) — 4개 언어.
