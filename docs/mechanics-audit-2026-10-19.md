# 러닝 · 게임 메카닉 전수 점검과 고침 (2026-10-17 ~ 19)

사용자: "뭔가 이런 메카닉적으로 문제 없는지 전수조사해봐 심각해" · "잠깐 그리고 홀드화면일때 우리 트랙 나오고 그런거 안되는데?"

러닝 한 번이 지나는 길을 처음부터 끝까지 따라가며 앱 · 서버 계산을 맞대어 봤다 — 위치 받기 → 거리 · 랩 · 속도 → 화면 · 알림 →
저장 · 정산(보상 · 에너지 · 내구도) → 올리기 · 서버 `record_session` → 목표 보너스 · 초대 · 코칭 · 기록 · 업적. 점검하는 동안
main 에 #107(과속 멈춤 0065) · #108(신발 경제 3판 0066) · #109(잠금화면 알림) · #110 이 들어와, 고침은 그 위에서 다시 맞췄다
(서버는 `0068_run_mechanics_fixes.sql`).

## 거리 — 한 기준으로 (`domain/RunDistance.kt`)

서버는 경로가 100m 를 넘으면 GPS 거리(걸음 거리 × 3 + 100m 까지), 그 전엔 걸음 거리를 친다(`record_session` 의 `v_distance_m`).
앱은 곳마다 다른 거리를 썼다.

| 곳 | 예전 | 이제 |
|---|---|---|
| 저장한 기록 · 내 정보 · 코칭 | 늘 걸음 거리 — 결과 화면 · 순위와 달랐다 | 서버와 같은 거리(`RunDistance.creditedMeters`) |
| 목표 진행 · 챌린지 · 코스 결과 | GPS 가 조금이라도 잡히면 바로 GPS — 러닝머신에서 걸음 2.50km 가 와이파이 떨림 0.04km 로 거꾸로 갔다 | 100m 전엔 걸음, 그 뒤 GPS(`RunDistance.liveKm`) |
| 코스 완주 횟수 | GPS · 걸음 중 큰 쪽 — 결과는 "97% · 완주 못 함"인데 완주 횟수는 늘었다 | 결과와 같은 거리 |
| 1km 랩(코칭 구간) | 화면 거리와 다른 기준 | 화면과 같은 거리. 무효 러닝은 랩을 남기지 않는다 |

자유 러닝 화면 · 결과는 예전 설계 그대로 GPS 거리만 보인다(걸음으로 셈한 거리를 적지 않는다) — 실내에서 경로가 100m 가 안 되면
결과(GPS)와 기록(서버가 친 걸음 거리)이 다를 수 있다. 바꿀지는 사용자 결정으로 남긴다.

## 위치 · 지도

| 문제 | 고침 |
|---|---|
| 위성 GPS 는 오차를 보지 않아, 150m 짜리 점이 기준점이 되면 다음 구간 문턱이 300m 로 뛰었다 | 오차 50m 넘는 위치는 위성이든 아니든 지도만 옮긴다 |
| 흐린 위치(기지국)도 "잡힌 위치"로 쳐, 인터넷이 끊긴 뒤 기지국 위치만 오는 동안 거리가 멈춰도 "신호 약함"이 뜨지 않았다 | 흐린 위치는 잡힌 것으로 치지 않는다(`GpsSignal`) |
| 와이파이 위치로 잡은 기준점에서 첫 GPS 점까지, 신호가 끊겼다 돌아온 첫 점까지를 한 구간 거리로 셌다 | 그때는 기준점을 새로 잡는다(지도에서도 잇지 않는다) |
| 사람이 낼 수 없는 속도로 튄 위치로 지도의 내 점 · 크루에게 보내는 위치가 옮겨졌다 | 튄 위치로는 옮기지 않는다 |
| 흐린 위치로 내 점이 경로 끝에서 수백 m 떨어진 곳으로 뛰었고, "코스 이탈"이 떴다 | 오차 50m 안의 위치로만 멀리 옮기고 코스 이탈을 본다 |
| 천천히 걸을 때의 보통 점 간격(30초 남짓)까지 끊김으로 그려 걸은 길 선이 대부분 사라졌다 | 끊김은 서버와 같은 60초(`segmentBreaks`) |
| 점이 드문 동안 걷고 있어도 지금 속도가 0 으로 떨어졌다 | 걸음이 10초 안에 늘었으면 마지막 속도를 둔다. 1분 넘게 점이 없으면 모른다 |
| 위치 기능을 끄면 한 번 잡혔던 러닝은 "GPS 연결됨"이 그대로 남았다. 멈춘 동안 켜도 "위치 꺼짐" 띠가 남았다 | 꺼짐을 바로 · 멈춘 동안에도 5초마다 다시 읽는다 |
| 화면이 꺼지면 일부 폰에서 1초 타이머 · 위치 감시가 잠들었다 | 기록하는 동안만 CPU 를 깨워 둔다(`WAKE_LOCK`, 끝나면 놓는다) |

## 과속 멈춤(#107)의 잘못 걸림 막기 (`domain/RunOverspeed.kt`)

#107 은 25km/h 넘는 구간이 30초 이어지면 러닝을 멈추고 신발 남은 내구도 절반 · 10분 러닝 금지를 준다. 그런데 과속 구간은
"기준점 → 새 위치"의 속도라, 실내에서 와이파이 위치가 두 자리(수십 m)를 몇 초마다 오가면 서 있는 러너도 30초를 채울 수 있었다.

- 두 끝 중 하나라도 오차가 20m 넘는 위치의 튐은 과속으로 세지 않는다(거리 · 경로에는 예전처럼 넣지 않는다).
- 30초를 채워도 처음 자리에서 150m(시속 25km 로 30초의 약 3/4) 멀어지지 않았으면 멈추지 않고 처음부터 다시 센다 — 오간 튐이다.
- 기준(25km/h · 30초 · 절반 · 10분)은 그대로다. 차 · 자전거는 바깥에서 GPS(몇 m)로 잡혀 예전처럼 멈춘다.

## 내구도 · 보상

| 문제 | 고침 |
|---|---|
| 거리가 0 인 러닝(걸음 0 · 경로 없음)은 닳지 않았다 — 앱이 걸음 0 인 러닝을 올리지 않았고, 서버도 거리 0 이면 건너뛰었다 | 거리 · 걸음과 상관없이 달린 시간(멈춘 시간 뺀 값) 1분마다 5(2026-10-19 사용자 결정 "걍 1분마다 5 닳는거로 바꿔 어떤식으로든간데", 서버 0068). 앱은 걸음이 0 이어도 시간이 있는 러닝을 올린다(2026-10-19 0시 이후 시작한 것부터 — 지난 러닝이 한꺼번에 올라가 신발을 닳게 하지 않게, `ZERO_STEP_UPLOAD_FROM_MS`). 무효 러닝은 그대로 닳지 않는다 |
| 결과 화면의 신발 칸이 러닝 전 값(100%)으로 돌아가 "안 닳는다"로 보였다 | 서버가 확인하기 전에는 이번 러닝으로 닳을 만큼을 뺀 값을 보인다 |
| 0% 신발로도 출발 전 점검이 "달릴 준비가 됐어요" — 보상 0 의 까닭을 몰랐다 | 다 닳았으면 "보상이 없어요", 10분이 안 남았으면 "약 N분만 보상을 받아요" |
| 러닝 중에 산 XP 부스터를 "×2 예상"으로 보였는데 서버는 시작할 때 켜져 있던 것만 친다 | 시작할 때 기준으로(`BoostDao.activeAt`) |
| 자정을 넘긴 러닝의 에너지를 끝난 날로 셌다(서버는 시작한 날) | 시작한 날(한국 시간)로 |

## 서버 0068 (`supabase/migrations/0068_run_mechanics_fixes.sql`)

0066 의 `record_session`(0065 과속 · 0066 신발 수명 그대로) 위에서 고쳤다. 판정 · 적립 금액 · 상한 · 1분마다 5 · 목표 보너스 금액 ·
초대 적립액 · 코칭 판정은 그대로다.

| 문제 | 고침 |
|---|---|
| 하루 금액 · 경로 없는 러닝 · 올린 날 상한에 걸려 덜(0) 받은 러닝도 에너지는 다 썼다 — 에너지를 상한보다 먼저 깎았다 | 받은 몫만큼만 쓴다(쓴 에너지 × 받은 SUP ÷ 상한 전 SUP) |
| 러닝은 시작한 날의 목표에 드는데 목표 보너스(`goal_claim`)는 오늘만 봤다 — 23:30 ~ 00:10 러닝 · 자정 뒤에 올린 러닝은 그날 보너스와 연속 일수를 잃었다 | `goal_claim_day(날)` — 최근 7일 안의 날, 같은 날은 한 번(꼬리표 `goal:날` 그대로). 앱은 러닝이 확인받으면 최근 7일부터 오늘까지 오래된 날부터 청구한다(받은 날 · 못 채운 날은 서버가 거절할 뿐). 그보다 앞서 시작한 러닝이 아직 올라가지 못했으면 그날 뒤는 미룬다 — 먼저 받으면 그날이 빠진 짧은 연속 일수로 굳는다(Codex 리뷰). 예전 앱의 `goal_claim()` 은 오늘로 그대로 |
| 초대 적립(두 사람 100 SUP 씩)이 경로 없는 러닝(폰이 센 걸음 1,000)에도 나갔다 | 경로가 받쳐 준 러닝의 걸음이 1,000 이상일 때만 |
| AI 코칭(0060)이 거리를 걸음 × 0.762 로 셌다 — 기록 · 결과와 달랐다 | 러닝의 인정 거리(`distance_meters`). 랩 수는 서버 거리의 정수 km 에서 ±1 까지 받는다 |
| 거리 0 러닝도 닳기 | 위 "내구도 · 보상" |

검사: `supabase/tests/schema_test.sql` "러닝 정산 점검(0068)" · `coaching_test.sql` · `run.sh` 전부 통과.

## 기록 · 업적 · 올리기

| 문제 | 고침 |
|---|---|
| 한 번 고른 코스(코스를 녹화해 저장하면 저절로 골랐다)가 그 뒤의 모든 자유 러닝을 코스 러닝(코스 안내 · 이탈 알림 · 완주 글)으로 바꿨다 | 러닝 시작 메뉴 · 크루 입구의 "자유 러닝"은 고른 코스를 풀고 시작한다. 녹화한 코스는 저장만 한다 |
| 하루를 놓쳐도 다음에 목표를 채울 때까지 옛 연속 일수("연속 12일")가 보였다 | 오늘 · 어제 채웠거나 보호막이 어제를 덮었을 때만 이어진 값, 아니면 0(`StreakRules`) |
| 기록 상세 · 지난 도전은 몇 m 로도 페이스를 나눠 1분 기록이 65'37"/km 로 보였다 | 50m 부터(러닝 중 · 결과와 같다, `RunPace`) |
| 분석의 평균 페이스 · 속도가 시간만 잰 러닝(거리 0)의 시간까지 나눠 느리게 나왔다 | 거리와 시간이 모두 있는 러닝만(무효 제외) |
| 업적이 지금 값으로만 열려, 연속 일수가 끊기거나 값이 줄면 연 업적이 다시 잠겼다 | 계정마다 가장 높았던 값을 남겨 그것으로 연다(믿을 수 있는 값만, 계정을 지우면 지운다). 이 폰의 값(걸음 · 거리 · 가장 긴 연속 일수 — 줄지 않는다)은 계정마다 적지 않는다 — 한 폰을 두 계정이 쓰면 앞 계정의 값이 뒤 계정에 굳었다(Codex 리뷰) |
| 서버가 러닝을 기록 · 지급한 뒤 크루 표시 · 코스 기록이 끊기면 러닝이 "정산 대기"로 남고 일꾼의 기다림이 몇 시간까지 늘었다 | 러닝은 바로 확인으로 적고, 뒤 일은 따로 다시 낸다(같은 러닝을 다시 보내도 한 번). 뒤 일이 남은 러닝은 최근 목록이 아니라 표시로 찾아 오래된 것부터 낸다 — 오래 막힌 동안 러닝이 쌓여도 빠지지 않는다(Codex 리뷰) |
| 올리기 일꾼이 대기열을 마지막으로 본 직후 끝난 러닝은 새 예약이 버려져 다음 러닝 · 앱을 다시 켤 때까지 "정산 대기"였다 | 돌고 있는 일꾼 뒤에 하나를 잇는다(`APPEND_OR_REPLACE`) |
| 수리를 누른 뒤 러닝이 올라가 더 닳았으면 견적보다 많이 치렀다 | 견적에 보인 만큼만 고치고 치른다(`p_points`) |

## 신발 내구도를 다 썼을 때 안내 (2026-10-19 사용자 "내구도 다 소모하면 따로 안내가 있어야")

예전엔 달리는 중에 내구도가 바닥나도 신발 칸이 0% 가 될 뿐 아무 안내가 없었고, 결과에도 까닭이 없었다(그 뒤 걸음은 서버가 적립하지
않는다 — 0066).

- 러닝을 시작할 때 신은 신발의 남은 내구도로 보상을 받을 수 있는 시간(남은 내구도 × 12초)을 읽어 둔다(`WalkSessionState.shoeLifeSec`).
- 그 시간을 넘기면(`shoeWornOut`) — 자유 · 크루: 지도 위 띠 "신발 내구도를 다 썼어요 · 이제 걸음은 보상이 없어요"(다른 문제 띠보다 뒤,
  일시정지보다 앞), 챌린지 · 코스 · 다이어트: 같은 안내 띠. 소리 · 진동 한 번. 잠금화면 알림 줄에도 "내구도를 다 써서 보상이 없어요".
- 결과: "신발 내구도를 다 써서 그 뒤 걸음은 보상에 들지 않았어요"(자유 러닝은 판 위 한 줄, 그 밖은 보상 줄).
- 다 닳은 신발로 시작하면 출발 전 점검(자유 러닝)이 먼저 알리고, 달리기 시작하면 바로 띠가 뜬다. 기록은 그대로 이어진다.

## 잠금 화면(홀드 화면)에서 러닝 화면

#109 는 잠금 화면에 러닝 알림(시간 · 거리 · 페이스)을 띄웠지만, 지도 · 경로는 앱을 열어야 보였다.

- 달리는 동안 러닝 화면에 있으면 잠금 화면 위에 러닝 화면이 그대로 뜬다(`setShowWhenLocked`) — 전원 버튼을 누르면 잠금을 풀지 않아도
  지도 · 경로 · 거리 · 시간 · 일시정지가 보인다.
- 러닝이 끝나거나 다른 화면으로 가면 바로 끈다 — 잠금이 다시 덮어, 지갑 · 설정 같은 다른 화면은 잠금을 풀어야 열린다.
- 화면을 저절로 켜지는 않는다(주머니에서 켜지지 않게). 다른 앱을 보다 잠갔으면 예전처럼 알림이 보인다.
- 실제 기기의 잠금 화면에서는 보지 못했다.

## 사용자 결정으로 남긴 것

- 무효 러닝(가짜 위치 · 사람 속도를 넘는 이동 등)은 지금처럼 닳지 않게 두었다 — 이것도 닳게 할지는 사용자 결정.
- 업적 최고값은 업적 화면을 볼 때(연속 일수는 늘) 남긴다. 강화(0054)는 시도 기록이 없어 업적에 세지 않는다.

- 자유 러닝 화면 · 결과는 GPS 거리만, 기록 · 순위는 서버 거리 — 실내 러닝에서 둘이 다르다.
- 순위표는 경로 100m 미만 러닝의 걸음 거리도 센다(서버 규칙 그대로).
- 신발 마모 · 적립 배율은 올릴 때 신고 있는 신발로 셈한다 — 러닝 뒤 올리기 전에 신발을 바꾸면 바꾼 신발이 닳는다(서버에 신발 번호를 보내야 고친다).
- 러닝 시간은 앱이 보낸 값을 서버가 믿는다(경로 시각과 맞대어 보지 않는다).
