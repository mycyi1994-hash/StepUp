# 아이템 · 운영자 페이지 · 보상 이벤트 (2026-11-17)

사용자 "지급하고 싶을 때 쉽게 · 알람도 가게" · "운영자 페이지 만들자 — 24시간 보상 2배 같은 것도 설정" ·
"러닝 부스터 · 에너지 드링크 · 내구도 / 하루 할당량 초기화권 · 보상 2배권" · "출발 전에 고르기 · 같은 종류는 겹쳐서 못 쓴다".

서버 0106(`supabase/migrations/0106_items.sql`) · 운영자 페이지 `web/ops/`(`stepupcrew.com/ops/`) · 푸시 문구 `supabase/functions/push-send`.
앱(2026-11-17 같은 날): 하단 **아이템 탭**(가방) · 출발 전 점검의 **아이템 고르기** — 아래 "앱".

## 아이템

| 종류 | 이름 | 효과 | 언제 |
|---|---|---|---|
| `RUN_BOOSTER` | 러닝 부스터 | 고른 러닝 1회 적립 × 1.5 | 출발 전에 고른다 |
| `REWARD_DOUBLE` | 보상 2배권 | 고른 러닝 1회 적립 × 2 | 출발 전에 고른다 |
| `ENERGY_DRINK` | 에너지 드링크 | 고른 러닝 1회 에너지를 절반만 | 출발 전에 고른다 |
| `DURABILITY_RESET` | 내구도 초기화권 | 신발 내구도를 가득 | 바로 쓴다 |
| `ENERGY_RESET` | 하루 할당량 초기화권 | 오늘 쓴 에너지를 되돌린다 | 바로 쓴다 |

- 값(1.5 · 2 · 0.5)은 `economy.item_kinds.value` — 배포 없이 바꾼다(SQL Editor: `update economy.item_kinds set value = 1.3 where kind = 'RUN_BOOSTER';`).
  다시 배포해도 운영 중 바꾼 값을 덮지 않는다. 끄기는 `enabled = false`.
- **하루 할당량 = 하루 에너지**(기본 10칸 = 6,000보)다. 하루 금액 상한(600 SUP) · 걸음 상한(48,000) · 올린 날 상한은 부정 방지 선이라 그대로다.
- **같은 종류는 겹치지 않는다**: 러닝 부스터와 보상 2배권은 같은 묶음(`REWARD`)이라 한 러닝에 하나만 고른다(서버가 거절).
  적립 배수는 24시간 부스터(× 2) · 보상 이벤트 · 러닝 아이템 가운데 **가장 큰 것 하나**만 적용한다(`economy.run_reward_mult`) — 곱하지 않는다.
- 가득 찬 신발 · 오늘 쓴 에너지가 없을 때는 초기화권을 쓰지 않는다(아이템이 사라지지 않는다).
- 러닝 아이템은 출발할 때 가방에서 빠진다. 무효 러닝은 효과가 없고 돌려주지 않는다. 크루 러닝에는 적립 배수만 적용된다(크루 러닝은 개인 에너지를 쓰지 않는다).
- 유효기간 · 유저끼리 주고받기 · SUP 로 사기는 없다(정해지지 않았다).

## 앱이 부르는 함수

| 함수 | 하는 일 |
|---|---|
| `items_me()` | 종류마다 개수(0 개도) · 값 · 쓰는 때, 지금 켜진 보상 이벤트, 24시간 부스터가 끝나는 때 |
| `item_use(종류, 요청 번호, 신발)` | 바로 쓰는 아이템. 같은 요청 번호는 한 번만 |
| `run_items_use(러닝 시작 시각, 종류들)` | 출발할 때 고른 아이템을 그 러닝에 묶는다. 같은 러닝 · 같은 종류는 한 번만 빠진다 |

- 러닝 시작 시각은 앱이 러닝을 올릴 때 보내는 `p_started_at` 과 같은 값이어야 한다(서버가 그 값으로 찾는다).
- 인터넷 없이 출발했으면 올리기 일꾼이 **러닝보다 먼저** `run_items_use` 를 보낸다(과속 신고와 같은 순서). 이미 기록한 러닝에는 붙이지 못한다.
- 러닝 기록의 `walk_sessions.reward_mult` 에 적용된 배수가 남는다(결과 화면용).

## 운영자 페이지 — `stepupcrew.com/ops/`

키로 들어간다(워킹데이 검토 페이지와 같은 방식 — 서버에는 해시만, 키는 그 탭을 닫으면 사라진다).

```sql
select economy.ops_key_new('담당자 이름');   -- 한 번만 보이는 키
update economy.ops_keys set revoked_at = now() where label = '담당자 이름';   -- 막기
```

- **아이템 지급**: 누구에게(이메일 — 붙여 넣기 · 이름으로 찾기 / 최근 7일 달린 사람 / 전체) → 무엇을 → 몇 개(1 ~ 99) → 사유 → 푸시 여부 → 확인.
  가입하지 않은 이메일은 빼고 지급하고 화면에 알려 준다. 응답을 잃고 다시 눌러도 한 번만 지급된다(요청 번호).
  요청 번호는 **보낸 내용**(받는 사람 · 종류 · 개수 · 사유 · 푸시)에 묶는다 — 답을 못 받았으면(끊김 · 5xx) 기록 탭을 다녀오거나
  화면이 다시 그려져도 같은 내용이면 같은 번호로 다시 보낸다. 내용이 달라지거나 서버가 분명히 답하면 새 번호(2026-11-17 점검 —
  예전에는 화면을 다시 그리기만 해도 번호가 바뀌어 "다시 눌러 주세요"가 두 번 지급이 될 수 있었다). 이벤트 시작도 같다.
- **보상 이벤트**: 이름 · 배수(1 초과 ~ 5) · 기간(1 ~ 168시간) · 지금 / 예약. 그 시간에 **시작한** 러닝의 적립 × 배수(모든 사람).
  겹치는 이벤트는 만들지 못한다. 끄면 그때부터 꺼진다. 지금 시작하는 이벤트만 시작 푸시가 간다(예약은 안 간다).
- **기록**: 최근 지급(되돌리기 — 아직 갖고 있는 만큼만 거둔다) · 이벤트 기록 · 아이템 현황(가진 사람 · 개수 · 쓴 수).
- 지급 · 되돌리기 · 이벤트는 `public.admin_audit` 에 남는다(`detail->>'by'` = 키 이름).

## 앱

- 하단 탭 다섯 — 러닝 · 함께 뛰기 · 신발 · **아이템** · 내 정보(사용자 "아이템 탭만 추가" — 강좌 탭은 넣지 않았다). 길은 `bag`(`Routes.BAG`)
  — `items` 는 예전 신발 보관함 · 거래소 길이라 그대로 둔다. 화면 `ui/screens/items/BagScreen.kt`(시안 "B 확정 · 아이템 탭").
  - 위에서부터: 보상 이벤트 띠(켜져 있을 때) · 러닝할 때 고르는 아이템 셋 · 바로 쓰는 아이템 둘. 주 버튼은 바로 쓰는 아이템을 골랐을 때 아래 "사용하기" 하나.
  - 개수 · 효과 값은 `items_me` 그대로. 못 읽으면 다시 시도. 칸은 두 테마 모두 어두운 남색(그림이 어두운 바탕용).
- 출발 전 점검(`FreeRunShoeCheckContent`)에 "이번 러닝에 쓸 아이템" — 가진 것만, 같은 묶음은 하나(`domain/ItemKind.kt` `RunItemPicks`).
  - 고른 것은 러닝이 켜질 때(`WalkSessionService.beginTracking`, 새 러닝만) 시작 시각과 함께 폰에 적고 바로 `run_items_use`(`ItemsRepository.startRun`).
  - 신호가 없으면 올리기 일꾼이 **러닝보다 먼저** 보낸다(`SessionUploadWorker` — 과속 신고 다음).
  - 고른 것은 점검에서 **"이 신발로 출발"을 누른 그 출발에만** 실린다(`ItemsRepository.arm` — 누른 때부터 10분). 점검을 닫거나 다시 열 때,
    출발을 그만둘 때(권한 안내 · 위치 안내 닫기 · 3-2-1 취소 · 시작 거절)마다 비운다(`clearPicks`). 점검 없이 켜지는 러닝(크루 · 번개 대기실
    출발, 챌린지 · 코스 · 다이어트)에는 쓰지 않는다 — 2026-11-17 점검: 예전에는 고르다 만 아이템이 10분 안에 시작한 크루 러닝에 쓰였고,
    점검을 10분 넘게 열어 두면 "출발하면 고른 아이템을 써요"라고 하고는 쓰지 않았다.
  - 보상 이벤트 · 24시간 부스터가 이미 켜져 있으면 그보다 **크지 않은 배수 아이템은 고르지 못한다**(흐리게 + 한 줄 안내 — `RunItemPicks.covered`).
    서버는 큰 것 하나만 쓰므로 고르면 아이템만 사라졌다. 에너지 드링크는 그대로 고른다.
  - 폰 시계가 앞서 서버가 시작 시각을 받지 않으면("러닝 시작 시각이 올바르지 않습니다") 버리지 않고 러닝과 함께 다시 보낸다(하루 안의 러닝만).
    그 밖의 거절은 버리고 가방을 다시 읽어 미리 뺀 개수를 되돌린다.
  - 로그아웃 · 계정 지우기 때 가방 사본 · 고른 것을 비운다(`ItemsRepository.clear` — `forgetAccountOnPhone`).
- 푸시 링크: `bag` → 아이템 탭, `run` → 러닝 탭(`InviteLinks.PushTarget.Bag` · `RunTab`).
- 그림 `res/drawable-nodpi/item_*.webp`(원본 `design/items/`), 문구 `res/values*/items_bag.xml`(네 언어).
- 검사: `ItemsTest`(고르기 규칙 · 가방 읽기 · 러닝에 묶기 · 신호 없음 · 다른 계정 · 서버 거절 · 오래된 고르기 · 누른 출발에만 실림 ·
  쓸모없는 배수 아이템 · 앞선 폰 시계 · 로그아웃) · `AppChromePolicyTest`(탭 다섯).
  기기 검사(ScreenGallery · ChromeNavigation)에 아이템 탭을 더했다.
- 아직 없음: 러닝 결과 화면의 "적립 ×1.5 적용" 한 줄(서버 `walk_sessions.reward_mult` 를 읽어야 한다) · 홈의 보상 이벤트 띠 · 상점 칸.

## 남은 일

1. **앱**: 위 "아직 없음". 보상 이벤트는 앱과 상관없이 서버가 적립을 계산한다. 아이템 지급은 이 앱이 깔린 뒤에 한다(옛 앱에는 아이템 탭이 없다).
2. push-send 다시 올리기(위).
3. 정할 것: 유효기간 · 예전 부스터 3종(에너지 셀 · 연속 보호막 · 24시간 적립 부스터)을 아이템으로 합칠지 · SUP 로 사는 상점.
4. 점검에서 남긴 것(2026-11-17): 전체 지급 · 전체 푸시 · 전체 되돌리기는 사람마다 한 줄씩 도는 반복이다 — 수천 명이 되면 시간 초과가 날 수 있다
   (묶음 `insert … select` 로 바꾸기). 고른 두 아이템 중 하나가 사라졌으면(되돌린 지급 · 다른 폰에서 씀) 둘 다 쓰이지 않는다(잃지는 않는다).
