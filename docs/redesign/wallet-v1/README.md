## 데이터 — 기존 원장 그대로, 읽기만

- 잔액 · 누적 적립 · 누적 사용: 기존 `observeTotals`(전체 합 · 양수 합 · 음수 절댓값 합) 그대로.
- 이용 내역: `RewardDao.observeLedgerPage(kind, limit)` — 전체 · 적립(`amount > 0`) · 사용(`amount < 0`)을 원장 전체에서 거르고
  `timestamp DESC, id DESC` 로 30줄씩 늘려 읽는다(같은 시각도 겹치거나 빠지지 않는다). 원장 id 가 목록 열쇠다.
- 금액: 기존 정밀도(원장 소수 4자리 → 두 자리, 0 쪽으로). 양수 `+`, 음수 `−`, 0 은 부호 없이 `0.00`(`-0.00` 없음). 0 인 줄은 전체에서만.
- 종류 이름: 기존 `RewardType` 대응 그대로(걷기·러닝 적립 · 목표 달성 보너스 · 신발 강화 · 신발 민팅 · 이벤트 적립 · 신발 구매 · 판매 등 —
  이름만 시안 말투로), 모르는 종류는 "기타 내역"(내용은 상세에서). 원장에 없는 km · 페이스 · 해시 · 확정 상태를 붙이지 않는다.
- 일시: 사용자 시간대. 목록은 `MM.dd HH:mm`, 올해가 아닌 줄과 상세는 연도까지.
- 다시 불러오기 · 거르개 · 연결 확인은 원장에 쓰지 않는다(적립 · 차감 · 재지급 없음).

## WEB3 지갑 줄 — 실제 연결 상태만

| 상태 | 표시 |
|---|---|
| 웹 지갑 페이지 주소 없음(빌드) | 12 준비 중, 누르지 않음 |
| 확인 중 | "연결 상태 확인 중" — 연결 여부를 단정하지 않음 |
| 로그인 전 | "로그인하면 연결할 수 있어요", 누르지 않음 |
| 연결 전 | 01 → 혜택 안내(첫 연결 선물 · 러닝 몇 km 마다 — 서버 `draw_status` 가 준 숫자만) → 기존 웹 지갑 페이지 |
| 연결됨 | 02 → 14 연결 상태 → 신발 뽑기 |
| 읽지 못함 | "연결 상태를 확인하지 못했어요" + "다시 확인" |

연결 상태는 서버 `draw_status.wallet_linked`(설정 › 연결된 계정과 같은 출처)다. 화면에 돌아올 때마다 다시 읽는다(웹 지갑 페이지에서 연결하고 돌아오면 바로 바뀐다).
SUP 잔액 · 원장, 로그인, 뽑기 기회는 서로 다른 상태로 둔다.

## 시안과 다르게 한 것

| 무엇 | 왜 |
|---|---|
| 14 연결 상태 시트에 "지갑 페이지 열기" 글자 버튼 | 기존 지갑 화면의 "지갑 페이지 열기"(SUP · 신발을 앱과 지갑 사이로 옮기기, 2단계 인증)를 연결한 뒤에도 쓴다 — 지우지 않고 안쪽으로 옮겼다 |
| 15 재연결 필요 · 뽑기 07/08/09/25 연결 대기 · 성공 · 실패 시트는 넣지 않음 | 연결은 기존 웹 지갑 페이지(브라우저)에서 끝나고, 앱이 아는 것은 서버의 연결 여부뿐이다 — 만료 · 재승인 상태나 연결 진행을 앱이 알 방법이 없어 꾸미지 않는다 |
| 로그인 전 줄 "로그인하면 연결할 수 있어요" | 연결은 로그인한 계정에만(기존 웹 지갑 페이지 규칙) — 시안에 없는 상태 |
| 웹 지갑 페이지 주소를 만들지 못하면 "연결하지 못했습니다…" 알림 | 기존 지갑 화면의 안내 문구 그대로 |
