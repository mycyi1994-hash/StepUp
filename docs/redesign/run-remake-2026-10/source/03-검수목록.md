# StepUp 구현 검수 목록

이 문서는 구현자가 실행할 검사다. 이번 인계 작업에서는 앱을 수정하거나 아래 검사를 실행하지 않았다. 전체 이미지에 대한 PNG 검사와 육안 검수 결과는 ../03-review/final-audit.json에 별도로 있다.

## 시각과 탐색

- 공식 로고 자산이 유지되며 화면별로 다시 그린 로고가 없다.
- 하단 탭 순서가 러닝·신발·뽑기·커뮤니티·내 정보이고 공통 정책으로 표시된다.
- U01의 다섯 모드가 같은 크기이며 자유 러닝 안에 중복 시작 버튼이 없다.
- 지도·지명·숫자·버튼이 겹치지 않고 실제 타일 출처가 가려지지 않는다.
- 360dp급 좁은 화면, 긴 크루명·신발명, 큰 글씨, 키보드가 열린 상태에서 주요 행동에 도달한다.
- 시트 뒤 화면을 누를 수 없고, 뒤로·바깥 누름으로 위험 동작이 실행되지 않는다.
- 현재 앱의 신발 보관함·능력치·관리 진입이 색감 변경 후에도 남아 있다.

## 세션과 데이터

- 자유 러닝 시작·카운트다운 취소·재개·종료·저장 실패 재시도를 확인한다.
- 회전·잠금·앱 전환·프로세스 복원 후 같은 세션과 기록을 유지한다.
- 위치 권한 없음·대략적 위치·기기 위치 꺼짐·GPS 끊김이 구분된다.
- 지도에 없는 GPS 구간을 직선으로 채워 거리 보상에 반영하지 않는다.
- 거리·시간·페이스·진행률이 같은 세션 기준으로 일치한다.
- 저장 실패 후 재시도로 중복 기록이 생기지 않는다.
- 저장 완료와 보상 확인/반영/제외/미지급이 실제 응답과 일치한다.
- 경로 공유 OFF의 실제 출력 이미지에 지도·장소·출발지·도착지가 없다.
- 삭제 취소/실패는 원본을 보존하며 성공은 기간 합계와 통계에 반영된다.
- 챌린지 미달성 결과와 다이어트 중간 종료를 완주로 표시하지 않는다.
- 코스 선택만으로 운동이 시작되거나 게시판 공개가 일어나지 않는다.

## 크루 실제 연결

두 대 이상의 기기 또는 구분된 테스트 클라이언트로 확인한다. 30명 목록은 격리된 테스트 환경에서 데이터로 검증한다. 실제 사용자에게 시험 알림을 보내지 않는다.

- 조회만 했을 때 방이 생성되거나 참가자가 늘지 않는다.
- 크루원과 진행자의 준비·출발 권한이 구분된다.
- 준비 취소와 출발 동시 요청에서 서버 명단을 따른다.
- 참가자가 같은 서버 시작 시각을 사용한다.
- 한 명의 일시정지·종료가 다른 사람의 개인 기록을 멈추지 않는다.
- 공유 OFF인 참가자의 위치·거리·순위가 다른 기기에 공개되지 않는다.
- 통신 끊김 후 같은 방/세션으로 복구하고 오래된 타인 핀을 숨긴다.
- 이미 출발한 방의 신규 참가와 기존 참가자 복귀를 구분한다.
- 알림·기록 공유는 미리보기 후 전송하며 재시도 중복을 막는다.
- 방이 없어짐·진행자 이전·권한 상실·서버 오류에서도 기록을 보존한다.

## 저장소 검사

실제 checkout의 AGENTS.md와 도구 옵션을 확인한 뒤 실행한다. 다음 파일은 조사 대상 저장소에서 존재를 확인했다.

- tools/check_design_contract.py
- scripts/check-strings.py
- tools/check_experience_assets.py
- scripts/check-fakes.py

Android SDK가 준비된 환경에서 해당 변경의 빌드와 단위 테스트를 실행한다. 저장소의 Gradle wrapper로 :app:compileDebugKotlin, :app:testDebugUnitTest, :app:lintDebug를 확인한다. 명령 성공만으로 화면 검수를 대신하지 않는다. SDK가 없다는 오래된 문구도 현재 환경에서 다시 확인한다.

회귀 검사 후보는 RunStartFlowTest, RunJourneyDesignTest, RunSaveRecoveryTest, RunSettlementPersistenceTest, RunLocationStateTest, RunCrashRecoveryTest, RecordsDesignTest, RouteMapFitTest, CourseQueuePersistenceTest, ChromeNavigationTest, MyShoesDesignTest다. 기존 테스트를 먼저 실행하고, 실제로 새로 변경한 동작에 필요한 검사만 추가한다.

## 완료 증거

implementation-checklist.csv의 각 항목에 연결된 파일/상태, 실제 캡처, 검사 결과를 적는다. 한 화면의 변형 상태는 같은 컴포넌트의 테스트 조건으로 대응할 수 있다. 단순히 PNG 파일이 존재한다고 구현 완료로 표시하지 않는다.

동일 소스 버전에서 만든 빌드와 캡처를 비교한다. 최종 인계에는 변경 파일, 대표 실제 캡처, 실행한 검사, 미검증 상태, 남은 API/지도/기기 연동을 포함한다. 외부 연동이 막혀도 별도로 완성 가능한 UI 작업은 계속하고, 미연동 상태를 성공으로 꾸미지 않는다.
