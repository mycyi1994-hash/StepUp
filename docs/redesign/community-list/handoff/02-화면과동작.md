# 02. 화면과 동작

전체 31개 장면은 `screens.json`에 개별 PNG와 함께 정리되어 있습니다. 논리 화면은 목록, 상세, 작성/수정, 장소 검색, 지도, 권한 안내, 지역 선택입니다. 댓글 입력·게시 중·빈 목록·오류는 화면 상태이며 메뉴·신고·범위 선택·임시저장은 시트 또는 대화상자입니다.

## 핵심 경로

```text
목록 ─ 글 선택 → 상세 ─ 댓글 입력 → 등록 후 상세
  ├─ 지도/썸네일 → 지도 → 장소 선택 → 그 장소의 목록
  ├─ 범위 → 500m / 1km / 3km → 목록 갱신
  └─ 글쓰기 → 본문 작성 → 장소 검색 → 지도 확인 → 작성 화면
                                                   └─ 올리기 → 게시 중 → 목록 맨 위에 내 글

상세 ─ 내 글 메뉴 → 수정 / 삭제 확인
     └ 다른 글 메뉴 → 숨기기 / 신고 사유 → 신고 결과

작성 ─ 뒤로 → 임시저장 / 계속 쓰기 / 삭제하고 나가기
목록 ─ 다시 글쓰기 → 임시저장 이어쓰기 / 새로 쓰기
```

## 공통 상태 규칙

- 뒤로 가기: 모달이 열려 있으면 먼저 닫기. 지도·장소 선택에서 돌아오면 원래 화면과 작성 내용을 유지.
- 글쓰기/수정 중 본문 또는 장소가 바뀌었다면 이탈 시 확인. 내용이 그대로면 추가 확인 없이 복귀.
- 선택 상태: 범위는 기본 1km, 500m/1km/3km 중 하나. 임시 선택과 적용한 값을 구분하고 취소 시 원래 범위 유지.
- 장소 필터: 선택 장소의 글만 보이고 `전체 장소`로 해제. 범위 밖 장소의 상세를 명시적으로 열었다면 이유 없이 빈 목록이 되지 않도록 범위/필터 규칙을 일관되게 처리.
- 지도 핀의 글 수와 목록 집계는 같은 범위·필터·숨김 기준을 적용. 빈 목록인데 핀에 글이 있다고 표시하지 않기.
- 길거나 한글/영문이 섞인 제목은 목록에서 최대 2줄, 상세에서 전부 표시.

## 읽기와 댓글 — 01~05

목록에서 글을 열면 작성자 → 제목/본문 → 장소 카드 → 반응 → 댓글 순서입니다. 댓글은 공백 제외 내용이 있을 때 등록 가능하며 최대 200자입니다. 성공 후 입력을 비우고 새 댓글과 댓글 수를 반영합니다. 제출 실패 시 입력을 보존하고 재시도 가능하게 합니다. 좋아요는 현재 선택 상태와 개수를 함께 바꾸고 서버 실패 시 복구합니다.

## 글쓰기와 장소 — 06~13

입력은 본문 한 칸, 최대 1,000자. 별도 제목·카테고리 선택을 앞에 두지 않습니다. 첫 줄을 제목으로 사용하고 나머지를 본문으로 저장/표시하되, 기존 서버의 제목 길이·검증 제한은 확인해서 본문 손실 없이 맞춥니다. 한 줄만 쓴 글도 허용합니다.

시안에는 가까운 장소가 미리 표시되어 있고 변경할 수 있습니다. 실제 위치를 모르거나 기본 장소가 확정되지 않은 경우 임의의 여의도 장소를 저장하지 말고 장소 선택 상태를 명시합니다. 게시에는 유효한 본문과 선택한 장소가 필요합니다.

장소 검색 → 검색 결과 선택 → 지도에서 장소명과 주소 확인 → `이 장소로 선택` → 작성 화면 복귀입니다. 이 과정에서 본문을 유지합니다. 검색 결과가 없으면 검색어를 지우거나 바꿀 수 있습니다.

게시 중에는 제출을 막아 중복 게시를 방지합니다. 성공해야 목록에 내 글을 추가합니다. 실패하면 본문과 장소를 보존합니다. 글 수정은 기존 글 ID와 댓글·좋아요를 유지하며 새 글로 중복 생성하지 않습니다.

## 지도와 범위 — 14~17

장소 핀 또는 장소 목록을 선택하면 장소명·거리와 글 미리보기를 보여줍니다. `이 장소 글 보기`는 해당 장소의 목록으로 연결됩니다. 지도에는 보는 사람의 현재 위치와 글이 연결된 공개 장소를 표시합니다. 작성자의 실시간 위치는 표시하지 않습니다. 글 옆 거리는 보는 사람 또는 수동 선택 지역의 중심에서 공개 장소까지의 거리입니다.

위치 미확보 상태에서는 거리나 현재 위치를 임의 생성하지 않습니다. 수동 지역을 사용한다면 `선택한 지역에서`로 문구를 바꿉니다. 지도 공급자·검색 API는 현재 앱의 구현을 먼저 확인합니다.

## 관리와 임시저장 — 18~25

내 글에는 수정·삭제, 다른 글에는 숨기기·신고 메뉴를 제공합니다. 글 숨기기는 해당 글에 대한 표시 제어이며 작성자 차단과 다른 행동입니다. 숨김 직후 되돌리기를 제공하고 기존 차단 기능을 숨김에 잘못 연결하지 않습니다.

삭제는 확인 후 진행하고 성공한 경우에만 목록에서 제거합니다. 실패하면 원래 글을 보존합니다. 글 삭제 시 댓글 처리 정책은 서버 계약과 함께 확인합니다.

신고는 사유 단일 선택 후 접수합니다. 시안의 사유는 광고·도배 / 욕설·비방 / 개인정보 노출 / 기타 부적절한 내용입니다. 서버 사유 목록과 명시적으로 매핑하고 접수 성공을 받은 뒤에만 완료 문구를 보여줍니다. 신고자가 글쓴이에게 노출되지 않는지는 서버 설계와 확인합니다.

임시저장은 본문·장소·작성/수정 구분·수정 대상 ID를 함께 보존합니다. 이어쓰기를 선택하면 복원하고, 새로 쓰기는 이전 임시글을 지우는 의미가 명확해야 합니다. 실제 앱에서는 기존 로컬 저장소를 사용해 앱 재시작 후에도 복원되는지 확인합니다. HTML 시안은 메모리 저장만 합니다.

## 권한과 상태 — 26~31

위치 안내에서 `내 위치 사용하기`는 실제 OS 권한 흐름으로, `지역 직접 선택`은 권한 없이 지역 검색으로 이어집니다. 거절·영구 거절·위치 찾기 실패 시 수동 선택 경로를 유지합니다. 최초 권한 문구를 실제로 허용받은 상태와 혼동하지 않습니다.

빈 목록은 첫 글 남기기와 범위 넓히기를 제공합니다. 로딩은 목록의 자리를 유지합니다. 목록 오류는 재시도, 게시 오류는 입력 보존 후 재시도입니다. 플랫폼 키보드 표시 시 댓글 입력/게시 버튼이 키보드와 하단 인셋에 가려지지 않도록 처리합니다.

세부 문구와 보이는 배치는 PNG가 기준입니다. 위 동작은 시안의 임시 동작을 실서비스로 옮길 때 지켜야 할 기준이며, HTML이 구현하지 않은 모든 서버 동작이 이미 완성되었다는 뜻은 아닙니다.
