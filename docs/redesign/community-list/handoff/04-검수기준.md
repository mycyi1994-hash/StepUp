# 04. 검수 기준

## 시각 확인

- [ ] 기본 목록 첫 화면에서 지도와 다른 사람의 게시글이 동시에 보인다.
- [ ] 장소 지도 썸네일·제목·본문 미리보기·작성자·시간·반응의 정렬이 기준 PNG와 맞는다.
- [ ] 짙은 남색, 흰색 주요 버튼, 얇은 구분선을 유지한다.
- [ ] 글쓰기 버튼·알림·하단 메뉴·키보드가 서로 가리지 않는다.
- [ ] 최소 360~390dp급 화면과 글자 확대 상태에서 핵심 행동이 잘리지 않는다.
- [ ] 로고·헤더·하단 메뉴·시스템 상태 표시줄이 중복으로 그려지지 않는다.
- [ ] 모든 앱 화면이 기존의 동일한 디자인 시스템을 사용한다.

## 핵심 동작

- [ ] 목록 → 상세 → 뒤로 이동 시 스크롤과 필터가 유지된다.
- [ ] 댓글 등록 성공 후 댓글과 개수가 한 번만 반영되고 실패 시 입력이 유지된다.
- [ ] 좋아요와 개수가 일치하며 실패하면 상태가 복구된다.
- [ ] 글쓰기에는 제목/종류 선택이 강제되지 않는다. 공백만으로 등록되지 않는다.
- [ ] 장소 검색 → 지도 확인 → 작성 복귀 시 본문과 선택 장소가 유지된다.
- [ ] 게시 중 중복 제출을 막고, 성공 후 내 글이 목록 상단에 한 번만 나타난다.
- [ ] 수정은 같은 글을 갱신하며 댓글·좋아요를 잃거나 새 글을 추가하지 않는다.
- [ ] 삭제 취소는 글을 보존하고, 삭제 성공 후에만 목록에서 제거한다.
- [ ] 글 숨기기와 사용자 차단이 구분되고, 숨김 되돌리기가 가능하다.
- [ ] 신고 사유가 실제 서버 계약과 맞고, 서버 성공 후에만 완료 화면이 나온다.
- [ ] 임시저장은 본문·장소·수정 대상 정보를 복원한다. 앱 재시작도 확인한다.
- [ ] 500m/1km/3km 범위 변경, 장소 필터, 지도 핀의 집계 기준이 일치한다.
- [ ] 위치 거절/실패 후에도 지역 직접 선택으로 진행 가능하다.
- [ ] 로딩·빈 목록·목록 오류·게시 오류를 강제로 재현해 확인했다.
- [ ] 본문/댓글의 최대 길이, 긴 한 줄, 줄바꿈과 이모지 입력이 내용 손실 없이 처리된다.

## 데이터와 기존 기능

- [ ] 장소까지 거리와 러닝 목표 거리를 혼용하지 않는다.
- [ ] 장소·거리·글쓴이·성공 결과가 예시 데이터로 고정되지 않는다.
- [ ] 기존 계정·크루·게시글·선호 설정을 초기화하거나 교체하지 않는다.
- [ ] 기존 인증·로그아웃·서버 오류 정책을 따른다.
- [ ] 새 화면의 내 글 판별과 수정·삭제 권한은 서버에서도 확인된다.

## 제출 증거

저장소에서 요구하는 디자인 계약·문자열/리소스 검사와 관련 테스트를 실행하고, 동일 변경 상태에서 앱을 빌드해 캡처합니다. 이번 요청과 무관한 전체 테스트 확장보다 변경된 UI와 동작의 확인을 우선합니다.

최소 캡처: 기본 목록, 상세와 댓글, 작성 중, 장소 확인, 게시 후, 삭제 확인, 신고 시트, 빈 목록, 위치 안내, 게시 실패. 실제 Android 캡처와 디자인 PNG를 구분해 이름을 붙입니다. 31개 장면 중 구현/연결/미연결 상태를 `screens.json`의 ID로 보고하면 됩니다.

## 전달 자료에서 이미 확인한 것

원본 `design/verification.json`은 **HTML 시안**에서 16가지 검증을 수행한 기록입니다. 댓글·좋아요·작성/장소 선택·임시저장·게시·수정/삭제·숨김·신고·범위·오류 재시도·375px 가로 넘침·브라우저 오류 등을 확인했습니다. Android 구현, 실제 API, 실제 위치·신고 접수의 검증 기록은 아닙니다.

이번 가공 단계에서는 31개 개별 PNG, 6개 보드/요약 이미지, 문서와 참조 파일의 존재·크기·파일 해시를 확인합니다. 앱 빌드나 실서비스 동작 검증을 완료했다고 표현하지 않습니다.
