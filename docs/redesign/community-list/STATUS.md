# 목록형 커뮤니티(동네 이야기) — 구현 현황 (2026-09-27)

사용자가 준 인수인계 묶음(`handoff/`의 01·02·04 · `screens.json`, 시안 PNG는 `reference/`에 390px로 줄여 둠)을
기존 앱에 구현했다. 커뮤니티 첫 화면이 **위에 지도, 아래에 가까운 곳의 글 목록**이 되고, "함께 뛰기"(모임 · 크루)는
두 번째 세그먼트로 그대로 남았다. 새 UI에 크루 결성 · 배지 · 랭킹을 더하지 않았고, 기존 크루 · 번개 · 계정 데이터는 건드리지 않았다.

## 서버 계약 (0041_place_stories.sql)

| 항목 | 내용 |
|---|---|
| 장소 | `posts.place_address` 추가(120자). 장소 이름 · 좌표는 기존 `place` · `lat` · `lng`를 일반 글에도 쓴다 |
| 쓰기 | `story_create(title, body, place, address, lat, lng)` — 전체 게시판 FREE 글, 도배 제한은 post_create와 같다(1시간 20편) |
| 고치기 | `story_update(post, …)` — 같은 글 번호(댓글 · 좋아요 유지). 내 글 · 번개 아님 · 크루 글 아님을 서버가 확인 |
| 목록 | `post_feed` 뷰 맨 뒤에 `place_address` 열을 더했다(기존 열 · 권한 그대로) |
| 삭제 · 좋아요 · 댓글 · 신고 | 기존 `post_delete` · `post_toggle_like` · `comment_create` · `content_report` 그대로. 삭제하면 댓글도 함께 지워진다(FK cascade) |

본문 한 칸의 첫 줄이 제목(120자)이 되고, 나머지는 줄바꿈을 포함해 본문으로 간다. 첫 줄이 120자를 넘으면 120자에서 잘라
나머지를 본문 앞에 둔다 — 고칠 때 `StoryText.join`이 원문을 그대로 되살린다(이모지는 코드포인트 경계에서 자른다).

## 앱에서 새로 쓰는 것

- 장소 검색: 지도 타일과 같은 MapTiler 계정의 Geocoding(새 외부 서비스 아님). 결과가 적으면 기기 지오코더로 보탠다.
  시설(poi)은 `types`에 적어야 나온다 — 빼면 "여의나루역" 같은 이름이 안 잡힌다(2026-09-27 실제 응답으로 확인).
- 숨긴 글 · 임시저장: 이 폰의 DataStore(`strideup_prefs`)에 계정마다 따로. 계정 삭제 때 함께 지운다.
- 직접 고른 지역: 같은 DataStore. 위치 권한이 없어도 "선택한 지역에서"로 본다.

## 미연결 · 남은 것

- **서버 적용**: 0041은 main에 합쳐야 Supabase에 적용된다(deploy-sql). 그 전의 앱에서는 올리기 · 고치기가
  "글이 올라가지 않았어요"(입력 유지)로 끝난다. 읽기 · 댓글 · 좋아요 · 삭제 · 신고는 기존 계약이라 그대로 동작한다.
- **장소 검색 품질**: MapTiler(OpenStreetMap)에 없는 한국 가게 · 작은 공원이 있다. 카카오 · 네이버 장소 검색을 쓰려면
  새 API 키(사용자 결정)가 필요하다. 그 전에는 "지도에서 장소 보기"로 직접 고른다.
- **예전 글**: 목록형 이전에 장소 없이 쓴 자유 · 꿀팁 글은 지도 · 거리에 들어가지 않고 목록 끝 "장소 없이 올라온 이전 글"에 남는다.
- **신고한 글**: 시안대로 접수 뒤에도 보인다(5건이 쌓이면 서버가 모두에게서 숨긴다). 안 보려면 "이 글 숨기기".
- **임시저장 칸은 하나**: 다른 글을 쓰다 임시저장하면 앞의 임시저장을 바꾼다(시안과 같음).
- **내 위치 캡처**: CI 에뮬레이터에는 위치가 없어 기기 캡처는 "선택한 지역에서" 경로로 찍는다. 문구만 다르고 배치는 같다.
