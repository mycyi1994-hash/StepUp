- 외부 러닝 소식 · 대회(`NewsScreen` · `RunningFeedRepository`)는 그대로다 — 공지와 자료 · 경로가 따로다.

## 읽음 — 들어온 것만으로 읽지 않는다

- 예전에는 알림함을 열자마자 모두 읽음으로 바꿨다(`LaunchedEffect { markAllRead() }`) — 없앴다.
- 알림을 열어 내용 시트가 뜨거나 갈 곳(댓글 · 크루 게시판)으로 옮겨 가면 **그 알림만** 읽음(`markRead(id)` — read 만 바꾼다).
  저장에 실패해도 내용은 보이고 "이 알림의 읽음 표시를 저장하지 못했어요"를 알린다.
- "모두 읽음"은 확인 창 없이, 누르는 동안 다시 누를 수 없다. **누른 때 목록에 있던 알림까지만**(`markReadUpTo(가장 최근 번호)`) —
  요청 중에 들어온 알림은 새 알림으로 남는다. 성공하면 "모두 읽음으로 표시했어요", 실패하면 저장된 상태 그대로 "읽음 표시를 저장하지 못했어요"(13).
- 읽음은 행 삭제 · 초대 응답(actioned) · 가입 · 보상 지급과 따로다. "모두 읽음"을 눌러도 답하지 않은 초대 버튼은 남는다.
  설정의 "알림 기록 지우기"(`clearAll` → `clearExceptPendingActions`)는 그대로 — 둘을 바꿔 쓰지 않는다(이름 · 주석도 고쳤다).
- 날짜 묶음과 "12분 전"은 화면에 돌아올 때와 30초마다 다시 계산한다(예전에는 연 순간의 시각에 고정).

## 초대 — 기존 기능 보존

| 장면 | 동작 |
|---|---|
| 05 크루 초대 | 크루 이름 · 대상은 알림에 저장된 실제 값. 여는 것 · "크루 보기" · 닫기만으로 수락하지 않는다 |
| 수락 | 기존 `acceptCrewInvitation → crewRepository.join` 결과 그대로. 알림마다 처리 중 표시로 겹쳐 보내지 않고, 처리 중에는 "확인 중…" · 수락 · 거절을 함께 막는다(시트는 닫을 수 있다) |
| 06 · 가입 완료 | 서버가 Requested 면 "가입 신청을 보냈어요"(06), Joined 면 "크루에 가입했어요" — 신청을 가입 완료로 보이지 않는다. 이미 응답한 초대를 다시 열면 서버의 지금 크루 목록(가입 · 신청)으로 보이고, 찾지 못하면 "응답한 초대예요" |
| 07 · 모름 | 서버가 받지 않았으면(거절) "초대를 수락하지 못했어요 · 처리되지 않았어요"(07, 다시 수락). 응답을 못 받았으면(끊김 · 5xx) **다시 수락하지 않고** join 뒤에 받은 크루 목록부터 본다 — 가입 · 신청이 있으면 그 결과(초대는 응답한 것으로), 목록을 새로 받았는데 없으면 07, 목록도 못 받았으면 "응답 상태를 확인하지 못했어요 · 가입 상태 확인" |
| 21 거절 | 초대 시트 안에서 내용만 바뀐다(겹치지 않음). "여의도 러너스의 초대 알림이 지워져요 · 현재 가입한 크루는 바뀌지 않아요" → 그 초대 알림 하나만 지운 뒤 "초대를 거절했어요". 실패하면 초대는 남고 다시 거절 · 취소 |
| 22 로그인 필요 | "나중에"는 초대로 돌아간다(초대 보존). "로그인"은 기존 다시 로그인 길(달리는 중이면 먼저 저장) — 로그인하고 새로 열린 앱은 알림함에서 그 초대를 다시 보인다. 자동으로 수락하지 않는다 |
| 08 함께 뛰기 | "대기실 보기"는 보기만. "수락하고 보기"는 기존처럼 이 폰의 알림에 수락 표시만 하고 대기실로 — 실제 참가 · 출발은 대기실이 서버와 확인한다. 대기실 정보가 없는 초대는 거절 · 닫기만 |

- 예전 가짜 초대 정리(`purgeLegacyInvites`)는 그대로. 예시 초대를 앱이 넣지 않는다. 지금 앱은 크루 · 함께 뛰기 초대 · 답글 알림을 새로 만들지 않는다 —
  예전 버전에서 받아 둔 알림이 있을 때만 이 시트들이 보인다.

## 공지 자료 — 서버 표 `announcements`(0043)

- 코드에 앱 공지의 자료 계약이 없어서 새로 만들었다: `supabase/migrations/0043_announcements.sql` — 안정된 id, 언어별 제목 · 본문(jsonb),
  게시 시각, 공개 여부, 정해 둔 버튼 하나(DRAW · RUN_HISTORY · NOTIFICATION_SETTINGS · PRIVACY_SETTINGS). 로그인 없이 읽고(공개 안내), 앱은 쓸 수 없다.
  공개 · 게시 시각이 지난 글만 보인다(RLS). 본문은 빈 줄로 문단, "## " 줄은 소제목, "---" 는 구분선.
- **글은 넣지 않았다** — 전달본의 공지 넷(무료 뽑기 이용 안내 등)은 디자인 예시라 운영 공지로 올리지 않았다(`sample-content.json` 은 기기 테스트 장면에만).
  서버에 글이 없으면 앱은 "아직 공지가 없어요". 공지를 올리는 법은 0043 머리 주석(대시보드 SQL, service_role).
- 앱: `AnnouncementApi`(익명 키로 읽기) · `AnnouncementRepository` — 받은 목록을 앱 파일(`announcements.json`)에 사본으로 두고,
  새로 받지 못하면 사본을 보인다. 서버가 목록에서 뺐거나 하나만 물었을 때 주지 않은 글은 사본에서도 지운다(서버 답이 먼저).
  닿지 못한 것 · 배포 전 서버(표 없음)는 내린 글이나 빈 목록으로 보지 않는다.
- 서버 표는 main 에 합쳐지면 `deploy-sql` 이 올린다. 그 전의 서버에서는 공지 메뉴가 "공지를 불러오지 못했어요"를 보인다.

`res/values*/notifications.xml`(한 · 영 · 일 · 중 102개). 신발 알림은 "○○ 민팅 완료" 대신 "○○ 신발을 받았어요". 처리하지 않은 이전 보상 알림의 줄 제목은

## 아직 연결되지 않은 것

- 공지 글 올리기 화면(운영 도구)은 없다 — 대시보드 SQL 로 올린다. 공지 푸시 · 외부 게시도 하지 않는다.
- 크루 · 함께 뛰기 초대 알림과 답글 알림은 지금 앱이 새로 만들지 않는다(예전 버전에서 받아 둔 것만). 초대를 보내는 기능은 이 작업 범위가 아니다.
- 함께 뛰기 "수락"은 기존처럼 이 폰의 표시일 뿐이다 — 서버의 참가 확인은 대기실에서 한다.
