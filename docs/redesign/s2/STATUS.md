## 구현 요청이 오면 시작할 순서

1. 현재 브랜치·변경 상태를 확인하고 이 폴더와 `design/s2/README.md`를 읽는다. 기존 기능은 현재 소스 기준으로 확인한다.
2. 제안과 사용자 추가 지시의 차이가 있으면 반영한다. 이미 정해진 S2 스타일이나 이미지 추출을 다시 질문하지 않는다.
3. 공통 색/글자/간격/원형 행동/탭/상태 부품을 설계하고 홈·신발·러닝 대표 화면에 적용한다. 문자열·아이콘·숫자는 실제 Compose 요소다.
4. 미확보 자산은 안내된 대체안으로 진행한다. 상품/보유와 불일치하는 신발 그림으로 전체 카탈로그를 덮지 않는다.
5. 같은 소스의 빌드와 원래 크기 Android 캡처로 사용자에게 비교를 보여준다. 확인한 범위와 다른 부분을 명시한다.
6. 이후 시작/로그인/운동 상태 → 신발/마켓/뽑기 → 커뮤니티 → 프로필/상세 화면 순서로 확장한다.

## 우선 조사할 구현 위치

- `app/src/main/java/com/stepup/android/ui/StepUpRoot.kt`: 기존 네 기본 탭+가운데 뽑기 행동, 내비게이션 연결.
- `app/src/main/java/com/stepup/android/ui/AppChromePolicy.kt`: 부모 탭/헤더/하단바 표시 정책.
- `app/src/main/java/com/stepup/android/ui/theme/`: 기존 공통 디자인 토큰.
- `app/src/main/java/com/stepup/android/ui/components/`: 공통 헤더·버튼·풍경·지도·폼 등.
- `ui/screens/home/HomeScreen.kt`, `customize/CustomizeScreen.kt`, `walk/WalkScreen.kt`: 첫 대표 적용 대상(앞에 app/src/main/java/com/stepup/android/).
- `ui/screens/gacha/MysteryBoxScreen.kt`: 준비 상태와 실제 결과 연결. 기존 상자 재사용.
- `data/prefs/UserPrefs.kt`, `domain/Sneaker.kt`, `data/repo/`: 현재 설정/신발/정산의 사실 확인용. 리디자인만을 위해 정책을 바꾸지 않는다.

실외 GPS, 서버 정산/거래/실시간 모임, 지갑/뽑기 운영 성공은 이 인계에서 검증하지 않았다. 화면의 성공 상태를 연결 완료의 증거로 사용하지 않는다. 저장 식별자 `strideup.db`, `strideup_prefs`, 계정·보유·기록을 보존한다.
