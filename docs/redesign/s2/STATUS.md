## 구현 요청이 오면 시작할 순서

1. 현재 브랜치·변경 상태를 확인하고 이 폴더와 `design/s2/README.md`를 읽는다. 기존 기능은 현재 소스 기준으로 확인한다.
2. 제안과 사용자 추가 지시의 차이가 있으면 반영한다. 이미 정해진 S2 스타일이나 이미지 추출을 다시 질문하지 않는다.
3. 공통 색/글자/간격/원형 행동/탭/상태 부품을 설계하고 홈·신발·러닝 대표 화면에 적용한다. 문자열·아이콘·숫자는 실제 Compose 요소다.
4. 미확보 자산은 안내된 대체안으로 진행한다. 상품/보유와 불일치하는 신발 그림으로 전체 카탈로그를 덮지 않는다.
5. 같은 소스의 빌드와 원래 크기 Android 캡처로 사용자에게 비교를 보여준다. 확인한 범위와 다른 부분을 명시한다.
6. 이후 시작/로그인/운동 상태 → 신발/마켓/뽑기 → 커뮤니티 → 프로필/상세 화면 순서로 확장한다.

## 3차 — 머리글 · 로그인 · 카운트다운 · 공유 카드 (2026-09-26)

- 머리글: 보유 SUP 알약의 면과 테두리를 없애 글자만(숫자 밝게 · 단위와 화살표 흐리게). 누르면 지갑, 자리 · 태그 그대로.
- 홈: 아래 줄 왼쪽을 보유 SUP 대신 오늘 거리로 — 보유 SUP 는 머리글에만.
- 로그인: 로고 → 큰 제목 → 아치 풍경(S2 로그인 원본) → Google 버튼 → 약관. Google 버튼은 Google 브랜드 규칙에 맞는 기존 버튼 그대로(시안의 원형 G 버튼으로 바꾸지 않음).
- 파티 출발 카운트다운: 육각 배지 대신 파란 한 줄 + 가는 큰 숫자.
- 공유 카드(그림): 파란 면 → 푸른 검정 바탕 + 도시 야경 + 달린 길 + 가는 큰 거리 · 시간 · 페이스. 로고는 어두운 바탕용 공식 워드마크. SUP 는 여전히 적지 않는다.

## 4차 — 신발 안쪽 (2026-09-26)

- 신발 상세: 계열 · 등급 → 이름 → 민팅 번호 · 레벨 · 보유 → 등급 무대(14차 — 예전 기울인 파란 면) 위 신발 → 능력치 한 줄(서버 신발은 효율 · 착화감 · 내구도, 예전 신발은 적립 · 행운 · 내구도). 시안의 네 칸 능력치를 새로 만들지 않았다. 자세한 막대 · 강화 · 수리 · 판매는 그대로.
- 보관함 맨 위 착용 신발: 같은 S2 머리(착용 중 · 등급, 이름, 신발, 능력치 한 줄).
- 도감: 진행도를 파란 한 줄 + 가는 큰 숫자 + 얇은 막대로.
- 마켓 상품: 계열 · 등급 → 모델 이름 → 신발, 시세는 판매가 | 구매가 | 최근가 한 줄. 사기 · 팔기 · 매물 · 입찰은 그대로.
- 공통: 선택 칩(PillChip)을 S2 모양으로 — 고른 칩은 흰 알약에 짙은 글자. `S2ShoeStage`를 공통 부품으로 옮김.
