# StepUp S2 전체 앱 리디자인 기획서 v1

작성일: 2026-09-26 · 상태: 검토용 기획안 · 앱 구현 및 배포 전

## 1. 목표와 이번 범위

오늘의 활동을 확인하고 러닝을 시작하는 경험을 중심으로, StepUp Android 앱 전체를 Figma **S2 무대** 디자인에 최대한 가깝게 바꾼다. 어두운 배경, 중앙에 집중된 정보, 아치형 풍경, 큰 기록 숫자, 흰 원형 행동 버튼, 얇은 파란 강조선을 일관되게 적용한다.

대상은 일반 러너와 가볍게 걷기부터 시작하는 사용자다. 처음부터 지갑이나 블록체인을 이해해야 운동할 수 있는 흐름을 만들지 않는다. 핵심 흐름은 **오늘의 활동 → 러닝 시작 → 기록 저장 → 보상 상태 확인 → 신발·함께 뛰기**다.

사용자가 확정한 내용은 ① S2에 최대한 동일하게 적용 ② 기존 앱과 시안의 기능 차이를 정리 ③ 현재 확보한 이미지로 진행이다. 나머지 기능 배치와 미정 요소 처리 방식은 아래의 제안이다. 이 문서 작성으로 앱 변경·빌드·배포를 시작하지 않는다.

## 2. 확인한 기준과 자료의 한계

- 현행 앱 기준: 현재 작업장의 `eb697e5` 커밋. 작업 시작 시 미커밋 변경 없음. 원래 이전 main 작업장의 문서는 이전 캐릭터 방향이 섞여 있어 최신 작업장과 인계서를 우선했다.
- 현재 소스의 화면 이동 경로 34개, 화면 함수 35개, 팝업 선언 19개 목록을 확인했다. 시작·로그인·안내와 같은 별도 흐름, 한 경로 안의 여러 상태는 이 숫자와 별개다.
- S2 메타데이터에는 390×844 프레임 45개가 있다. `04 kit`는 앱 페이지가 아니라 공통 부품 참고이며, 뒤의 풍경 5장은 홈의 변형이다. 45개 모두를 독립 메뉴로 만들지 않는다.
- Figma 전체 보드, 첨부된 확대 화면, 추출한 이미지와 노드 목록을 기준으로 기획했다. 모든 화면의 세부 문구·폰트·색상·도형 좌표를 원본 수준으로 확보한 것은 아니다. 정확한 디자인 수치가 확인되지 않은 부분은 구현 전 대표 화면 비교로 조정한다.
- 확보 자산: 원본 17종, 투명 여백 정리 8종, 개별 이미지 레이어 렌더 13종. 이들은 서로 다른 38종의 그림이 아니라 원본과 파생본이 중복된 수치다.
- 미확보 합성 자산: 뽑기 상자, SUP 도트 코인, 시작 카드, 아치 배경 완성본. 사용자 지시에 따라 추가 추출은 이번 진행의 선행 조건으로 두지 않는다.
- 이번 조사는 화면/소스 수준이다. GPS·서버·계정·마켓·지갑의 실제 운영 성공을 새로 검증한 것은 아니다.

## 3. 화면 구조

하단 메뉴는 S2의 **러닝 / 신발 / 같이 뛰기 / 내 정보** 네 칸으로 맞추는 안을 제안한다. 현재 가운데 있는 뽑기 진입은 **신발 → 새 신발 뽑기**로 옮겨 한 번에 들어가도록 한다. 뽑기 자체를 삭제하지 않는다.

| 메인 메뉴 | 가장 먼저 보이는 내용 | 안쪽에 유지할 기능 |
|---|---|---|
| 러닝 | 오늘 활동 요약, 목표, 풍경, 러닝 시작/재개 | 코스 선택·만들기·게시판, 최근 활동 상세, 챌린지, 소식 |
| 신발 | 실제 착용 신발, 이름·등급·레벨, 보유 수, 신발 바꾸기 | 보관함, 상세·강화·판매, 마켓·거래, 도감, 뽑기 |
| 같이 뛰기 | 가까운 번개, 내 크루, 지난 모임 | 모임 지도·상세·참여·대기실, 크루 만들기, 글·댓글·신고, 랭킹, 영역 지도 |
| 내 정보 | 내 이름, 활동 요약, 잔액과 보상 상태 | 기록·통계·기록 지도, 지갑, 챌린지·업적, 알림, 프로필 수정, 설정 |

일반 상세 화면에서는 부모 메뉴를 유지한다. 로그인·첫 안내·권한 설명·작성 폼·카운트다운·러닝 집중 화면에서는 하단 메뉴를 숨긴다. 실제 러닝이 진행 중이면 홈의 주 버튼을 `러닝 재개`로 바꾸고 중복 세션을 만들지 않는다. 뒤로 가기로 진행 중 기록을 버리지 않는다.

## 4. 시각 및 공통 부품

### S2에서 그대로 가져갈 것

- 검정에 가까운 남색 바탕, 흰 주요 글자, 차분한 보조 글자, 파란 강조.
- 큰 숫자와 짧은 제목 중심의 중앙 정렬. 정보를 사각 카드 여러 개에 나누던 기존 구성을 줄인다.
- 아치 안에 들어가는 풍경과 얇은 파란 선, 신발의 큰 단독 이미지.
- 흰 원형 주 버튼 + 아래 행동 이름. 탭 선택은 밝은 아이콘·글자와 짧은 파란 선으로 표시한다.
- 핵심 화면에 한 개의 주 행동. 나머지는 간결한 보조 링크나 상세 진입으로 둔다.

### 실제 Android 사용을 위해 보완할 것

- 시안의 가짜 상태바·홈 인디케이터는 이미지로 넣지 않는다. 실제 Android 시스템 영역을 사용한다.
- 아이콘 그림이 작아도 터치 영역은 최소 48dp. 원형 버튼의 아이콘과 설명은 같은 행동에 연결한다.
- 본문·버튼 문구는 읽을 수 있는 크기를 유지하고, 큰 글씨 설정에서는 본문이 늘어나거나 스크롤되게 한다. 시안 크기에 맞추려고 글자를 강제로 축소하지 않는다.
- 화면 높이가 작으면 장식 풍경·지도 높이를 먼저 줄인다. 주 행동과 기록 숫자는 가리지 않는다.
- 숫자·상태·버튼·탭·차트는 실제 UI로 만든다. 화면 전체를 한 장의 이미지로 붙이지 않는다.
- 공통 헤더, 원형 행동 버튼, 뒤로 가기, 탭, 상태 배지, 폼, 팝업을 한 벌로 관리한다. 화면마다 크기와 모양이 달라지지 않게 한다.
- 기존 언어·테마 설정과 소리/진동/모션 선택을 유지한다. 기본 시각 검토는 S2 다크 테마로 하고 밝은 테마는 동일한 정보 구조에서 가독성을 별도로 확인한다.

## 5. 주요 이용 흐름

### 시작과 첫 사용

앱 준비 → 짧은 로고 전환 → 로그인 여부 확인 → 처음이면 S2 소개 → 홈 순서다. 기존 사용자의 로그인·안내 완료 상태는 유지하고 앱을 업데이트했다고 다시 가입시키지 않는다.

소개에는 실제 제공하는 러닝 기록·신발·같이 뛰기를 설명한다. 신체 정보·목표 체중·새 모드 선택은 시안에 있지만 정책이 정해지지 않아 첫 진입 필수 단계로 넣지 않는 안을 제안한다. 활동 목표는 이미 있는 일일 걸음 목표를 재사용할 수 있다. 코스 선택은 건너뛰고 자유 러닝을 시작할 수 있다.

### 홈과 러닝

홈은 오늘 걸음/목표 → 아치 풍경 → 오늘 보상 상태 → 시작 버튼 순서로 정리한다. 최근 7일 상세·거리·운동 시간은 활동 상세로 옮겨 찾을 수 있게 한다. 풍경은 장식이며 현재 위치나 실제 날씨라고 오인할 문구를 붙이지 않는다.

시작을 누르면 필요한 권한을 확인하고, GPS 준비 상태를 보여준 뒤 카운트다운한다. 거절 상태에는 다시 요청 또는 설정으로 이동하는 행동을 제공한다. 위치가 충분하지 않으면 정확한 측정이 시작된 것처럼 표시하지 않는다.

러닝 중에는 시간, 거리, 페이스, 실제 경로, 일시정지를 우선한다. 일시정지 후에는 재개와 종료가 분명하게 구분된다. 시안의 길게 눌러 종료는 보조 입력 방식으로 두고, 접근 가능한 종료 버튼과 확인창도 제공한다. 종료 확인을 취소하면 일시정지 화면으로 돌아간다.

결과는 먼저 기록 저장 상태를 보여주고, 서버 보상은 `확인 중 / 확정 / 실패`로 분리한다. 실패해도 저장된 운동 기록은 남는다. 재시도 버튼이 같은 기록이나 보상을 중복 생성하지 않도록 기존 정산 흐름을 유지한다. 결과에서 기록 보기·코스 저장·공유로 이어진다.

### 신발과 거래

착용 중인 신발과 둘러보는 신발을 구분한다. 스와이프로 이미지를 바꿨다고 착용이 바뀌지 않는다. `신발 바꾸기 → 선택 → 착용` 후 실제 저장이 성공하면 착용 표시를 갱신한다.

상세에는 현재 모델이 실제로 제공하는 능력치만 노출한다. 시안의 효율·행운·편안·내구 네 항목을 이유 없이 새 능력치로 추가하지 않는다. 기존 강화·판매·도감은 유지한다.

마켓은 내 보유품과 판매 중 상품을 구분하고 상세에서 가격·수량·거래 상태를 확인한다. 구매/판매 확인창에는 실제 조건을 보여준다. 처리 중 중복 입력을 막고, 성공 응답 후에만 잔액·보유 목록을 바꾼다. 연결 미완료 상태에서는 구매 성공이나 가짜 상품 재고를 보여주지 않는다.

뽑기는 기존 준비 상태와 실제 결과를 사용한다. 준비 전에는 이유와 가능한 다음 행동을 설명한다. `10 SUP`, `하루 3회`, `70/24/5/1%` 같은 시안 수치는 서비스 정책 확인 전 실제 값으로 적용하지 않는다.

### 같이 뛰기

번개러닝은 한 번의 모임이고 크루는 지속되는 그룹이다. 시안의 `crew` 이름을 그대로 데이터 개념으로 해석하지 않고 기존 모임·크루 구분에 연결한다.

목록/지도 → 모임 상세 → 참가 신청 → 참여 확정/대기실 → 러닝 흐름으로 정리한다. 시간·장소·거리·참가 조건·참여 상태가 먼저 보인다. 모임 만들기는 기존 작성 기능의 정보 범위를 유지한다. 서버에서 목록을 못 받았을 때와 실제 주변 모임이 없을 때를 다르게 안내한다.

시안의 함께 달리는 지도에 여러 사람이 보인다는 이유로 실시간 위치 공유를 새로 켜지 않는다. 우선 내 러닝과 모임 참여 상태를 보여주고, 다른 사람의 실시간 위치는 기존 제공 여부·동의·서버 지원이 확인될 때 별도 기획한다.

### 내 정보와 설정

활동 요약과 주요 진입을 간결하게 보여준다. 기록·통계·주간/월간 추이·기록 지도·챌린지·업적을 보존한다. S2의 체중 수치 자리는 데이터와 목적이 확정되기 전 기존 운동 시간 등 실제 활동 정보로 구성하는 안을 제안한다.

지갑의 확정 잔액과 확인 중 보상을 분리한다. 외부 지갑 연결 버튼은 실제 연결 상태를 따른다. 알림은 읽음 상태와 대상 화면 이동을 유지한다. 설정은 알림, 개인정보, 연결 계정, 언어, 테마, 소리/진동/모션, 도움말로 이어지고 기존 값을 보존한다.

## 12. 완료 기준

- 기본 다크 화면이 S2의 정보 순서·중앙 구도·풍경 비율·버튼·탭을 따른다. 원본 미확보로 다른 부분은 명시한다.
- 45개 프레임이 구현 화면/기존 상태/변형/부품/보류 항목 중 하나에 대응하며 미분류가 없다.
- 기존 34개 이동 경로의 기능이 유지되고, 새 메뉴에서 실제로 도달할 수 있다. 팝업·시작 흐름·복구 상태를 별도로 확인한다.
- 실제 소유 신발·기록·계정·설정이 보존된다. 예시 잔액·확률·보상·다른 사람 위치를 사실처럼 노출하지 않는다.
- 대표 화면은 Android 실제 캡처로 비교한다. 작은/일반 화면 폭, 큰 글씨, 하단 시스템 영역, 키보드, 뒤로 가기를 확인한다. 밝은 테마·언어는 영향받는 공통 부품과 긴 문구를 중심으로 확인한다.
- 러닝 시작→일시정지→재개→종료→저장/재시도와 신발 착용·주요 화면 이동을 확인한다. 서버/GPS/지갑 운영 검증은 화면 검토와 구분해 보고한다.
- 앱 소스 변경 시 기존 디자인 규칙 검사·문자열/자산 검사·변경에 맞는 동작 검사를 수행하고, 빌드와 캡처의 소스를 일치시킨다. 기획 작성 단계에서는 빌드나 테스트를 실행하지 않는다.

## 13. 검토할 핵심 제안

이 기획의 기본안은 **네 칸 메뉴, 신발 안으로 이동한 뽑기, 기존 기능의 하위 화면 보존, 미정 신기능의 보류, 기존 상자/텍스트 코인을 사용한 우선 구현**이다. S2의 외형을 맞추는 작업과 새로운 서비스 정책을 만드는 작업을 구분했다.

후속 구현 시작 시 사용자 수정 의견을 반영해 이 안을 확정한다. 그 전까지 기존 PRODUCT/DESIGN 계약과 앱 코드는 변경하지 않는다.
