# StepUp AI 코칭 구현 지시서

이 패키지는 독립된 코칭 탭의 화면, 동작, 데이터 경계와 검수 기준을 정의한다. 코칭을 러닝 종료 팝업이나 결과 화면의 긴 설명으로 만들지 않는다. 오늘 할 훈련, 지난 러닝 분석, 주간 변화를 연결한다.

현재 요청의 산출물은 이미지와 인계 문서다. 이 패키지만으로 운영 배포, 외부 AI 유료 호출, 개인정보 전송, 커밋·푸시를 승인한 것으로 해석하지 않는다. 실제 구현 요청을 받은 세션에서 아래 순서로 진행한다.

## 1 우선순위와 변경 금지

- 사용자의 최신 지시가 오래된 S2 미술 방향보다 우선한다. 원래의 남색·파란색 톤, 큰 핵심 정보, 짧은 문구, 얇은 파란 세로선 코칭 표현을 사용한다.
- 승인된 러닝 중 화면은 다시 디자인하지 않는다. 실시간 안내는 규칙 기반이며 AI 요청을 보내지 않는다.
- 코칭은 별도 영역이다. 상위 메뉴에서 어디에 진입점을 둘지는 현재 앱 경로와 사용자 결정을 확인한다. 그림의 하단 메뉴 선택 표시만 보고 메뉴를 삭제하거나 여섯 번째 전역 메뉴를 추가하지 않는다.
- 그림은 기존 5개 하단 항목을 보존한 제안이다. 실제 공유 상단바·하단바·경로 선택 정책을 재사용하며 화면별 복제본을 만들지 않는다.
- 러닝 저장, 계정 정체성, 보상 계산, 기존 신발 관련 미완료 변경을 보존한다. AI 실패가 러닝 저장이나 정산 실패가 되어서는 안 된다.
- 코칭 화면과 AI 입력·출력에는 SUP, 보상, 등급 경쟁, 다른 크루원의 개인 페이스를 넣지 않는다.
- 16장은 새로운 기능의 시안이다. 예시 기록, 동의 상태, 계획, 완료 체크를 실제 계정 상태로 하드코딩하지 않는다.
- 이미지의 글자·그래프·버튼을 통째로 배경에 굽지 않는다. Compose 등 기존 네이티브 구성요소로 구현하고 래스터 이미지는 참고로만 쓴다.

## 2 코칭 탭의 구조

| 영역 | 사용자 질문 | 화면과 연결 |
|---|---|---|
| 오늘 | 오늘 무엇을 하면 되나 | 01 코칭 홈 → 02 훈련 상세 |
| 분석 | 지난 러닝에서 무엇이 달라졌나 | 기록 선택 → 03 분석 → 16 목표 페이스 확인 |
| 변화 | 꾸준히 하고 있나 | 04 주간 변화 → 13 다음 주 계획 검토 |
| 시작과 설정 | 무엇을 보내고 어떻게 제어하나 | 05 동의 → 06 목표 설정, 14 설정 → 15 해제 확인 |

러닝이 끝난 뒤에는 로컬 저장을 먼저 완료하고 결과 화면을 즉시 보여준다. 코칭 진입은 저장된 기록과 연결하며, 서버 확인과 분석은 별도 상태로 진행한다. 종료 확인·저장 진행 중 화면에 AI 분석을 끼워 넣지 않는다. 결과에서 코칭으로 이동한 경우에도 기존 결과 화면으로 정상 복귀해야 한다.

화면 13의 주간 계획과 화면 16의 목표 페이스는 제안이다. 사용자가 적용하기 전에는 현재 목표나 일정이 바뀌지 않는다. 적용은 러닝 시작이 아니다.

## 3 AI가 맡는 범위

| 기능 | 담당 | AI 호출 |
|---|---|---|
| 거리·시간·속도·평균 페이스·구간·주간 합계·그래프 | 검증된 기록과 계산 코드 | 없음 |
| 러닝 중 음성·진동·GPS 안내·목표 페이스 알림 | 기기 규칙 엔진 | 없음 |
| 날짜·목표 설정·추천 적용·동의·토글·오류 문구 | 앱과 서버 정책 | 없음 |
| 러닝 해석 | 서버가 제공한 사실 중 중요한 사실 선택과 짧은 설명 | 기록별 결과를 재사용 |
| 다음 훈련 추천 | 코드가 만든 허용 후보 중 선택과 추천 이유 | 승인된 입력이 바뀔 때만 |
| 주간 요약과 다음 주 제안 | 코드 집계·허용 계획 후보 + AI의 요약·이유 | 주차별 결과를 재사용 |
| 반복되는 일반 안내·기록 부족·제한·실패 | 고정 번역 문구 | 없음 |

훈련의 시간, 순서, 강도, 목표 페이스를 LLM이 자유롭게 발명하게 하지 않는다. 운영자가 검토한 템플릿과 계산 규칙에서 허용 후보를 만든 뒤 AI가 그중 하나를 고르고 이유를 설명한다. 5분 걷기 + 15분 달리기 + 5분 걷기는 예시이며 모든 사용자에게 자동 적용하는 처방이 아니다.

최초 버전에 AI 채팅, 상시 대화 기억, 실시간 LLM 음성 코치, 의료 평가, 심박·회복 점수, 부상 예측을 추가하지 않는다.

상태 화면은 독립적인 새 전역 경로를 16개 만드는 요구가 아니다. 공유 상태 컴포넌트와 화면 모델로 재사용한다. 실제 문구·구성은 이 문서와 상태표가 이미지의 우연한 철자·간격보다 우선한다.

### 오늘과 훈련

- 주간 체크는 저장된 실제 활동에서 계산한다. 미래의 계획을 완료 체크로 표시하지 않는다.
- 25분 도식은 5:15:5 시간 비율이다. 단계별 합계와 전체 시간이 맞아야 한다.
- 설명은 편집 가능한 자원 문자열로 관리한다. 선택 근거는 1개, 행동은 1개만 먼저 보여준다.
- 목표를 바꿔도 기존 러닝이나 현재 진행 중인 훈련을 소급 변경하지 않는다.
- 추천이 없으면 검증된 일반 템플릿을 '기본 훈련'으로 보여줄 수 있다. 이를 AI 맞춤 추천이라고 부르지 않는다.

### 분석

- 한 기록의 거리·시간·평균 페이스와 완료한 구간을 먼저 보여준다. AI 문장보다 숫자가 먼저 준비되어야 한다.
- 평균 페이스는 전체 유효 시간 ÷ 전체 유효 거리다. 구간 페이스의 단순 평균으로 대체하지 않는다.
- 페이스는 초/km이며 작은 값이 빠르다. 7분에서 8분으로 내려가는 그래프는 느려지는 방향이다.
- 마지막 0.24km를 1km 구간처럼 비교하지 않는다. 부분 구간은 별도 표기하거나 구간 비교에서 제외한다.
- 3km 구간이 1km 구간보다 40초 느리다는 관측은 '피로·부상·체력 저하'의 확정 근거가 아니다.
- 비교 대상이 없으면 2주 평균이나 향상률을 생성하지 않는다. 일부 사실만 유효하면 유효한 사실만 표시한다.

### 주간 변화

- 사용자 시간대 기준 월요일 시작, 종료 시각 미포함의 주 범위를 사용한다. 서버와 앱 기준을 일치시킨다.
- 완료한 주와 진행 중인 주를 구분한다. 미래 날짜는 0회 실적으로 오인시키지 않는다.
- 단순히 거리가 늘었다고 건강이 좋아졌거나 더 뛰어야 한다고 말하지 않는다.
- 계정·시간대·기록 삭제·입력 정정에 따라 집계와 연결된 분석 버전을 무효화한다.
- 다음 주 계획은 현재 선호와 허용 템플릿을 기반으로 제안하고 화면 13에서 확정한다.

## 5 데이터와 현재 코드의 연결

먼저 저장소의 AGENTS.md와 최신 인계 문서, 실제 현재 브랜치를 읽는다. 다음 경로는 확인한 연결 지점이며 구현 완료 선언이 아니다.

| 경로 | 확인할 내용 |
|---|---|
| app/src/main/java/com/stepup/android/ui/StepUpRoot.kt | 기존 경로·공유 chrome·코칭 진입 위치 |
| app/src/main/java/com/stepup/android/service/WalkSessionService.kt | 활성 시간, 일시정지, RunLap, 저장 완료 이벤트 |
| app/src/main/java/com/stepup/android/data/local/Entities.kt | WalkSessionEntity와 업로드 상태 |
| app/src/main/java/com/stepup/android/domain/RunTrack.kt | 좌표·epoch 밀리초 시각의 직렬화 |
| app/src/main/java/com/stepup/android/domain/RunRecords.kt | 시간대·주간 집계·가중 평균 페이스 |
| app/src/main/java/com/stepup/android/data/repo/RunRecordsRepository.kt | 계정별 로컬 기록과 삭제 계약 |
| app/src/main/java/com/stepup/android/data/repo/RunSettlementRepository.kt | 저장·정산 트랜잭션 경계 |
| app/src/main/java/com/stepup/android/data/repo/ServerSessionRecorder.kt | 서버 기록 전송과 계정 소유권 |
| app/src/main/java/com/stepup/android/data/remote/StepUpServer.kt | record_session 응답의 sessionId |
| supabase/migrations/ 및 supabase/functions/ | 서버 검증·RLS·새 분석 작업의 배치 위치 |

중요한 선행 조건은 다음과 같다.

1. 로컬 WalkSessionEntity.id와 서버 SessionRecorded.sessionId는 별개다. 로컬 id를 그대로 분석 서버에 보내지 않는다. 계정 소유권을 유지한 매핑 저장 또는 검증된 서버 조회 경로를 먼저 설계한다.
2. 현재 WalkSessionEntity에는 명시적인 영구 laps 필드가 없다. 서비스에 RunLap이 있다고 종료 후에도 구간 정보가 안전하게 남는다고 가정하지 않는다.
3. RunTrack의 시각은 epoch 밀리초다. 위치 간 벽시계 시간만으로 구간을 만들면 일시정지 시간이 섞일 수 있다. 활성 시간·일시정지 구간·보간 규칙을 확인하고 부족하면 정확한 구간 코칭을 생략한다.
4. 과거 legacy/guest 기록을 현재 로그인 사용자에게 자동 귀속시키지 않는다. 로컬에서 보이는 것과 외부 AI 전송 권한은 다르다.
5. RunRecordsRepository의 현재 삭제는 로컬 기록 삭제 계약이다. 이를 서버 기록·AI 분석·공급자 보관 데이터까지 모두 삭제된 것으로 표현하지 않는다.
6. 서버의 CLEAN/FLAGGED/VOID와 보상 판정은 기존 도메인이다. AI 추가를 이유로 그 판정이나 보상 금액을 바꾸지 않는다. 분석 가능 여부는 별도의 명시적인 품질 규칙으로 계산한다.

## 6 서버 처리 흐름

1. 앱은 기록을 로컬에 저장하고 기존 결과 흐름을 완료한다.
2. 업로드와 서버 확인을 별도 진행한다. 확인 전에는 '서버 확인 대기'이며 'AI 분석 중'으로 꾸미지 않는다.
3. 인증된 요청에서 서버 기록 ID, 지원 locale, 분석 종류만 받는다. 사용자 ID, 계산된 보상, 클라이언트의 임의 숫자를 분석의 진실로 믿지 않는다.
4. 서버가 토큰의 사용자를 확인하고 해당 기록 소유권, 최신 동의, 데이터 품질, 중복 작업, 한도를 검사한다.
5. 서버 저장 기록으로 특징값과 근거 목록을 만든다. 외부 전송용 DTO에는 원본 좌표·이름·연락처·크루원 식별자·정확한 시작 장소·사용자 원문 메모가 없어야 한다.
6. 영속적인 작업을 큐에 넣고 job ID와 상태를 반환한다. 화면을 닫아도 작업은 유지된다. 서버 함수의 떠 있는 Promise 하나를 영속 큐 대신 사용하지 않는다.
7. 워커는 전송 직전에 동의·소유권·예산을 다시 확인하고 공급자를 호출한다.
8. 구조화 응답의 형식, 근거 ID, 허용 추천 ID, 문구 정책을 검증한 뒤 결과를 저장한다.
9. 앱은 상태를 구독하거나 제한된 간격으로 확인하여 코칭 영역만 채운다. 화면 재진입은 저장 결과를 읽으며 매번 새로 생성하지 않는다.
10. 계획·목표 적용은 별도의 사용자 확인 명령이다. AI 생성 완료가 적용 승인 이벤트가 아니다.

기록별 분석, 주간 분석, 추천은 서로 다른 job kind로 구분한다. 새 DB·함수 이름은 기존 코드와 충돌하지 않게 결정하되 예시 이름 run_insights, coaching_jobs, coaching_preferences, coaching_consents를 기존에 이미 있는 표처럼 취급하지 않는다.

### 소유권과 중복 방지

- 기본 키와 캐시 키에 owner, source ID, kind, locale, feature fingerprint, 정책·프롬프트 버전을 포함한다. 계획은 선호 revision도 포함한다.
- 앱에서 버전이나 모델을 임의 변경하여 계속 새 분석을 만들 수 없게 서버가 키를 정한다.
- 고유 제약, 원자적 작업 생성, 워커 lease와 만료 복구, 최대 재시도를 둔다.
- 네트워크가 끊긴 공급자 호출은 이미 과금됐을 수 있다. '절대 한 번만 호출·과금'이라고 보장하지 말고, 중복 결과 생성 억제와 제한된 재시도로 관리한다.
- 인증 사용자는 자기 결과만 읽고 생성 상태·원본 근거·소유자를 임의 수정하지 못한다. 서비스 권한을 쓰는 함수도 JWT와 소유권을 먼저 확인한다.
- 로그아웃·계정 전환 시 화면과 로컬 캐시를 계정별로 격리한다. 진행 중 이전 계정 요청의 응답을 새 계정 화면에 붙이지 않는다.

## 7 AI 출력 계약

숫자와 그래프는 코드가 만든다. AI는 중요한 근거를 선택하고 짧게 해석하며 허용 후보 중 다음 행동을 선택한다.

권장 출력 필드:

| 필드 | 역할과 제한 |
|---|---|
| schema_version | 서버가 정한 버전 |
| kind | run 또는 weekly 또는 recommendation |
| observation_fact_id | 서버가 제공한 근거 ID 중 하나 |
| explanation | 짧은 해석, 새로운 숫자·원인 단정·진단 금지 |
| next_action_candidate_id | 허용된 훈련·페이스 후보 중 하나 또는 null |
| action_reason | 왜 그 행동을 제안하는지 1문장 |
| limitation_code | 부족한 기록·비교 불가 등을 정의된 enum으로 |

화면의 '3km 구간이 첫 구간보다 40초 느렸어요' 같은 수치 문장은 선택된 fact ID를 서버/앱 템플릿으로 렌더링한다. 모델이 반환한 숫자로 원본 기록을 덮어쓰지 않는다. 추천의 시간·목표 페이스·요일도 candidate ID가 가리키는 검증된 값에서 렌더링한다.

현재 공급자가 지원하는 구조화 출력 형식을 확인해 JSON Schema로 응답을 제한한다. 형식 일치는 사실 일치와 다르므로 ID allowlist, 수치 연결, 문자열 길이, locale, 금지된 건강·보상·비교 문구를 별도로 검증한다. SDK가 일부 길이·범위 제약을 전송에서 제거할 수 있으므로 서버 검증을 생략하지 않는다. [공식 구조화 출력 문서](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)

모델에 도구 실행 권한, 데이터베이스 쓰기 권한, 외부 웹 검색, 임의 URL 열기를 주지 않는다. 입력의 사용자 메모·코스 이름을 지시문으로 해석하지 않는다. 최초 버전은 숫자 요약과 제한된 enum 선호만 보내며 자유 입력은 제외한다.

거절 응답, 출력 중단, 잘못된 JSON, 모르는 fact/candidate ID, 근거 없는 원인 주장, 잘못된 언어는 성공으로 표시하지 않는다. 안전한 고정 안내와 기본 기록으로 돌아가고 제한된 재시도 정책을 적용한다.

## 9 동의와 개인정보

화면 05의 문구는 구현용 동의 초안이다. 실제 공급자·계약·처리 목적·항목·기간·국외 이전 등 적용 요건을 검토하여 최종 문구와 처리방침을 맞춘 뒤 활성화한다. 'Anthropic' 표기는 현재 계획을 반영하며 공급자가 달라지면 문구도 바꾼다.

- 동의는 기본 미선택이며 기능 설명을 읽고 명시적으로 선택할 수 있어야 한다. 나중에를 선택해도 일반 러닝을 막지 않는다.
- 동의 버전·시각·scope를 서버에 남긴다. 기능 이용 동의와 자동 분석 토글은 분리한다.
- 자동 분석과 주간 리포트 토글은 시안에서 기본 꺼짐이다. 자동화 정책이 확정되기 전에는 임의로 켜지 않는다.
- 주간 리포트 생성 동의는 푸시 알림 권한이 아니다. 알림은 기존 별도 권한과 설정을 따른다.
- AI 사용 해제는 신규 분석을 막고 진행/대기 작업을 취소한다. 이미 외부로 전달된 요청을 없던 일로 만들 수 있다고 약속하지 않는다.
- 화면 15의 '저장된 AI 분석도 삭제'는 별도 미선택 항목이다. 확정 뒤 요청 처리와 실제 삭제 결과를 구분하고, 원본 러닝은 삭제하지 않는다.
- 데이터 처리와 삭제 계약은 StepUp 보관분, 캐시, 작업·로그, 외부 공급자 보관분을 구분한다. 외부 데이터의 즉시 삭제나 미보관을 보장하지 않는다.
- 사용자 이름을 보내지 않는다고 완전 익명이라고 주장하지 않는다. 계정에 연결되는 러닝 요약도 적절하게 보호한다.

공급자 보관 기간은 사용 계약과 기능·모델의 예외에 따라 달라질 수 있다. 일반 수치를 앱 문구에 영구 하드코딩하지 말고 실제 적용 조건을 확인한다. [Anthropic 조직 데이터 보관 안내](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)

## 10 비용과 지연

- API 키는 서버 비밀로만 보관한다. APK·웹 클라이언트·로그·이미지·문서에 넣지 않는다.
- 모델 ID, 가격표, 일일 횟수, 월 예산, 최소 유효 거리·표본 수는 운영 설정으로 분리하고 확정 전에는 실제 AI를 켜지 않는다.
- 과거 대화의 모델명·회당 1원·몇 초 완료를 확정 사양으로 복사하지 않는다. 실제 모델 가용성·가격·실측 지연을 확인한다.
- 비용은 입력·출력·캐시 토큰과 실제 재시도까지 기록한다. 사용자 성공 횟수와 공급자 원가는 별도로 센다.
- 공급자 호출 전 예산을 원자적으로 예약하고 결과로 정산한다. 사용자 제한뿐 아니라 프로젝트 월 상한과 긴급 중지 장치를 둔다.
- 한도는 서버가 판단하고 필요하면 reset_at/retry_after를 내려준다. 미정이면 화면 12처럼 날짜·횟수·유료 업그레이드를 발명하지 않는다.
- 기록 부족·부적합·미동의는 공급자를 부르지 않는다. 기본 훈련과 분석 그래프는 AI를 기다리지 않는다.
- 앱 진입 때마다 홈·분석·주간에서 동시에 같은 모델을 부르지 않는다. 재사용 가능한 분석에서 홈 요약을 파생한다.
- 주간 작업은 시간대·주 범위·동의·기록 revision을 명시한다. 묶음 처리 여부는 지연 허용 범위와 현재 공급자 조건을 확인해 결정한다.

## 11 디자인 구현 기준

- 코칭 홈의 추천 영역만 큰 주요 면으로 사용한다. 모든 줄을 카드로 감싸거나 파란 테두리를 반복하지 않는다.
- 안내 문구는 작은 라벨 + 하나의 핵심 문장 + 필요할 때 한 줄 근거다. 상세 설명은 별도 화면으로 옮긴다.
- 주행 화면처럼 모든 것을 한 화면에 강제 압축하지 않는다. 코칭은 여러 페이지와 자연스러운 스크롤을 허용한다.
- 그래프는 네이티브 데이터로 그린다. 축·단위·영점·미래 날짜·빠름/느림 방향·부분 구간을 테스트한다.
- 인원 순위, 실패 낙인, 과도한 경쟁·게임 연출을 사용하지 않는다.
- 색상만으로 상태를 구분하지 않는다. 선택 체크·아이콘·텍스트를 함께 사용한다.
- 최소 터치 영역 48dp를 확보하고 시스템 글자 확대, 작은 기기, 긴 번역, 스크린 리더 순서를 확인한다.
- 한국어·영어·일본어·중국어 UI 자원을 분리한다. 서버 코칭도 지원 locale별 캐시를 분리한다. 한국어 시안 길이 때문에 다른 언어가 잘리지 않게 높이를 유연하게 둔다.
- 모달은 취소·뒤로가기·시트 닫기 동작이 일관되어야 한다. 적용 버튼 연타를 중복 처리하지 않는다.
- 모달이 열리면 하단 메뉴를 포함한 배경은 비활성이다. 접근성 포커스도 모달 안에 제한하고 닫은 뒤 원래 위치로 돌린다.
- 선호·계획·목표를 저장 중이면 중복 적용을 막는다. 실패하면 기존 설정을 유지하고 명확한 재시도를 제공한다. 화면 06의 시작 문구는 코칭 선호 저장을 뜻하며 러닝을 자동 시작하지 않는다.
- 두 장의 예전 결과·분석 화면을 되살리지 않는다. 이번 패키지의 독립 코칭 구조를 기준으로 한다.

## 12 구현 순서

1. 경로·데이터 감사: 최신 규칙, 관련 미완료 변경, 서버 ID 매핑, laps/활성 시간 보존, 계정 범위를 확인한다. 막힌 부분만 구체적으로 보고한다.
2. 기본 계산과 품질 판정: AI 없이 구간·주간 집계·fixture 테스트를 만든다. 레거시 데이터의 한계를 처리한다.
3. 화면과 상태: 먼저 mock 상태로 01–16 화면과 전환을 구현한다. 현재 승인된 러닝 화면을 바꾸지 않는다.
4. 동의·선호·권한: 서버와 앱의 동의·취소·계정 격리를 연결한다.
5. 서버 큐와 캐시: 모의 공급자로 idempotency, 한도, 실패·취소·삭제를 검증한다.
6. 실제 공급자 연결: 모델·예산·처리 정책이 정해진 뒤 제한된 내부 데이터로 평가한다.
7. 추천 적용과 주간 작업: 사용자 확인, 계획 revision 충돌, 시간대, 푸시 분리를 검증한다.
8. 앱 캡처와 운영 준비: 같은 수정본에서 실제 화면을 캡처하고 시안 대비 확인한다. 배포는 별도 승인 범위에 따른다.

### 상태와 보안

- 미동의·게스트·다른 계정·소유권 불명 레거시 기록은 외부 호출하지 않는다.
- 네트워크 재시도·앱 재진입·빠른 연타·동시 기기에서 중복 job과 사용자 한도 차감이 중복되지 않는지 확인한다.
- 동의 철회 직전/직후의 queued·running job, 삭제된 원본, 로그아웃 후 도착 응답을 테스트한다.
- 공급자 429/5xx, timeout, 중단 응답, JSON 오류, 허용되지 않은 ID, 언어 오류를 검증한다.
- 원본 GPS·이름·토큰·민감한 원문이 외부 요청·일반 로그에 포함되지 않는지 테스트한다.
- 무효·미지원 데이터 때문에 러닝 저장·정산이 되돌려지지 않는지 확인한다.
- 목표 페이스 적용과 계획 적용이 자동 시작·현재 러닝 변경을 일으키지 않는지 확인한다.

### 시각과 전달

- 16개 상태를 실제 기기/에뮬레이터에서 캡처하고 번호와 연결한다.
- 데이터가 없거나 실패할 때 가짜 AI 문구·그래프·완료 체크가 남지 않는지 확인한다.
- 공유 하단바·상단바를 화면마다 새로 만들지 않았는지 확인한다.
- 검증한 결과와 아직 남은 정책·데이터 제약을 분리해서 보고한다. 이미지 제작을 기능 구현 완료로 보고하지 않는다.

## 14 활성화 전 결정할 항목

| 항목 | 현재 경계 |
