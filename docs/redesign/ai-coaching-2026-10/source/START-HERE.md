# Claude에게 전달할 시작 지시

이 폴더 전체를 Claude가 접근할 수 있게 전달하고, 아래 요청과 함께 시작하세요. 시안 이미지만 보내지 말고 지시서와 화면 목록도 함께 전달하세요.

## 전달 요청

StepUp에 독립된 AI 코칭 영역을 구현해 주세요. 먼저 `CLAUDE-HANDOFF.md`, `SCREEN-INDEX.md`, 현재 저장소의 `AGENTS.md`와 최신 인계 문서를 읽고, 실제 코드·데이터 구조를 확인하세요.

디자인은 `images/`의 최종 시안 16장을 기준으로 합니다. 오늘의 훈련, 완료한 러닝의 분석, 주간 변화가 연결되는 구조입니다. 러닝 종료 확인창이 아닙니다. 승인된 러닝 중 화면과 기존 공유 상단바·하단바는 다시 디자인하지 마세요. 코칭 진입 위치는 기존 경로를 확인하고, 전역 메뉴를 임의로 삭제하거나 추가하지 마세요.

원래의 남색·선명한 파란색 톤, 큰 숫자와 짧은 문장, 얇은 파란 세로선 코칭 표현을 유지하세요. 모든 정보를 둥근 카드에 넣지 마세요. 스크린샷을 앱 배경으로 붙이지 말고 기존 네이티브 구성요소로 구현하세요.

실시간 안내·구간 계산·그래프·주간 집계는 AI 없이 처리합니다. AI는 서버에서 검증된 사실을 짧게 설명하고, 사전에 검토된 훈련 후보 중 다음 행동을 제안합니다. 위치 원본·이름·보상 정보는 보내지 마세요. 숫자와 목표는 AI가 자유 생성하지 않게 하세요.

먼저 로컬 기록 ID와 서버 기록 ID의 연결, 종료 후 구간 기록 보존, 일시정지를 제외한 활성 시간, 계정별 소유권을 확인하세요. 서비스에 구간 객체가 있다는 이유만으로 영구 저장된 것으로 가정하지 마세요. 부족한 기록에는 가짜 구간·비교·추천을 만들지 마세요.

동의, 기록 없음, 처리 중, 데이터 부족, 오프라인, 실패·재시도, 한도, 설정, 동의 해제, 계획·목표 적용 확인까지 포함하세요. 추천을 생성하는 것과 사용자가 실제 적용하는 것은 별도 동작입니다. 목표 적용만으로 러닝이 시작되면 안 됩니다.

구현을 진행할 권한을 받은 경우, 데이터 감사 → 기본 계산 → 시안·상태 → 동의·소유권 → 모의 공급자·큐·캐시 → 승인된 실제 공급자 연결 순서로 진행하세요. 기존 미완료 변경을 보존하고 단계별 검증 결과를 보고하세요.

모델·예산·이용 제한·자동화 정책·개인정보 문구는 아직 확정되지 않았습니다. 시안의 예시 숫자로 운영 정책을 정하지 마세요. 실제 유료 호출, 개인정보 외부 전송, 배포·푸시는 별도 승인이 필요합니다.

## 전달 파일

- `CLAUDE-HANDOFF.md`: 화면 동작, 데이터 연결, AI 경계, 보안·비용·검수 기준.
- `SCREEN-INDEX.md`: 16개 화면의 순서와 진입·이탈, 최종 이미지 링크.
- `images/`: 최종 PNG 16장. 08·09·16은 검수 수정본인 `-v2` 파일을 사용.
- `MANIFEST.json`: 파일 목록, 해시, 생성·검수 메타데이터.
- `PROMPTS-CORE.json`, `PROMPTS-ADDITIONAL.json`, `PROMPTS-REVISIONS.json`: 재생성용 프롬프트.

## 상태

이 패키지는 디자인과 구현 지시서입니다. 앱 구현, 테스트 통과, AI 공급자 연결, 정책 승인, 배포 완료를 의미하지 않습니다. 시안의 러닝 기록은 설명용 예시이며 실사용자 데이터가 아닙니다.
