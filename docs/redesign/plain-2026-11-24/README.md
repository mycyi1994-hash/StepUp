# StepUp 새 빌드 재디자인 — 개발 적용 안내

- 기준: 테스트 APK 1.21.0 (versionCode 23030, 커밋 8027f7e), 저장소 `mycyi1994-hash/StepUp` main
- 시안: `시안/밝게` · `시안/어둡게` (1179×2556 = 393×852dp × 3), 지금 화면 캡처는 `시안/지금_캡처`
- 그림: `그림/` (캐릭터 · 신발 PNG, 이름은 `res/drawable-nodpi` 규칙대로 소문자 영문)
- 전/후 한눈에: 같은 폴더의 `StepUp_바뀐화면_보고_2026-11-24.pdf`

## 1. 범위 · 지킬 것

- 디자인만 바꾼다. 기능 · 서버 호출 · 버튼이 하는 일 · 문구 뜻은 그대로(CLAUDE.md 「지킬 것」).
- 한 화면에 큰 주 버튼 하나. 나머지 행동은 글자 버튼.
- 빼는 정보 없음. 화면에서 옮긴 정보는 아래 표의 「옮긴 곳」에 적어 둠.
- 글은 4개 언어 리소스에 있는 문구를 그대로 쓴다. 새 문구는 표에 `새 문구`로 표시(ko 기준, en · ja · zh 번역 필요).

## 2. 먼저 할 공통 작업 (이것만 해도 모든 화면이 바뀜)

### 2-1. 색 — `ui/components/RunStyle.kt`
지금 `LightRunTone` · `NavyRunTone` 값은 그대로. 아래만 더한다.

| 이름 | 밝게 | 어둡게 | 쓰는 곳 |
|---|---|---|---|
| eff (효율) | #1F5EFF | #4A7DFF | 효율 숫자 · 막대 |
| com (착화감) | #7B5CFF | #9A80FF | 착화감 숫자 · 막대 |
| dur (내구도) | #14B08A | #2FCB9F | 내구도 숫자 · 막대(가득) |
| gold (보상 · 주의) | #E8930C | #FFB938 | 내구도 줄었을 때 · 스텝 서지 · SUP 동그라미 |
| track (막대 바탕) | #E6E6EB | #222A3D | 모든 진행 막대 바탕 |

- 연한 파스텔 면(파랑 · 보라 · 초록 옅은 배경)은 쓰지 않는다. 면은 흰 카드 / 회색 안쪽 칸(`inset`) 두 가지만, 색은 숫자 · 막대 · 글자 버튼에만.

### 2-2. 주 버튼 — `RunButton`
- 바깥에 한 겹 더 두른 파란 빛 테두리를 뺀다. 높이 58dp · 모서리 29dp · 오른쪽 흰 원 44dp 화살표는 그대로.

### 2-3. 숫자 뒤 단위
- 큰 숫자(30sp 이상) 뒤 단위는 6dp 띄운다. 「16회」에서 「회」가 6에 붙어 보이던 것을 고침.
- 같은 숫자를 탭과 본문에 두 번 쓰지 않는다.

### 2-4. 새 공통 부품 3개 (`ui/components/` 에 추가 권장)
- `ListCard` + `ListRow`: 흰 카드 하나(모서리 22dp, 좌우 안쪽 18dp)에 줄을 구분선(1dp, divider)으로 나눈다. 줄 = 왼쪽 이름(15.5sp SemiBold) · 오른쪽 값(16sp Bold, 숫자 폭 고정) · 필요하면 아래 가는 막대(3dp, 위 9dp 띄움). 값 칸은 줄바꿈 금지.
- `EmptyState`: 가운데 정렬. 캐릭터 그림(높이 110~120dp, `ContentScale.Fit`) → 제목 18sp Bold(위 16dp) → 설명 14sp(위 6dp, 보조 글자색) → 글자 버튼 하나(위 14dp, 선택). 모든 빈 · 오류 상태가 이것 하나를 쓴다.
- `ProductImage`: 신발 사진은 상자(회색 칸)에 넣지 않고 바탕 위 가운데. 높이만 고정(상세 128dp · 시트 112dp · 탭 120dp), 너비는 비율대로(`Modifier.height(N.dp)`, `ContentScale.Fit`). 신발 그림 파일 위아래 투명 여백 때문에 칸 밖으로 삐져나오던 것. 여백 자른 그림은 `그림/sneaker_*_trim.png` 참고.

## 3. 스댕이 · 텝텝이(캐릭터) 쓰는 법

- 상황을 알려 주는 자리에만, 한 화면에 하나. 버튼 · 사진 · 글자 위에 겹치거나 카드 밖으로 걸치지 않게.
- 놓는 자리: ① 빈 · 오류 상태 가운데(`EmptyState`) ② 카드 안 오른쪽 끝(46~70dp).
- 비율 고정: 높이 dp만 정하고 `ContentScale.Fit`. 작은 폰(360dp)에서 찌그러지지 않고 통째로 작아진다.
- 앞발 하나만 든 표정(ㅇㅋ · 안녕 · 최고 · 화이팅 · 잘한다)은 쓰지 않는다. 작게 보면 손가락 모양으로 오해할 수 있음. 해당 그림은 `그림/` 에 넣지 않았다.

## 5. 다 하고 확인할 것

- 360dp 폭 · 글자 크기 130%에서: 글자가 칸 밖으로 넘치지 않는지, 한 글자만 다음 줄로 떨어지지 않는지(값 칸은 `softWrap = false` 또는 `maxLines = 1`).
- 신발 · 캐릭터 그림이 자기 칸 밖으로 나가거나 찌그러지지 않는지.
- 어두운 테마에서 흰 카드 → `panel`, 막대 바탕 → track(어둡게) 값인지.
- 큰 숫자 뒤 단위가 붙어 보이지 않는지.
- 한 화면에 주 버튼이 하나인지.
- 잠금 화면 덮개 규칙: 새 시트도 `if (LockCover.hidesWindows()) return` 로 시작(CLAUDE.md 2차 점검).

## 6. AI 코딩 도구에 붙여 넣을 지시문

> StepUp 안드로이드 앱(Compose) 디자인만 바꾼다. 기능 · 서버 호출 · 문구 뜻은 바꾸지 않는다. 이 폴더의 `00_먼저_읽어주세요.md` 2장(공통)을 먼저 적용하고, 4장 표의 화면을 한 줄씩 적용한다. 각 화면은 `시안/밝게/<번호>_*.png` 와 똑같이 보이게 맞추고, 어두운 테마는 `시안/어둡게/` 를 본다. 새 공통 부품은 ListCard · ListRow · EmptyState · ProductImage 네 개를 `ui/components/` 에 만든다. 2-6장의 「넣지 않는 것」은 만들지 않는다. 캐릭터 그림은 `그림/` 의 파일만 쓰고 3장 표의 자리에만 둔다. 새 문구는 values(영어) · values-ko · values-ja · values-zh 네 곳에 모두 넣는다. 끝나면 5장 확인 목록을 360dp 에뮬레이터에서 확인하고 화면마다 캡처를 남긴다.
