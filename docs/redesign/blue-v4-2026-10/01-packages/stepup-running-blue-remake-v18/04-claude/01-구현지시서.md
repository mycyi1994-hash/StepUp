# StepUp 러닝 전체 리메이크와 신발 색감 적용 지시서

기존 Android 앱에 승인된 남색·파랑 시안을 적용한다. 러닝 109개 화면·상태를 빠짐없이 대응하고, 신발탭은 현재 구조를 유지한 채 색감과 조명만 바꾼다. 이 전달물은 구현을 위한 정적 시안과 동작 지침이며, 앱 구현·Figma 컴포넌트·실기기 검증 완료본은 아니다.

## 읽는 순서와 우선순위

1. 이 문서와 [화면별 동작표](02-화면별-동작표.md), [검수 목록](03-검수목록.md)을 읽는다.
2. [전체 화면 목록](../전체-화면목록.md)에서 해당 PNG를 직접 열어 본다.
3. 실제 대상 저장소의 AGENTS.md, CLAUDE.md와 현재 진행 상태를 읽는다. 사용자 최신 지시가 과거 문서의 미술 방향보다 우선한다.
4. 현재 기능·저장 데이터·API·권한·세션 동작을 확인하고 화면 상태에 연결한다.

이 문서의 코드 경로는 2026년 10월 3일에 확인한 stepup-waitlist-implementation을 기준으로 한다. 사용자의 실제 대상 checkout이 다르면 같은 역할의 코드를 찾아 적용한다. 문서를 맞추기 위해 다른 저장소로 옮기거나 작업 중인 변경을 덮어쓰지 않는다.

최신 스타일은 HOME.png의 남색·전기 파랑·흰색 버튼이다. 예전 노란 버튼, 캐릭터, 오렌지 스포츠 안, 네 개 하단 탭 지시를 복원하지 않는다. 이전 지시서의 동작도 현재 사용자 요구·현행 데이터 모델과 대조한다. manifest.json의 legacyActions와 legacyText는 과거 자료이며 현재 연결 사양이 아니다.

그림과 이 문서가 충돌하면 다음 기준으로 해결한다.

- 로고는 앱의 공식 원본 자산이 우선한다. 생성 이미지의 글자 모양을 따라 다시 그리지 않는다.
- 실제 기록·잔액·등급·레벨·내구도·권한·인원은 실제 모델 값이 우선한다.
- 신발은 “원래 구조에서 색감만 변경”이 우선한다. 그림에서 안 보이는 기능을 삭제하지 않는다.
- 버튼의 상태 변경·확인·저장·공유는 아래 동작 지침과 현행 서비스 계약을 따른다.
- 간격·장식은 PNG의 방향을 공통 컴포넌트로 통일한다. 장면마다 달라진 테두리 모양까지 복제하지 않는다.

## 전달 범위와 완료 범위

러닝은 승인 메인 1장, 기존 러닝 상태 62장, 크루 달리기 상태 20장, 권한·코스 관리·결과 추가 상태 26장으로 총 109장이다. 새로 생성한 그림은 108장이다. 크루의 예전 시작 메뉴 R01은 새 U01에 통합했고, 나머지 크루는 CR02~CR21이다. R01과 CR01을 혼동하지 않는다.

109장은 UI 상태 표본이다. 시트·로딩·실패·선택 상태별로 별도 Activity나 Navigation destination을 109개 만들 필요는 없다. 109개 모두 화면/컴포넌트의 어떤 상태에서 재현되는지 대응표에 남긴다. 항목별 구현·검증 상태는 [실행 체크리스트](implementation-checklist.csv)에 기록한다.

신발 시안 1장은 별첨 [색감 참고](reference/shoes-blue.png)다. 따라서 전달 이미지 총수는 러닝 109장과 신발 참고 1장이다. reference/logo-reference.png는 비교용 공식 로고 사본이며, 앱에는 기존 브랜드 자산을 재사용한다.

다른 탭 전체, 지갑, 뽑기 정책, 신발 강화·수리 정책, 크루 모집·운영·채팅을 다시 설계하는 작업으로 확대하지 않는다. 필요한 버튼은 기존 화면에 연결한다.

러닝/신발/뽑기/커뮤니티/내 정보의 하단 다섯 탭과 순서를 유지한다. focused 러닝·입력·카운트다운·결과·상세 화면에서는 현행 공통 표시 정책으로 숨김 여부를 처리한다. 각 화면에 헤더와 하단 탭을 따로 그리지 않는다.

상단 SUP 잔액 버튼은 HOME과 U01의 시각 기준을 따른다. 모든 상세 화면에 복제하지 않는다. 결과·진행 상세의 “이번 러닝 SUP”는 잔액과 다른 정보로 분리한다.

공통 요소는 기존 디자인 시스템에 추가/수정한다. 주요 버튼, 보조 버튼, 다섯 러닝 모드 카드, 수치 묶음, 진행바, 상태 배지, 지도 컨테이너, 시트, 기록 행, 빈 상태, 오류 안내, 크루 인원 행을 공유한다. 공통 테마 변경이 다른 네 탭에 미치는 영향은 확인하며, 필요하면 러닝 범위 테마를 사용한다.

다음은 구현 시작값 제안이며 승인된 픽셀 치수라고 주장하지 않는다. 작은 폰과 큰 글씨 설정에서 조정한다.

- 좌우 여백 20~24dp, 큰 영역 사이 20~24dp, 같은 묶음 안 8~12dp.
- 주요 버튼 높이 56~64dp, 일반 터치 영역 최소 48dp. 시트 버튼은 키보드와 시스템 하단 영역 위에 둔다.
- 본문 16sp 전후, 설명 14sp 전후, 화면 제목 28~32sp. 숫자는 폭이 흔들리지 않도록 처리한다.
- 버튼의 눌림은 짧고 작게, 화면 전환은 약 180~220ms를 시작값으로 검토한다. 상시 번쩍임·떠다니는 장식·과한 입자는 넣지 않는다.
- 긴 제목과 큰 글자는 높이와 스크롤로 대응한다. 글자를 작게 눌러 넣거나 버튼을 화면 밖으로 밀지 않는다.

PNG는 폭 886~887px, 높이 1774px인 검토 이미지다. 픽셀을 dp에 직접 대입하지 않는다. 이미지에 있는 상태 표시줄·키보드·홈 바는 OS 영역으로 대체한다. 장식, 신발, 조명은 이미지 자산으로 쓸 수 있지만 글자·숫자·아이콘 버튼·입력·탭·진행바는 네이티브 UI로 만든다.

## 러닝 시작과 세션

HOME의 러닝 시작은 U01로 간다. U01은 자유 러닝 / 크루 달리기 / 러닝 챌린지 / 추천 코스 / 다이어트 모드 다섯 개 같은 크기의 가로 버튼이다. 자유 러닝만 큰 영웅 영역으로 만들거나 카드 안에 시작 버튼을 하나 더 넣지 않는다. 내 러닝 기록은 H01로 간다.

자유 러닝은 추가 목표 선택을 강제하지 않는다. 필요한 권한 분기 후 R01 카운트다운을 거쳐 R02 또는 위치 없는 R02_TIME으로 들어간다. 카운트다운을 취소하면 기록을 만들지 않고 진입 화면으로 돌아간다.

세션 ID, 모드, 시작 시각, 유효 운동 시간, 거리, 경로 세그먼트, 목표, 루틴 구간과 반복, 일시정지 상태를 UI 생명주기와 분리한다. 화면 회전·앱 전환·지도 확대·백그라운드 복귀로 초기화하지 않는다. 이미 달리는 세션이 있으면 새로운 세션을 중복 생성하지 않는다.

진행 중 일시정지와 뒤로는 현재 모드의 일시정지 상태로 연결한다. 종료 확인 중에는 내 측정을 정지한다. “계속 달리기”를 명시적으로 눌렀을 때만 재개하고, 시트를 닫거나 시스템 뒤로를 누르면 정지 상태를 유지한다.

E02 목표 수정에서 적용·취소는 이전의 일시정지 상태로 복귀한다. 0.5km 증감은 시안의 조작 방식이며 허용 범위는 기존 모델 검증을 따른다. E03은 진행 상세 시트이고 목표 수정·선택 코스 보기의 진입점이다. 불필요한 별도 단계나 복잡한 설정을 추가하지 않는다.

## 권한과 위치

권한은 현재 승인 상태를 확인해 필요한 단계만 보여준다. 앱 설명 시트와 실제 OS 허용창을 구분한다. OS 허용창을 이미지나 가짜 버튼으로 대신하지 않는다.

P01 신체 활동 설명, P02 재요청 가능한 거절, P03 시스템 설정이 필요한 거절을 구분한다. L01 위치 설명, L02 앱 위치 권한 없음, P04 대략적 위치, E07 기기 위치 기능 꺼짐도 서로 다른 원인이다. 설정에서 돌아오면 상태를 다시 읽는다. P05 알림 거절은 사용자 선택과 기존 OS 실행 조건에 맞게 처리한다.

시간 전용 R02_TIME은 시간만 기록하고 거리·페이스는 미측정으로 표시한다. 추천 코스나 거리 챌린지에는 위치가 필요하다. 대략적 위치만으로 충분한지 여부는 현행 정확도 정책을 따르며, 정확하지 않은 경로를 정확한 측정처럼 보이지 않는다.

L04는 GPS 끊김이고 CR18은 크루 통신 끊김이다. GPS 미확인 구간을 직선으로 이어 이동 거리로 만들지 않는다. 시간과 기존 유효 기록은 유지한다. 복구된 새 좌표는 새 구간으로 처리한다.

## 지도와 코스

모든 시안 지도는 위치·크기·대비 참고다. 지도 이미지의 지명·강 위치·거리·시작/끝을 실제 지리 또는 경로로 복제하지 않는다. 기존 공급자의 실제 타일, 실제 좌표와 실제 경로 결과를 연결하고 출처 표기를 가리지 않는다.

추천은 내 현재 위치에서 출발하는 흐름이다. “출발점 길찾기”를 추가하지 않는다. 시작점이 다른 코스를 보여주려면 현재 위치 기준으로 다시 추천해야 한다. 추천 API나 보행 가능한 경로 검증이 없다면 실제 추천 기능이 완성됐다고 보고하지 않는다. 도식·샘플은 검사용 데이터로 격리한다.

K04/K07에서 진행한 구간과 남은 추천 경로를 구분한다. 기록한 선은 현재 실제 위치까지만 이어진다. 지도 확대에서도 측정은 계속한다. K08 자유 러닝 전환은 코스 안내만 끄며 세션·시간·거리·경로를 유지한다.

K09/K10/K11은 “코스 선택 / 코스 만들기 / 코스 게시판” 세 메뉴를 같은 위치에서 공유한다. 코스 선택 확인 K13은 코스만 적용하며 운동을 시작하지 않는다. K14는 선택 해제이고 코스 삭제가 아니다. K15 코스 저장은 러닝 기록 저장과 분리한다. 게시판 공유는 기본 비공개에서 명시적인 올리기 동작 후 처리한다.

공유된 코스 순위는 실제 서버 기록을 표시한다. 빈 순위·로그인 필요·불러오기 실패는 기존 상태를 같은 틀 안에서 처리하고 임의의 1위를 만들지 않는다. K17은 공유 코스 없음, K18은 조회 실패이므로 혼용하지 않는다.

## 챌린지와 다이어트

챌린지는 U02에서 10분 / 1km / 3km를 선택한다. U01에 별도의 10분 진입을 만들지 않는다. 목표 도달 C01은 한 번만 안내하며, 계속 달려도 기존 달성 상태를 지우지 않는다. 중간 종료 C02는 실제 운동 기록을 남기되 목표 달성으로 집계하지 않는다.

U05/D06에서 몸 정보와 경험을 입력한다. D01은 OS 숫자 키보드, D02는 해당 입력 오류, D03은 수정 취소다. 오류나 추천 실패가 나도 입력한 값을 유지한다. 범위 검사는 기존 정책을 사용한다. 몸무게를 근거로 감량 보장이나 새로운 의학적 규칙을 만들지 않는다.

U06의 15분 루틴은 이번 시안 예시다. 실제 추천 서비스 규칙에 따라 내용이 달라질 수 있다. 이 예시를 적용하는 경우 준비 걷기 3분, (러닝 1분 + 걷기 2분) 3회, 마무리 걷기 3분으로 정확히 15분이다. 러닝 합계 3분과 걷기 합계 12분이 맞아야 한다.

주 타이머는 현재 구간의 남은 시간, 전체 진행은 누적 운동 시간이다. “다음”은 예고이며 건너뛰기 버튼이 아니다. D12 재개 시 동일 구간·반복·남은 시간으로 복귀한다. D10 루틴 완료는 아직 저장 전이고 저장 성공 뒤 S02, 중간 종료 후 저장 성공은 D13이다.

## 저장과 보상

저장 요청 E04, 저장 실패 S01, 저장 완료 결과를 구분한다. 같은 세션으로 재시도하여 중복 저장을 막는다. 저장 실패 중에도 기록 원본을 보존한다. S01의 기록 확인은 저장 대기 요약이며 저장 완료로 표시하지 않는다.

결과의 기본 데이터는 날짜·모드·거리·시간·평균 페이스·평균 속도·경로·해당 세션 신발·등급·레벨·내구도다. 현재 구현에서 표시하던 정보를 시안 일부에 없다는 이유로 삭제하지 않는다. 공간이 부족하면 주요 수치를 먼저 두고 같은 화면을 스크롤한다. E10/E11을 정보가 포함된 결과의 기준으로 삼고, R05는 간결한 배치 참고로 사용한다.

보상 상태는 현행 Settle 모델에 대응한다.

| 모델 | 시안 | 표시 |
|---|---|---|
| PENDING | E10 | 예상 금액, 확인 중 |
| DONE | E11 | 서버 확인 금액, 반영 완료 |
| VOID | E08 | 지급 제외와 서버 사유 |
| NOT_PAID | E09 | 미지급과 관련 내역 |

기록 저장 성공과 보상 반영 성공은 별개다. 화면 전환이나 짧은 타이머만으로 보상을 완료시키지 않는다. 실제 금액이 0이면 시안의 +0.80을 표시하지 않는다.

공유 E05/CR21은 미리보기 후 명시적으로 전송한다. 경로 포함 OFF일 때 내보내는 이미지에서도 지도·장소·출발지·도착지를 제거한다. UI 토글만 끄고 내보내기에는 경로가 남는 상태는 실패다.

R06/H14는 저장한 기록 삭제, R07은 저장 전 기록 폐기다. 취소/바깥 누름/뒤로로 삭제하지 않는다. 삭제 성공 시 목록과 합계를 갱신하고, H16 실패에서는 원본을 유지한다. 모든 결과의 “처음 화면으로”는 러닝 메인 HOME으로 연결하는 이번 전달물의 동작 기준이다.

## 기록과 통계

기록의 ID를 목록·상세·지도·삭제에 동일하게 전달한다. 상세에서 돌아오면 기간·필터·스크롤을 복원한다. H03 기간 선택은 적용 전에는 원래 목록에 반영하지 않는다.

H07 최초 기록 없음, H08 선택 기간 없음, H09 로딩, H10 조회 실패, H15 통계 없음은 서로 다른 상태다. 실패를 빈 목록으로 숨기지 않는다.

기간 합계는 화면에 불러온 일부 행만 합산하지 않는다. 유효한 전체 기간 데이터로 집계한다. 평균 페이스는 유효 거리 세션의 시간 합을 거리 합으로 나눈다. GPS 없는 기록은 시간과 횟수에 포함할 수 있지만 미측정 거리를 0km 실측처럼 만들지 않는다.

주간/월간과 날짜는 사용자 시간대와 현행 규칙으로 계산한다. 시안 날짜·수치를 하드코딩하지 않는다. H12는 해당 과거 기록의 저장 경로이며, 다시 현재 위치 권한을 요구하거나 기록을 수정하지 않는다.

## 크루 달리기

크루 진입은 U01에서 바로 시작한다. 크루가 하나면 바로 해당 상태, 여러 개면 최근 선택과 CR19, 소속이 없으면 CR14다. 로그인 필요 시 기존 인증에 복귀 경로를 저장한다. 내 진행 중 세션이 있으면 그 세션 복귀가 우선이다.

대기실은 최대 30명을 고려한다. 크루 총 인원, 이번 대기실 인원, 준비 인원, 확정 출발 인원을 구분한다. 30명 모두를 한 화면에 억지로 넣지 않고 목록을 스크롤하며, 내 준비 상태와 주 버튼을 고정한다. 크루명·러닝명·출발 시각·거리·예상 시간 또는 페이스·만나는 곳을 읽기 쉽게 표시한다.

CR04/CR05는 같은 일반 참가자의 준비 전/후다. CR06은 진행자 역할 예시이므로 CR05 다음에 자동으로 진행자 화면으로 전환하지 않는다. 진행자와 크루장은 다른 권한이다. 역할은 서버 값으로 결정한다.

PartyApi.open은 생성/참가를 일으킨다. 단순 진입 미리보기나 방 조회에 호출하지 않는다. 가입 크루의 방을 참가 없이 조회하는 API가 있는지 먼저 확인하고, 없다면 실제 추가 연동 항목으로 기록한다. 조회만 했는데 참가 인원이 늘어나면 안 된다.

준비 전 권한과 위치 상태를 확인한다. 위치 기록 허용과 크루원에게 위치 공개는 분리하며 공개 기본값은 OFF다. 다른 사람의 미공개 위치·거리·순위를 0이나 가짜 값으로 대신하지 않는다. 공개 대상도 같은 러닝 참가자로 한정한다.

진행자가 출발할 때 미준비 인원이 있으면 CR07에서 확정 명단과 제외 인원을 확인한다. 서버 시작 시각과 명단을 받아 CR08을 표시한다. 기기별 로컬 3초 타이머가 각자 출발을 확정해서는 안 된다. 준비 취소·나가기·시작이 경합하면 서버 결과를 따른다.

CR11/CR12는 내 기록만 정지·종료한다. 진행자가 끝내도 다른 참가자의 개인 측정은 보존한다. CR18 네트워크 끊김 동안 내 측정은 유지하고 오래된 타인 좌표를 실시간처럼 보이지 않는다. 재접속은 동일 partyId/sessionId로 복구한다.

이미 출발한 방에 신규 사용자를 뒤늦게 합류시키지 않는다. CR16은 새 대기실이나 자유 러닝으로 안내한다. 기존 출발 참가자의 재접속은 신규 참가와 구분한다. CR15 혼자 대기에서 혼자 출발 가능 여부는 기존 서버 계약을 확인하고 UI와 일치시킨다. 시안에 없는 다인 보너스를 임의 지급하지 않는다.

CR20은 대기실 알림 미리보기, CR21은 기록 공유 미리보기다. 대상 크루와 내용을 확인한 뒤 해당 전송 버튼을 눌러야만 메시지를 보낸다. 화면 진입으로 전송하지 않는다. 전송 성공 후 중복 전송을 방지하고, 실패하면 내용과 선택을 유지한다.

대기실 나가기, 진행자 이전, 방 종료, 크루 접근 권한 상실, 준비/참가/출발/전송 실패는 기존 서버 의미를 유지하고 공통 확인 시트·오류 컴포넌트를 재사용한다. 전용 PNG가 없는 서버 예외도 성공으로 위장하지 않는다.

## 신발탭의 추가 지시

최신 사용자 요구는 기존 신발탭의 구조를 유지하면서 새 색감만 적용하는 것이다. 별첨 shoes-blue.png는 스타일 참고이며 현재 앱 구조의 완전한 복제본이 아니다.

코드 확인상 현재 CustomizeScreen에는 내 신발/신발 보관함, 선택한 소유 신발 ID, 착용 신발 구분, 레벨·번호·등급·능력치, 상세 관리 연결, 정렬·필터·보관함이 있다. 시안에 생략됐어도 유지한다. 이전 캡처의 2열 배치를 맞추기 위해 현행 화면을 통째로 재구성하지 않는다. 기존 코드가 이미 승인된 다른 배치라면 그 배치를 유지한다.

선택한 신발과 실제 착용 중인 신발은 다르다. 목록 터치나 뽑기 결과에서 신발을 열었다는 이유로 자동 착용시키지 않는다. 착용 표시와 내구도·등급·레벨은 해당 소유 신발의 실제 값에 연결한다.

조명과 받침은 기존 신발 표시 영역 안에 적용하고 신발 원본 실루엣을 보존한다. 배경 이미지를 통째로 깔아 보유 목록을 밀어내지 않는다. 불필요한 마켓/도감 큰 버튼을 새로 추가하지 않되, 기존 관리 기능 자체를 삭제하지 않는다. 로딩·빈 보유 목록·조회 실패도 현재 상태를 유지한 채 색감만 맞춘다.

## 구현 순서와 인계

1. 현재 대상 checkout과 변경을 확인하고 화면 ID를 현재 route/상태에 대응시킨다.
2. 공통 색·버튼·카드·시트·헤더 표시 정책을 적용한다.
3. HOME/U01부터 자유 러닝의 시작·정지·종료·저장·결과까지 한 줄로 연결해 실제 캡처한다.
4. 챌린지·추천/저장 코스·다이어트·기록/통계·권한/오류 상태를 확장한다.
5. 크루 진입·참가·준비·출발·개인 측정·복귀·공유를 연결한다.
6. 신발은 기존 구조에 색감만 적용하고 선택/착용/보관함의 회귀를 확인한다.
7. 체크리스트에 실제 검사와 캡처 경로를 기록한다. 실제 연동이 안 된 항목을 따로 남긴다.

정적 PNG 제작 완료와 앱 구현 완료를 혼동하지 않는다. 이 패키지의 109개 “검토 완료”는 이미지 검수 상태다. 앱 기능·API·기기 검사 상태는 새 체크리스트에서 모두 미검증으로 시작한다. 배포·운영 데이터 변경이나 다른 사람에게 메시지를 보내는 행동은 구현 지시서 작성만으로 수행하지 않는다.
