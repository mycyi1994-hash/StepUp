# StepUp 커뮤니티 기본 화면 리메이크 지시서

기존 러닝 이야기 기능을 유지하면서 제공된 43개 화면의 남색과 파란색으로 UI를 바꾼다. 첫 화면은 왼쪽 지역 설명, 오른쪽 작은 지도, 아래 글 목록이다. 글쓰기에는 코스 첨부와 쉬운 장소 선택 진입을 남긴다. 큰 지도 중심의 구도나 본문만 있는 옛 작성 화면으로 되돌리지 않는다.

이 패키지는 정적 PNG 시안과 구현 명세다. 앱 코드, 작동하는 서버 연결, 분리된 네이티브 부품, 편집 가능한 Figma 파일은 포함하지 않는다. `01-screens/CMxx.png`가 화면별 최종 이미지이고 `screen-index.json`은 상태와 파일의 대응표다. CM07은 중복 장소 목록이라 폐기했으므로 번호가 빠져 있다.

## 적용 범위와 우선순위

이번 43장은 일반 글 목록, 지역과 지도, 글 상세와 댓글, 일반 글쓰기와 임시저장, 수정과 삭제, 숨김과 신고, 권한과 오류 상태다. 커뮤니티 상단의 러닝 이야기 / 크루 모집 / 크루 채팅 세 탭을 유지한다. 크루 모집과 채팅의 상세 화면은 이번 패키지에서 새로 그린 범위에 포함되지 않는다.

최근 러닝 선택, 코스가 붙은 작성 화면과 게시글, 기록이 없거나 오래된 경우 등 WRITE01~17의 새 톤 시안은 별도 제작 중이다. 이번 CM12의 코스 버튼을 삭제하거나 비어 있는 장식으로 구현하지 않는다. 기존 쉬운 글쓰기 기능을 연결하고 후속 WRITE 전달본으로 해당 상태의 색감을 맞춘다. `audit/community-writing-coverage.json`에 원본과 새 화면의 대응을 적었다.

우선순위는 최신 사용자 요구 → 이 지시서의 상태와 동작 → 최종 PNG → 과거 패키지 순서다. 과거 문서의 ‘크루 모집 제외’는 그 문서의 제작 범위이며, 현재 제품의 크루 탭을 삭제하라는 뜻이 아니다. API나 기존 기능을 바꿀 필요가 발견되면 UI 수정과 구분해 보고한다.

## 공통 디자인

- 배경 #031427, 내용 면 #0B2B50, 선택과 하단면 #0754FF, 강조 #48D9FA, 본문은 밝은 흰색 계열이다. 흰 주 버튼의 파란 하단면, 채운 파란 선택 탭을 공통 부품으로 만든다.
- `assets/STEPUP-원본로고.png`를 사용한다. 로고를 타이핑하거나 다시 그리지 않는다. 커뮤니티에는 SUP 잔액 알약을 추가하지 않는다.
- 커뮤니티 첫 화면에는 공통 상단 로고와 제목, 세 글자 탭, 하단 다섯 탭을 표시한다. 다섯 탭은 러닝 / 신발 / 뽑기 / 커뮤니티 / 내 정보다. 상세·작성·검색·지도 안쪽 화면에는 이를 반복하지 않는다.
- 글 행은 왼쪽 제목·짧은 본문·작성자·시각·반응, 오른쪽 공개 장소 썸네일이다. 전체 행을 두꺼운 카드로 감싸지 않고 얇은 구분선을 사용한다. 지도 아래에서도 같은 행 부품을 쓴다.
- `최신순`은 정렬 상태 설명이다. 화살표나 새로운 정렬 메뉴를 붙이지 않는다.
- 지도 화면의 지도는 390dp 폭 기준 높이 196dp 이하를 목표로 하고, 화면 높이를 줄여야 하면 지도부터 줄인다. 제목만 있는 축약 목록으로 바꾸지 않는다. 장소를 누르면 아래 목록이 즉시 필터링되므로 ‘이 장소 글 보기’를 추가하지 않는다.
- 시트는 불투명한 남색 면과 배경 전체를 덮는 어두운 가림막을 사용한다. 시트 아래의 배경 버튼은 누를 수 없고 접근성 포커스에서도 제외한다.
- 한 화면에 큰 주 버튼은 하나다. 다른 행동은 보조 버튼이나 글자 버튼으로 구분한다. 로딩·비활성·눌림·오류도 동일한 부품의 상태로 구현한다.

## 크기와 입력

PNG는 약 887×1774의 정적 참고 이미지이며 정확한 크기는 screen-index.json에 기록했다. 이를 기기의 고정 좌표로 복사하지 않는다. 기존 네이티브 레이아웃에 맞춰 헤더, 스크롤 본문, 하단 행동 영역을 분리한다. 본문은 보통 16sp 이상, 보조 정보는 14sp 안팎을 출발점으로 실제 글꼴 확대에서 확인한다. 숫자 폭, 한글 줄바꿈, 버튼 최소 높이를 공통으로 정한다.

Android 최소 터치 영역 48dp를 확보한다. 상태 표시줄, 키보드, 제스처 바는 OS 영역이며 이미지로 그리지 않는다. 시안에 OS 표시가 없는 화면도 실제 앱에서는 상하 안전 영역을 적용한다. 키보드가 뜨면 입력창과 등록 버튼이 함께 올라오고, 내용은 스크롤된다. 고정 글쓰기 버튼 아래에 마지막 행이 가려지지 않도록 목록 하단 여백을 둔다. 좁은 화면·큰 글꼴에서는 본문 스크롤을 허용한다.

## 지역과 지도

지도는 기존 실제 지도 공급자, 실제 좌표, 라이선스 표기를 사용한다. PNG의 지도는 색감과 배치 참고이며 타일이나 제품 데이터로 배포하지 않는다. 로고·지역명·헤더는 지도와 분리된 영역이다. 라벨이 겹칠 때는 핀 군집화와 선택 강조를 사용하며 동일 장소 라벨을 중복해서 그리지 않는다.

현재 위치 점은 열람자의 GPS이고 장소 핀은 글에 지정된 공개 장소다. 작성자의 실시간 위치를 공개하지 않는다. 현재 위치를 모르면 임의의 도시, 거리, 파란 현재 위치 점을 만들지 않는다. GPS 실패와 권한 거부, 조회 중을 서로 다른 상태로 표시한다. 위치 권한은 사용자가 ‘내 위치 사용하기’를 선택했을 때 OS로 요청한다. 영구 거부와 첫 요청을 구분하고 대략적 위치도 처리한다.

수동 지역에서는 ‘선택한 지역에서’라는 기준을 표시하고, 거리는 선택 지역 중심과 공개 장소 사이의 거리로 계산한다. 러닝 거리와 장소까지의 거리는 별개다. CM43은 GPS 위치가 생긴 화면이 아니다. 핀의 글 수는 현재 범위·장소·숨김 조건의 실제 목록과 맞춰 갱신한다.

범위 변경 시 임시 선택값과 적용값을 나눈다. 적용 버튼을 눌러야 목록 기준이 바뀌고 취소·뒤로 가기는 기존 값을 유지한다. 실제 기본 반경은 저장된 사용자 선택을 따른다. 3km를 모든 사용자에게 덮어쓰지 않는다.

## 이동과 상태 보존

`화면별-동작.md`와 `flow-map.json`의 화면 번호는 장면 식별자이며, 번호마다 별도 라우트를 만들라는 뜻이 아니다. 조회·성공·실패는 가능한 한 같은 화면의 상태로 구현한다.

글 제목과 본문을 누르면 상세, 오른쪽 장소 썸네일과 상세 장소 카드를 누르면 해당 장소의 지도다. 중첩 클릭으로 두 화면이 열리지 않게 한다. 지도 핀 선택은 같은 화면 안의 목록 필터이고 ‘전체 장소’는 그 필터만 해제한다.

뒤로 가기는 실제 진입 화면으로 돌아간다. 피드에서 연 지도는 피드로, 상세에서 연 지도는 해당 상세로 돌아간다. 모든 지도 뒤로 가기를 CM01로 하드코딩하지 않는다. 지역·반경·장소 필터·목록 스크롤·선택한 커뮤니티 탭을 보존한다. 상세의 ‘글 목록으로’는 목록 복귀를 명시적으로 선택한 경우다.

## 쉽게 쓰는 일반 글과 코스 첨부

CM12는 선택적 코스 영역, 공개 장소, 문구 버튼, 본문, 올리기의 순서다. 진입하자마자 키보드를 올리지 않는다. 제목이나 종류부터 고르게 하지 않고 본문의 첫 유효 문장을 목록 제목으로 사용하되 원문 전체를 보존한다.

장소 검색 결과와 빠른 장소 후보는 한 번 누르면 작성 화면으로 돌아간다. CM15의 확인 단계는 지도에서 지점을 직접 지정할 때만 사용한다. 기존 코드에서 모든 검색 결과 뒤에 확인 화면이 나온다면 이 동작을 고친다. 장소 선택 중 취소해도 본문과 코스 첨부는 그대로 남는다. 공개 장소를 GPS로 조용히 확정하지 않는다.

문구 버튼은 편집 가능한 시작 문장을 넣는다. 사용자가 작성한 문장을 덮어쓰거나 같은 문구를 반복 삽입하지 않는다. 최근 장소가 없으면 해당 바로가기를 숨기고, 코스 주변은 실제 경로가 있을 때만 제공한다.

게시 조건은 유효한 공개 장소와 비어 있지 않은 본문 또는 유효한 공유 기록이다. 일반 글에는 코스가 필수가 아니다. 코스 공유는 실제 완료한 본인 기록만 허용하며, 오늘·어제·2일 전·3일 전의 달력 날짜를 앱 기준 시간대에서 계산한다. 72시간으로 바꾸지 않는다. 기준은 완료 시각이며 서버에서도 검증한다. 날짜가 지나 이미 게시된 글을 자동으로 지우지 않는다.

기록 첨부가 있으면 실제 기록으로만 기본 문장을 만들고 사용자 편집을 우선한다. GPS 없는 기록은 실제 존재하는 시간·거리만 표시한다. 가짜 경로를 만들지 않는다. 임시글의 코스가 만료되면 교체하거나 첨부만 제거하고 본문·장소·원본 기록은 보존한다.

CM13·17~25·44의 예시는 코스를 첨부하지 않은 일반 글이다. 본문 ‘오늘도 가볍게 달렸어요. 도화동에서 3km, 천천히 뛰니 좋네요.’에 3km가 있다고 실제 러닝 기록이 첨부된 것으로 처리하지 않는다.

게시 중 중복 요청을 막고 실제 서버 성공 후에만 CM18을 표시한다. 실패 시 내용·장소·첨부를 유지한다. 응답이 끊겨 결과가 불확실하면 같은 요청의 결과를 조회하거나 기존 멱등 키를 사용한다. 새 요청을 무조건 보내 중복 글을 만들지 않는다. API 글자 제한은 현행 계약을 확인하며 디자인 예시의 1,000자·200자를 새 서버 규칙으로 단정하지 않는다.

임시저장은 계정별로 작성/수정 모드, 수정 대상 ID, 본문, 공개 장소와 출처, 첨부 기록, 사용자가 편집했는지 여부를 함께 보관한다. 새 글 쓰기에서 기존 초안을 지우는 행동을 명확히 표시한다. 저장 실패를 저장 완료로 안내하지 않는다.

## 댓글과 관리

댓글은 전송 중 중복 제출을 막고 서버 성공 후 입력창을 비우고 개수를 갱신한다. 실패하면 입력을 보존한다. 좋아요 실패는 직전 상태와 개수로 복구한다. CM39처럼 짧은 안내를 쓰고 글 읽기를 막는 확인 모달을 띄우지 않는다.

내 글 메뉴에는 수정·삭제, 다른 글 메뉴에는 글 한 건 숨기기·신고가 나온다. 수정은 같은 글 ID와 기존 댓글·반응을 유지한다. 삭제 실패 시 기존 글은 남는다. 숨김은 작성자 차단과 다르며 되돌리기를 제공한다. 저장 범위와 동기화 방식은 기존 계약에 맞춘다.

신고는 사유 선택을 유지하고 서버 접수 후에만 완료를 표시한다. 접수는 제재나 삭제 완료가 아니다. 표시 문구를 실제 StoryReportReason과 서버 값에 정확히 연결한다. CM27·40의 사유 선택이 API 호출 중 또는 실패 후 초기화되지 않아야 한다.

로그인 만료는 기존 로그인 복귀 경로를 재사용하고 글과 첨부를 보존한다. 로그인했다고 자동 게시·삭제하지 않는다. 일반 네트워크 오류를 ‘삭제된 글’로 처리하지 않는다. CM38은 접근 불가가 확인된 경우이며, 상세 조회 통신 실패에는 재시도를 제공한다. 이처럼 기존 코드에 있고 이번 43장에 별도 이미지가 없는 상태를 삭제하지 않는다.

## 현재 코드와 연결할 지점

로컬 `stepup-waitlist-implementation`의 아래 파일을 읽기 전용으로 확인했다. 이는 실제 구현 완료나 실행 검증을 의미하지 않는다. Claude는 작업 중인 브랜치의 최신 파일과 계약을 다시 확인하고 적용한다.

- `CommunityScreen.kt`: 러닝 이야기 / 크루 모집 / 크루 채팅 세 탭과 기존 번개 모임 경로가 이미 있다. 시안에 없는 기존 경로를 지우지 않는다.
- `stories/StoryParts.kt`, `StoryMapScreen.kt`, `StoryMap.kt`: 목록 행과 지도에 공통 스타일을 적용한다. 목록/지도/썸네일을 서로 다른 데이터로 꾸미지 않는다.
- `stories/StoryComposeScreen.kt`: 기록·장소·문구·초안 구조를 유지한다. 현재 `onPick`이 `ComposeStep.CONFIRM`으로 이동하는 부분은 검색 결과 즉시 선택 요구와 다르다. 검색 결과는 저장 후 WRITE로, 지도 직접 지정만 CONFIRM으로 연결한다.
- `stories/StoryDetailScreen.kt`: 좋아요 실패 등 현재 공통 오류 표시와 새 시안의 본문 내 안내를 맞춘다. 댓글 입력·등록 버튼을 오류 안내로 가리지 않는다.
- `stories/StoryComposeViewModel.kt`, `StoryDetailViewModel.kt`, `domain/StoryRuns.kt`: 소유권·기간·요청·보존 규칙을 유지한다. 색상 변경을 위해 서버 숫자나 데이터 모델을 예시 값으로 바꾸지 않는다.
- `stories/StoryPlacePicker.kt`, `StoryLocationScreens.kt`, `StoryOriginState.kt`: 실제 지도·공개 장소 선택·수동 지역 기준을 연결한다.

경로 접두사는 `app/src/main/java/com/stepup/android/ui/screens/community/`이며 domain 파일은 해당 domain 폴더다. 파일 스냅샷 정보는 `audit/code-reference.json`에 있다. API 전체 감사를 마친 자료는 아니므로 여기만으로 기능 누락이 없다고 결론 내리지 않는다.

## 구현 후 확인

한국어 360~430dp 폭과 글꼴 확대, 키보드 표시, 시스템 제스처 영역에서 글자·버튼·시트 겹침을 확인한다. 정상·빈 결과·로딩·실패를 실제 데이터로 구분하고 게시·댓글·좋아요·삭제·신고 실패 후 입력과 수치가 유지되는지 확인한다. 지도 공급자 오류와 게시글 조회 오류도 각각 재현한다.

장소 한 번 선택, 수동 지역 거리 기준, 위치 권한 거부, 목록에서 지도와 상세를 오간 뒤 상태 복원, 초안 재개와 계정 변경을 확인한다. 코스 첨부는 3일 전 경계·자정 이후 재진입·GPS 없음·기록 조회 실패를 후속 WRITE 명세와 함께 확인한다.

완료 보고에는 실제 수정한 파일, 실행한 확인, 남은 제약을 적는다. 시안 43장 제작 완료를 앱 구현 완료나 Figma 컴포넌트 제작 완료로 표현하지 않는다.
