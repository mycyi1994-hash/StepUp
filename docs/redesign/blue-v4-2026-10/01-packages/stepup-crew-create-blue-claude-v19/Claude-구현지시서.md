# StepUp 크루 만들기 리메이크 구현 지시서

현재 StepUp의 크루 만들기와 대표 이미지·초안 흐름을 첨부19장처럼 리메이크한다. 기존 기능과 저장 데이터를 보존하고, 공통 남색·전기 파랑 톤과 읽기 쉬운 버튼을 적용한다. 먼저 현재 브랜치의 AGENTS.md와 최신 디자인 문서를 읽는다. 이 문서는 시안 전달본이며 앱 변경·배포 완료 보고서가 아니다.

## 1. 적용 범위와 우선순위

CP25~39, CP69, CP77, CP78, CP88을 구현 대상으로 본다. 각 번호는 화면 상태이며 독립 경로19개를 새로 만들라는 뜻이 아니다. 상태별 버튼은 화면별동작.md를 따른다. 이미지와 명세가 미세하게 다르면 실제 데이터·동작은 명세와 현행 서비스 계약을 우선한다.

기존 CP40~65 등 운영 기능은 삭제하지 않는다. 이번 묶음은 생성 직후 관리 CP77까지이며 그 안의 수정·가입 관리 목적지는 다음 리메이크 묶음이다. 기존 CP01/03/71/72는 연결 참고로 동봉했다. 전체104경로 감사는 완료되지 않았다.

## 2. 시각 구성과 재사용

배경 #031427, 패널 #0B2B50, 강조 #0754FF, 정보 강조 #48D9FA, 본문 #F5F8FF를 사용한다. 큰 주 버튼은 흰 면과 파란 하단면을 유지한다. 오류는 좁은 필드 테두리와 문구로, 초안 삭제는 연한 코랄 버튼으로 구분한다. 대표 이미지의 크루 고유색은 유지한다.

공통 로고는 프로젝트 원본을 그대로 사용한다. CP01 배경의 로고를 새로 그리지 않는다. 생성·크롭·관리의 집중 화면에는 SUP나 하단 전체 탭을 추가하지 않는다. 목록 뒤 시트는 호출 화면을 유지한 채 어둡게 덮는다. 시트 본문은 불투명 남색이어야 한다.

화면 전체 PNG를 배경으로 깔고 투명 버튼을 얹는 방식은 금지한다. 글자·수치·입력·선택·버튼·목록은 실제 Compose 요소로 만들고, 사진이나 대표 그림만 이미지로 쓴다. 시안의 시계·홈 바를 앱에 그리지 않는다. 공통 헤더·버튼·시트·지역 선택·입력 필드를 재사용한다.

design-tokens.json은 구현용 제안 값이다. 기존390dp 기준, 좌우20dp, 주 버튼56dp, 터치 최소48dp로 시작하고 작은 기기와 큰 글자에서 맞춘다. 내용은 스크롤하되 고정 버튼·IME·시스템 하단 영역과 겹치지 않게 한다. 주 버튼은 한 화면에서 하나만 우선 강조한다.

## 3. 만들기 단계와 입력

소개 CP26 → 러닝 방식 CP31 → 모집 CP33 → 미리보기 CP34 → 서버 생성 성공 CP35 순서다. CP26의 채워진 내용은 예시이며 첫 사용자는 빈 초안에서 시작한다. 두 번째 이후 단계의 뒤로는 직전 단계다. 첫 단계에서 변경된 내용을 두고 나갈 때 CP38을 띄운다.

현행 CrewRules를 따른다. 이름은 앞뒤 공백을 제외한1~40자, 한 줄 소개120자, 크루장 한마디300자, 정원1~9999명, 주간 목표1~99999km다. 이름 중복을 금지하는 새 규칙을 넣지 않는다. CP36은 빈 이름의 실제 검증 예시다. 선택 항목을 임의 필수로 바꾸지 않는다. 입력 오류는 해당 필드 가까이 설명하고 초점을 이동할 수 있게 한다.

거리 선택은 한 개 또는 없음이다. 분위기는 현행 toggleMood의 독립 선택/해제다. 초보 환영 등을 선택했을 때 기존 입력을 지우지 않는다. 예시3~5km,20명,100km를 정책으로 고정하지 않는다. 크루 가입 정원과 크루 달리기 한 세션30명 한도를 구분한다.

지역은 공유 검색 CP03의 실제 결과를 반환한다. 목록 필터 변경과 초안 지역 입력은 다른 호출자다. 지역 변경 후 이름·이미지·다른 입력을 유지한다. 좌표가 없으면 공덕동 예시 좌표를 추측해서 채우지 않는다.

CP32는 적용을 눌러야 초안이 바뀐다. 요일은 복수 선택, 시간은 OS 선택기다. ‘정기 일정 없음’은 요일·시간을 모두 비우는 버튼으로 명확히 표현한다. 요일 없이 시간만 남기지 않는다. CP88은 생성 초안의 목표만 바꾸며 기존 크루 목표 API를 호출하지 않는다. 기존 크루의 직접 목표 수정은 CP46으로 이어진다.

## 4. 대표 이미지

CP27에서 사진 선택과 기본 이미지 선택을 제공한다. 현재 사진이 있을 때만 삭제 행동을 추가한다. 삭제하면 이름형 이미지로 돌아간다. Android Photo Picker를 사용하고 취소하면 기존 이미지를 보존한다. 광범위 사진 접근 권한을 모든 사용자에게 선요청하지 않는다.

CP28은 사용자가 사진을 고른 별도 분기다. 다른 화면의 이름형 기본 이미지와 동시에 저장하는 것이 아니다. 원본 사진을 팬·핀치로 맞추고 실제 정사각형 좌표로 크롭해 적용한다. 현행 결과512px 저장 방식을 보존한다. 처리 중에는 적용 중복을 막고 완료 전 기존 이미지를 지우지 않는다. 이미지 읽기/저장 실패는 CP29, 접근 불가는 CP69다.

기본 이미지 CP30은4개 바탕 중 하나이며 실제 이름을 앱에서 그린다. ‘공덕 한바퀴’가 들어간 PNG를 모든 크루에 사용하지 않는다. 긴 이름은 적절히 줄바꿈한다. 사진을 고르지 않아도 생성할 수 있다. 실제 권한·설정 창은 OS를 사용한다.

## 5. 미리보기·저장·실패

미리보기의 새 크루1/20명은 입력 예시다. 실제 생성은 버튼을 눌러 서버 성공과 crewId를 받은 뒤 확정한다. 모집 휴식으로 만들 때는 버튼을 ‘크루 만들기’로 바꾼다. 레벨 값이 없으면 ‘새 크루’이며 임의 Lv.1, 경험치, 보상을 만들지 않는다.

생성 요청 중 입력과 주 버튼을 잠그고 진행 상태를 표시한다. 동일 clientKey를 보존하며 결과 불명 타임아웃은 기존 서버 계약에 따라 같은 요청을 확인한다. CP37은 일반 실패여서 미리보기에서 다시 저장한다. 이름/소개/이미지 오류는1단계, 지역/일정 오류는2단계, 정원/목표 오류는3단계로 돌아가 해당 오류를 보여준다. 입력과 이미지, 성공하지 않은 초안을 보존한다.

CP35에서 관리 CP77 또는 새 크루 채팅으로 이어진다. 채팅은 생성된 동일 crewId를 사용한다. 생성 API 성공 전에 멤버·소유권·채팅 생성 완료를 가정하지 않는다.

## 6. 초안 보존과 삭제

CP38의 ‘저장 후 나가기’는 초안 저장 완료 후 이동한다. ‘계속 작성’, 닫기, 취소는 현재 값을 유지한다. 저장 오류가 나면 입력을 버리거나 나간 것처럼 보이지 않게 해야 한다. 현행 코드의 keepDraft에 전용 실패 UI가 검증되어 있는 것은 아니므로 오류 복구는 구현 확인 대상으로 남긴다.

CP39의 ‘이어서 만들기’는 저장된 단계·이름·이미지·선택값을 복원한다. ‘새로 만들기’는 즉시 지우지 않고 CP78로 간다. CP78 확인 후에만 해당 생성 초안을 삭제하고 빈 초안을 시작한다. 취소하면 CP39와 초안을 유지한다. 실제 크루 해산·탈퇴와 다른 동작이다. 사진 파일은 다른 저장 초안에서 사용하는지 확인한 기존 수명 관리 규칙을 보존한다.

CP39/78 시안 배경은 목록 진입 예시다. 운영 크루 선택 CP25에서 열었다면 실제 호출 화면을 배경으로 유지한다. 다른 페이지를 임의로 목록으로 바꿔치기하지 않는다.

## 7. 생성 직후 관리

CP77은 created=true 변형이다. 가입 신청, 소개 수정, 모임 정보 수정, 모집 설정, 주간 목표, 크루 채팅의6행과 목록으로 돌아가기 버튼을 둔다. 신청0건은 빈 신청 목록으로 연결된다. 일반 관리 CP40에는 기존 멤버 관리·운영 설정이 있으며 이 시안 때문에 없애지 않는다.

관리 화면마다 서버에서 실제 크루장 권한을 확인한다. 권한이 사라진 경우 기존 읽기 전용 복귀 안내를 보존한다. 크루장 나·새 크루·1명·0건은 예시 데이터다. 다른 크루로 이동하면 그 크루의 값으로 바뀌어야 한다.

## 8. 검수와 남은 작업

19개 상태별로 실제 기기 캡처를 만든다. 긴 이름·빈 이름·선택 입력 생략·모집 휴식·목표 없음·사진 취소/실패·키보드 표시·작은 화면·큰 글자·뒤로·임시저장 복원·중복 탭·인증/권한 변경을 확인한다. 현재 계정·저장소를 초기화해서 예시를 맞추지 않는다.

이 패키지에서 확인한 것은19장 개별 시각 검수와 파일/압축 무결성이다. 실제 앱·API·접근성·애니메이션 검증은 수행하지 않았다. 사진 로딩/처리 중, 생성 전송 중, 수정 데이터 로딩/실패, 초안 저장/삭제 오류, 관리 권한 변경 등 추가 상태는 audit/additional-state-audit.json에 남겼다. 기본 상태 이미지가 있다는 이유로 이 상태까지 제작 완료로 보고하지 않는다.

결과 보고에는 변경 파일, 구현한 CP 상태, 실행한 확인, 남은 연결·제약을 적는다. 새 시안을 앱 구현 완료의 증거로 제출하지 않는다.
