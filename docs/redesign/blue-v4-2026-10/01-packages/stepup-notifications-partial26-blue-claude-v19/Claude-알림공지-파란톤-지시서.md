# StepUp 알림·공지 26개 상태 · Claude 구현 지시서

최신 승인 남색·전기 파랑 톤을 기존 Android 알림·공지 기능에 적용한다. NOT01~26의 정적 시안 26개이며 기존 기본23장과 추가 NOT24~26을 합친 중간 전달본이다. NOT27~46의20개는 미제작이다. 이 문서·화면별동작.md·screen-index.json·PNG를 함께 읽는다. 앱 구현·실행 검증 완료본이 아니며 기존 예외 분기를 삭제하지 않는다.

## 화면과 공통 구성

- 배경 #031427, 표면 #0B2B50, 전기 파랑 #0754FF, 청록 #48D9FA, 글자/주 버튼 #F5F8FF, 보조 글자 #ABC7EF. 기존 Pretendard를 사용한다.
- 이 묶음은 보조 화면이다. SUP 잔액 알약이나 STEPUP 로고를 별도로 추가하지 않는다. 원본 로고는 다른 루트 화면에서 그대로 유지한다.
- 알림함은 뒤로/알림/설정 헤더와 내 알림/공지 글자 탭. 선택 밑줄은 글자 아래 짧게 둔다. 작은 종류 아이콘·본문·시간·읽지 않은 점·이동 화살표의 단순 목록을 사용한다.
- 알림·공지 상세는 AppChromePolicy의 Profile/Detail이다. 러닝·신발·뽑기·커뮤니티·내 정보 5탭을 유지하며 내 정보가 선택된다. 커뮤니티는 여러 사람, 내 정보는 한 사람 아이콘이다. PNG의 시스템 표시줄은 예시이고 실제 OS에 맡긴다.
- 내용 시트는 탭까지 덮고 뒤 목록을 어둡게 한다. 읽기/응답 기능은 다른 페이지를 겹쳐 만드는 대신 같은 시트의 상태로 처리한다. 거절 확인은 X 없이 취소, 일반 시트는 X/뒤로/바깥/드래그 닫기를 유지한다. 거절 저장 중만 기존 dismissible 제한을 따른다.
- 한 화면에 흰 주 버튼은 하나다. 보조 버튼은 남색 테두리 또는 텍스트로 구별한다. 48dp 이상 터치 영역, 큰 글씨에서 줄바꿈·스크롤, 시스템 하단 여백을 확보한다. 핵심 버튼을 말줄임으로 자르지 않는다.
- PNG는 배치·색감 참고다. 글자·아이콘·탭·시트·버튼은 실제 Compose UI로 구현한다. 화면 전체를 PNG로 붙이지 않는다. Figma 레이어나 모든 분리 신규 자산이 있는 전달물이 아니다.

## 알림 목록과 읽음

NotificationRepository/NotificationDao의 로컬 목록을 사용한다. 본문은 NotificationType와 저장된 인자를 표시 시점에 현지화한다. 날짜는 현재 시간대에 맞춰 오늘/어제/이전을 나누고 탭별 스크롤 위치를 보존한다. 목록 한도100개와 저장소 전체의 읽지 않은 수가 같은 의미는 아니다.

알림함에 들어온 것만으로 읽음 처리하지 않는다. 사람이 모두 읽음을 눌렀을 때 그 시점 newestId까지만 읽음 처리한다. 처리 도중 도착한 새 알림은 읽지 않은 상태로 남는다. 모두 읽음은 행 삭제·초대 응답·보상 지급과 별개다. NOT02는 행을 그대로 두고 점만 제거한 상태다.

개별 내용을 열면 해당 알림만 읽음 처리한다. NOT03/04/14는 그 결과로 새 알림 수가2개로 줄고 해당 행의 점이 사라진 예시다. 저장 실패 시 읽음 성공을 꾸미지 않고 실제 저장 상태를 유지한다. 내용을 열 수 있어도 읽음 저장만 실패할 수 있다. 이 조합은 추가 NOT40으로 따로 남겼다.

로딩은 NOT11의 스켈레톤, 참 빈 목록은 NOT10, 초기 조회 실패는 NOT12다. 로딩을 빈 목록으로 표시하지 않는다. 모두 읽음 저장 실패는 NOT13처럼 기존 행·미읽음 점을 유지하며 안내한다. 알림 설정에서 OS 푸시가 꺼져 있어도 내부 알림함의 내용을 임의 삭제/잠금 처리하지 않는다.

설정의 알림 기록 지우기 clearAll/clearExceptPendingActions와 혼동하지 않는다. 그 기능은 미응답 크루/파티 초대와 미처리 이벤트 보상을 보존하는 별도 정책이다. 이번 알림함에 새 일괄 삭제 버튼을 추가하지 않는다.

## 알림 종류별 내용

NOT03은 저장된 적립 내용이다. 지금 잔액으로 덮어쓰거나 다시 받기 버튼을 만들지 않는다. 금액 표시는 아래 showsAmount 보정 기준을 따른다. 금액 없는 기록은 제작된 NOT25를 사용한다.

NOT04는 알림에 저장된 모델 이름을 보여준다. 모델 이름이나 slotKey는 소유 신발의 고유 ID가 아니다. 보유 목록으로 이동하고, 임의의 한 켤레 상세·즉시 착용·중복 지급을 만들지 않는다.

NOT09는 처리하지 않은 EVENT_REWARD의 지급 미확인 안내다. 알림에 금액이 있다는 이유로 지급 가능·완료를 확정하지 않는다. 챌린지에서 기존 실제 자격/지급 상태를 확인하며 알림창에서 로컬 보상을 만들지 않는다. 이미 actioned인 이전 보상 등 GeneralSheet는 저장된 내용과 확인만 제공한다.

댓글은 실제 게시물 접근 가능 여부를 먼저 확인한다. 서버가 삭제/비공개라고 확인한 경우만 NOT14를 표시한다. 통신 실패와 로그인 필요는 별도 토스트이며 읽음 처리하지 않는다. 이 추가 장면은 NOT41/42다. 내용이 열리는 댓글은 현재 focusComment 동작으로 연결한다.

## 크루 초대와 함께 뛰기

읽음(read), 응답(actioned), 실제 크루 가입은 다른 상태다. 시트 열기·크루 보기·대기실 보기·닫기만으로 수락하지 않는다. 크루명과 대상ID는 저장된 실제 값이다. 예시 여의도 러너스/민수를 서비스 데이터에 심지 않는다.

NOT05 초대 수락은 기존 acceptCrewInvitation→crewRepository.join 결과를 따른다. 서버가 Joined를 확인하면 가입 완료, Requested면 NOT06 승인 대기다. NOT07은 처리되지 않았다고 확인한 실패이므로 다시 수락할 수 있다. 응답을 못 받아 결과를 모르는 경우는 NOT29/30이며 가입 상태부터 확인한다. 이를 NOT07로 대체하면 중복 가입 요청 위험이 있으므로 별도로 보존한다.

이미 응답한 알림을 다시 열 때 현재 서버 크루 목록의 Joined/Requested/Answered를 확인한다. 대상 ID가 없으면 없는 경로를 만들지 말고 해당 현재 분기의 확인/닫기 동작을 유지한다. 처리 중에는 응답 버튼 연타를 막으며, 닫았다고 서버 요청이 취소됐다고 단정하지 않는다.

NOT08 함께 뛰기 초대의 수락하고 보기는 이 기기의 알림에 수락 표시를 저장한 뒤 대기실로 이동한다. 실제 참가·준비·출발은 대기실이 서버와 확인한다. 보기만 하는 대기실 보기와 구별한다. 수락 표시 완료/저장 실패/대기실 ID 없음/저장 중은 추가 NOT33~35/46이다.

NOT21 거절 확인은 기존 시트 내용만 바꾼다. 거절 성공 시 해당 초대 알림만 삭제하고 완료를 알린다. 크루 탈퇴나 러닝방 참가 취소 기능이 아니다. 파티 초대는 보낸이와 대기실 상태가 바뀌지 않는다는 문구로 대체한다. 거절 처리 중/실패/성공 목록은 NOT31/32/43으로 추가 제작한다.

NOT22 로그인은 초대를 처리하지 않은 채 로그인으로 보낸다. 돌아오면 같은 초대를 다시 열되 자동 수락하지 않는다. 취소해도 초대는 남는다. 초대가 중간에 삭제되었으면 억지로 복원하지 않는다. 현재 returnToSignIn 실패 안내도 보존한다.

## 공지 데이터와 상세

AnnouncementRepository의 운영자 공지만 표시한다. 외부 러닝 뉴스·대회와 별개다. NOT15/16의 제목·본문·날짜는 시안 예시다. 클라이언트에 예시 공지를 초기 데이터로 삽입하지 않는다.

실제 서버의 언어별 제목/본문·게시일·허용된 NoticeAction을 따른다. 본문의 소제목/문단/구분선은 noticeBlocks 규칙으로 읽기 좋게 표시한다. 임의 중요/NEW 배지나 가격·보상 이미지를 추가하지 않는다. action이 없거나 지원하지 않는 값이면 CTA도 없다(NOT45).

공지 목록의 참 빈 상태는 NOT17, 사본 없는 초기 실패는 NOT18, 로딩은 NOT20이다. 새로 고침 실패 시 저장된 목록을 유지하고 NOT23의 인라인 배너/다시 버튼을 제공한다. 배너가 있을 때 중복 의미의 'StepUp의 새로운 안내' 소제목은 생략할 수 있다. 저장된 빈 목록과 갱신 실패의 조합은 NOT44다.

상세는 목록에서 받은 내용을 먼저 보여주고 서버에 다시 확인한다. 서버가 공개된 내용을 주지 않는다고 확인하면 NOT19로 전환하고 캐시에서도 제거한다. 통신 실패일 뿐이면 기존 사본을 유지한다(NOT38). 사본도 없으면 상세 조회 실패(NOT37), 아직 대기라면 상세 스켈레톤(NOT36)이다. 이 구분을 단일 '볼 수 없음' 화면으로 합치지 않는다.

NOT16 무료/상급 뽑기 안내는 예시 공지 본문이다. 지갑 연결 준비 상태 문구를 포함했지만 실제 운영자 공지·기능 상태가 기준이다. 이동 버튼을 눌러도 자동으로 뽑거나 보상을 지급하지 않는다.

## 구현·검증과 남은 범위

NOT01~26의 최신 PNG가 현재 묶음의 구현 기준이다. NOT27~46은 audit/notifications-additional-states.json 및 추가제작-20개.md에 남았다. 미제작 분기를 삭제하거나 비슷한 그림으로 처리 완료 선언하지 않는다. 전체 앱104경로 대조와 다른 기능 추가 상태 감사도 아직 남아 있다.

현재 checkout의 AGENTS.md/CLAUDE.md와 작업 중 변경을 먼저 확인한다. 실제 구현 여부는 이 전달 작업에서 검증하지 않았으므로 implementation-checklist.csv는 미확인으로 시작한다. 앱 코드를 변경한 결과나 커밋·푸시·실행 테스트 결과가 포함된 전달물이 아니다.

구현 시 NotificationsDesignTest/NotificationPersistenceTest/NotificationNavigationTest 등 기존 검증을 확인하고, 실제 기기 캡처로 다음을 점검한다: 다국어·큰 글씨·긴 제목, 시트 버튼 잘림, 5탭/헤더 중복, 읽음 저장 실패와 새 알림 경쟁, 초대 승인/대기/미확인 분기, 로그인 복귀, 공지 철회/캐시/오프라인 구분, 시트 포커스와 뒤로 복귀. 현재 코드·서버와 문서가 충돌하면 차이를 기록한다.

시각 검수는 정적 이미지에 대한 것이다. 모든 행동이 앱에서 검증됐다고 보고하지 않는다. PNG 파일 무결성·문서 링크 검사와 런타임 검증을 구분한다.
## 이번 전달에서 보완한 데이터 기준과 추가3개

현재 NotificationsScreen.kt의 showsAmount(entity)는 `entity.type == EVENT_CLAIMED || !ServiceLocator.serverEconomyOn`이다. serverEconomyOn=true에서는 예전 로컬 REWARD_EARNED/GOAL_REACHED/PARTY_FINISHED/COURSE_COMPLETE 기록을 현재 서버가 인정한 적립금으로 보여주지 않는다. EVENT_CLAIMED 등 실제 허용된 유형과 서버 상태만 금액을 표시한다. 목록 messageFor와 시트 showsAmount 양쪽에 동일 조건을 적용한다.

NOT03 및 일부 시트 뒤 목록의 “2.40 SUP가 적립됐어요”는 비서버 보상 모드의 기존 예시다. 그 배경 문구를 현재 모드에 그대로 복제하지 않는다. 현재 서버 경제의 과거 러닝 기록은 NOT25처럼 “2,400걸음 러닝 기록”으로 보여준다. 숫자는 실제 저장값이고 SUP 적립을 새로 확정하는 동작이 없다.

NOT24는 GeneralSheet다. 예시 “부스트가 활성화됐어요”와 저장 시각, 확인만 제공한다. 확인/X/뒤로/바깥 닫기는 목록 복귀다. 부스트를 다시 지급하거나 새 목적지를 만들지 않는다.

NOT25는 RewardSheet의 showsAmount=false 분기다. 제목 “기록 알림”, 실제 기록 문구와 일시, 지갑 보기 하나다. 목록에서도 해당 금액을 숨기고, 개별 읽음 저장이 성공한 만큼만 새 알림 수/점을 변경한다. 지갑 이동은 보상 수령과 다르다.

NOT26은 실제 Joined 결과다. 서버 가입 완료 확인 후만 체크와 “크루에 가입했어요”를 표시한다. 크루 보기는 현재 크루 상세로 이동한다. ID가 없으면 확인으로 닫는다. Requested/Answered/Unknown을 이 성공 화면으로 대신하지 않는다. 미제작 NOT27~46까지 완성되었다고 보고하지 않는다.
