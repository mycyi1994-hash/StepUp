# StepUp · 코스 첨부 글쓰기 구현 지시서

## 목적과 기준

기존 커뮤니티의 목록형과 쉬운 글쓰기를 유지하면서 승인된 남색·전기 파랑 톤으로 바꾼다. 본문 하나, 공개 장소, 선택 가능한 러닝 기록으로 글을 올릴 수 있어야 한다. 제목·분류를 먼저 입력시키는 단계는 만들지 않는다.

이 패키지는 기존 `StepUp-Claude-커뮤니티기본43장-파란톤-지시서.zip`에 이어지는 20개 상태다. 새 페이지 20개를 만들라는 의미가 아니다. 작성 화면 하나의 조건, 두 선택 시트, 게시 후 목록·상세로 구성한다. `screen-index.json`의 진입 조건과 `화면별-동작.md`를 같이 읽는다.

우선순위는 최신 사용자 결정 → 이 패키지의 동작 명세 → PNG의 배치·색감 → 예전 화면이다. 현재 기능·데이터·인증을 보존하고 실제 코드와 다른 점은 아래 두 변경 요구를 반영한다. 데이터 계약이 불명확하면 성공한 것처럼 그리지 않는다.

## 시각 구성

배경 #031427, 패널 #0B2B50, 파랑 #0754FF, 밝은 시안 #48D9FA, 본문 #F5F8FF를 사용한다. 다른 앱처럼 검은색·회색만으로 단순화하지 않는다. 둥근 패널과 얇은 파랑 경계, 큰 흰색 주 버튼의 파란 하단면을 맞춘다. 프레임마다 다른 색·아이콘 스타일을 만들지 않는다.

작성 순서는 기록 칸 → 공개 장소 → 최대 세 개 장소 버튼 → 네 개 문구 버튼 → 편집 가능한 본문 → 안내 → 주 버튼이다. 화면 아래 키보드·시스템 바의 안전 영역을 확보한다. 작은 화면과 큰 글자에서는 본문을 스크롤하고 주 버튼을 찌그러뜨리지 않는다. 기본 폭 390dp, 터치 영역 최소 48dp, 본문 16sp부터 맞추고 실제 기기에서 검증한다. PNG의 px를 dp로 그대로 옮기지 않는다.

시트는 불투명 남색 면이며 배경 전체에 동일한 어두운 가림을 적용한다. X/뒤로는 작성 내용을 보존한다. 항목은 충분한 터치 높이로 만든다. 원형 그림문자나 캐릭터를 추가하지 않는다. 오류는 색만 쓰지 말고 읽을 수 있는 문장으로 표시한다.

WRITE12 목록은 공식 STEPUP 로고와 3개 커뮤니티 탭, 5개 하단 탭을 유지한다. 원본 로고 파일을 재사용하며 다시 그리지 않는다. 나머지 상세/작성/선택에는 SUP 잔액, 로고, 하단 탭을 반복하지 않는다. 모든 탭과 헤더는 현행 공통 컴포넌트/노출 정책을 통해 연결한다.

## 기록과 장소

1. 새로 붙일 수 있는 기록은 **서버가 확인한 본인 완료 기록 중 한국 날짜로 오늘~3일 전**이다. 72시간 계산이 아니다. 2026-10-03 기준 9월 30일은 가능, 9월 29일은 불가능하다. 서버가 준 오늘 기준을 우선하고 돌아오거나 게시하기 전 재검증한다. 앱 시계를 바꿔 우회하도록 만들지 않는다.
2. 기존 게시물에 이미 붙은 기록(`kept`)은 3일이 지나도 유지한다. 수정한다고 지우거나 다시 선택하게 하지 않는다. 새 첨부를 교체할 때만 현재 기간·소유권을 검사한다.
3. 날짜 필터는 전체/오늘/어제/2일 전/3일 전이다. 행 또는 붙이기를 한 번 누르면 바로 작성으로 돌아온다. 3일 이전 기록은 과거 기록 목록에서 읽을 수 있지만 새 첨부 후보로 넣지 않는다.
4. 유효 GPS 경로가 없으면 지도 없이 확인된 거리·시간만 보여준다. 실제 값이 없으면 감추거나 미측정으로 표시한다. ‘3.24km’처럼 시안 수치를 임의 생성하지 않는다. 장소 선택은 여전히 가능하고 코스 주변 버튼은 표시하지 않는다.
5. 코스 주변/내 주변/최근 장소/직접 검색의 우선순위로 최대 세 개를 노출한다. 최근 장소가 없으면 숨긴다. 검색 진입은 장소 선택 시트에서도 항상 제공한다. 주변 권한이 없으면 WRITE07로 검색·지도 선택·설정을 제공한다.
6. 공개할 장소와 작성자 실시간 위치는 다르다. 사용자가 지정한 장소를 표시한다. 내 위치를 모르면 거리나 파란 현재 위치 점을 지어내지 않는다. 수동 지역 기준이면 거리 기준을 명시한다. 게시했다고 목록의 선택 지역을 바꾸지 않는다.
7. 확정된 장소 목록/검색 결과는 한 번 탭하면 `setPlace` 후 작성으로 복귀한다. 현행 `StoryComposeScreen.kt`는 검색 결과도 CONFIRM으로 보내므로 이 부분은 변경해야 한다. 지도에서 임의 좌표를 직접 고르는 경우에만 CM15 확인을 남긴다.

지도의 그림은 모두 구도 예시다. 기존 지도 공급자·타일·저작권 표기와 공개 경로 데이터를 사용한다. 같은 기록 ID는 선택·작성·목록·상세에서 동일한 경로/수치를 재사용한다. 생성 이미지 간 세부 선 모양 차이를 새로운 경로로 구현하지 않는다.

## 쉬운 작성과 초안

문구 버튼은 편집 가능한 시작 문장을 넣는다. 빈 본문 또는 앱이 넣은 문장 그대로인 경우 교체할 수 있다. 사용자가 직접 수정한 본문에는 덮어쓰지 말고 한 줄 아래 한 번만 붙인다. 같은 문구를 반복 탭해 중복 추가하지 않는다.

기록을 고를 때 실제 날짜·거리로 기본 문장을 만들 수 있으나 기존 사용자 문장을 덮어쓰지 않는다. 공개 장소도 명확한 후보가 없으면 자동 확정하지 않는다. 시안의 줄바꿈은 자동 줄바꿈이며 본문 첫 문장을 둘로 쪼개 제목이 사라지게 만들지 않는다. 목록 제목은 기존처럼 본문 첫 줄/문장에서 파생한다.

일반 글은 공개 장소와 공백이 아닌 본문이면 게시할 수 있다. 유효 첨부가 있고 본문이 비었다면 실제 기록에서 만든 기본 문장을 사용자에게 미리 보여준 뒤 기존 규칙에 따라 게시한다. 만료/사용 불가 첨부는 교체하거나 빼기 전 게시를 막는다. 로딩·기록 조회 실패·진행 중·서버 확인 대기는 일반 글 작성을 막는 조건이 아니다.

첨부를 빼거나 교체해도 사용자가 쓴 본문과 선택 장소를 지우지 않는다. 과거 거리 언급이 남아도 자동 수정하지 않는다. 게시 시 데이터 검증 실패는 입력 보존 후 안내한다. 초안에서 러닝 시작·기록 보기·인증 등으로 이동하기 전에 계정별로 저장하고 복귀 시 복원한다. 저장 실패를 성공 처리하지 않는다.

뒤로/나가기는 CM20 임시저장·계속 쓰기·버리기, 재진입은 CM21을 재사용한다. 초안 복원 시 첨부 날짜·유효성을 다시 검사한다. 다른 계정으로 바뀌면 다른 사람의 초안과 첨부를 자동 게시하지 않는다.

## 상태 판정과 게시

WRITE01은 조회 성공 및 서버/로컬 완료 기록 없음이 확인된 경우다. WRITE02는 오래된 마지막 완료 기록이 실제로 있는 경우다. 판정 근거가 부족하면 WRITE11의 중립 문구를 사용한다. 조회 실패나 아직 서버 확인 중인 기록을 ‘한 번도 달리지 않음’으로 잘못 분류하지 않는다.

최초 조회 중은 WRITE14, 진행 중이고 붙일 완료 기록이 없으면 WRITE15, 서버 확인 전 최근 로컬 기록이면 WRITE18이다. 기존 첨부가 이미 있다면 조회 재시작/실패 때문에 이를 지우지 않는다. 상태 우선순위는 현행 `StoryComposeRules.card`를 확인한다.

올리기 요청 중에는 기존 CM17에 현재 코스·본문·장소를 유지하고 중복 탭을 막는다. 확정 성공 후에만 WRITE12 목록/WRITE13 상세와 실제 개수를 갱신한다. 필터 밖에 있는 글을 현재 목록에 억지로 삽입하지 않는다. 실패는 WRITE08, 만료는 WRITE04, 첨부 사용 불가는 WRITE19, 인증 문제는 WRITE20이다. 결과 불명일 때는 같은 요청의 성공 여부부터 조회해 중복 글을 만들지 않는다.

WRITE20은 **‘로그인하고 계속 쓰기’ 하나만 주 버튼**으로 보여준다. 현행 SIGN_IN 분기는 재로그인 버튼 옆에 게시 버튼도 남길 수 있으므로 가시성을 조정한다. 로그인 성공 후에는 초안을 복원해 사용자가 다시 올리게 한다. 로그인 자체가 게시 동의가 아니다.

WRITE13의 달린 기록은 읽기 전용 공유 요약이다. 현재 `StoryRunCard`에도 클릭 이동이 없다. 공개 장소 카드의 확대는 CM06으로 연결한다. 작성자의 사적인 내 기록 페이지나 전체 위치 기록을 타인에게 열지 않는다. 내 글/타인 글 메뉴와 댓글·좋아요·삭제·수정·신고는 기존 공통 화면을 재사용한다. 이미 게시된 첨부 수정은 이 카드 구도를 유지하고 버튼을 ‘수정 완료’로 바꾸는 조건 변형이다.

## 구현 검증

- WRITE01~20 각각의 진입 조건을 테스트 데이터로 재현한다. 만료 직전/날짜 변경 직후, 서버 날짜/기기 날짜 차이, 이미 게시된 첨부 수정도 확인한다.
- 같은 기록의 거리·시간·경로가 선택→작성→게시 목록→상세에서 같아야 한다. 러닝 2.10km와 장소까지 2.6km를 같은 필드로 쓰지 않는다.
- GPS 없음·위치 거부·최근 장소 없음·조회 실패에서도 일반 글이 작성되는지, 장애가 필수 입력을 지우지 않는지 확인한다.
- 인증 후 초안 복귀, 중복 탭, 게시 응답 유실, 재시도 때 중복 생성 여부를 확인한다.
- 한국어 긴 문구, 320/360/390dp, 큰 글자, 키보드, 시스템 하단 바에서 잘림/겹침을 확인한다. 캡처의 OS 상태바 자체를 앱에 그리지 않는다.
- 로그아웃/삭제/설정 등의 기존 동작을 없애지 않는다. 모션은 즉각적인 버튼/시트 피드백 정도로 제한하고 줄이기 설정을 따른다.

이 전달본은 정적 시안 눈검수와 파일 무결성만 확인했다. 앱 빌드·기기 동작·서버 연동 검증은 수행하지 않았다. 구현 후 실제 캡처로 다시 확인해야 한다. 추가 장소 API/글 상세 통신 오류 및 전체 104개 경로 누락 감사는 별도 진행 항목으로 남아 있다.
