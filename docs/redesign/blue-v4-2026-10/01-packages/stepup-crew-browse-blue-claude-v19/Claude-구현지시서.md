# StepUp 크루 둘러보기·가입 38장 구현 지시서

기존 크루 명함형의 정보와 동작을 유지하며 승인된 남색·파랑 톤으로 바꾼다. 커뮤니티에는 러닝 이야기 / 크루 모집 / 크루 채팅이 있고, 이번 범위는 크루 모집의 둘러보기·가입이다. 새 기능과 권한을 이미지에서 추측해 추가하지 않는다.

## 1. 적용 우선순위

현재 사용자의 명시 요구 → 이 문서의 상태·데이터 규칙 → 최신38장 PNG의 배치 → 기존 앱의 연결·정책 순서로 해석한다. 이미지 예시 값이 서비스 규칙을 덮어쓰지 않는다. 실제 권한/API와 충돌하면 기능을 가짜로 완성하지 말고 충돌 지점을 기록한다. 오래된 크루 패키지의 검정/초록 톤은 사용하지 않는다.

현재 프로젝트는 Android 코드 기준으로 확인했다. 기존 Compose 구성·인증·화면 경로·ViewModel·API를 재사용한다. 현재 작업 브랜치와 저장소 지침을 먼저 읽는다. 이 자료만 보고 별도 웹페이지를 만들지 않는다.

## 2. 고정할 외형

공식 `assets/STEPUP-원본로고.png` 또는 앱의 동일 원본을 그대로 사용한다. 다시 그린 글자로 교체하거나 로고 비율·색을 바꾸지 않는다. 공통 바탕 #031427, 면 #0B2B50, 강조 #0754FF, 정보 #48D9FA, 글자 #F5F8FF다. 크루가 올린 이미지의 고유 색은 보존한다.

크루 목록은 대표 이미지·크루 이름 → Lv./현재 인원과 정원 → 한 줄 소개 → 지역·정기 일정·러닝 방식 → 크루장 → 주간 목표 순서다. 서로 다른 크루의 개성은 실제 이미지·소개·활동 정보로 드러낸다. 전부 동일한 신발 그림이나 같은 예시 크루로 치환하지 않는다.

레벨은 단순 Lv. 표기, 인원은 읽기 쉬운 숫자다. 금색 왕관·방패·가짜 등급·XP·이모티콘 장식은 추가하지 않는다. 기존 일관된 벡터 아이콘을 사용한다. 카드의 얇은 파란 경계, 흰 주 버튼의 파란 하단면을 유지한다. 불필요한 자동 반짝임은 넣지 않는다.

`design-tokens.json`을 출발점으로 기존 앱 토큰에 연결한다. 화면 폭390dp 기준이지만 887px를 dp로 복사하지 않는다. 한국어 본문은16sp부터, 보조14sp부터 시작하고 실제 긴 문장으로 확인한다. 레벨·인원·크루장·중요 행동을 잘라내서 높이를 맞추지 않는다.

## 3. 공통 영역과 스크롤

목록(CP01/05/06/07/91/95)에만 로고·커뮤니티3탭·하단5탭을 함께 둔다. 상세·검색·멤버·신청은 뒤로가기가 있는 집중 화면이다. 상세 아래에 전체 탭을 다시 넣지 않는다. 이 범위에는 SUP 잔액 알약이 없다.

목록 상단의 지역·정렬 줄은 고정하고 카드 목록이 스크롤한다(CP95). 기존 코드에서 필터도 LazyColumn 안에 있었으므로 고정 영역과 목록 영역을 나눌 때 높이가 겹치지 않게 한다. 마지막의 번개 모임·같이 달리기 진입은 보존한다. 시안의 적은 카드 수를 실제 결과 수로 제한하지 않는다.

정상 목록은 모집하기가 주 버튼 하나다. 빈 목록/오류/로그인 필요에서는 범위 변경/재조회/로그인을 주 버튼으로, 모집하기는 보조 행동으로 둔다. 화면 아래 큰 모집 버튼을 또 중복하지 않는다.

CP94는 멤버 상세의 하단이며 별도 탭이 아니다. 채팅·같이 달리기 대기실·크루 게시판을 기존 목적지에 연결한다. 크루장도 기존 활동 연결을 유지한다. 스크롤했다고 역할·인원·주간 수치가 바뀌면 안 된다.

상태 표시줄·제스처 바는 OS에 맡기고 시안의9:41이나 막대를 그리지 않는다. 콘텐츠 아래에는 고정 버튼 높이와 하단 안전 여백을 확보한다. 키보드가 떠도 신청 입력과 제출이 접근 가능해야 한다. 큰 글자/작은 화면은 스크롤로 해결한다. 시트는 불투명 남색이며 배경은 한 번만 어둡게 처리하고 터치를 막는다.

## 4. 데이터와 역할

`crewId`, `leaderId`, `memberId`, `applicationId`, `viewerRole`, `returnTo`, 목록 조건과 스크롤, 신청 초안·작업 상태를 이동 동안 보존한다. 같은 크루 카드와 상세는 같은 원본을 읽는다. 예시 이름·인원을 하드코딩하지 않는다. 대표 이미지·인원·크루장·목표를 탭할 때 카드 전체 클릭이 함께 실행되면 안 된다.

현행 역할 우선순위는 OWNER → MEMBER → PENDING → VISITOR다. 멤버와 크루장은 모집 휴식/정원 마감이어도 기존 권한을 가진다. 방문자는 휴식 → 정원 마감 → 바로 가입(openJoin) → 승인 신청 순으로 하단 행동을 결정한다.

| 관계·상태 | 하단 행동 | 관련 시안 |
|---|---|---|
| 방문자·승인형 모집 | 가입 신청하기 | CP08/14 |
| 방문자·기존 바로 가입 | 바로 가입하기 | CP92/93 |
| 신청 대기 | 신청 내역 보기 | CP20/15 |
| 멤버 | 크루 멤버 보기 | CP21/87/94 |
| 방문자·모집 휴식 | 비활성 모집 휴식 | CP22 |
| 방문자·정원 마감 | 비활성 정원 마감 | CP23 |
| 크루장 | 기존 크루 관리 유지 | 새 시안 다음 묶음 |

CP73은 방문자/대기자 더보기다. 멤버에게는 기존 CP60의 탈퇴 포함 메뉴, 크루장에게는 기존 운영 설정을 사용한다. 미포함 이미지를 이유로 기능을 삭제하거나 모든 사람에게 운영 버튼을 노출하지 않는다.

30명은 이번 예시 정원이다. 크루 달리기 한 세션 최대30명과 크루 가입 정원을 혼동하지 않는다. 현행 정원은 nullable이고 상한은 실제 CrewRules/API를 따른다. 정원이 없는 기존 크루에는 현재 인원만 표시한다.

## 5. 레벨·목표·개성

레벨 값이 없으면 새 크루, 조회 실패가 구분되는 경우 CP68이다. 실패를 Lv.0이나 새 크루로 바꾸지 않는다. 레벨 계산식·포인트·게임 등급을 새로 정의하지 않는다. API가 레벨만 따로 실패하는 상태를 제공하지 않으면 그 상태를 억지로 만든 척하지 말고 적용 여부를 보고한다.

주간 목표는 저장된 목표가 있을 때만 나타낸다. 합계126km/목표160km의 표시 비율은79%, 실제 막대 길이는126÷160, 남은 거리는34km다. 100% 초과 실제 값은 그대로 표시하고 막대만 최대100%로 제한한다. 참여 멤버9명은 전체24명과 다른 목록이다. 순위나 경쟁 점수는 추가하지 않는다.

래스터 시안의 막대 길이를 그대로 베끼지 않는다. 반복 예시의 그림·글자 형태에 작은 차이가 있으므로 실제 대표 이미지와 실제 문자열을 재사용한다. `assets/crew-examples`는 기존 비교용 대표 이미지이며 생성 PNG에서 다시 잘라 쓰지 않는다. 새 이미지가 없는 크루는 앱의 기존 이름형 기본 이미지를 사용한다.

## 6. 지역·정렬·빈 상태

지역과1/3/5km, 가까운/최근/활발한 순은 적용 전까지 임시 선택이다. 닫으면 기존 조건을 보존한다. 직접 고른 지역이 기준이면 가까운 순 설명은 ‘선택한 지역에서 가까운 크루부터’로 표시한다. CP04의 예시 ‘내 주변’ 표현을 수동 검색 지역에 고정하지 않는다.

지역 검색 결과는 실제 검색 결과 ID와 좌표를 반환한다. 목록의 지역 변경과 생성/수정 초안의 지역 입력은 다른 호출자다. 권한이 없어도 이름 검색이 가능하다. CP71은 앱 설명 시트이며 OS 권한 창을 앱 UI로 재현하지 않는다. 이미 허용됐다면 중복 설명 없이 현재 위치를 확인한다.

로그인 필요 CP91, 최초 로딩 CP06, 정상 빈 결과 CP05, 통신 실패 CP07을 구분한다. 상세도 로딩 CP67, 삭제/접근 불가 CP66, 일시 통신 실패가 서로 다르다. 상세 일시 실패에는 현행 CrewDetailFailed의 재시도를 보존한다. 그 상태의 새 정적 시안은 이번38장에 포함되지 않았으며 후속 코드 상태 감사 대상이다.

## 7. 신청·취소·결과

CP14의 빠른 문구는 선택/해제 가능하고 직접 쓴 한마디를 덮어쓰지 않는다. 문구 선택과 한마디를 따로 전송한다. 선택 입력이므로 비어 있어도 신청 가능하다. 현행 한마디 최대300자와 서버 검증을 따른다. 글자 수를 표시한다면 실제 입력 길이를 계산하고 예시 숫자를 복사하지 않는다.

전송 중 버튼은 진행 상태로 바꾸고 연속 탭을 차단한다. 성공은 서버의 대기 상태 CP15/20, 확정 실패는 입력을 보존한 CP17, 모집 변경은 CP24다. 타임아웃으로 결과가 불명확하면 같은 요청 결과를 먼저 확인한다. 화면에서 멤버 수를 먼저 증가시키지 않는다.

CP16 취소 성공 후 최신 상세로 돌아간다. 실패는 대기 상태와 입력을 보존하고 같은 모달에서 오류·재시도를 제공한다. 취소와 승인이 경합하면 서버 최종 상태가 우선이다. 요청 중 창을 닫아도 실행이 취소됐다고 가정하지 않는다.

CP18 승인 뒤 CP87은 서버에서 멤버가 된 것을 확인한 결과다. 24→25는 검수 예시이며 조회 값에 추가로1을 더하지 않는다. CP19 미승인은 통신 실패와 다르고 멤버 권한을 주지 않는다. 새 푸시 시스템을 구현했다고 가정하지 말고 기존 알림/재조회와 연결한다.

기존 openJoin은 CP92에서 직접 가입 요청한다. 신청 양식/대기 단계를 끼워 넣지 않는다. 서버의 Member/Pending/Declined 등 실제 결과에 따른다. 확정 실패 CP93에서는 역할·인원을 유지한 채 같은 버튼으로 재시도한다.

## 8. 이번 전달본 밖의 연결

`flow-map.json`의 externalAndPending을 확인한다. 모집하기는 운영 중인 크루/작성 초안 상태에 맞춰 기존 CP25/26/39로 연결한다. 멤버 공개 프로필 CP56, 멤버 메뉴 CP60/61, 신고 CP64/65, 크루장 운영, 채팅·대기실·게시판과 번개 모임은 기존 기능을 보존한다. 이 패키지에는 목적지의 새 시안이 모두 들어 있지 않다.

재사용 CM01은 러닝 이야기 탭의 연결 참고다. 이번 리메이크로 커뮤니티3탭의 기존 초안·읽던 위치를 지우지 않는다. 하단5탭 역시 기존 목적지로 연결한다.

## 9. 구현 후 확인·보고

각 CP 번호의 조건으로 캡처하고 실제 값이 예시와 다른 것은 허용한다. 작은 화면, 긴 크루명, 여러 줄 소개, 큰 글자, 키보드, 시스템 하단 영역을 확인한다. 고정 버튼이 마지막 행을 가리거나 활성 주 버튼이 두 개 생기지 않아야 한다. 터치영역48dp, 스크린리더 라벨·선택 상태, 색 외의 오류/선택 표시를 제공한다.

가입·취소 중복 탭, 결과 불명, 정원 변경, 인증 복귀, 뒤로가기 입력 보존, 이미지/레벨/크루장 중첩 클릭, 다른 크루 ID 치환을 검증한다. 주간 막대는 실제 수치로 계산한다. 기능별 변경 파일·실행한 확인·남은 제약을 보고한다. 새 시안을 구현 완료나 서버 성공 증거로 제출하지 않는다.

이 자료 제작 단계에서는38장 개별 시각 검수와 파일/압축 검증만 수행했다. 앱 구현·런타임 검증은 아직 수행하지 않았다.
