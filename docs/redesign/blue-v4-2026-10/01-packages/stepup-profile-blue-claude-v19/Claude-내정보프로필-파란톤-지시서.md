# StepUp 내 정보·프로필 편집 — 파란 톤 구현 지시서

내 정보는 러닝 패스 한 장과 기록·챌린지·지갑·설정 진입을 유지한다. 편집 화면은 사진과 닉네임만 다룬다. 승인된 남색·파란 쇼케이스 분위기를 적용하되, 기존 계정·저장 규칙과 메뉴를 보존한다.

이 전달본은 **개별 정적 PNG 21장과 구현 명세**다. 앱 코드 수정·실행 검증·Figma 편집 원본·분리된 새 신발 일러스트 제공을 뜻하지 않는다. 전체 리메이크의 일부이며 다른 메뉴와 추가 상태 감사는 계속 남아 있다.

## 1. 화면 구성

### 내 정보: PF01~04, PRO12

공통 헤더 → 내 정보 제목 → 사진·닉네임·러너 레벨·프로필 수정 → 러닝 패스 → 내 러닝 기록 보기 → 챌린지·지갑·설정 → 공통 하단 5개 탭 순서다.

- STEPUP 로고는 동봉된 원본을 공통 헤더 컴포넌트에서 사용한다. 새로 그리거나 글꼴로 흉내 내지 않는다.
- PF 화면과 저장 후 돌아온 PRO12는 루트 화면이다. 승인된 v16 계열처럼 채운 파란 SUP 버튼과 하단 탭이 있다. 편집 화면 PRO01~11·13~17에는 공통 로고·SUP·하단 탭이 없다.
- 러닝 패스는 누적 거리와 총 러닝 횟수만 요약한다. 최근 기록·시간·통계는 기존 기록 화면에서 확인한다. v16 스타일 예시에 없던 챌린지·지갑·설정을 삭제하지 않는다.
- 러너 레벨은 기존 `state.runner.level`이다. 신발 강화 레벨과 혼용하거나 누적 러닝 횟수로 계산하지 않는다. 기존 육각 장식 대신 작은 `Lv.12` 표시로 단순화했다.
- 패스의 신발은 실제 착용 신발 자산을 사용한다. 시안의 클라우드 러너를 모든 사람에게 고정하거나 소유 증거로 사용하지 않는다. 착용 신발 조회 전에는 자리를 비우거나 기존 로딩 처리를 따른다. 없음도 가짜 신발로 채우지 않는다.
- 패스의 도시·바닥은 장식이다. 실제 위치나 지도·러닝 경로를 나타내지 않는다.
- 프로필 사진 및 ‘프로필 수정’ 버튼은 같은 편집 경로로 간다. 카드의 숫자 자체에 새 탐색 행동을 만들지 않는다.
- 챌린지는 현재 `CHALLENGE_HISTORY`로 연결된다. 이름이 같다는 이유로 이벤트 목록이나 즉시 러닝 시작으로 변경하지 않는다.
- 지갑 행은 실제 SUP 잔액을 표시한다. 데이터 도착 전 `—`; 소수 처리도 기존 `formatSupDown`을 유지한다.

### 프로필 수정: PRO01~11, PRO13~17

뒤로 가기·제목 → 원형 사진 → 사진 변경 → 짧은 즉시 저장 안내 → 닉네임 입력 → 필요할 때만 오류 안내 → 화면 아래 저장 버튼 순서다.

- 저장된 이름과 정규화한 입력이 다를 때만 저장을 켠다. 시안의 ‘민수’는 예시다.
- 사진은 고르면 바로 저장한다. 닉네임은 저장 버튼을 눌러야 저장한다. 둘을 일괄 저장 방식으로 바꾸지 않는다.
- 사진 메뉴는 ‘앨범에서 사진 선택’, ‘기본 이미지 선택’, ‘닫기’만 둔다. 카메라·전체 사진 접근 권한·사진 삭제·유료 이름 변경을 추가하지 않는다.
- 기본 이미지는 기존 16개 ID와 순서를 보존한다. 시안의 단색 기호는 선택지 배치 참고다. 현재 `AvatarEmojis`가 실제 옵션 원본이며, PNG에서 기호를 잘라 쓰거나 임의의 새로운 동물·캐릭터로 교체하지 않는다. 접근성 이름도 현재 `pe_avatar_names` 순서와 일치시킨다.
- 기본 이미지 저장 완료 전에는 새 선택에 체크를 붙이지 않는다. 저장된 기본 이미지가 있으면 그 기존 체크를 유지한다. 사용자 사진을 쓰는 경우에는 체크가 없다. PRO04·14·15는 후자의 예시다.
- 같은 기본 이미지를 누르면 저장 없이 닫는다. 새 이미지 저장 중에는 선택·닫기·바깥 터치·뒤로 닫기를 막는다. 성공하면 시트를 닫고 편집 화면 사진만 갱신한다. 실패하면 시트 안에서 안내하고 이전 사진과 선택 상태를 유지한다.
- 시안의 사람 윤곽은 사진 파일이 없는 경우의 대체 이미지다. 저장된 기본 이미지나 정상 사용자 사진을 이것으로 덮어쓰지 않는다.

## 2. 이름 입력과 저장

현재 상수는 `NICKNAME_MAX = 16`, 저장은 `trim().take(16)`이다. 변경 판정도 같은 정규화를 쓴다. 빈 문자열은 유효하며 기본 호칭으로 표시된다. 최소 글자 수·중복 확인·계정 ID 변경 규칙을 만들지 않는다.

| 상태 | 입력 | 저장 버튼 |
|---|---|---|
| PRO01 변경 없음 | 민수, 2/16 | 비활성 |
| PRO02 이름 변경 | 달리는민수, 5/16 | 활성 |
| PRO05 이름 비움 | 빈 값, 0/16 | 원래 민수였다면 활성 |
| PRO06 최대 길이 | 오늘도한강에서천천히달리는민수야, 16/16 | 활성, 오류 아님 |
| PRO10 저장 중 | 누른 순간의 초안 유지 | 저장 중…, 중복 요청 차단 |
| PRO11 저장 실패 | 입력한 초안 유지 | 다시 저장 |
| PRO12 성공 | 실제 저장된 새 값 | 내 정보로 돌아가 한 번 안내 |

글자 수는 현재 입력 상태의 길이이며 저장 시 공백 제거와 다르다. 공백만 입력한 값도 정규화하면 빈 값이다. Kotlin `String.length` 기준과 현재 입력 변환을 그대로 대조하고 한글 조합·붙여넣기·이모지 경계는 기기에서 확인한다. 정책을 바꾸는 작업과 단순 색감 변경을 혼합하지 않는다.

입력은 한 줄이며 길면 커서 위치까지 가로 스크롤한다. 편집 중 말줄임하거나 글자를 지나치게 줄이지 않는다. 지우기 X는 입력이 있을 때만 보이고 48dp 이상의 터치 영역과 ‘닉네임 지우기’ 이름을 갖는다.

사진 작업과 이름 작업은 별개의 성공·실패 상태다. 사진 저장 중 이름 입력은 가능하지만 이름 저장은 잠시 막는다. 이름 저장 중에는 이름 입력, 사진 변경, 저장 재요청을 막는다. 실패한 작업의 메시지로 다른 작업의 실제 저장 결과를 덮지 않는다.

사진 오류는 PRO08처럼 사진 영역 바로 아래에 붙이고, 이름 오류는 PRO11처럼 닉네임 영역 아래에 붙인다. 둘 다 실패했다면 각 영역에 남기며 본문 스크롤을 허용한다. 사진 오류를 이름 저장 오류처럼 설명하지 않는다.

## 3. 돌아가기와 재진입

1. 이름에 변경이 없으면 바로 내 정보로 돌아간다. 사진만 바꾼 경우도 같다.
2. 저장하지 않은 이름이 있으면 PRO09를 연다. ‘계속 수정’은 초안을 보존하고 시트만 닫는다.
3. ‘닉네임 버리고 나가기’는 이름 초안만 버린다. 이미 저장된 사진은 유지한다.
4. ‘이미 바꾼 사진은 유지돼요.’는 이번 방문에서 사진이 실제로 변경됐을 때만 보인다. 이름만 변경한 경우 그 줄을 생략한다.
5. 저장 작업은 현재 앱 범위 `ProfileEditor`에서 계속된다. 화면을 나갔다고 반쯤 저장된 파일을 확정하거나 성공을 가정하지 않는다.
6. 이름 저장 실패 후 재진입하면 실패 초안을 복원한다. 저장된 이름으로 덮어쓰지 않는다.
7. 성공이 확인되면 `NICKNAME_SAVED`를 이전 내 정보 진입점에 전달하고 편집 화면을 닫는다. PRO12 안내는 한 번만 표시하고 현재 2.6초 동작을 유지한다. 화면 밖에 있는 사용자를 임의로 편집 화면에 다시 데려오지 않는다.

사진 파일은 현재 긴 변 512px 이하·JPEG 품질 90·방향 보정 정책을 유지한다. 임시 파일의 유효성을 확인한 뒤 교체하며 설정 저장 실패 시 기존 파일·ID·리비전을 보존한다. 외부 서버 업로드로 바꾸지 않는다. OS 사진 선택을 취소하면 사진과 이름 모두 그대로다.

## 4. 로딩·빈 화면·실패

- **PF02:** 기록을 읽는 중. 거리·횟수는 `—`, 가짜 0을 쓰지 않는다. 프로필·잔액이 이미 읽힌 예시라 해당 값은 남아 있다.
- **PF03:** 기록만 읽지 못함. 카드 안 ‘다시 시도’는 보조 버튼이며 기록 보기·다른 메뉴는 계속 사용할 수 있다.
- **PF04:** 실제 기록이 0건. `0.0 km`, `0회`. 걸음 기반 러너 레벨·잔액까지 0으로 되돌리지 않는다. 신규 설치 전체 0 상태와는 다른 데이터 조합이다.
- **PRO13:** 저장된 이름·사진 정보를 아직 읽는 중. 실제 값이 없으므로 임의 이름·사진·카운트를 넣지 않는다. 편집 폼은 준비 후 표시한다.
- **PRO07/14:** 결과를 모르는 저장 작업은 작은 불확정 진행 표시 하나만 쓴다. 가짜 백분율 없음.
- **PRO08/11/15:** 오류가 발생한 입력과 이전 저장값을 보존한다. 네트워크 탓으로 단정하지 않는다. 이 편집은 현재 로컬 저장이다.
- **PRO17:** 사진만 즉시 저장 완료. 이름 변경이 없다면 하단 저장 버튼은 여전히 비활성이다.

현재 프로필 초기 읽기의 `.catch { emit("") }` 및 아바타 `emit(0)`은 읽기 실패를 기본값으로 처리한다. PRO13은 ‘초기 로딩’ 시안이지 이 오류가 해결됐다는 증거가 아니다. 실제 실패를 별도로 표시할지에 대한 구현 검토가 남아 있으며, 이 패키지 때문에 저장된 이름·사진을 기본값으로 다시 기록해서는 안 된다.

## 5. 화면 크기와 키보드

PNG는 887×1774 세로 시안이다. 픽셀을 그대로 고정 배치하지 않고 현재 기기의 dp·상태 표시줄·내비게이션 인셋에 맞춘다. 본문·시트는 짧은 화면과 큰 글자에서 스크롤할 수 있어야 한다.

프로필 편집은 기본 좌우 24dp, 제목 20~22sp, 입력 18sp, 본문 14~16sp를 기준으로 삼는다. 활성 저장은 최소 56dp 높이, 보조 동작은 48dp 이상 터치 영역이다. 일반 글자는 기울이지 않는다. 루트의 스포츠 제목·큰 수치에만 승인된 굵기를 적용한다.

PRO16은 키보드가 열린 배치 참고다. 키보드 자체는 Android IME가 그린다. 생성 이미지의 키를 앱 코드나 그림으로 구현하지 않는다. 폼이 스크롤되며 사진 일부가 위로 사라져도 입력창·안내·저장 버튼은 키보드 위에 남는다. 완료 키는 키보드를 닫고, 실제 저장은 저장 버튼으로 한다. 사진 메뉴를 열 때 포커스를 해제하되 초안은 유지한다.

선택·비활성·오류는 색만으로 전달하지 않는다. TalkBack 이름, 저장 중 상태 알림, 선택 여부, 포커스 순서를 제공한다. 모션은 누름·시트·실제 처리 스피너로 제한하며 번쩍임·자동 회전 신발·지속적인 파티클은 추가하지 않는다.

## 6. 자산과 구현 범위

공식 로고, 기존 Pretendard 파일과 라이선스를 동봉한다. 새 PNG는 단일 화면 비트맵이다. 버튼·시트·입력·텍스트·카드 테두리는 공통 Compose 컴포넌트로 만들고, 그림에서 버튼을 잘라 터치 영역에 붙이지 않는다. 신발·도시 배경의 분리된 새 제작 자산은 이 묶음에 없다. 기존 프로젝트 자산을 재사용한다.

H01·H07 두 장은 기존 러닝 패키지에서 그대로 가져온 연결 참고다. 21장에 중복 집계하지 않는다. 그 이미지에 하단 탭이 없더라도 현재 기록 화면에 하단 탭을 유지하기로 한 규칙과 `AppChromePolicy`를 따른다. 지도는 실제 서비스 지도를 사용하며 시안의 경로를 복제하지 않는다. H01의 이번 달 수치와 PF01의 전체 누적 수치를 혼동하지 않는다.

## 7. 구현 후 확인할 것

- 실제 로고·착용 신발·프로필 사진·누적 러닝 값 연결, 가짜 소유·잔액 없음.
- 사진·프로필 수정, 기록, 챌린지 이력, 지갑, 설정, 5개 탭이 모두 기존 경로로 연결됨.
- 빈 이름 저장, 변경 없는 저장 차단, 16자·앞뒤 공백·한글 조합·붙여넣기, 긴 이름에서 편집 버튼 잘림 없음.
- 사진 선택 취소·실패·성공, 기본 이미지 동일 선택·새 선택·저장 중·실패, 체크 시점 일치.
- 사진 후 이름 취소, 이름 저장 실패 후 재진입, 작업 중 뒤로 가기, 중복 저장과 성공 안내 재표시 방지.
- 로딩·실패를 0으로 보이지 않음. 레벨과 러닝 누적 거리는 다른 데이터 출처 유지.
