# StepUp 시작·로그인·첫 설정 17장 · Claude 구현 지시서

기존 Android 앱의 시작·로그인·첫 사용 화면을 승인된 남색·파란 톤으로 바꾼다. 이 문서와 [화면별 동작](화면별동작.md), [화면 목록](screen-index.json), 개별 PNG를 함께 읽는다. UI 시안과 동작 지침이며 실제 앱 구현·서버 검사·Figma 레이어 완료본은 아니다. 새 웹페이지를 만들지 않는다.

## 전달 범위

ONB01~11, ONB20~25의 17개 상태다. ONB20은 프로필 아이콘을 수정한 r2, 나머지는 r1이다. 원래 후보12개에 현재 코드에서 발견한 첫 설정5개 상태를 추가했다. 5개는 몸 정보·목표·모드의 3페이지와 목표 주의·러너 선택 상태다. 17개의 독립 경로를 새로 만들라는 뜻이 아니다.

권한 안내는 기존 러닝 v18의 U01/P01~05/L01~02/R01을 재사용한다. 연결 참고 PNG는 reference에 넣었으며 신규17개에 포함하지 않는다. 이전 통합 v2의 시작·로그인 미제작12개를 이 후속본으로 대체하고 새 첫 설정5개를 더한다. 다른 기능의 상세 동작 지침은 유지한다.

## 시각과 컴포넌트

기본 바탕 #031427, 면 #0B2B50, 전기 파랑 #0754FF, 청록 #48D9FA, 흰 글자 #F5F8FF, 보조 #ABC7EF. 글씨와 조절 버튼이 먼저 읽혀야 한다. 기존 앱의 Pretendard 계열 폰트와 탭 아이콘을 사용하고, 동봉 로고·폰트 라이선스를 유지한다. ONB24의 주의 안내만 의미 있는 경고 색을 사용한다.

원본 STEPUP 로고는 assets/logo_wordmark_on_dark.png를 사용한다. 생성된 PNG의 로고를 새로 따거나 글자로 재작성하지 않는다. 로그인 사진도 기존 assets/home_banner_blue_night.png를 아치 마스크로 보여준다. 지도 또는 현재 위치가 아니다. 조명·신발 무대는 승인 HOME 스타일 참고이며 아직 분리된 신규 배경 레이어가 제공된 것은 아니다.

로그인은 로고 → 제목 → 아치 사진 → 상태 안내 → Google 버튼 → 동의 문구/법적 링크 순서다. ONB01/05~10은 같은 레이아웃에서 안내만 바뀐다. 버튼 위 안내 슬롯은 가장 긴 문구 높이를 확보하고 상태 변경으로 로그인 버튼이 움직이지 않게 한다. PNG의 소폭 위치 차이를 별도 좌표로 하드코딩하지 않는다. 작은 기기나 큰 글씨에서는 사진을 줄이고 전체 스크롤을 허용한다. 글씨·링크를 잘라 맞추지 않는다.

Google 버튼은 프로젝트의 Google G 자산과 흰 바탕·읽기 쉬운 일반 글씨를 유지한다. 앱의 기울어진 게임식 주 버튼으로 바꾸지 않는다. ONB05에서만 서버 확인 중 표시와 비활성 상태를 보여준다. 안내/첫 설정의 주 버튼은 흰 바탕과 얇은 파란 하단 경계다. 다음/계속/건너뛰기의 명칭을 상태마다 임의로 바꾸지 않는다.

로그인·시작·첫 설정에는 SUP 잔액과 하단 탭이 없다. ONB20은 SETTINGS_GUIDE의 Form 헤더로 뒤로+제목만 있고 하단 탭이 없다. ONB11은 HOME이므로 원래 로고·잔액·하단5탭을 유지한다. ONB02의 시트는 배경 홈의 탭까지 덮고 탭을 시트 안에 복제하지 않는다. OS 상태바·계정 선택창·권한창·제스처 바는 시스템이 그린다.

## 현재 코드에서 먼저 확인할 곳

`ui/screens/splash/SplashScreen.kt`, `ui/screens/login/LoginScreen.kt`와 `LoginRules.kt`, `ui/screens/onboarding/OnboardingScreens.kt`, `ui/screens/setup/S2SetupScreens.kt`, `ui/screens/home/HomeScreen.kt`, `ui/StepUpRoot.kt`, `ui/AppChromePolicy.kt`, `domain/Onboarding.kt`, `domain/BodyProfile.kt`, `domain/Sneaker.kt`, `data/prefs/UserPrefs.kt`, `values-ko/onboarding_v1.xml`과 `strings.xml`을 읽는다. 모두 app/src/main/java/com/stepup/android 또는 app/src/main/res 아래의 기존 파일이다. 실제 checkout이 달라졌다면 새 코드와 먼저 대조한다.

## 시작과 Google 로그인

1. 시작 대기 ONB03은 실제 초기화 작업이 끝날 때 다음으로 넘어간다. 로고를 오래 보여주기 위한 최소 지연이나 가짜 진행률을 만들지 않는다. 현재 코드의 14초 타임아웃/실패면 ONB04다. 다시 시도는 같은 초기화를 재실행한다.
2. ONB01의 Google로 계속하기는 OS Credential Manager 계정 선택을 연다. Picking 동안 중복 탭을 막는다. 앱이 계정 목록 모달을 또 그리거나 비밀번호를 입력받지 않는다.
3. 계정을 선택한 뒤 서버 토큰 확인 단계가 ONB05다. 버튼 안 로딩 표시는 하나만 사용한다. 서버의 TokenResult.Ok가 오기 전 로그인 완료·첫 가입 보상·홈 진입을 확정하지 않는다.
4. 서버에 연결할 수 없으면 ONB06, 선택/로그인 실패는 ONB07, 기기 계정 없음은 ONB08이다. ONB09는 signInAgain 사유가 실제로 저장되어 있는 경우에만 표시한다. 단순 통신 실패를 계정 만료로 바꾸지 않는다.
5. OS 계정 선택 취소는 오류가 아니다. 일반 진입이면 ONB01로, 다시 로그인하는 진입이면 기존 ONB09 안내로 조용히 돌아온다. 모든 종료 경로에서 phase를 Idle로 복구한다.
6. 약관과 개인정보 링크는 기존 `https://stepupcrew.com/terms.html`, `https://stepupcrew.com/privacy.html`을 연다. 외부 Intent 열기 자체가 실패한 경우만 ONB10 안내를 기존 4초 정책으로 표시한다. 브라우저 내부 페이지 로딩 결과를 추측하지 않는다. 기존 법적 문구를 변경하거나 새 동의 기능을 만들지 않는다. 이 작업에서 해당 법률 문서 내용은 검토하지 않았다.
7. 로그인 성공 후 기존 로그인 방법 저장·푸시 동기화·경제 새로고침·업로드 작업 등을 유지한다. 신규 회원 조건과 서버 결과를 무시하고 무료 횟수를 UI에서 새로 지급하지 않는다.

## 첫 설정과 안내의 순서

현재 루트에서 로그인 → 필요한 경우 건너뛸 수 있는 S2SetupFlow → MainScaffold → 첫 안내 순서다. `guideSeen`과 `s2SetupSeen`의 기존 조건을 확인한다. 예전 문서의 로그인 즉시 안내 설명만 보고 첫 설정을 지우지 않는다. 복귀 회원에게 첫 설정을 무조건 다시 띄우지 않는다.

ONB21의 다음은 몸 정보를 로컬 저장한 후 ONB22로 간다. 키는 100~230cm에서1cm, 몸무게는25~250kg에서0.5kg 단위다. 누르고 있으면 현재400ms 후70ms 간격 반복을 유지하며 손을 떼거나 화면을 나가면 취소한다. 한 번 탭과 길게 누르기에 접근 가능한 설명을 제공한다. 최솟값/최댓값에서 범위를 넘기지 않는다.

ONB21의 건너뛰기는 몸 정보를 저장하지 않고 모드 단계로 간다. 목표를 계산할 몸 정보가 없으므로 목표 단계를 강제하지 않는다. ONB22의 다음은 목표를 로컬 저장하고 모드로, 건너뛰기는 목표를 새로 저장하지 않고 모드로 간다. 이전 단계에서 이미 저장한 몸 정보까지 삭제하지 않는다.

현재 초깃값은 키165cm/몸무게60kg/기간12주다. 새 목표를 고르지 않았다면 목표는 현재 몸무게 또는 저장된 목표다. ONB22의58kg·ONB24의49kg는 사용자가 값을 바꾼 상태의 표본이다. 권장 목표나 자동 입력 값으로 설정하지 않는다. 하루 걸음 목표도 실제 저장값을 읽어 표시하고 로딩 중8,000을 확정 값으로 보여주지 않는다.

BMI와 목표 계산은 BodyMath를 재사용한다. ONB21은60/(1.65²)=22.0, ONB22는58kg/12주로−2.0kg·주당약0.2kg·목표BMI21.3, ONB24는49kg/8주로−11.0kg·주당약1.4kg·목표BMI18.0이다. 분류·주의 문구는 기존 앱 표시를 재현한 것이며 새로운 건강 권고를 추가한 것이 아니다. 기존 주의 조건은 감량 속도가 주당1kg 초과하거나 목표BMI가 저체중 구간일 때다. 현재 동작은 설명이므로 ONB24에서 다음을 막거나 추가 확인을 강제하지 않는다.

ONB23/25는 한 화면의 라디오 선택이다. 계속은 고른 모드를 저장하고 setupSeen을 기록한 후 나간다. 건너뛰기는 임시 선택을 버리고 기존 저장 모드(최초 기본 라이트)를 유지한다. 두 모드의 SUP 적립 규칙을 다르게 만들지 않는다. bodyProfile은 현재 기기에만 저장하며 이 입력으로 적립이나 러닝 기록을 바꾸지 않는다.

## 코드와 시안 사이에 남은 실제 연결 작업

- `runMode`를 소비하는 곳은 조사 시점의 UserPrefs/S2SetupScreens뿐이다. HomeScreen은 HomeShoeCard를 조건 없이 호출한다. 즉 모드 선택 저장은 있지만 홈 표시 전환은 연결되지 않았다. 선택 설명에 맞는 홈 바인딩이 실제로 동작하는지 구현하고 캡처로 검증해야 한다. ONB11은 신발을 보여주는 첫 홈 표본이며 라이트 홈까지 완료됐다는 뜻이 아니다. 하단5탭은 모드 때문에4개로 줄이지 않는다. 예전 RunMode 주석의4탭은 최신5탭 지침보다 우선하지 않는다.
- 몸 정보 로딩 전 `stored ?: return`은 비어 보일 수 있다. 최초 로컬 조회 중/조회 실패의 공통 상태가 필요하다. 완료로 가정하고 예시값을 저장하지 않는다.
- 현재 몸 정보 저장은 코루틴을 시작한 뒤 다음 단계로 이동한다. 저장 실패, 빠른 다음/건너뛰기, 저장 완료 순서, 모드 저장 실패/중복 탭의 처리 확인이 필요하다. 그림만으로 이 동작이 보장됐다고 보고하지 않는다.
- 몸 정보 건너뛰기로0→2 이동 후 BackHandler가2→1로 돌아간다. 입력하지 않은 몸 정보로 목표 화면이 열리는 경로를 검토하고 기본값이 사용자 입력으로 저장되지 않게 한다. 실제 방문 단계에 맞게 뒤로 이동하도록 수정 여부를 명시한다.
- 설정에서 다시 여는 몸 정보/목표·모드 화면은 별도 경로다. 최초 단계 번호와 건너뛰기를 그대로 복제하지 않는다. 추가 상태 및 경로 감사에 남겨 둔다.

위 항목은 아직 구현·실행 검증되지 않은 사항이다. 부족한 상태를 이미지에 없다는 이유로 생략하지 않는다. [추가 점검 목록](audit/onboarding-additional-states.json)에 따로 기록했다.

## 첫 안내와 첫 러닝 홈

ONB02는 처음 홈에 왔고 안내 미확인인 경우다. 외부 초대/딥링크 목적지나 진행 중 러닝 복구가 있으면 그 처리를 우선하고 안내는 다음 홈 진입까지 미룬다. 세 행은 설명이므로 클릭 버튼이나 화살표를 붙이지 않는다.

러닝 시작은 안내 확인 상태를 저장하고 U01 러닝 방법 고르기로 간다. 운동 기록을 즉시 시작하지 않는다. 먼저 둘러보기·X·뒤로·바깥·아래로 닫기는 확인 상태를 저장하고 홈에 머문다. 앱 강제 종료만으로는 확인 상태를 저장하지 않는다. 크기가 큰 글씨에서는 시트 내부를 스크롤하고 주/보조 동작을 접근 가능하게 유지한다.

ONB11은 오늘 활동 없음 + 활동 권한 없음 + 조회 완료 러닝 수0 + 누적 걸음0일 때만 표시한다. 기록 수를 읽는 중(null)을0으로 취급하지 않는다. 권한창은 이 홈을 보기만 해서는 열지 않는다. 러닝 시작 → U01의 방법 선택 이후 기존 권한 흐름을 따른다. 작은 기록 보기·코스 찾기는 기존 경로를 유지한다.

스타터는 코드의 Cloud Runner/일반/Lv1/내구도100 예시다. 잔액0.00은 조회 완료 표본이고 신규 가입 시 반드시0이라는 보장이나 고정값이 아니다. 실제 보유 신발/잔액/기존 기록이 있으면 그대로 표시한다. 돌아온 사용자의 보유 신발을 스타터로 덮어쓰지 않는다.

ONB20은 내 정보 → 설정 → 도움말·문의 → 앱 사용 안내에서 연다. 뒤로는 도움말로, 러닝 홈으로는 HOME으로 간다. guideSeen을 초기화하지 않는다.

## 구현 후 확인

작은 높이·큰 글씨에서도 로그인과 법적 링크, 설정 조절 및 건너뛰기가 잘리지 않는지 확인한다. Google 취소/중복 탭/오프라인/계정 없음/재로그인/브라우저 없음, 첫 설정 저장/건너뛰기/뒤로/경계값, 실제 모드 홈 전환, 딥링크·세션 복구 중 안내 지연을 각각 검사한다. TalkBack에는 각 조절값과 버튼 역할·선택 상태가 읽혀야 한다. 로딩 애니메이션은 실제 대기만 나타내고 동작 줄이기 설정을 따른다.

`implementation-checklist.csv`의 미확인은 이 패키지에서 실제 앱 구현 여부를 검증하지 않았다는 뜻이다. 현행 구현을 먼저 확인한 뒤 경로·변경 파일·실제 캡처·검증 결과를 기록한다. 정적 이미지 검수와 앱 실행 검증을 구분하고 남은 연결·미제작 상태를 함께 보고한다.
