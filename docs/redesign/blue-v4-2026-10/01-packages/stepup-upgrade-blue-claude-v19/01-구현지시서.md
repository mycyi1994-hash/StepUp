# StepUp 신발 강화 · 파란 쇼케이스 구현 지시서

첨부한 17장 시안을 기준으로 기존 Android 앱에 신발 강화 흐름을 구현한다. 신발 상세의 강화하기 버튼에서 독립된 강화 화면으로 이동하고, 하위 등급 신발 3개를 선택한 뒤 성공률과 능력치 변화를 확인해 실행한다.

사용자의 최신 결정에 따라 성공률 계산 안내 화면은 제외한다. 이 문서와 화면 목록을 함께 읽고 진행한다. 시안은 디자인 참고이며 실제 앱 구현 완료 자료가 아니다.

## 1. 이번에 반영할 결정

- 기존 16번 성공률 계산 안내 화면을 만들지 않는다. 관련 도움말 아이콘, 링크, 경로, 팝업, 계산표도 추가하지 않는다.
- 성공률 관련 화면 정보는 재료별 추가 성공률, 선택 후 갱신되는 최종 성공률, 재료 소각 안내로 정리한다.
- 계산식과 등급별 보정표는 이 개발 문서와 balance-rules.json에서만 관리한다.
- 17장 시안의 원래 번호를 유지한다. 파일은 01~15, 17, 18이며 16번은 빠져 있다.
- 17장은 상태별 참고 이미지다. 모두 별도 내비게이션 페이지로 만들지 않는다. 재료 없음·조회 중·조회 실패는 같은 선택창의 상태이고, 선택 개수에 따른 화면도 같은 강화 본문의 상태다.
- 강화 메인은 독립 화면이다. 재료 선택과 실행 전 최종 확인은 하단 시트로 구현한다. 수리는 별도 모달이라는 기존 방향을 유지하며 이번 범위에 새 수리 흐름을 섞지 않는다.

새 시안에서도 기본 확률과 재료 합계의 계산 내역을 제거했다. 재료별 보정값과 최종 성공률만 표시한다. 이 전달본은 기존 강화 규칙과 흐름을 유지하면서 외형을 승인된 HOME v15의 파란 쇼케이스 계열로 바꾼 것이다.

문서의 01~18 번호는 images/UP01.png~UP18.png에 대응한다. UP16은 삭제된 상태다. 정적 시안 17장, 구현 지시서, 규칙과 검수자료를 제공하며 실제 앱·서버 구현은 수행하지 않았다. 현재 코드와 새 계약의 차이는 [05-현재코드-차이.md](05-현재코드-차이.md)를 함께 읽는다.

자료가 충돌할 때는 사용자의 최신 결정, 이 문서, balance-rules.json, 첨부 PNG 순으로 해석한다. 예전 자료의 같은 등급 재료, 최대 레벨 15, SUP만 차감하는 강화 동작을 이번 흐름에 복원하지 않는다.

## 2. 진입과 기본 흐름

신발 상세 → 강화하기 → 01 강화 화면 → 빈 슬롯의 + → 02 재료 선택 → 선택한 3개 넣기 → 03 준비 완료 → 강화하기 → 04 최종 확인 → 강화 시작 → 05 진행 중 → 06 성공 또는 07 실패.

상세에 강화하기 버튼을 직접 제공한다. 기존 관리 메뉴에도 강화 진입이 있다면 동일한 화면으로 연결해 중복된 강화 구현이 생기지 않게 한다. 신발 상세의 다른 데이터와 기능은 유지한다.

뒤로 가기는 강화 진입 전 신발 상세로 돌아간다. 요청 전 단순 재료 선택만으로는 보유 신발을 변경하지 않는다. 실행 중에는 화면을 나가더라도 같은 시도의 결과를 다시 확인할 수 있어야 한다.

## 3. 강화 화면의 구성

위에서 아래로 다음 순서를 유지한다.

1. 공통 뒤로 가기와 신발 강화 제목.
2. 현재 신발 이미지와 해당 등급의 배경·프레임, 신발명, 등급 배지와 바로 오른쪽 No. 번호.
3. 강화 재료 제목과 선택 개수 n / 3.
4. 같은 너비의 재료 슬롯 3개.
5. 성공 시 변화: 레벨, 효율, 착화감의 독립된 세 줄.
6. 강화 성공률과 최종 수치.
7. 실패해도 재료 신발 3개는 소각돼요. 안내.
8. 흰색 실행 버튼.

재료 슬롯은 비어 있을 때 +와 신발 추가를 표시한다. 채워지면 신발 이미지, 등급, 레벨, 소유 번호, 추가 성공률을 표시하고 오른쪽 위 X로 제거할 수 있게 한다. 어느 빈 슬롯을 눌러도 기존 선택을 유지한 재료 선택창을 연다.

변화 행은 항목명 — 입체 바 — 현재값 → 다음값을 한 줄로 배치한다. 각 행에 별도의 둥근 스틸 블루 배경을 둔다. 세 행 전체를 또 하나의 카드로 감싸지 않는다. 변경되지 않는 내구도를 강화 보상처럼 추가하지 않는다.

| 선택 상태 | 성공률 표시 | 실행 버튼 |
|---|---|---|
| 0개 | 기본 확률 표시, 예시 대상은 70.0% | 재료 신발 3개를 선택해주세요, 비활성 |
| 1개 | 선택한 1개 보정까지 반영한 잠정값 | 재료 신발 2개를 더 선택해주세요, 비활성 |
| 2개 | 선택한 2개 보정까지 반영한 잠정값, 예시 78.4% | 재료 신발 1개를 더 선택해주세요, 비활성 |
| 3개 | 최종 성공률, 예시 80.4% | 강화하기, 활성 |
| 요청 대기 또는 처리 중 | 실행 시점의 값 유지 | 중복 실행 불가 |

0~2개 상태의 성공률은 선택에 따른 미리보기다. 100%가 되어도 재료 3개가 없으면 실행할 수 없다. 수치 조회가 안 된 상태는 0%로 표시하지 않는다. 01 시안에 성공률 대시가 남아 있더라도 계산 가능한 실제 대상은 위 규칙을 따른다.

최종 확인은 04 시안처럼 대상, 사용할 재료 3개, 최종 성공률, 소각 안내와 취소 / 강화 시작만 제공한다. 반복적인 확인창을 추가하지 않는다.

## 4. 재료 선택

재료 선택은 한 개의 하단 시트로 구현한다. 시트 위에 또 다른 재료 시트를 겹치지 않는다.

목록의 각 항목에는 신발 이미지, 이름, 등급, Lv., 소유 번호, 성공률 보정값과 선택 표시를 둔다. 목록과 하단 선택 요약은 같은 소유 ID 집합을 사용한다. 동일 모델이라도 서로 다른 보유 신발이면 구분해 선택할 수 있다.

선택 규칙은 다음과 같다.

- 강화 대상보다 실제 등급이 낮은 신발만 후보로 표시한다. 재료 3개의 등급은 서로 달라도 된다.
- 대상 자신, 같은 소유 ID 중복, 타인 소유, 소각된 신발은 제외한다.
- 거래·사용 중 등의 제약은 서버의 실제 사용 가능 여부를 따른다. 자동으로 착용 해제하거나 거래를 취소해 재료로 만들지 않는다.
- 선택은 최대 3개다. 이미 3개를 선택한 상태에서 다른 항목을 눌러도 네 번째가 추가되거나 기존 선택이 몰래 교체되면 안 된다.
- 시트에서의 변경은 임시 선택이다. 선택한 n개 넣기를 눌러 적용한다. 1~2개만 넣고 돌아갈 수도 있다.
- X, 뒤로 가기, 아래로 닫기, 바깥 탭은 임시 변경을 취소하고 열기 전의 적용된 선택을 유지한다.
- 아무것도 선택하지 않았을 때 선택 완료 버튼은 비활성이다. 적용된 재료를 모두 비우려면 메인 슬롯의 X를 사용한다.
- 하단 고정 요약과 버튼이 마지막 목록 항목을 가리지 않도록 목록에 여유 공간을 둔다.
- 네트워크 오류만으로 적용된 선택을 지우지 않는다. 새 조회에서 실제로 사용 불가가 확인되면 해당 항목만 해제하고 나머지는 유지한다.

불필요한 검색 탭, 재료 자동 소각, 자동 추천 선택, 새로운 화폐 비용을 추가하지 않는다. 초보자도 신발을 누르고 넣기만 하면 다음 단계로 갈 수 있게 한다.

## 6. 강화 규칙

사용자가 정한 규칙은 레벨 상한 20, 기본 성공률 100 − 레벨 × 3%, 하위 등급 신발 3개, 실패해도 재료 3개 소각이다. 재료 레벨과 등급 차이에 따른 보정은 사용자가 설계를 맡긴 범위이며 아래 기존 제안을 이번 구현 기준안으로 정리한다.

현재 대상 레벨 L을 기준으로 계산한다. 목표 레벨 L+1을 식에 대신 넣지 않는다.

```text
기본 성공률(%) = 100 − 3 × 현재 대상 레벨

재료 1개의 보정(%p)
  = (2 + 0.4 × (재료 레벨 − 1)) × 등급 차이 계수

계수
  1단계 하위: 1.00
  2단계 하위: 0.50
  3단계 하위: 0.25

최종 성공률(%) = min(100, 기본 성공률 + 재료 3개의 보정 합)
```

등급 순서는 현재 도메인의 COMMON < RARE < EPIC < LEGENDARY를 사용한다. REDLINE과 FINISH의 별도 시각 프레임은 유지하되 현재 LEGENDARY 시리즈를 별도 확률 등급으로 올려 계산하지 않는다. 작업 시점의 실제 등급 모델이 바뀌었다면 서버와 UI가 같은 등급 간격을 쓰는지 먼저 확인한다.

| 예시 대상과 재료 | 값 |
|---|---|
| 레전더리 현재 Lv10 | 기본 70.0% |
| 에픽 Lv10, 1단계 하위 | +5.6%p |
| 레어 Lv10, 2단계 하위 | +2.8%p |
| 에픽 Lv1, 1단계 하위 | +2.0%p |
| 위 3개 최종 성공률 | 80.4% |

위 표는 개발용이다. 앱에 계산표나 계산 안내 화면으로 노출하지 않는다. 확률은 0.1% 단위 정수로 처리할 수 있다. 예를 들어 80.4%는 804/1000이며, 화면에 표시하는 확률과 서버의 실제 판정 확률을 일치시킨다. 100%에서는 확률 판정 실패가 없어야 한다. 요청 검증 실패나 통신 오류는 확률 실패와 별개다.

재료 레벨은 1~20을 전제로 한 식이다. 기존 데이터가 범위를 벗어나면 조용히 20으로 바꾸거나 데이터를 낮추지 않는다. 별도 이전 정책이 정해지기 전에는 해당 예외를 서버에서 검증하고 지원되지 않는 후보를 사용 가능하다고 표시하지 않는다.

성공 시 레벨 +1, 효율 +0.5%p, 착화감 +0.2%p(기존 20% 상한)를 적용하고 실패 시 대상 신발의 레벨과 능력치는 유지하는 것은 이전 시안의 제안이다. 이번 지시서는 그 제안을 그대로 이어간다. 이미 서버의 레벨 기반 유효 수치 계산에 증가분이 포함되어 있다면 원시값까지 다시 올려 이중 증가시키지 않는다.

추가 SUP 요금은 이번 기준안에 없다. 기존 SUP 차감 강화 호출을 그대로 붙여 재료와 SUP를 동시에 차감하지 않는다. 결과를 실제로 판정하고 재료를 처리할 새 계약에 연결한다.

Lv20은 시도 불가다. 기존 Lv20 초과 보유 신발을 임의로 낮추지 않으며 실제 보유 레벨을 보존하고 추가 강화만 제한한다. 13번의 20/20을 모든 계정에 하드코딩하지 않는다.

속성, 행운, 원시 착화감 배율, 설명용 이모티콘, 불필요한 뱃지나 추가 능력치를 넣지 않는다. 버튼과 선택 목록은 읽기 도구에 이름·선택 여부·사용 가능 여부를 제공한다. 입체 바는 장식이며 입력용 슬라이더로 읽지 않는다.

## 8. 요청 처리와 결과 복구

서버가 보유 상태, 재료 사용 가능 여부, 등급·레벨·확률을 검증하고 성공 여부를 판정한다. 클라이언트가 성공을 임의 추첨하거나 먼저 신발을 지우고 나중에 서버에 맞추는 방식으로 구현하지 않는다.

구현에서 필요한 계약은 다음과 같다. 명칭은 제안이므로 기존 프로젝트의 구조에 맞춰 정하되 의미를 유지한다.

| 동작 | 필요한 정보 |
|---|---|
| 재료 목록 조회 | 대상 ID, 실제 후보 소유 ID, 등급, 레벨, 이름, 모델, 번호, 사용 가능 여부 |
| 강화 견적 | 대상 ID, 서로 다른 재료 ID 3개, 현재 버전, 최종 확률, 성공 시 실제 수치, 규칙 버전 |
| 강화 요청 | 계정에 종속된 고유 요청 키, 대상·재료 ID, 확인한 견적 버전 |
| 결과 조회 | 같은 요청 키에 대한 미접수 / 처리 중 / 확정 성공 / 확정 실패 / 명확한 거절 결과 |

같은 요청 키의 재시도는 같은 결과를 돌려줘야 하며 재료를 다시 소각하면 안 된다. 요청 키는 전송 전에 보관해 앱 재시작 뒤에도 조회할 수 있게 한다. 대상과 재료를 동시에 사용하는 다른 요청도 검증으로 차단한다.

확률 판정, 재료 3개 소각, 성공 시 대상 갱신, 결과 기록을 하나의 일관된 처리로 묶는다. 부분 성공 상태를 남기지 않는다. 소각은 실제 자산의 사용 불가와 보유 목록 반영을 포함한다. 온체인 신발이라면 현재 자산 관리 절차와 일치해야 하며 DB 목록에서 숨긴 것만으로 NFT 소각 완료라고 표시하지 않는다. 체인 미확정·부분 처리 상태는 기존 결과 확인 흐름에서 추적한다.

실행 전 재검증에서 보유 상태, 레벨, 최종 확률이나 소각 대상이 바뀌면 기존 확인을 근거로 그대로 실행하지 않는다. 최신 준비 상태를 보여주고 다시 최종 확인을 받는다. 확정 미접수라면 재료는 보존한다.

통신 상태별 처리는 다음을 따른다.

- 요청을 전송하지 않았다는 것이 확실함: 14. 연결 재확인만 수행하고 자동 실행하지 않는다.
- 전송 또는 접수 여부를 모름, 응답 유실, 처리 중 앱 종료: 15. 동일 요청의 결과만 조회한다.
- 서버가 확률 실패로 확정함: 07. 이때만 재료 소각 완료와 대상 유지 결과를 표시한다.
- 검증 거절로 확정됨: 거절 이유에 맞춰 12/18/준비 화면으로 돌아간다. 확률 실패처럼 표현하지 않는다.

05/15에서 나중에 확인을 누르면 상세에 해당 요청의 결과 확인 진입을 유지한다. 미확인 재료와 대상에 새 강화 요청을 시작할 수 없도록 한다. 네트워크가 끊겼다는 이유로 새 요청 키를 만들어 다시 강화하지 않는다.
