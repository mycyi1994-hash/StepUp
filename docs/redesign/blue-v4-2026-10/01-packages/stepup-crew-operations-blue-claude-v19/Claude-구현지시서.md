# StepUp 크루 운영 리메이크 구현 지시서

현재 앱의 크루 운영 기능을 이 전달본38장의 남색·전기 파랑 톤으로 바꾼다. 기본 구도·기능·서버 데이터와 역할별 권한을 유지한다. 먼저 작업 브랜치의 AGENTS.md와 최신 디자인 문서를 읽고 현재 코드와 대조한다. 화면별 구체 행동은 화면별동작.md를 따른다.

## 1. 범위와 근거

대상은 CP40~65,CP74~76,CP79~81,CP83~86,CP89~90이다. 같은 페이지의 역할·요청 결과·시트 변형을 별도 PNG로 제시했다. 기존 경로를 그대로 활용하며 번호마다 새 경로를 만들지 않는다. 이전 크루 둘러보기·가입38장 및 만들기19장과 이어진다.

화면의 수치는 가상 예시다. 실제 데이터·동작은 이 명세와 현재 서비스 계약을 우선한다. 이번 전달은 앱 구현, 커밋, 푸시, 배포 또는 API 검증 완료 보고가 아니다. 추가 상태의 미완료 여부는 audit/additional-state-audit.json에 명시했다.

## 2. 공통 시각 기준

배경 #031427, 패널 #0B2B50, 파랑 #0754FF, 강조 #48D9FA, 본문 #F5F8FF를 쓴다. 큰 주 버튼은 흰 면과 파란 하단면, 삭제성 행동은 어두운 코랄 면과 코랄 글자로 구분한다. 한 화면에서 큰 주 행동은 하나만 강조한다. 그림의 주인공은 각 크루의 대표 이미지이며 크루 고유색은 보존한다.

프로젝트 원본 로고·기존 폰트·벡터 아이콘을 재사용한다. 관리·프로필·확인 화면에 SUP, 등급 방패, 왕관, 경험치, 게임 보상을 추가하지 않는다. 저장된 레벨은 평문 Lv.값이며 계산식을 만들지 않는다. 전역5탭 정책은 유지하되 이 묶음의 집중 화면에는 하단 전역 탭을 새로 붙이지 않는다.

전체 PNG를 앱 배경으로 깔고 투명 버튼만 얹지 않는다. 글자·수치·목록·버튼·선택·폼은 Compose로 분리하고 대표 그림만 이미지로 쓴다. 시계와 홈 바는 OS가 그린다. 상태 변화 때문에 대표 이미지나 레이아웃이 다시 생성되어 흔들리지 않도록 같은 컴포넌트를 사용한다.

390dp 기준 좌우20dp, 주 버튼56dp, 최소 터치48dp에서 시작한다. 이는 구현 제안값이며 래스터 픽셀을 역산한 규격이 아니다. 긴 크루명·사람 이름은 줄바꿈으로 처리하고, 내용은 스크롤하되 고정 행동과 시스템/키보드 영역을 침범하지 않게 한다. 시트는 불투명 남색, 배경은 동일 호출 화면 위의40~50% 검정 scrim이다. 아래 문구가 시트 안으로 비치지 않게 한다. 시안별 미세한 아이콘·마진 차이는 공통 컴포넌트 값으로 통일한다.

## 3. 크루장과 크루원의 권한

크루장 상세 CP76/89의 주 버튼은 크루 관리다. 더보기는 운영 설정 CP74/90으로 간다. 일반 멤버 상세 CP21/86에서는 멤버 보기와 멤버 메뉴 CP60을 사용한다. 방문자·가입 대기는 별도 CP73 메뉴를 유지한다. 화면 버튼을 숨기는 것과 별개로 서버가 실제 권한을 검사해야 한다.

CP84는 크루장이 보는 일반 멤버의 공개 프로필이다. CP56과 같은 공개 정보에 더보기만 추가한다. 현재 크루장·본인·가입 대기자에게 내보내기나 크루장 지정 메뉴를 보여주지 않는다. 가입 신청자 CP85에는 신청 날짜·신청 문구와 아직 멤버가 아니라는 안내만 넣고 회원 가입일이나 주간 거리를 만들어 넣지 않는다.

크루장 변경 성공 후 이전 소유자는 일반 멤버로 남는다. CP86에서 새 크루장 민수를 표시하고 관리 행동을 제거한다. 뒤로 돌아간 오래된 관리 화면에서도 권한이 남지 않게 재조회한다. 총 인원과 주간 기록은 변하지 않는다. 자동 탈퇴시키지 않는다.

## 4. 수정·모집·주간 목표

CP41~43은 실제로 값이 변경된 입력 예시다. CP41은 소개를 편하게로, CP42는 거리를1~3km로, CP43은 목표를100km로 바꾼 상태다. 유효하면서 변경된 값이 있을 때만 저장한다. 기존 이름1~40자,소개120자,한마디300자,정원1~9999명,목표1~99999km 제한과 현재 멤버보다 정원을 작게 할 수 없는 검증을 따른다. 이름 중복 등 새 규칙을 임의로 추가하지 않는다.

지역·사진·일정은 기존 공유 선택 흐름을 사용한다. 거리는 한 개 선택, 분위기는 독립 토글이다. 요일 없이 시간만 남기지 않는다. 뒤로/키보드/지역 변경 때문에 다른 입력을 지우지 않는다. 기존 수정 초안 복원·저장·이탈 동작을 보존한다. 변경 적용 전 기존 공개 크루 정보와 입력 중 초안을 구분한다.

모집 멈춤은 CP44 확인 후 성공 시 CP89, 재개는 CP45 확인 후 성공 시 CP76이다. 모집을 멈춰도 멤버·권한·레벨·누적 기록은 그대로다.24/30의6자리 문구는 정원이 있는 예시다. 이미 만원이거나 정원 미설정이면 현행 전용 문구를 사용한다.

가입 방식은 기존 기능이다. CP74/90의 행을 제거하지 않는다. 승인제와 자유가입 중 변경했을 때 적용 가능하고, 서버 성공 후 설정이 바뀐다. 이 정책 시트의 새 정적 시안은 아직 추가 제작 대상이다. 실패를 표시하는 기능까지 검증된 것으로 보고하지 않는다.

CP46~47~83은 별도160→200km 목표 변경 분기다. 기존 누적126km를 보존해63%,남은74km가 된다. 성공 전에 목표를 바꾼 것처럼 표시하지 않는다. 생성 초안의 목표 CP88과 기존 크루의 목표 API를 혼동하지 않는다. 참여자는 이번 주 기여가 있는 멤버만이며 전체 멤버24명과 참여자9명을 구분한다.

## 5. 가입 신청과 승인

목록 CP48→신청 CP49→승인 확인 CP50→성공 CP51→남은 신청 CP79 순서다. 거절은 CP52→CP53의 별도 분기다. 목록0건 CP54는 조회 성공 후에만 표시한다. 로딩·실패를 빈 목록으로 바꾸지 않는다.

승인 결과의 인원·정원·남은 신청 수는 서버 결정 응답을 사용한다. 예시 승인 후25/30,거절 후24/30이다. 이미 처리된 신청은 다시 결정할 수 없게 하고 현재 상태를 설명한다. 도윤·지연 등 예시 이름으로 요청 대상을 찾지 말고 applicationId/userId를 사용한다. fixture.json의 각 분기는 독립 스냅샷이다.

정원 충돌 CP81에서는 신청을 유지한 채 정원 설정이나 신청 재조회로 이어진다. 자동으로 정원을 늘리거나 다시 승인하지 않는다. 일반 오류 CP80의 다시 확인은 크루와 신청 상태를 읽어 확정 여부를 확인하는 행동이다. 불명확한 요청 결과를 성공으로 바꾸거나 무조건 재전송하지 않는다.

## 6. 멤버·크루장 변경·탈퇴

멤버 관리 CP55는 전체 명단을 스크롤한다. 크루장 행은 크루장 소개, 다른 행은 공개 프로필이다. 내보내기는 CP75→CP57 확인 후 성공했을 때만 명단과 인원을 재조회한다. 실패하면 현재 멤버 상태를 유지한다.

크루장 후보 CP58에는 현재 일반 멤버만 표시하고 현재 크루장과 신청 대기자는 제외한다. 행을 누르면 CP59 확인을 띄운다. 멤버 메뉴에서 특정 사람을 골랐다면 그 대상을 지정한 확인으로 이어진다. 서버 성공 후 CP86으로 돌아가며 이전 소유자는 일반 멤버다.

일반 멤버의 탈퇴 CP61, 다른 멤버가 남아 있는 크루장의 탈퇴 안내 CP62, 크루 해산 CP63을 구분한다. 크루장은 먼저 권한을 넘긴 다음 일반 멤버 흐름으로 탈퇴해야 한다. 혼자라면 해산 확인으로 이어진다. 해산 성공 후 모집 목록으로 돌아간다. 일반 탈퇴 성공은 기존 상세를 새 역할로 갱신하는 현행 동작을 유지한다.

현행 서비스의 탈퇴/해산 성공 후 해당 크루의 로컬 채팅·홈 자료 정리는 보존하되 다른 크루나 계정을 지우지 않는다. 실패 또는 취소 단계에서 자료를 먼저 지우면 안 된다. 로컬 정리 실패와 서버 결과가 어긋나는 경우는 구현 검증 대상으로 남아 있다. 자유가입 크루에는 재가입에 승인 신청이 필수인 것처럼 안내하지 않는다.

## 7. 신고·요청 중·오류

신고는4가지 사유 중 하나를 선택해야 전송할 수 있다. 기타만 메모 칸을 열며 최대500자다. SPAM/ABUSE/OTHER와 모집 내용 메모 RECRUIT_CONTENT의 기존 전송 규칙을 유지한다. 신고 실패는 사유·메모를 그대로 둔 채 오류와 재시도를 제공한다. 실제 접수 성공 뒤에만 CP65를 띄운다. 접수는 제재나 문제 해결을 뜻하지 않는다.

모든 변경 요청에서 중복 탭을 막고 진행 상태를 보여준다. 확인 시트는 전송 중 닫기/뒤로로 요청을 중복하거나 성공한 것처럼 건너뛰지 못하게 한다. 오류는 의미색·문구로 식별하고 현재 값과 대상을 유지한다. 권한·정원·대상 소속 변경은 서버의 최신 결과가 우선한다.

## 8. 구현 검수와 남은 범위

38개 상태 각각의 실제 기기 캡처를 남기고 크루원/크루장/신청자,긴 이름,작은 화면,큰 글자,키보드,빈 목록,서버 실패,중복 탭,뒤로 이동,다른 기기의 권한 변경을 확인한다. 새 시안을 동작 검증 증거로 대신하지 않는다.

가입 방식 시트·조회 중·조회 실패·이미 처리된 신청·기타 신고·전송 중·후보0명 등은 추가 시안 목록에 남아 있다. 최초95개 크루 후보를 그렸다는 이유로 크루 기능 전체 또는 앱 전체를 완료로 보고하지 않는다. 크루의 채팅·함께 달리기·게시판 진입은 기존 CP94 참고처럼 보존한다.

이 패키지에서 수행한 것은38장 개별 시각 확인,파일·압축 무결성 검증,현행 코드의 읽기 전용 동작 대조다. 앱 소스 수정·빌드·API·기기 실행 검증은 하지 않았다. 구현 결과에는 변경 파일,실제 캡처,검증한 상태와 남은 상태를 별도로 적는다.
