# 신발 수치와 수리 금액 기준

이미지의 신발·번호·레벨·능력치·잔액·획득일은 예시다. 실제 계정과 소유 데이터는 바꾸지 않는다. 모든 요청에는 실제 소유 ID를 사용하고 mintNumber나 모델 ID를 대신 보내지 않는다.

## 네 개의 바

| 항목 | 표시값 | 채움 |
|---|---|---|
| 레벨 | level / 유효한 실제 maxLevel | level / maxLevel |
| 효율 | 기존 bonusPercent와 formatBonus | bonusPercent / StatScale.EFFICIENCY_MAX_PERCENT |
| 착화감 | 기존 energySavingPercent | energySavingPercent / StatScale.ENERGY_MAX_PERCENT |
| 내구도 | 기존 formatDurability | 실제 durabilityPoints / 100 |

확인된 효율 기준은27.5%, 착화감 기준은20%, 내구도 기준은100이다. 레벨 상한은 최신 정책20으로 이행하되 실제 서버·도메인과 일치시킨다. 구현 경계는 현재 코드와 차이 문서를 따른다.

예시의 바 길이는 레벨5/20=25%, 효율8/27.5≈29.09%, 착화감5.8/20=29%, 내구도92/100=92%다. 생성 이미지의 길이는 미술적 근사치다. 표시 숫자와 계산식이 픽셀 길이보다 우선한다. 채움은 프레임을 제외한 트랙 기준으로 계산한다.

0일 때는 채움과 하이라이트가 없어야 한다. 미세한 양수에 큰 최소 폭을 강제하지 않고 사선 모서리도 채움 폭에 맞춰 줄인다.100%에서 프레임을 침범하지 않는다. 유효하지 않은 분모를 막되, 로딩 중인 값을 실제0으로 표시하지 않는다.

서버 효율은 efficiencyBps/100으로 계산한다. 착화감은 에너지 절감 표시값을 유지한다. 기존 내구도 표기는 소수점을 내림하므로99.6은99/100이다. 비용 계산에는 표시용으로 내린99가 아니라 원래99.6을 사용한다.

## 수리 비용

현재 서버의 등급 순서는 일반0, 레어1, 에픽2, 레전더리3이다. 확인한 계산식은 다음과 같다.

단가 = round((1 + 0.25 × 등급순서) × (1 + 0.05 × 레벨), 4)

전체 수리 포인트 = round(100 − 실제 내구도, 2)

비용 = round(수리 포인트 × 단가, 4)

실제 실행은 서버가 판단한다. 화면이 로컬 공식으로 계산해 소유 상태·잔액 검증이나 서버 견적을 대체하면 안 된다. 비용이 바뀌면 사용자에게 바뀐 가격을 다시 확인받는다. 최대금액·견적 검증 계약이 아직 없는 현재 서버의 한계를 숨기지 않는다.

| 예시 | 결과 |
|---|---|
| 레어 Lv5 단가 |1.5625 SUP |
| 내구도68에서100 |32 ×1.5625 =50 SUP |
| 잔액83.07에서50 사용 |33.07 SUP |
| 잔액20, 비용50 |30 SUP 부족 |
| 내구도92에서100 |8 ×1.5625 =12.5 SUP |
| 잔액83.07에서12.5 사용 |70.57 SUP |

금액은 서버 정밀도와 일치하는 십진수로 다룬다. 최대4자리 소수와 불필요한 뒤0 제거를 고려한다. 기존 메뉴의 ceil로 만든 정수 값을 정확한 차감액처럼 옮기지 않는다. 예를 들어12.5를13 SUP 확정 비용으로 표시하지 않는다. 계정 잔액은 실제 기존 포맷을 유지하되 확인 버튼의 금액과 실제 차감액이 다르면 안 된다.

처리 중 이전 잔액은 요청 전 확인값이다. 예상 잔액은 아직 완료된 잔액이 아니다. 완료 후에는 서버에서 확정된 사용 금액과 최신 잔액을 표시한다. 다른 거래가 끼어들었는데 단순 뺄셈으로 실제 남은 잔액을 단정하지 않는다.
