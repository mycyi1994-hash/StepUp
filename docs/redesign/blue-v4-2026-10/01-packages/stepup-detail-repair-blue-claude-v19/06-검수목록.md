# 신발 상세와 수리 구현 검수

아래 항목은 Claude가 실제 앱 구현 후 확인할 목록이다. 현재 체크되지 않은 상태이며 정적 시안 제작만으로 앱 검증을 통과한 것이 아니다.

- [ ] 원본 신발·등급 프레임과 기존 공통 로고가 유지된다.
- [ ] 레벨·효율·착화감·내구도 네 독립 행이 한 줄 형식을 유지한다.
- [ ] 등급 배지를 착용 상태로 덮어쓰지 않고 번호가 바로 오른쪽에 있다.
- [ ] 바 길이는 실제 함수값·상한으로 계산되고0/작은 양수/100%가 맞다.
- [ ] 최신 최대20 정책과 서버 상한의 차이를 해결하거나 미완료로 명시한다. 기존 계정 값을 임의로 낮추지 않는다.
- [ ] 선택과 착용, 모델 ID와 소유 ID, 민트 번호와 체인 번호가 구분된다.
- [ ] 착용 성공은 실제 저장된 wearing ID로 확인하고 안내는 한 번만 표시한다.
- [ ] 조회 실패·없는 신발·이미지 실패·첫 착용 상태가 구분된다.
- [ ] 직접 강화는 별도 강화 페이지, 수리는 모달로 열린다.
- [ ] 관리에서 수리·판매·신발 기록에 접근하며 착용 중 판매는 막힌다.
- [ ] 수리 전 확인 금액, 회복량, 잔액, 부족분이 실제 데이터와 일치한다.
- [ ]99.6 같은 소수 내구도는 비용 계산에서 표시용 정수로 바뀌지 않는다.
- [ ] 진행 중 중복 실행을 막고 닫기나 뒤로 가기를 서버 취소로 오해하지 않는다.
- [ ] 네트워크 끊김 뒤 결과 확인은 읽기 요청이며 자동 수리 재실행이 없다.
- [ ] 비용 변경은 새 확인 화면에 반영되고 서버 견적 검증의 미구현 부분을 숨기지 않는다.
- [ ] 완료 화면의 사용 금액과 잔액은 해당 작업의 확정 및 동기화 근거가 있다.
- [ ] 로그인 이후 자동 착용이나 자동 수리를 하지 않는다.
- [ ] 동일 모델의 다른 보유 신발이 섞이지 않는다.
- [ ]320~390dp와 큰 글씨에서 버튼·수치·관리 메뉴가 잘리지 않는다.
- [ ] 모달 초점·닫기·뒤로 가기·48dp 터치 영역을 확인한다.
- [ ] 기존 밝은 테마·언어·계정·저장소 식별자가 보존된다.
- [ ] 저장소가 요구하는 디자인 계약과 문자열·리소스 검사, 변경 관련 기존 테스트를 수행한다.
- [ ] 실제 앱 빌드와 동일한 변경 상태에서 캡처한다.
- [ ] 변경 파일, 실행한 검사, 실제 캡처, 미완료 연동을 보고한다.

시안 검수 증거는 audit/시각검수.json, 예시 계산 검증은 audit/수리예시검증.json에 있다. 이 둘은 앱 실행이나 서버 거래를 검증한 자료가 아니다.
