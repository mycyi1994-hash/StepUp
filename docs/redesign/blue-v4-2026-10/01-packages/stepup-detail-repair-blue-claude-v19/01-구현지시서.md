# StepUp 신발 상세와 수리 구현 지시서

이 전달본은 신발 상세 19개와 수리 모달 11개 상태를 승인된 남색과 파란 조명 톤으로 정리한다. 각 PNG는 정적 시안이며 Android 구현 완료 화면이 아니다. 기존 내 신발과 보관함 구성은 별도 신발탭 전달본을 유지한다.

기본 배치는 [신발 상세](images/SD01.png), 수리 확인은 [수리 모달](images/RP01.png)을 따른다. [화면별 동작표](02-화면별-동작표.md)에 모든 상태의 진입 조건과 버튼 연결을 정리했다.

## 상세 화면

상단은 뒤로 가기, 신발 상세 제목, 관리 버튼이다. 이 상세 경로에 메인 로고·SUP 잔액·하단 탭을 새로 중복 삽입하지 않는다. 공통 화면 정책과 시스템 안전 영역을 사용한다.

본문 순서는 신발 무대, 신발 이름과 등급·번호, 네 능력치 행이다. 이름이 길면 두 줄까지 허용하고, 등급 배지와 바로 오른쪽 번호는 함께 유지한다. 착용 여부를 보여주려고 등급 배지를 대체하지 않는다. 이름은 실제 모델의 현지화 이름, 번호는 선택한 소유 신발의 mintNumber다.

네 행은 레벨, 효율, 착화감, 내구도 순서다. 각각 별도의 둥근 파란 배경을 두고 그 안에 항목명·바·수치를 한 줄로 배치한다. 네 행 전체를 다시 감싸는 큰 카드는 만들지 않는다. 바 아래에 SUP 보너스, 에너지 절약 같은 설명을 반복하지 않는다. 속성·행운·원시 착화감 배율·에너지 추가 행은 본문에 넣지 않는다.

하단에는 작은 파란 강화하기 버튼과 더 넓은 흰 착용 버튼을 둔다. 강화하기는 선택한 소유 ID를 갖고 별도 강화 페이지로 이동한다. 이전 상세 지시서의 관리 메뉴에만 강화가 있던 방식보다 최신 사용자 지시가 우선한다. 강화 화면과 재료 소각 규칙은 별도 강화 17장 전달본을 따른다. 삭제된 성공확률 설명 모달을 복원하지 않는다.

착용하지 않았다면 이 신발 신기, 이미 착용했다면 비활성 지금 신고 있어요, 요청 중이면 비활성 신발 바꾸는 중…을 표시한다. 목록에서 선택하거나 상세를 여는 것만으로 착용 요청을 보내지 않는다.

## 관리와 신발 기록

[미착용 관리](images/SD13.png)와 [착용 중 관리](images/SD14.png)는 같은 모달 컴포넌트다. 수리하기, 판매하기, 신발 기록 세 행을 사용한다. 수리는 해당 소유 신발의 비용을 조회하는 모달로, 판매는 현재 판매 절차로 연결한다. 착용 중에는 판매만 비활성화하고 사유를 보여준다. 자동으로 신발을 벗기지 않는다.

두 관리 이미지의 아이콘 차이는 생성상의 차이다. 실제 구현은 미착용 관리의 간결한 아이콘 없는 행으로 통일하고, 착용 상태에 따른 활성 여부만 바꾼다. 직접 강화 버튼이 있으므로 관리 메뉴에 중복 강화 항목을 추가할 필요는 없다.

신발 기록은 기존 획득일·체인 정보에 접근하는 읽기 전용 모달이다. 본문을 능력치 자세히와 신발 정보로 다시 나누지 않는다. 등록 없음, Token, Vault는 실제 ChainMark에 따라 표시한다. No.0007과 Token #142 같은 서로 다른 식별자를 합치지 않는다. 주소·거래 성공·체인 등록을 추측해서 채우지 않는다.

## 색과 신발 무대

| 역할 | 색상 기준 |
|---|---|
| 화면 배경 | #031427 |
| 기본 파란 표면 | #0B2B50 |
| 주 파랑 | #0754FF |
| 조명과 강조 | #48D9FA |
| 기본 글자 | #F5F8FF |
| 보조 글자 | #AAC3EA |

신발은 기존 원본 아트와 등급별 프레임을 재사용한다. 파란 조명과 낮은 원형 받침은 무대 안에 한정한다. Rare 예시의 파란 프레임을 모든 등급에 적용하지 않는다. 에픽·레전더리의 기존 등급색과 레드라인·피니시의 시리즈 구분을 유지한다.

바의 형태는 기존 승인된 카툰 입체형을 유지한다. 짙은 외곽선, 파란 프레임의 윗면과 아랫면, 남색 트랙, 이어진 단일 채움, 짧은 윗면 하이라이트로 만든다. 눈금·분할 블록·손잡이를 추가하지 않는다. 레벨은 노랑, 효율은 파랑, 착화감은 보라, 내구도는 청록이다. 반복 반짝임이나 상시 펄스는 넣지 않는다.

주 버튼은 흰 면과 짧은 파란 하단면, 보조 버튼은 파란 면, 비활성은 낮은 대비의 남색 회색이다. 생성 이미지의 미세한 테두리·아이콘·버튼 명암 차이를 화면별 복제하지 말고 공통 컴포넌트로 통일한다.

## 수리 모달

관리에서 수리하기를 누르면 대상 신발과 최신 내구도·수리 비용·잔액을 조회한다. 수리 화면은 별도 전체 페이지가 아니라 상세 위의 하단 모달이다.

확인 화면은 제목, 신발 이름과 번호, 내구도 현재→최대 바, 보유 잔액과 수리 후 예상 잔액, 비용이 들어간 수리 버튼 순서다. 부분 수리 슬라이더나 추가 결제 메뉴를 만들지 않는다. 이미 최대 내구도이면 닫기만, 잔액이 부족하면 부족분과 비활성 수리 버튼을 보여준다. [금액과 데이터 기준](04-데이터와-금액기준.md)을 따른다.

진행 중에는 중복 요청을 막고 이전 잔액과 예상 잔액을 구분한다. 나중에 확인하거나 모달을 닫아도 서버 요청이 취소되었다고 말하지 않는다. 요청 후 연결이 끊기면 결과 확인과 나중에만 제공한다. 결과 확인은 조회이며 수리 재요청이 아니다.

완료는 해당 작업의 성공과 최신 내구도·잔액 확인 후에만 표시한다. 성공 응답은 받았지만 동기화가 미완료이면 완료 금액을 추측하지 말고 확인 중으로 남긴다. 현재 서버 복구 계약의 한계는 [코드 차이](03-현재코드와-차이.md)에 명시했다.

## 배치와 접근성

시안은 대부분853×1844px이며 이 수치를 dp 고정 좌표로 옮기지 않는다. 390dp 화면 기준 좌우16dp, 능력치 행 기본54dp, 행 사이8dp, 모서리14dp에서 시작한다. 네 바의 시작점과 끝점, 숫자 열 폭을 맞춘다. 항목명 약17sp, 값 약16sp, 터치 영역은48dp 이상으로 검토한다.

작은 화면에서는 먼저 신발 무대와 여백을 줄이고, 필요하면 본문을 스크롤한다. 글자 확대 시 행 높이와 이름 줄바꿈을 허용한다. 수치와 버튼을 작게 줄여 억지로 한 화면에 넣지 않는다. 고정 하단 버튼과 시스템 내비게이션이 내용을 가리지 않게 한다.

모달 밖에는 일관된 어두운 스크림을 적용하고, 바깥 내용은 입력을 받지 않으며 접근성 초점도 모달 안에 둔다. 열고 닫을 때 초점을 복원한다. 닫기·뒤로 가기의 처리 중 동작은 화면별 동작표와 같아야 한다. 스크림 아래 상세의 값은 실제 상태를 유지하고 모달 그림을 위해 지우지 않는다.

진행바는 입력용 슬라이더가 아니다. 읽기 도구에는 항목명과 실제 값·상한을 전달하고 장식 면은 읽지 않는다. 색상만으로 등급이나 비활성을 구분하지 않는다. 기존 밝은 테마와 언어 지원을 삭제하지 않는다.
