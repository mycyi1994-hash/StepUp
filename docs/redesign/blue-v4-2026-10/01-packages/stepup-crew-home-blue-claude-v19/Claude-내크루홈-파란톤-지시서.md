# StepUp 내 크루 홈 · Claude 구현 지시서

기존 내 크루 홈의 구도와 기능을 유지하면서 승인된 남색·전기 파랑 톤으로 바꾼다. 기준 화면은 [CH00](01-screens/CH00.png)이다. 큰 크루 카드 → 크루 채팅과 다음 러닝 → 참석 상태 → 주간 활동 → 고정 공지 순서를 유지한다. 전역 메인 화면으로 바꾸거나 새로운 게임 기능을 붙이지 않는다.

이 전달본은 CH00~CH31의 정적 상태 32장이다. 새 제작 27장, 승인 파일을 픽셀 변경 없이 재사용한 5장이다. 32개의 새 경로를 만들라는 의미가 아니다. 실제 앱 코드 수정·기기 실행·서버 검증은 이 패키지 제작 과정에서 하지 않았다. Figma 레이어나 앱 컴포넌트 소스도 아니다.

## 적용 순서와 근거

1. 현재 프로젝트의 AGENTS.md 및 저장소 지침을 읽고 작업 중인 변경을 보존한다.
2. `CrewHomeNavGraph.kt`, `CrewHomeScreen.kt`, `CrewHomeDetails.kt`, `CrewMeetingScreens.kt`, `CrewWeekScreens.kt`, `CrewHomeParts.kt`, 관련 ViewModel·Repository·Domain을 먼저 확인한다. 파일 해시와 실제 경로는 [source-snapshot](audit/source-snapshot.json), [경로표](audit/routes.json)에 있다.
3. [화면별 동작](화면별동작.md)의 진입·버튼·복귀와 현재 상태 모델을 연결한다. 기존 Android Kotlin/Compose 컴포넌트를 수정하며 별도 웹페이지로 다시 만들지 않는다.
4. 패키지의 시안과 동작 명세를 함께 적용한다. 예시 숫자·이름·모임·날짜는 실제 서버값으로 대체한다. 이미지에 있는 숫자를 API 기본값으로 넣지 않는다.
5. 현재 코드와 달라지는 문구·색·보조 설명은 [차이 목록](audit/code-design-differences.json)에 따로 기록했다. 데이터 계약을 임의로 바꾸지 않는다.

## 색과 구성

- 배경 `#031427`, 주요 면 `#0B2B50`, 전기 파랑 `#0754FF`, 강조 `#48D9FA`, 본문 `#F5F8FF`를 기준으로 한다. 값은 [design-tokens.json](design-tokens.json)을 따른다.
- 흰 주 버튼에는 얇은 파란 하단면을 둔다. 한 화면의 주 행동은 한 개를 기본으로 하며, 참석 여부 시트의 두 선택지는 같은 남색 보조 버튼으로 표현한다.
- 크루 대표 이미지의 자주색 19:30 그림은 크루 고유 이미지다. 공통 색상에 맞춘다는 이유로 실제 사용자가 올린 이미지를 전부 파랗게 덮지 않는다.
- 작은 선 아이콘을 기존 아이콘 세트로 통일한다. 생성 이미지의 아이콘을 잘라 쓰거나 이모지로 대체하지 않는다. 같은 사람의 아바타 색은 같은 컴포넌트에서 관리한다. 기록 응답에는 크루장 정보가 없을 수 있으므로 아바타 색만으로 역할을 단정하지 않는다.
- 이 묶음은 모두 중첩 화면이다. 전역 5개 하단 탭, SUP 잔액, 원본 로고를 새로 넣지 않는다. 전역 화면에 쓰는 공식 로고는 보존용 자산으로만 동봉했다.
- 기준 PNG는 약 887×1774의 비교 이미지이며 dp 값이 아니다. 기존 반응형 폭, 시스템 바·키보드 인셋, 48dp 터치 영역을 유지한다. 화면이 짧거나 글자가 커지면 본문이 스크롤되고 하단 행동은 가리지 않게 한다.
- 제목·수치·중요 장소명을 잘라 고정 높이에 맞추지 않는다. 크루 카드의 레벨·인원·크루장 탭 영역이 부모 카드 탭과 중복 실행되지 않아야 한다.

## 홈과 소개

CH00에서 크루 카드 본문은 CH01, 레벨은 CH03, 인원은 CH04, 크루장 이름은 CH05로 간다. CH01의 대표 이미지를 누르면 기존 공통 확대 화면 CH02를 쓴다. 한눈에 보이는 소개 정보는 실제 지역·일정·거리/속도 설명과 크루장 안내만 사용한다.

크루 채팅은 일반 크루원 CH07, 크루장 CH30으로 연결된다. 같은 크루의 방이 이미 뒤에 있으면 기존 `backToRoom` 동작으로 그 방과 읽던 위치를 복구한다. 채팅 정보에서 내 크루 홈을 다시 열 때도 `openCrewHome`의 중복 스택 방지를 유지한다. 그림 파일이 여러 곳에서 필요하다는 이유로 방을 새로 만들지 않는다.

홈의 다음 러닝 타일과 참석 상태 행은 같은 meetingId의 상세 CH09/11/12로 간다. 홈에서 참석 여부를 즉시 저장하지 않는다. 주간 영역은 CH15, 고정 공지는 실제 noticeId의 CH20으로 이동한다.

CH22는 일반 멤버 메뉴다. 크루 소개, 크루원, 공지, **크루 게시판**, **함께 달리기**, 크루 나가기를 보존한다. 게시판·함께 달리기는 현재 호출자가 전달하는 경로를 사용한다. 크루장은 마지막 행을 관리로 바꾸고 기존 CP40 흐름으로 연결한다. 일반 멤버의 나가기는 기존 확인 시트(CP61)를 거치며, 성공 후 홈·채팅 캐시와 관련 스택을 정리해 크루 목록으로 돌아간다. 실패를 성공처럼 표시하지 않는다.

CH23은 모임이 없는 분기다. 주간 126km와 미읽음 메시지 3개는 존재할 수 있다. 모임이 없다는 이유로 이 값을 0으로 만들지 않는다. 시안은 고정 공지도 없는 별도 예시다. 공지가 있으면 실제 공지를 계속 표시한다.

CH26은 저장된 홈 정보도 없는 최초 조회 실패다. 갱신 실패로 기존 정보가 남아 있을 때는 기존 내용을 유지하고 작은 재조회 안내를 보여주는 현재 동작을 보존한다.

## 크루 레벨·명단·프로필

크루 레벨은 서버가 제공하는 현재 레벨을 표시한다. CH03의 다음 레벨은 표시 자리이며 승급 조건은 현재 미정이다. `승급 기준 준비 중`을 유지하고 임의 XP, 필요 거리, 보상, 랭크, 승급률을 만들지 않는다. 레벨이 없으면 현재 코드의 새 크루 상태를 따른다. 주간 거리나 참여 인원도 조회 전에는 실제 값처럼 0을 넣지 않는다.

CH04의 24명은 전체 인원이고 보이는 7개 행은 첫 화면이다. 스크롤로 전체를 볼 수 있어야 한다. 검색은 현재의 이름 필터와 검색어 보존 동작을 사용한다. CH27은 지연 1명 결과이며 키보드는 닫힌 상태다. 검색어 지우기 X는 입력값만 지운다. 빈 검색 결과와 조회 실패를 구분한다.

CH05/06은 현행 내 크루 홈의 프로필이다. 실제 이름·역할·가입일, 크루장에게만 있는 안내문, 가장 최근의 공개 러닝 한 건을 표시한다. 일반 회원에게 크루장 안내를 복사하지 않는다. 현재 데이터에 없는 선호 지역·거리·개인 소개·온라인 여부를 만들지 않는다. 이 프로필을 채팅의 공개 프로필/내보내기 메뉴 화면으로 강제 대체하지 않는다.

최근 러닝 행의 시각은 현재 코드와 같이 **완료 시각**이다. 해당 runId를 CH19로 연다. 공개 기록이 없는 사람에게 샘플 기록을 넣지 않는다.

## 모임과 참석

CH09은 미응답·8명, CH11은 참석 저장 성공·9명, CH12는 불참 저장 성공·8명이다. 이 숫자는 설명용 분기다. 실제 앱은 저장 응답에 들어 있는 참석 인원을 그대로 사용한다. `기존 값 + 1`로 계산하지 않는다. 모임 참석 인원, 크루 소속 인원, 주간 기록 참여 인원은 서로 다른 값이다.

CH10은 이미 응답한 사람이 `참석 여부 변경`을 눌렀을 때다. 선택 즉시 요청하고, 성공하면 닫는다. 닫기·뒤로는 응답을 바꾸지 않는다. 저장 중에는 두 선택과 닫기·뒤로를 막아 중복 전송을 방지한다. CH25는 YES에서 NO로 변경하다 실패한 예시이며 기존 YES와 9명을 유지한다. 실패 문구 아래 별도 확인 단계를 더하지 않고 원래 선택을 재시도할 수 있게 한다.

모임 정원은 크루 정원 30명과 별개다. 이 시안의 모임은 정원을 설정하지 않은 예시라 정원 숫자를 표시하지 않는다. 실제 capacity가 양수이면 표시하고 가득 찼을 때 신규 참석만 막는다. 이미 참석한 사람은 불참으로 바꿀 수 있어야 한다. 시작된 모임에는 변경 버튼을 숨기고, 삭제된 모임·통신 오류·소속 종료는 각각 다른 상태로 처리한다.

CH13은 실제 참석자 명단이다. 진행자는 먼저 표시하며 크루장과 진행자가 같은 사람인지 별도 값으로 판단한다. 이름을 누르면 해당 userId의 홈 프로필을 연다.

## 지도

CH09/14의 지도는 모이는 좌표 한 곳을 보여준다. CH19는 서버가 반환한 공유 경로를 보여준다. PNG에 있는 `지도 예시`와 `경로 예시` 그림은 구현 자산이 아니다. 기존 `StepUpMap`·타일·지도 저작권 표기·실제 좌표를 사용한다. 임의 지도를 실제 위치처럼 표시하지 않는다.

집결 좌표가 없으면 가짜 핀이나 경로를 그리지 않는다. 장소 이름은 그대로 보여주고 현행 지도 앱의 장소 이름 검색을 사용할 수 있다. 외부 앱이 없으면 현재 화면에서 안내한다. 집결 장소를 여는 데 현재 위치 권한을 새로 요구하지 않는다. 돌아오기 버튼은 기존 모임으로 돌아가며 새 모임 화면을 중복 적재하지 않는다.

현재 크루 공유 경로는 서버에서 출발·도착 각각 300m를 제외하고 최대 64점으로 제한한다. CH19의 끝점은 잘린 공유 구간의 끝이며 실제 출발·도착점이 아니다. 원래 좌표를 복원하거나 두 끝점을 직선으로 닫지 않는다. 남은 점이 2개 미만이면 지도를 숨긴다. 지도에 공개하지 않는 구간도 전체 거리·시간 계산에서는 임의 차감하지 않는다.

## 주간·참여 기록

KST 월요일~일요일과 서버의 시작 시각 기준 주/일 분류를 유지한다. 목록은 완료 시각 내림차순이다. 자정을 넘긴 러닝의 날짜 소제목과 시각이 다른 이유를 임의로 보정하지 않는다.

CH15는 9.28~10.4, 월 61.2 + 화 64.8 = 126km, 목표 160km, 반올림 79%, 9명이다. 아직 오지 않은 수~일은 `—`이고 선택하지 않는다. 과거 실제 0km인 날은 0으로 표시하며 미래와 다르다. 현재 요일만 강조하고 과거 주에는 오늘 강조를 넣지 않는다.

CH17은 9.21~9.27, 142km, 11명이다. 현재 서버는 과거 주에도 **현재 크루의 목표**를 반환하므로 `현재 목표 160km`와 그 기준을 안내한다. 과거 목표가 저장되어 있다고 가정하지 않는다. 실제 목표가 없으면 목표·퍼센트·진행 막대·남은 거리를 숨기고 실제 누적만 보여준다. 100%를 넘으면 막대 길이만 제한하고 숫자를 100으로 잘라 쓰지 않는다.

날짜 선택 CH16은 즉시 적용한다. 주간 화면의 요일 탭은 그 날짜의 CH18, 개인 행은 그 주·그 userId의 기록, 전체 버튼은 그 주 전체 기록을 연다. CH18의 드롭다운을 눌러 다른 주를 선택하면 현행 동작대로 날짜·개인 필터를 풀고 그 주 전체로 바뀐다. 필터 설명과 실제 목록이 일치해야 한다.

CH18에 보이는 6건은 전체가 아니다. 더 읽기, 원본 endedCursor와 id를 이용한 페이지 구분·중복 제거를 유지한다. 기록 상세에서 돌아왔을 때 조회 범위와 목록 위치를 보존한다. 페이지 추가 조회 실패 안내는 현재 코드가 실패를 별도 표시하지 않아 후속 보완 대상으로 남겼다.

CH19의 5.2km, 36:24, 7′00″는 같은 기록의 값이다. 거리/시간이 페이스를 계산할 수 없는 경우 `—`를 유지한다. 하단 `참여 기록으로`는 기존 목록에서 왔으면 그 필터로 복귀하며, 프로필에서 왔으면 현재 주 전체 참여 기록을 연다. 상단 뒤로는 원래 호출자로 돌아간다.

CH24는 조회 결과가 실제 0km·0명인 별도 분기다. 로딩이나 오류에 이 빈 상태를 먼저 보여주지 않는다. 본문은 크루에 공개한 기록만 합산된다는 점을 설명한다.

## 채팅·공지 재사용

- CH02 = 기존 CP09.
- CH07 = CHAT02 r2, CH08 = CHAT04.
- CH30 = CHAT03, CH31 = CHAT05.

위 5장은 원본 파일 그대로다. 재사용 여부와 원본 해시는 [screen-index.json](screen-index.json)에 있다. 별도 UI를 또 구현하지 않는다.

채팅 재사용 이미지는 9월28일의 기존 독립 스냅샷이고 새 홈·모임·공지 이미지는 9월29일 예시다. 이를 같은 순간의 데이터라고 하드코딩하지 않는다. CH20/21의 공지는 홈에 보이는 제목·작성일과 맞춘 새 예시이며 기능은 기존 ChatRoutes.NOTICE/NOTICES다. 일반 크루원에게 수정 메뉴를 주지 않는다. 공지에 실제 연결 모임이 있을 때만 모임 행을 표시한다. 작성·수정·삭제·연결 선택은 이전 크루 채팅 전달본의 규칙을 보존한다.

## 완료 판단과 남은 상태

현재 32장은 개별 시각 검수 완료다. [추가 상태 목록](audit/additional-state-audit.json)의 로딩·권한·정원 충돌·캐시·키보드 등은 별도 시안 또는 실행 검증 대상으로 남아 있다. 32장이 있다는 이유로 전체 기능 검증 완료라고 보고하지 않는다.

구현 후에는 다음을 실제 기기/에뮬레이터로 확인해 보고한다.

1. 작은 화면·큰 글자에서 모임 버튼, 시트 선택지, 기록 값이 시스템 바·키보드에 가리지 않는지.
2. 같은 방↔홈↔정보 왕복 시 중복 화면 없이 읽던 위치로 돌아가는지.
3. 참석 저장 성공/실패/정원 충돌/닫기/재진입/느린 이전 응답에서 홈과 상세의 인원이 일치하는지.
4. 모임 없음, 기록 없음, 최초 실패, 기존 데이터의 갱신 실패가 서로 구분되는지.
5. 주·날짜·개인 필터, 미래 날짜, 과거 0km, 페이지 추가 조회 및 상세 복귀가 맞는지.
6. 탈퇴·내보내기·해산·계정 변경 후 기존 크루 정보·채팅·경로가 뒤로 가기나 캐시로 다시 노출되지 않는지.
7. 실제 지도 타일과 권리 표기를 유지하며 좌표 없음·경로 없음에서 가짜 그림을 넣지 않는지.

결과에는 변경 파일, 구현한 상태, 실제로 실행한 확인과 아직 확인하지 못한 부분을 구분한다. 시안 PNG 제작을 앱 구현 완료로 표현하지 않는다.
