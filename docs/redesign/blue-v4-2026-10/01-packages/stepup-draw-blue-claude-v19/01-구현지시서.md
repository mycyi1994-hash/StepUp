# StepUp 뽑기 — 파란 쇼케이스 스타일

기존 뽑기 기능을 유지하며 승인된 파란 쇼케이스 톤으로 바꾼다. 무료 뽑기와 상급 뽑기를 한 화면의 두 패널로 보여준다. [기본 화면](images/DRAW02.png), [원본 로고](assets/STEPUP-원본로고.png)를 기준으로 한다.

이번 전달물은 DRAW00~DRAW33의 정적 PNG 34장과 동작·검수 문서다. DRAW00은 기존 신발탭 SH01을 재사용한 진입 참고다. 앱 코드, Figma 컴포넌트, 분리된 새 상자 애니메이션 자산이 완성됐다는 뜻이 아니다.

## 구현 우선순위

현재 서버·보유 신발·지갑 연결 규칙과 이 문서의 동작표가 이미지의 예시 숫자보다 우선한다. 스타일은 최신 승인 톤을 사용한다. 기존 앱의 무료/상급 글자 탭 배치는 이번 두 패널로 대체하지만 그 안의 상태 판단과 서비스 로직은 재사용한다.

1. 현재 작업 트리의 변경을 확인하고 기존 사용자 작업을 유지한다.
2. 공통 헤더·버튼·패널·시트·타이포를 먼저 만든다.
3. 메인 두 패널에 현재 상태 모델을 연결한다.
4. 안내 시트와 요청·상자 열기·결과·복구를 연결한다.
5. 검수목록의 상태를 재현하고 실제 앱 캡처로 확인한다.

## 화면 구성과 크기

공통 STEPUP 로고와 채워진 SUP 버튼 → 신발 뽑기 제목 → 무료 패널 → 상급 패널 → 기회 받는 방법 → 기존 다섯 하단 탭 순서다. 두 패널의 상자 그림은 왼쪽, 횟수·상태는 오른쪽, 주 버튼은 아래에 둔다.

기본 뷰포트에서는 두 칸의 주요 상태와 버튼을 볼 수 있게 한다. 887×1774 PNG를 dp로 복사하지 않는다. 작은 화면과 큰 글씨에서는 콘텐츠 스크롤을 허용하며, 두 번째 버튼이 하단 탭이나 시스템 영역 뒤로 사라지지 않게 한다. 텍스트를 억지로 줄이거나 두 칸을 글자 탭으로 바꾸지 않는다.

공통 하단 탭은 러닝 / 신발 / 뽑기 / 커뮤니티 / 내 정보다. 기존 아이콘을 사용한다. 뽑기 선택은 파란 면·흰 아이콘·글자로 나타낸다.

DRAW10~14,20,33 같은 요청·연출·결과 화면에서는 로고·SUP 헤더를 유지하고 하단 탭만 숨긴다. 헤더 아래 뒤로/닫기 또는 건너뛰기 자리를 통일한다. 시안에서 일부 화살표가 빠져 있어도 앱의 기존 복귀 동작을 제거하지 않는다.

## 시각 기준

| 역할 | 값 |
|---|---|
| 배경 | #031427 |
| 패널·시트 | #0B2B50, 시트는 불투명 |
| 주요 파랑 | #0754FF |
| 청록 강조 | #48D9FA |
| 본문 | #F5F8FF |
| 보조 글자 | #AAC3EA |

원본 STEPUP 로고를 그대로 쓴다. 재타이핑·재생성·다른 로고로 교체하지 않는다. 이미지의 로고 근사치보다 원본 자산이 우선이다.

제목은 굵고 약간 기울어진 인상을 주되 긴 한국어 안내 본문은 정자로 읽기 쉽게 둔다. 기존 글꼴 체계와 라이선스를 우선한다. 캐릭터, 이모티콘, 영어 구호, 추가 보상 아이콘을 만들지 않는다.

주 버튼은 흰 면·남색 글자·얇은 파란 하단면이다. 누름은 약한 1~2dp 이동 또는 명도 변화로 표현한다. 비활성은 흐린 파란 면과 보조 글자를 사용한다. 터치 영역은 최소 48dp다. 그림에 따라 다른 모서리 모양은 하나의 공통 버튼으로 통일한다.

조명은 상자·신발 무대 중심에 둔다. 화면 전체를 깜빡이거나 텍스트에 광원을 겹치지 않는다. 시트 배경은 검정 약 60% 딤으로 헤더까지 어둡게 처리한다. 시트가 뜨면 뒤 화면의 버튼과 하단 탭은 조작·접근성 초점 대상에서 제외한다. 높이가 부족하면 시트 본문만 스크롤하며 실행 버튼을 읽을 수 있게 유지한다.

## 서버 데이터

- 무료 잔여 = 현재 서버의 dailyLeft + signupLeft.
- 상급 잔여 = 현재 서버의 giftLeft + runLeft.
- 첫 가입 10회, 하루 3회, 첫 WEB3 연결 10회, 연결 후 1km당 1회는 현재 사용자 정책 예시다. 실제 UI는 서버 설정과 회원에게 해당하는 규칙을 읽는다.
- 지급·차감·신발 결과·등급은 서버가 정한다. 폰에서 횟수를 더하거나 임의 신발을 당첨시키지 않는다.
- 조회 중·실패·로그인 전은 —, 결과 후 횟수만 미확인은 확인 중이다. 미확인을 0으로 바꾸지 않는다.
- 미확인 동안 기회 내역을 열어 가짜 값을 보여주지 않는다.
- 시안의 83.07 SUP, 13회, 10회, 신발 번호, 0.6/1km는 예시다. 잔액은 기존 공통 헤더 데이터다.
- 진행바는 실제 진행/실제 기준 거리로 계산한다. 0.6/1km라면 60%다.
- 가격, SUP 결제, 확률, 나올 수 있는 신발 목록을 새로 넣지 않는다.

## 요청과 결과

사용 가능한 뽑기 버튼을 한 번 누르면 현재 계정·종류·기준 번호·잔여 수를 기존 방식으로 기록하고 요청한다. 처리 중에는 무료와 상급 모두 중복 요청을 차단한다.

서버가 신발을 확정하면 상자 열기 후 결과로 이동한다. 서버 거절이나 미시작이 확인됐을 때만 “기회는 사용되지 않았어요”를 쓴다. 통신 시간 초과·응답 유실은 성공/실패를 단정하지 않고 결과 확인으로 보낸다.

DRAW20의 “결과 다시 확인”은 같은 미확인 요청을 조회한다. 새로운 뽑기 API를 호출하지 않는다. 조회 중에는 버튼을 잠시 비활성화하고, 조회가 끝났는데 여전히 불명일 때 재확인을 허용한다. 애니메이션을 기다리는 시간과 서버 확인 시간을 섞지 않는다.

뒤로·다른 탭·앱 재실행에도 기존 미확인 요청을 보존한다. DRAW26의 두 패널 버튼 모두 같은 진행 중 결과로 돌아간다. 계정이 바뀌면 다른 계정의 미확인 신발이나 횟수를 섞지 않는다.

결과의 “내 신발 보기”는 받은 소유 ID를 선택한다. 선택과 착용은 별개다. 같은 모델을 여러 개 가지고 있어도 소유 ID별 레벨·내구도·번호를 구분한다.

남은 수가 0이면 “한 번 더” 대신 “뽑기 화면으로”다. 남은 수를 모르더라도 받은 신발 결과는 유지하며 DRAW33으로 표시한다. 상급 결과도 서버 등급 그대로 표현하고 레전더리를 보장하는 색·문구를 사용하지 않는다.

## 지갑 연결과 조건부 장면

현재 DrawViewModel은 연결 페이지에서 복귀한 뒤 서버 상태를 다시 읽어 연결과 선물 증가를 확인한다. 현재 소스에 연결 앱의 실시간 진행·실패 이벤트가 없으므로 DRAW07/09는 그 이벤트가 실제로 제공될 때만 사용한다. 단순 복귀, 취소, 시간이 오래 걸림을 실패로 추정하지 않는다.

DRAW25/27도 연결 완료와 첫 선물 지급 대기를 구분할 수 있는 명시적 서비스 상태가 있을 때만 연결한다. 연결됨·giftLeft=0만으로 지급 대기를 추정할 수 없다. 이미 선물을 쓴 회원일 수 있다. 그 상태가 없으면 정상 상태 조회·실패·재조회 동작으로 처리하고 조건부로 남긴 사유를 보고한다. 이 색감 변경 때문에 가짜 타이머나 임의 보상 로직을 넣지 않는다.

재연결은 기존 보유 기회를 유지하고 연결 완료 알림만 보여준다. 처음 연결 선물 10회를 다시 지급하지 않는다.

## 연출

DRAW11은 상자 열기의 한 장면이다. 실제 동작은 서버 결과가 정해진 뒤 약 2초 안에 닫힌 상자 → 뚜껑 열림·약한 빛 → 받은 신발 등장 → 결과 순으로 한다. “건너뛰기”는 같은 확정 결과로 즉시 이동한다. 동작 줄이기에서는 약 0.2초 또는 정적인 전환을 사용한다.

기존 음향이 있다면 현재 소리 설정을 따른다. 새 효과음을 강제로 재생하지 않는다. 로딩을 표현하려고 무한 상자 개봉을 반복하지 않는다.

새 흰색/코발트 상자의 뚜껑·몸통·그림자는 아직 분리 자산으로 제공되지 않았다. 기존 자산과 새 시안의 차이, 필요한 제작물을 [자산 문서](04-자산과-구현범위.md)에 기록했다. PNG 전체나 상자에 합쳐진 텍스트를 앱 배경으로 사용하지 않는다.

## 코드 확인 위치

기준 checkout은 stepup-waitlist-implementation이다. 실제 대상 저장소가 다르면 같은 역할의 파일을 찾는다.

- ui/screens/gacha/DrawHome.kt: 두 패널 레이아웃 적용.
- DrawRules.kt: DrawHomeCard, PremiumMode, drawInfoSheet 등 기존 상태 판단 재사용.
- MysteryBoxScreen.kt: 시트·흐름·하단 알림.
- DrawViewModel.kt: 요청·결과·지갑 복귀·pending 보존. 스타일 변경을 이유로 경제 규칙을 바꾸지 않는다.
- DrawSheets.kt, DrawFlowScreens.kt, DrawKit.kt: 공통 화면과 모션.
- ui/StepUpRoot.kt, ui/AppChromePolicy.kt: 공통 헤더와 하단 탭.
- res/values*/draw_v2.xml: 기존 다국어 문자열.
- docs/redesign/shoe-draw-v3/README.md: 현재 26개 코드 상태.

기존 밝은 테마를 삭제하지 않는다. 밝은 테마·큰 글씨·회전/복귀·작은 화면도 현재 지원 범위에서 기능과 대비를 확인한다. 이번 전달물에서는 실제 앱 빌드나 기기 검사를 수행하지 않았다.
