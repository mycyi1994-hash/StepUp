# 뽑기 구현 검수

다음 항목은 구현 후 확인할 목록이다. 지금 완료된 것은 PNG의 시각 검수와 전달 파일 검증이다.

## 구성

- [ ] 원본 STEPUP 로고·기존 다섯 탭을 사용한다.
- [ ] 무료/상급은 동시에 보이는 두 패널이다.
- [ ] 기본·로딩·실패에서도 패널 순서와 상자/텍스트 위치가 바뀌지 않는다.
- [ ] 320dp, 360dp, 390dp, 412dp 및 큰 글씨에서 주요 문구·버튼이 잘리지 않는다.
- [ ] 시트는 헤더까지 딤 처리하며 뒤 화면이 눌리거나 초점을 받지 않는다.
- [ ] 흐름 화면의 하단 탭만 숨기고 헤더·복귀 동작은 유지한다.
- [ ] 버튼 영역 48dp 이상, 텍스트 대비·스크린리더 라벨·초점 복귀를 확인한다.
- [ ] 밝은 테마도 기존 기능과 가독성을 유지한다.

## 상태와 데이터

- [ ] 서버 실제 횟수·잔액·모델·소유 ID를 표시한다. 시안 숫자를 고정하지 않는다.
- [ ] 로딩/실패/로그인 전의 —와 실제 소진 0을 구분한다.
- [ ] 첫 연결 전의 받을 수 있는 선물을 보유 수로 표시하지 않는다.
- [ ] 재연결 시 보상 재지급·+10 성공 안내가 없다.
- [ ] 연결/선물 확인 중·실패를 서비스 근거 없이 꾸며내지 않는다.
- [ ] 하루 러닝 지급 한도여도 이미 가진 상급 기회는 사용할 수 있다.
- [ ] 상급 일시 중단 때 상급만 막으며, 서버가 허용한 무료는 유지한다.
- [ ] 발행 한도 거절은 미사용 안내와 확인 버튼으로 끝낸다.
- [ ] 무료 소진 시 상급 보기 버튼은 같은 화면의 상급 패널로 이동한다.
- [ ] 경과 거리와 횟수 지급은 서버 확인 후 갱신한다.
- [ ] 신규 기회 토스트는 증가를 실제 확인한 경우에만 나타나고 버튼을 가리지 않는다.

## 요청·결과·복구

- [ ] 빠른 연속 누르기에도 뽑기 요청은 한 번만 발생한다.
- [ ] 한 종류가 미확인일 때 다른 종류의 새 요청도 막는다.
- [ ] 서버 결과 확정 전에는 상자를 열거나 임의 신발을 보여주지 않는다.
- [ ] 타임아웃/네트워크 유실을 미사용 확정 실패로 표시하지 않는다.
- [ ] 결과 재확인은 새 뽑기를 호출하지 않는다.
- [ ] 뒤로·앱 종료/재실행 뒤에도 기존 요청을 복구한다.
- [ ] 계정 전환 시 다른 계정의 결과·요청·횟수를 노출하지 않는다.
- [ ] 결과의 신발은 이미 보유에 반영된 실제 소유 ID이며 자동 착용하지 않는다.
- [ ] 같은 모델 두 소유 신발의 번호·레벨·내구도가 섞이지 않는다.
- [ ] 마지막 기회와 남은 횟수 미확인 결과에 “한 번 더”가 없다.
- [ ] 상자 열기 건너뛰기/뒤로가 같은 결과로 연결된다.
- [ ] 동작 줄이기와 소리 설정을 따른다.
- [ ] 기존 관련 규칙 검사를 실행하고 새 두 패널의 상태 연결을 검증한다.

## 보고

변경 파일, 실제 앱 캡처, 실행한 검사와 결과, 미실행 검사, 조건부 상태 적용 여부, 미완성 자산을 함께 보고한다. 정적 PNG 검수 결과를 앱 테스트 통과로 쓰지 않는다.
