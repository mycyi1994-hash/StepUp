# StepUp 크루 채팅 리메이크 구현 지시서

기존 Android 앱의 크루 채팅을 이 패키지의 남색·파랑 디자인으로 바꾼다. 기존 동작과 권한은 유지한다. 44장은 화면의 **상태**를 나타내며, 새 경로 44개를 만들라는 뜻이 아니다. 이름·날짜·인원·읽음 수는 가상 예시이므로 실제 데이터에 연결한다.

## 1. 적용 순서와 연결

공통 컴포넌트 → 목록·크루원 방 → 크루장 방 → 정보·공지 → 메시지 행동 → 사진·검색·알림 → 실패·참여 종료 순으로 적용한다. [화면별 동작](화면별동작.md)을 체크리스트로 사용한다. [추가 상태 목록](audit/additional-state-audit.json)은 아직 개별 PNG가 없는 범위다. 기존 기능을 삭제해 시안과 비슷하게 만들지 않는다.

현재 ChatRoutes는 ROOM, INFO, MEMBERS, MEMBER, NOTICES, NOTICE, NOTICE_EDIT, SEARCH, PHOTO, VIEWER, REPORTED, ENDED의 12개다. 방은 crewId, 사람·공지·메시지는 각각의 실제 ID로 연결한다. 뒤로 가기는 실제 호출자와 스크롤 위치를 보존한다.

정보 화면의 연결은 다음과 같이 유지한다.

| 버튼 | 실제 목적지 |
|---|---|
| 크루원 보기 | CrewHomeRoutes.members, 내 크루 홈의 명단 |
| 크루 상세 보기 | openCrewHome, 내 크루 홈 |
| 멤버 관리 | 기존 크루장 관리 명단 CP55 |
| 공개 프로필 보기 | CrewRoutes.person, CP56/84 |

CHAT06은 남아 있는 채팅 명단 경로의 참고다. 이 시안이 있다는 이유로 현재 정보 화면의 진입점을 옛 경로로 바꾸지 않는다. 내 크루 홈은 별도 리메이크 묶음에서 이어진다.

## 2. 디자인과 공통 컴포넌트

원본 STEPUP 로고를 그대로 사용한다. CHAT01·31 목록만 로고, 커뮤니티 글자 탭 3개, 하단 탭 5개를 갖는다. 방과 중첩 화면에는 SUP와 전역 하단 탭을 넣지 않는다.

| 용도 | 기준 |
|---|---|
| 배경 | #031427 |
| 면 | #0B2B50 |
| 선·주 강조 | #0754FF |
| 보조 강조 | #48D9FA |
| 본문 | #F5F8FF |
| 주 버튼 | 흰 면 + 파란 하단면 |
| 삭제·숨김·내보내기 | 코랄 의미색 |

크루 대표 이미지의 고유색은 유지한다. 이미지 전체를 앱 배경으로 깔거나 버튼을 잘라 터치 영역을 얹지 않는다. 실제 Compose 텍스트·버튼·시트·리스트로 구현하고, 로고와 대표 이미지만 자산으로 사용한다.

아이콘은 프로젝트의 같은 세트를 재사용한다. CHAT16·36에서 생성된 전송 아이콘 차이는 새로운 자산 지시가 아니다. 기존 위쪽 화살표로 통일하고, 같은 회원의 ChatFace도 일정하게 표시한다. 이모지·왕관·새 게임 등급·가짜 온라인 수·지원하지 않는 ‘입력 중’ 표시는 넣지 않는다.

기준폭 390dp, 좌우 여백 20dp, 본문 16sp, 보조 14sp, 최소 터치 영역 48dp, 주 버튼 높이 56dp, 면 모서리 16dp, 시트 모서리 24dp로 시작한다. 실제 작은 화면과 큰 글자에 맞춰 조정한다. PNG의 887×1774를 화면 dp로 고정하지 않는다. 생성 원본 중 3장은 가로 886픽셀이며 늘려서 보정하지 않았다.

모달은 불투명 남색 면과 화면 전체를 덮는 약 55% 검정 scrim으로 구성한다. 다른 시트를 중복해서 쌓지 않는다. 키보드·시스템바 여백은 OS 값을 사용한다. PNG의 9:41·배터리·홈바를 앱에 그리지 않는다. 스크롤 본문과 고정 입력창·버튼 영역을 분리한다. 상시 광택·맥동 없이 누름, 시트 전환, 전송 중 상태에만 필요한 피드백을 적용한다.

## 3. 대화와 전송 복구

CHAT02는 도윤, CHAT03은 준호가 보는 같은 가상 대화다. 본인 메시지만 오른쪽 밝은 말풍선으로 표시한다. 크루장은 작은 텍스트 라벨로 구분한다. 전송 중·대기·실패에는 성공한 전송 시간이나 읽음 수를 붙이지 않는다.

텍스트는 최대 2,000자이며 공백만 있으면 보낼 수 없다. 보내기 버튼으로 전송하고 Enter는 줄바꿈으로 유지한다. 빠르게 두 번 눌러도 같은 메시지가 두 개 생기지 않아야 한다. 답장 해제는 인용 연결만 끊고 작성한 본문은 남긴다. 사진 선택 취소도 채팅 초안을 지우지 않는다. 일반 채팅 초안은 현재 앱이 살아 있는 동안 메모리에 보존되므로, 앱 재시작 후 영구 보존을 보장하는 설명은 넣지 않는다.

| 상태 | 동작 |
|---|---|
| CHAT19 전송 실패 | 같은 clientId로 재전송. ‘지우기’는 서버 ID 없는 로컬 실패 메시지만 제거 |
| CHAT20 전송 대기 | 서버가 받았는지 모르는 상태. 재연결 후 요청 키로 결과 조회 |
| 대기 메시지 미수신 확인 | 실패로 바꿔 사용자가 재전송하도록 안내 |
| 연결 끊김 | 작성 내용 유지, 새 전송·첨부 비활성 |

전송 대기를 확정 실패로 취급하거나, 재연결 때 새 요청으로 무조건 재발송하지 않는다.

과거 대화를 읽는 중에는 새 메시지가 와도 스크롤을 빼앗지 않는다. CHAT21의 새 메시지 버튼으로 최신 위치에 이동한다. 검색 복귀도 messageId와 seq를 사용한다. 현재 갱신 주기는 활성 방 3초, 오류 후 4초, 목록 15초다. 이를 WebSocket 구현 완료로 표현하거나 디자인 변경을 이유로 서버 구조를 바꾸지 않는다. 백그라운드나 가려진 방을 읽음 처리하지 않는다.

## 4. 권한·삭제·숨김·참여 종료

일반 멤버가 다른 사람의 메시지를 길게 누르면 답장·복사·신고가 나온다. 본인 삭제는 서버의 canDelete 조건을 따른다. 크루장이 다른 멤버의 메시지를 누르면 공지 등록과 숨기기가 추가된다. 텍스트가 없는 사진에는 복사·공지 행을 무조건 표시하지 않는다. ‘공지로 등록’은 본문을 채운 작성기를 열며 즉시 게시하지 않는다.

| 처리 | 결과 |
|---|---|
| CHAT18 본인 메시지 삭제 | 해당 내용만 삭제 안내로 교체, 인원 24명 유지 |
| CHAT40 크루장 숨김 | 해당 내용만 숨김 안내로 교체, 작성자 소속과 인원 유지 |
| CHAT35 민수 내보내기 성공 | 서버 기준 23명으로 갱신, 탈퇴 시스템 줄 한 번 표시 |

확인 전이나 실패 시 인원을 줄이지 않는다. 대상은 이름이 아닌 userId 또는 messageId로 유지한다. 전송 중 중복 탭과 이탈을 처리하고 실패 시 대상과 현재 내용을 남긴다.

소속이 끝나면 CHAT32로 이동하고 해당 방의 화면 스택을 정리한다. 뒤로 가도 지난 대화·사진이 열리면 안 된다. 크루장 권한만 사라졌다면 일반 멤버로 남으므로 방을 갱신하고 한 번 안내한다. 기존 탈퇴·해산·권한 이전 흐름을 유지한다.

삭제·숨김·참여 종료는 본문뿐 아니라 인용, 검색, 사진 뷰어, 캐시에서도 확인한다. 현재 imageNow와 image()는 캐시를 먼저 읽을 수 있으므로 원격 변경이 이미 열린 뷰어에 반영된다고 가정하지 않는다. 다른 기기에서 숨김·삭제·내보내기를 실행하는 검증이 필요하다. 이 패키지에서는 실행 검증을 완료하지 않았다.

## 5. 공지와 모임 연결

제목은 1~100자, 본문은 선택이며 최대 2,000자다. 수정은 변경이 있어야 저장할 수 있다. 고정 공지는 하나다. 새 공지를 고정하면 이전 고정만 해제하고 기존 공지를 임의로 삭제하지 않는다.

CHAT10은 새 공지 C ‘오늘은 러닝을 쉬어요’를 작성하는 화면이다. 모임 연결은 없다. 저장 성공 후 CHAT13에서 고정과 시스템 줄이 바뀐다. CHAT11은 기존 공지 A에 ‘물도 챙겨주세요.’를 더한 수정 초안이며, 기존 모임 연결을 유지한다. 이 두 분기를 연속된 상태로 붙이지 않는다. 공지 삭제는 CHAT11 → CHAT12 확인 → 서버 성공 후 대화 복귀 순서다.

현재 앱의 모임 연결 기능을 유지한다. 해당 크루의 앞으로 열릴 모임 조회, 선택, 연결 안 함, 빈 목록, 조회 실패가 필요하다. 기존 연결을 그대로 둔 수정과 새 연결 선택은 서버 계약대로 구분한다. 저장 중 선택한 모임이 사라지면 잘못된 연결만 풀고 제목·본문·고정 상태는 남긴다. 이 오류는 일반 CHAT43 저장 실패와 다르게 안내한다. 모임 상세에서 뒤로 가면 그 공지로 돌아온다.

CHAT43은 작성 내용을 남기고 재시도한다. CHAT44의 ‘저장 후 나가기’는 공개 게시가 아닌 로컬 초안 저장이다. 계정·크루·새 공지 또는 수정 대상별로 구분한다. 저장 실패를 성공처럼 넘기지 않는지 현재 구현을 추가 확인한다. 요청 중 기존 공지부터 변경하거나 같은 내용을 중복 게시하지 않는다.

## 6. 사진·검색·알림·신고

사진은 OS 갤러리·카메라 → CHAT26 미리보기 → 보내기 → 성공 CHAT27 순서다. 선택만으로 전송하지 않는다. 사진 설명은 선택사항이며 최대 2,000자다. 기존 압축·파일 한도·요청 키를 사용한다. CHAT42 오류에서는 사진과 설명을 남기고 같은 요청으로 재시도한다. CHAT41은 이미 보낸 사진 조회이므로 전송 버튼이 없다. 자료 없음, 깨진 사진, 권한 거절, 로딩, 삭제 후 접근 상실도 추가 상태 목록대로 처리한다.

검색은 기존 최대 60자 상태를 재사용한다. CHAT22의 검색어 강조와 지우기 X는 UI 보완이다. 결과는 해당 메시지로 돌아가고 이미 사라졌다면 안내한다. CHAT23은 조회 성공 후 결과 0건에만 사용한다.

CHAT24는 내 개인 알림 설정, CHAT37은 OS 기기 권한이다. 개인 설정 켜짐과 기기 알림 꺼짐은 동시에 가능하다. 기기 설정에서 돌아오면 실제 권한을 확인한다.

메시지 신고 사유는 ABUSE·SPAM·CONTENT 세 가지다. 현행 CONTENT는 서버의 OTHER 코드로 전송한다. 선택 전 전송은 비활성, 실패 시 선택한 사유는 유지한다. 성공 후 CHAT29는 접수 확인만 표시하며 제재 완료를 뜻하지 않는다.

## 7. 구현 검수와 남은 범위

각 번호의 실제 기기 캡처와 동작 결과를 남긴다. 특히 다음 조건을 확인한다.

- 일반 멤버·크루장·혼자 있는 크루·가입 크루 없음의 권한과 메뉴
- 긴 이름·작은 화면·큰 글자·키보드·스크린리더
- 전송 중 중복 탭·오프라인 후 재연결·결과가 불명확한 요청
- 다른 기기의 권한 변경·삭제·숨김과 이미 열린 사진 뷰어
- 공지 초안 복원·저장 실패·사라진 모임 연결
- 삭제된 메시지나 없는 프로필에 가상 데이터를 채우지 않는지

44장과 비슷해졌다는 이유만으로 추가 상태나 전체 앱 완료를 보고하지 않는다. 변경 파일, 실제 캡처, 검증한 조건, 남은 조건을 별도로 제출한다. 이 패키지가 완료한 것은 정적 시안 제작, 개별 시각 검토, 문서 연결, 파일 무결성 확인이다. 앱 코드 수정·빌드·서버/API·기기 터치 검증은 수행하지 않았다.
