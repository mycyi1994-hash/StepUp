# StepUp 신발탭 색감 변경 지시서

대상은 기존 Android 앱의 신발탭이다. **내 신발 / 신발 보관함 구조를 그대로 두고**, 승인된 남색·전기 파랑·흰색 톤을 적용한다. 그림은 정적 시안이며, 앱 구현이나 자산 레이어 분리가 완료된 파일이 아니다.

## 기준 이미지

- [내 신발](images/01-내신발.png)
- [신발 보관함](images/02-신발보관함.png)
- [원본 로고](images/STEPUP-원본로고.png)

그림보다 실제 원본 로고와 실제 계정 데이터가 우선한다. 이전 v17은 색감 참고용이었으며, 이번 두 장은 현재 내 신발/보관함 구성에 맞춘 참고다. 로고를 다시 그리거나 새로 타이핑하지 않는다.

## 유지할 구성

내 신발은 다음 순서다.

1. 공통 STEPUP 로고와 실제 SUP 잔액.
2. 내 신발 / 신발 보관함 탭.
3. 신발 이름, 작고 둥근 등급 배지, 레벨·신발 번호·실제 착용 여부.
4. 기존 등급 프레임 안의 실제 신발과 받침/조명.
5. 효율·착화감·내구도 세 줄.
6. 보유 신발 수와 가로 목록.
7. 러닝 / 신발 / 뽑기 / 커뮤니티 / 내 정보의 공통 다섯 탭.

현재 구조에 있는 상세·관리 진입도 유지한다. 본문에 새로운 대형 “자세히 보기” 버튼을 추가하지 않는다. 시안의 작은 관리 버튼은 기존 상세/관리 동작에 연결한다.

보관함은 보유 수·정렬 → 등급 필터 → 두 열의 개별 소유 신발 목록 순서다. 동일 모델의 다른 소유 신발도 소유 ID별로 구분한다. 등급·레벨·번호·착용 상태를 표시한다. 기존 도감·마켓·아이템 링크는 유지하되 새로운 주요 행동처럼 키우지 않는다.

## 스타일

| 역할 | 기준 |
|---|---|
| 전체 배경 | #031427 |
| 표면 | #0B2B50 |
| 주요 파랑 | #0754FF |
| 청록 강조 | #48D9FA |
| 기본 글자 | #F5F8FF |
| 보조 글자 | #AAC3EA |

SUP 버튼은 파란색을 채워 읽기 쉽게 만든다. 하단 선택된 신발탭은 파란 면과 흰 아이콘/글자로 구분한다. 새로운 아이콘 체계를 만들지 않고 앱의 공통 아이콘을 사용한다.

신발 무대에만 조명과 낮은 받침을 적용한다. 이름, 능력치, 보유 목록 주변에 조명이나 입자를 추가하지 않는다. 네온이 텍스트에 번지지 않도록 한다. 자동 반짝임이나 상시 움직임은 추가하지 않는다.

기존 등급 프레임의 의미와 색을 보존한다. 모든 신발을 파란 등급 프레임으로 통일하지 않는다. 레드라인/피니시는 기존 시리즈 처리이며 임의의 새 등급이 아니다.

화면마다 생성 이미지의 테두리나 아이콘이 미세하게 다른 부분은 공통 컴포넌트 기준으로 통일한다. 바깥 장식 테두리가 콘텐츠를 압박하면 생략할 수 있다. 이는 레이아웃을 바꾸라는 의미가 아니다.

## 데이터와 동작

신발의 선택과 착용은 별개다. 가로 목록이나 보관함 카드를 누르면 선택한 소유 ID의 정보를 보여준다. 착용 체크는 서버/저장소에서 실제 착용이 확인된 신발에만 붙인다. 조회, 선택, 상세 진입만으로 equip 요청을 보내지 않는다.

이름은 실제 모델 이름, 번호는 mintNumber, 요청 식별자는 실제 소유 ID를 쓴다. 모델 ID, 목록 순서, 체인 tokenId를 신발 번호 대신 쓰지 않는다. 같은 모델의 레벨·내구도를 합치지 않는다.

세 능력치는 현재 계산 함수를 재사용한다. 값 아래에 SUP 보너스/에너지 절약 설명 문구를 다시 붙이지 않는다. 기존 도움말 접근 기능은 유지한다.

| 시안 예시 | 구현 시 원칙 |
|---|---|
| 효율 +4.8% | 실제 효율값 / 실제 효율 상한. 예시 상한27.5%일 때17.45% |
| 착화감 7.5% | 기존 에너지 절감 표시값 / 실제 상한. 예시 상한20%일 때37.5% |
| 내구도92/100 | 실제 내구도 / 상한100 |

이미지의 채움 길이는 미술적 근사치다. 수치를 눈대중으로 고정하지 않는다. 효율은 파랑, 착화감은 보라, 내구도는 청록으로 구분하되 숫자도 항상 보이게 한다.

조회 중에는 예시 신발·0 잔액·0개를 표시하지 않는다. 실패와 실제 빈 목록을 구분한다. 아트가 없는 모델에 다른 신발 그림을 대신 넣지 않는다. 기존 다시 불러오기 및 신발 뽑기 진입을 유지한다.

## 수정 범위와 코드 확인

확인 기준 checkout은 stepup-waitlist-implementation이다. 실제 대상 저장소가 다르면 해당 역할의 파일을 찾아 수정한다. 다른 checkout으로 이동하거나 작업 중인 변경을 덮어쓰지 않는다.

- docs/redesign/shoes-ui-2026-09-28/README.md: 현재 구성과 데이터 규칙.
- app/src/main/java/com/stepup/android/ui/screens/customize/CustomizeScreen.kt
- 같은 폴더의 MyShoesModel.kt
- ui/components/ShoeDisplay.kt 및 현재 SneakerGradeStage/공통 신발 컴포넌트
- ui/StepUpRoot.kt, ui/AppChromePolicy.kt: 공통 헤더/하단 탭 정책.
- 현재 공통 색·타이포·버튼 컴포넌트.

이 문서는 신발 상세의 네 개 바, 강화 경제 규칙, 수리 정책을 변경하는 지시가 아니다. 해당 기능으로 가는 기존 경로를 유지한다. 이 색감 작업 때문에 API·보유 데이터·잔액·도감 모델·정렬 의미를 바꾸지 않는다.

## 구현 및 자산 사용

PNG 전체를 앱 화면으로 사용하지 않는다. 텍스트, 숫자, 탭, 버튼, 진행바는 실제 Compose UI다. 기존 원본 신발 아트와 로고를 재사용하며, 시안에서 잘라낸 낮은 해상도 그림으로 대체하지 않는다.

전달물에는 두 장의 정적 PNG와 로고, 프롬프트가 포함된다. Figma 컴포넌트, 독립 조명/받침 레이어, 실제 코드 변경은 포함되지 않는다. 조명/받침은 기존 무대 컴포넌트에 적용하거나 별도 자산이 필요한 항목으로 기록한다.

시안 크기는887×1774px이며 dp값이 아니다. 현재 여백과 글꼴 체계를 우선 사용하고, 터치 영역은48dp 이상으로 검토한다. 긴 이름과 큰 글씨는 줄바꿈/높이/스크롤로 대응한다. 목록을 화면에 넣으려고 읽을 수 없게 글자를 줄이지 않는다.

어두운 톤 시안이 밝은 테마 기능 삭제를 뜻하지 않는다. 현재 밝은 테마도 기능과 대비가 유지되게 확인한다.

검수 결과에는 변경 파일, 실제 앱 캡처, 실행한 검사, 미완료 항목을 포함한다. 현재 전달물은 정적 시안 검수만 완료했다.
