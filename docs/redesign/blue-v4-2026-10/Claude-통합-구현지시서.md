# StepUp 승인 파란 톤 통합 구현 지시서 · v4

이 문서를 먼저 읽고 [범위별 지시서](README.md)와 각 최신 PNG를 확인한 뒤 기존 StepUp Android 앱에 적용한다. 이 패키지는 2026-10-03까지의 정적 시안과 구현 지침이다. 앱 구현·서버 기능·Figma 편집 파일·신규 레이어 자산이 완성된 결과물이 아니다. 다른 웹사이트를 새로 만들지 않는다.

## 기준과 우선순위

사용자의 이후 명시적 지시, 대상 저장소의 적용 지침, 이 통합 문서의 최신 상태/범위, 해당 기능의 동작 문서, PNG의 배치 순서로 판단한다. 실제 데이터·원본 로고·서버 상태는 그림 예시보다 우선한다. 보상·강화 등 문서의 제안과 현재 서버 계약이 다른 부분은 충돌을 기록하고 적용 여부를 구분한다. 연결되지 않은 계약을 구현 완료로 보고하지 않는다.

기능별 문서의 “다른 탭은 이번 범위가 아님”은 당시 묶음의 경계다. 이번 통합 전달에서는 README에 포함된 각 묶음을 해당 문서대로 구현할 수 있다. 과거 완료 수와 남은 수는 최신 screen-catalog.json / 미완료-36개.md를 따른다. 기존 상세 지침의 버튼 동작·예외·검증을 짧은 통합 문서만으로 대체하지 않는다. 기존 러닝 캡처를 비교할 때는 [사용자가 전달한 캡처 검토 기준](03-audit/사용자제공-기존캡처-검토기준.md)의 조건을 먼저 확인한다. 이 조건을 새 구현 전체에 대한 무조건적인 통과로 적용하지 않는다.

## 시각 방향

승인된 러닝 HOME과 원본 STEPUP 로고가 기준이다. 남색 #031427, 파란 면 #0B2B50, 전기 파랑 #0754FF, 청록 #48D9FA, 흰 글자/주 버튼 #F5F8FF를 쓴다. 이전 오렌지·노란 버튼 안이나 캐릭터를 복원하지 않는다. 신발 무대에는 기존 등급 프레임과 받침·조명을 적용하며 콘텐츠 주변의 과도한 장식은 줄인다. 원본 로고는 생성된 그림의 글자를 재작성하지 말고 앱 자산을 사용한다.

러닝/신발/뽑기/커뮤니티/내 정보의5탭 순서와 기존 경로를 유지한다. 루트 화면의 채운 SUP 버튼과 상세의 헤더 정책을 혼동하지 않는다. SUP 버튼을 모든 페이지에 붙이지 않으며 화면별 문서와 AppChromePolicy를 확인한다. 특히 내 러닝 기록·통계 H01~H10/H15는 실제 구현에서 하단 탭 유지 결정이 시안보다 우선한다. 설정 Detail도5탭 유지, 설정 시트는 탭 위까지 덮는다.

신발 탭은 원래 내 신발/보관함 구도를 유지하는 색감 변경이다. 참고 PNG에 안 보인다는 이유로 실제 관리 기능을 삭제하지 않는다. 상세는 레벨·효율·착화감·내구도4개 독립 행, 강화는 독립 화면, 수리는 시트 기준이다. 삭제한 UP16 성공률 계산 설명 모달은 다시 만들지 않는다.

## 자료 사용

- screen-catalog.json의 reviewed는 정적 시각 검수 완료다. pending 36개는 신규 파란 톤 PNG가 없다. 설정 SET01~40은 최신본 검수 완료이며 SET31은 보완된 r2를 사용한다. 실제 구현/QA 상태는 implementation-tracker.csv의 미확인·미검증에서 시작한다.
- 화면 ID는 페이지 수가 아니라 상태 표본이다. 로딩·키보드·시트·성공·실패를 별도 Activity로 각각 만들지 않는다. 공통 컴포넌트와 상태 모델을 재사용한다.
- 공유 참고 이미지와 재사용 별칭이 있다. 530개 검수 상태는 고유 신규 이미지530장 또는 앱 페이지530개라는 뜻이 아니다. 파일별 해시는 통합 목록과 FILES-SHA256.json으로 확인한다.
- 글자·숫자·버튼·탭·진행바를 통 PNG로 붙이지 않는다. 실제 Compose 컴포넌트와 데이터에 바인딩한다. 신규 조명/상자 등의 분리 자산이 없는 부분은 기존 자산 재사용 또는 추가 자산 작업으로 남긴다.
- 지도 시안은 배치 참고다. 실제 타일·좌표·경로·출처 표기를 사용하고 임의 지리 그림을 서비스 지도처럼 사용하지 않는다. 시스템 권한창·키보드·갤러리 선택은 OS 기능이다.
- 시안의 계정 이름·SUP·거리·성공률·인원·앱 버전은 예시다. 날짜와 시간도 실제 모델 값을 따른다. 예시값을 실제 데이터나 새 정책으로 저장하지 않는다.
- prompts와 source-audits의 로컬 절대 경로는 출처 기록이다. 다른 컴퓨터에서 해당 경로가 없더라도 패키지의 상대 경로 PNG/문서를 사용한다. 과거 생성 스크립트를 실행할 필요 없다.

## 기능별 핵심 보존

러닝은 HOME→U01의5개 같은 크기 선택→권한→카운트다운→측정→저장→보상 확인 흐름이다. 자유 러닝에 추가 목표 선택을 강제하지 않는다. 저장 성공과 SUP 적립 완료를 구분한다. 세션·GPS 단절·백그라운드 복귀·중복 저장을 실제 모델로 처리한다.

뽑기는 무료/상급 두 패널이다. 가입 무료10회, 지갑 연결 상급10회, 매일 무료3회, 연결 회원의 유효 러닝1km당 상급1회 기준은 해당 문서와 서버 계약에 맞춘다. 결과가 확정되기 전 타이머로 신발이나 보상을 만들지 않는다. 조건부 상태를 실제 기능인 것처럼 강제로 연결하지 않는다.

강화는 하위 등급 재료3개·최대Lv20·현재레벨 기반 기본 확률100−3L·재료 등급/레벨 보정이며 실패도 재료 소각이다. 정확한 사용자 확정 규칙과 보정 제안, 현행 SUP차감 코드 차이는 강화 문서와 balance-rules.json에 구분돼 있다. 클라이언트 연출만으로 소각·확률·결과를 확정하지 않는다.

커뮤니티는 러닝 이야기/크루 모집/크루 채팅을 보존한다. 코스 글쓰기는 최근3일 기록 첨부와 쉬운 장소 선택이다. 이미 게시한 기록에 소급 기간 제한을 걸지 않는다. 크루 모집·운영·채팅·내 크루 홈은 권한별로 구분한다. 크루 인원과 러닝 방의30명 한도를 혼동하지 않는다. 채팅의 조사 당시 갱신은 방3초/목록15초 폴링이며 WebSocket 구현이 완료됐다는 뜻이 아니다.

내 정보는 러닝 패스와 기록/챌린지/지갑/설정 진입 유지다. 프로필 사진 즉시 저장과 이름 별도 저장을 구분한다. 설정은 SET01~40 모두 검수 완료이며 이번 ZIP의 설정40장 지시서와 화면별 동작을 적용한다. 시작·로그인·첫 설정 ONB01~11/ONB20~25도 최신 17장 지시서와 화면별 동작을 적용한다. 알림·공지 NOT01~26도 최신26개 지시서와 화면별 동작을 적용한다. 미제작 NOT27~46/지갑 화면은 기존 기능을 보존한다.

## 작업 및 보고

현재 checkout의 변경과 AGENTS.md/CLAUDE.md를 먼저 읽고 작업 중 변경을 덮어쓰지 않는다. 공통 토큰/헤더/버튼을 적용한 뒤 러닝 핵심1회 흐름, 신발·뽑기·관리, 커뮤니티·크루, 내 정보·설정·시작/로그인/첫 설정 순으로 상태를 연결한다. 기존 기능을 유지하는 작은 범위로 나눠 실제 캡처한다.

implementation-tracker.csv에 ID마다 실제 route/상태, 수정 파일, 실제 캡처, 검사 결과, 남은 사유를 기록한다. 큰 글씨·작은 화면·키보드·시트·실패·뒤로 복귀·권한 상실·연타·재접속을 해당 기능에 맞게 검사한다. 시각 검수 통과를 앱 실행 통과로 전용하지 않는다. 서버 미연결·미제작·정책 불일치는 별도 보고한다.

이 전달에는 실제 앱 코드를 수정하거나 커밋·푸시·배포한 결과가 없다. 이후 구현 보고에는 변경 내용, 실제 검증, 보완 중/미완료를 구분한다.

## 시작·로그인·첫 설정 보존

기존 Google 로그인과 OS 계정 선택을 유지하고, 사용자 취소·처리 중·실패·재시도 상태를 구분한다. 첫 안내를 닫거나 사용자가 선택했을 때만 안내 확인 상태를 기록한다. 로그인 후 키·몸무게 → 목표 → 모드의 첫 설정과 건너뛰기를 보존한다. 이번 ONB21~25가 그 신규 시안이다. 키·몸무게 설정 재진입과 최초 설정은 다른 맥락이다.

ONB20은 프로필 아이콘을 보완한 r2만 사용한다. 권한 화면 등 동봉한 기존 v18 참고는 연결 확인용이며 신규 17장 수에 포함하지 않는다. 로그인·첫 설정의 조회/저장 실패와 모드별 홈 연결 같은 추가 감사 사항은 해당 패키지 audit에 남아 있다. UI 시안만으로 서버 처리가 연결되었다고 보고하지 않는다.

## 알림·공지 추가 기준

이번 묶음은 NOT01~26까지다. NOT24 일반 안내/NOT25 금액 없는 기록/NOT26 크루 가입 완료를 포함한다. 알림 진입만으로 읽음 처리하지 않고, read/actioned/실제 가입을 구분한다. Joined만 가입 완료이며 Requested는 승인 대기다. 응답 미확인 상태에서 가입 요청을 무조건 재전송하지 않는다.

serverEconomyOn=true에서는 과거 로컬 계산 러닝 기록의 SUP금액을 현재 적립 완료로 표시하지 않는다. 현행 showsAmount와 messageFor 조건을 목록·시트 모두에 적용한다. NOT03 및 일부 배경의 적립 문구는 비서버 모드 예시이며 현재 모드에서는 NOT25처럼 교체한다. 실제 금액 표시 허용은 해당 기능 지시서와 현재 코드 계약을 따른다.

## 이번 통합본의 최신 상태

이 v4 하나에 기존15개 기능 묶음과 추가 알림·공지26개를 모두 합쳤다. 이전 통합본이나 후속 ZIP을 따로 합칠 필요 없다. 현재 기준은 러닝109 + 추가421 = 530개 정적 검수 상태다. v19 등록 후보457개 중36개 미제작(알림·공지20/지갑16)이며 전체104경로 대조와 추가 상태 감사도 남아 있다. 전체 앱 리디자인 완료 선언이 아니다.

기능별 문서의 과거 범위와 완료 수는 제작 이력이다. 최신 수치는 루트 README·screen-catalog.json·미완료-36개.md가 우선하고 버튼 동작·예외는 상세 문서를 따른다. 수정해야 할 실제 서비스 조건은 그림 예시보다 우선한다.

implementation-tracker.csv의 미확인·미검증은 이 전달에서 기존 구현을 실행 검증하지 않았다는 뜻이다. 먼저 현재 코드와 실제 캡처를 확인한다. 이번 작업은 사용자가 요청한 현재까지의 전달 정리이며 새 화면 제작이나 앱 코드 변경을 포함하지 않는다.
