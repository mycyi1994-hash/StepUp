# StepUp 출시 준비도와 남은 작업

점검일: 2026-09-24. 앱 기준 `53fc4b8`, 기록 문서 포함 HEAD `d1075f0`.

후속 소스 변경: 7~9차 46개 상태 마감과 프로필 핑크 착장 2종의 앉은 연출을 적용했다. [화면 마감 기록](DESIGN-FINISH-2026-09-24-KO.md), [프로필 기록](../../design/redesign-2026-09/assets/profile/README-KO.md). 사용자가 통합 확인 전 APK 생성을 보류했으므로 아래 수치는 원래 점검 기준이며, 새 소스의 컴파일·실행을 반영한 재평가가 아니다.

## 현재 판단

**정식 출시 준비도 약 50%, 디자인 완성도 약 60%로 평가한다.** 오차 범위는 각각 대략 ±10%p다. 완료 화면 수를 나눈 통계가 아니라, 현재 구현과 확인된 증거를 가중 평가한 작업용 추정이다. 시안 이미지 제작, 소스 적용, 실제 동작 검증을 동일한 완료로 세지 않았다. 남은 작업 시간의 절반이라는 의미도 아니다.

기준은 러닝·꾸미기·커뮤니티·기록·계정을 일반 사용자가 안정적으로 사용하는 Android 공개 출시다. 실제 온체인 송금/출금과 실물 상품 주문까지 제공하는 출시 준비도는 아직 산정할 근거가 부족하다. 기존 출시 문서의 v1 포인트 우선 방향과 현재 지갑/NFT/상점 노출 범위를 한 번 정리해야 한다.

| 평가 영역 | 비중 | 현재 추정 | 근거 |
|---|---:|---:|---|
| 화면 디자인·사용 흐름 | 30% | 60% | 주요 화면, 공통 헤더·탭·버튼, 분리 배경 적용. 7~9차 46항목과 앞선 화면의 마감이 남음 |
| 주요 기능 구현 | 25% | 65% | 실제 로그인 경로, 러닝, 기록, 서버·커뮤니티·마켓 코드와 테스트 존재. 실제 계정으로 전체 연결 검증 부족 |
| 계정·데이터·정산 신뢰성 | 20% | 40% | 업로드 소유자 보호와 로컬 정산 중복 방지는 일부 구현. 로컬 계정 분리·종료 복구·기기 변경 복원 미완료 |
| 실기기 안정성·품질 증거 | 15% | 35% | 일부 이전 버전의 기기 테스트와 캡처 존재. 최신 버전의 전체 흐름·성능·배터리·장시간 러닝 증거 없음 |

## 확인된 기반

- [최신 Build APK 35985313612](https://github.com/mycyi1994-hash/StepUp/actions/runs/35985313612)는 문자열, 디자인 규칙, 단위 테스트, debug APK, 서명 일치, unsigned release/R8를 통과했다. 정식 배포 서명이 통과했다는 의미는 아니다.
- 화면 틀과 기본 컴포넌트가 존재하고 배경·캐릭터·버튼·문구는 분리되어 있다. 캐릭터 몸·의상·신발의 모든 조합이 부위별로 분리된 것은 아니다.
- Google 로그인은 현재 실제 자격 증명과 서버 인증을 호출한다. 오래된 LAUNCH-PLAN의 가짜 로그인/네트워크 없음 설명은 현 상태와 다르다.
- 새 러닝의 계정 소유자와 업로드 토큰 일치 보호, 원자적 로컬 저장 및 중복 정산 방지 기반이 있다. 이것을 전체 계정 격리나 서버 정산 완료로 확대 해석하지 않는다.

## 남은 디자인 범위

[86개 화면·상태 목록](DESIGN-SCREEN-BACKLOG-KO.md)의 차수를 다시 집계했다. 번호는 서로 다른 페이지 수가 아니라 내부 탭·팝업·상태를 포함한다.

| 차수 | 항목 수 | 남은 화면군 |
|---|---:|---|
| 7차 | 23 | 커뮤니티 기본/이야기/내 크루/다른 모임, 크루 생성·게시판·대기실, 번개 상세·대기실, 글 작성·자유글·팁, 댓글/답글/신고, 게시판 실패/재로그인, 랭킹 6종 |
| 8차 | 9 | 지갑, 업적, 통계 기본·분기·날짜 상세·주간 상세, 기록 지도 기본·월간·전체 |
| 9차 | 14 | 로그인, 알림 목록, 설정 7종, 프로필 설정 목록, 첫 사용 안내 4종 |
| 합계 | 46 | 기존 기능 화면이 있는 상태에서 디자인 적용·마감을 이어갈 대상 |

나머지 40항목도 전부 최종 완료로 판정할 수는 없다. 이전 1~6차 적용 화면에서 작은 화면/큰 글씨/테마, 빈 상태·오류·로딩, 버튼 및 시트 사용의 일관성을 마감해야 한다. 앉은 프로필/벤치, 저해상도 장비 그림, 포즈와 착장의 정확성, 부위별 합성은 별도 잔여다. 앉은 포즈 자체는 출시 차단 사유가 아니지만 현재 착장을 잘못 보여 주거나 조작이 잘리는 것은 차단 사유다.

## 출시 전에 해결할 핵심 문제

### 1. 계정이 바뀌어도 기록·잔액·장비가 섞이지 않아야 함

- `WalkSessionEntity`는 기록 소유자를 저장하지만 `RewardEntity`·`SneakerEntity`에는 계정 구분이 없다.
- 최근 기록/누적 기록/잔액 조회는 현재 계정으로 제한하지 않는다. 업로드 소유자 보호와 화면에 보이는 로컬 데이터 분리는 서로 다른 문제다.
- 계정 삭제 성공 후 인증을 지우는 코드는 있으나 해당 화면에서 계정의 로컬 데이터 정리를 호출하지 않는다. 실제 삭제 범위·보관 정책·재가입/기기 변경 흐름을 함께 확인해야 한다.
- 완료 조건: A 기록 생성 → B 로그인 → A/B 기록·잔액·장비 독립, 삭제/재설치/새 기기 복원까지 실제 계정으로 확인.

근거: [Entities](../../app/src/main/java/com/stepup/android/data/local/Entities.kt), [Daos](../../app/src/main/java/com/stepup/android/data/local/Daos.kt), [연결 계정 화면](../../app/src/main/java/com/stepup/android/ui/screens/settings/ConnectedAccountsScreen.kt), [계정 점검](ACCOUNT-DATA-AUDIT.md).

### 2. 러닝 도중 종료와 저장 중단을 복구해야 함

- `RunCheckpointStore`는 있지만 현재 production 서비스에서 사용되지 않는다. 서비스는 `START_NOT_STICKY`를 반환하며 진행 상태는 메모리에 있다.
- 로컬 정산 재시도는 개선됐으나 걸음 정산 기준점, 크루/코스 후속 반영, 계정/장비 상태까지 하나의 복구 흐름으로 연결되지 않았다.
- 완료 조건: 화면 끄기, 다른 앱 전환, OS 종료, 강제 종료, 재시작, 저장 중 실패에서 기록 손실/중복 적립 없이 복구.

근거: [러닝 서비스](../../app/src/main/java/com/stepup/android/service/WalkSessionService.kt), [복구 저장소](../../app/src/main/java/com/stepup/android/service/RunCheckpointStore.kt), [복구 점검](RUN-RECOVERY.md).

### 3. 운동 수치와 서버 반영을 끝까지 맞춰야 함

- 진행 화면의 거리와 저장 거리에는 걸음 환산값을 사용하지만 결과 화면은 GPS 거리가 있으면 이를 우선한다. 같은 러닝의 진행/결과/기록이 다른 거리 기준을 사용할 수 있다.
- 실제 로그인 계정으로 러닝 → 업로드 → 서버 승인/거절 → 잔액/기록 반영, 통신 단절 → 재접속을 검증해야 한다.
- 커뮤니티 작성·댓글·신고·모임 참여, 마켓 거래 취소·실패·잔액 반영, 푸시·초대 링크도 실제 다중 계정 증거가 필요하다. 코드가 존재하는 것과 운영 서버에서 검증된 것은 구분한다.

근거: [러닝 화면](../../app/src/main/java/com/stepup/android/ui/screens/walk/WalkScreen.kt), [서비스](../../app/src/main/java/com/stepup/android/service/WalkSessionService.kt), [서버 기록 전송](../../app/src/main/java/com/stepup/android/data/repo/ServerSessionRecorder.kt).

### 4. 출시 기능과 안내 문구를 일치시켜야 함

- GIWA 연결/출금, 의상 판매, 실물 상점은 현재 지원하지 않거나 준비 중이다. 출시판에서 제공할 기능을 확정하고 화면·FAQ·웹 설명을 통일해야 한다.
- 예를 들어 지갑은 현재 출금을 지원하지 않는다고 표시하지만 고객지원 FAQ에는 향후 출금과 잔액 안전을 단정하는 문구가 남아 있다. 이런 안내를 실제 지원 범위와 맞춰야 한다.
- 계정 삭제·개인정보·위치정보·분석 정보 안내는 실제 서버/기기 처리와 일치해야 한다. 웹 소스는 존재하나 이번 웹 도구에서는 공개 URL을 불러오지 못했다. 사이트 장애로 단정하지 않고 게시/작동 확인을 남긴다.

### 5. 정식 배포와 운영 준비

- 현재 `targetSdk = 35`. Google의 현재 안내는 2026-08-31부터 일반 Android 앱 신규/업데이트 제출에 API 36 이상을 요구한다. 연장 승인 여부는 확인하지 않았으므로 API 36 전환·호환성 검증을 기본 작업으로 둔다. [공식 대상 API 안내](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
- 공개된 최신 파일은 debug APK이며 release 빌드는 unsigned다. 저장소 시크릿 목록에는 release 서명 4종이 없고, 확인한 이전 Release AAB 실행도 unsigned라고 기록돼 있다. 업로드 키·Play App Signing·서명된 AAB·배포용 로그인 인증서 연결이 필요하다.
- 앱 버전은 1.17.0(25)다. 정식 릴리스의 버전 코드와 배포 경로를 관리하고 이전 사용자 데이터 보존을 확인해야 한다.
- Firebase Analytics 코드는 있지만 Crashlytics 의존성/연결은 이번 소스 검색에서 확인되지 않았다. 크래시·서버 실패 감시, 운영 알림, 문의 대응, 백업/복원 절차를 마련해야 한다.
- Play Console의 개인정보/Data safety, 계정 삭제 경로, 앱 설명·아이콘·실제 화면 스크린샷, 권한 관련 신고와 테스트 트랙을 확인해야 한다. 계정 생성 앱은 앱 안과 웹의 삭제 요청 경로가 필요하다. [공식 계정 삭제 안내](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)
- 2023-11-13 이후 생성한 개인 개발자 계정에 해당한다면, 프로덕션 접근 신청 전 12명 이상이 연속 14일 참여하는 비공개 테스트 요건을 충족해야 한다. 현재 Play 계정 유형/테스트 이력은 미확인이다. [공식 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)

## 권장 실행 순서

1. **디자인 마감:** 7차 23항목 → 8차 9항목 → 9차 14항목. 각 묶음을 실제 APK에 적용하고 남은 차이를 기록한다. 기존 1~6차 잔여도 함께 관리한다.
2. **출시 차단 문제:** 계정 분리/삭제/복원 → 러닝 종료 복구 → 거리 기준과 서버 정산/재시도. 이후 외부 테스트 참가자의 실제 데이터를 받는다.
3. **출시 후보 검증:** 지원 Android와 실제 휴대전화에서 장시간 러닝, 화면 꺼짐, 배터리, GPS 오차, 업데이트/재설치, 큰 글씨, 로그인/거래/모임을 확인한다. 전체 캡처는 디자인 적용이 끝난 후보를 기준으로 묶어서 진행한다.
4. **스토어·운영:** API 36, 정식 서명, 배포용 OAuth 설정, 모니터링, 개인정보/삭제 안내, 스토어 자료와 테스트 트랙을 마무리한다.
5. **출시 승인:** 계정 혼합·기록 손실·중복 적립·막힌 핵심 동선 0건, 주요 화면 마감, 서명된 동일 버전 배포본과 테스트 증거 확보 후 정식 공개한다.

이번 점검에서는 앱 코드/서버 데이터/배포 설정을 변경하지 않았고 새 빌드나 장시간 화면 검사를 실행하지 않았다. 현재 소스, 기존 CI/검증 기록, GitHub 서명 설정 이름 및 Google 공식 출시 안내를 확인했다.
