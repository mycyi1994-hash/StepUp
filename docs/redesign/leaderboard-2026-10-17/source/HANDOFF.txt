StepUp 리더보드 — 개발 핸드오프
기준일: 2026-10-17
대상: 최신 3개 화면 및 러닝 트랙 애니메이션 배경

1. 작업 상태와 범위

사용자는 초기 4개 시안 중 통합 순위와 내 주변 순위의 방향을 선호했다. 이후 상위 3명, 특히 1위의 강조를 요청했고 개인 러닝 화면의 임팩트 강화와 주간 포인트 화면 재구성을 요청했다. 마지막으로 밋밋한 배경을 보완하기 위해 애니메이션 배경을 추가했다.

이번 구현 기준은 reference.html의 크루 순위, 개인 러닝 순위, 주간 포인트 3개다. 옛 4개 화면을 구현하지 않는다. 자유러닝 시작/카운트다운은 별도 작업이며 이 ZIP에는 포함하지 않는다.

현재 결과물은 웹 시안이다. 실제 앱 저장소, 네이티브 프레임워크, API 응답, 서버 순위 정책은 확인하지 않았다. 클로드는 실제 저장소의 지침과 기존 코드를 먼저 확인하고 앱의 리더보드 진입 구조에 3개 화면을 연결한다. 앱에 이미 있는 탭/내비게이션 방식을 우선 사용한다.

2. 패키지 파일

CLAUDE-PROMPT.txt: 그대로 전달할 구현 지시.
HANDOFF.txt: 화면·기능·정책·완료 기준.
motion-spec.json: 배경과 1위 효과의 수치.
data-contract.json: 데이터 어댑터에 필요한 항목의 제안. 현재 API 스키마가 아님.
reference.html: 3개 화면을 확인할 독립 실행 미리보기.
reference-fragment.html: 최신 인라인 시안, 이미지 포함.
source/preview.html: 최신 화면 CSS·마크업·모션·상호작용 원본.
source/shared-style.html: StepUp 공통 미리보기 스타일. 일부 사용하지 않는 초기 공통 클래스도 포함되어 있으며 앱에 모두 옮길 필요 없음.
source/build.mjs: 이동 가능한 fragment 빌더. Node 기본 모듈만 사용.
assets/logo.png: 실제 StepUp 흰색 워드마크, 900×156.
VALIDATION.txt: 이번에 수행한 검증과 미수행 검증.
manifest.sha256: 패키지 파일 무결성 확인용.

미리보기의 이미지 데이터는 포함되어 있다. 폰트·스타일·아이콘 관련 CDN에는 인터넷 연결이 필요할 수 있다. 빌더는 reference-fragment.html만 갱신한다. reference.html은 이번 전달 시점의 래퍼다.

3. 공통 시각 기준

배경 #061B30
강조 블루 #1450FF
주요 글자 #FFFFFF
보조 글자 #9DB0C8 / #B4C9E2
구분선 #29435F
보조 표면 #102B46

미리보기 기준은 360×824 CSSpx이다. 앱의 화면 높이를 824로 고정하라는 의미가 아니다. 실제 safe area와 스크롤, dp/pt, 글꼴 배율에 맞게 반응형으로 구성한다. 하단 내 순위 영역이 목록을 덮지 않게 끝 여백을 확보한다.

본문은 Pretendard 계열, 숫자는 굵고 조밀한 형태를 참고한다. 시안의 Bahnschrift는 Windows 참고 글꼴이며 앱에 있다고 가정하지 않는다. 기존 프로젝트 숫자 서체를 확인한다. 로고는 글꼴로 재작성하지 말고 실제 자산 형태를 보존한다.

미리보기 캐러셀, 휴대폰 외곽/그림자, 가짜 상태바, 아래 시안 선택기, 위 ‘애니메이션 배경’ 스위치, Tweak 조절기, 시안용 데이터 문구, window.openai 상태 저장은 제품 UI에 넣지 않는다. 배경 비교 스위치는 디자인 검토용이다.

4. 크루 순위 화면

구조:
제목/주간 기간 → 큰 1위 영역 → 나란한 2·3위 → 이후 순위 목록 → 하단 우리 크루 순위.

1위는 전체 너비의 블루 영역으로 독립한다. 기본 높이 약 190, 모서리 22. 왕관 아이콘과 ‘이번 주 1위’, 크루 이미지, 이름, 참여 인원, 1인당 거리, 순위 변화를 보여준다. 배경 숫자 1은 약 188 크기의 이탤릭으로 존재감을 준다. 수치와 이름보다 앞에 겹치지 않는다.

2·3위는 동일한 크기의 좌우 영역, 높이 약 87, 간격 10이다. 2위의 숫자는 밝은 아이스 블루, 3위는 한 단계 낮은 톤으로 구분한다. 일반 목록과 같은 크기로 줄이지 않는다.

이후 순위는 정렬된 목록이다. 시안은 4·5위까지만 보여주지만 실제 앱은 기존 페이지네이션 또는 추가 조회를 연결한다. 상위 3명과 뒤의 목록이 중복되지 않아야 한다.

하단 우리 크루는 순위, 크루명, 순위 변화, 거리다. 탭하면 우리 크루의 바로 앞뒤를 보여주는 상세를 연다. 시안의 12위, 18.4km, 3계단 상승을 하드코딩하지 않는다. 크루 미소속/미참여 사용자 상태도 처리한다.

집계 기준 제안은 ‘이번 주 참여 러너 1인당 거리’다. 서버 정책이 다르면 단위와 기준 문구, 값 모두 같이 연결한다. 총거리 값을 가져와 ‘1인당 거리’라고 표시하면 안 된다. 이 UI 작업에서 서버 집계 규칙을 조용히 바꾸지 않는다.

5. 개인 러닝 순위 화면

구조:
제목/기간 → 큰 나의 순위와 변화 → 바로 앞 러너/거리 차이 → 내 주변/상위 러너 전환 → 목록 → 하단 나의 러닝 기록.

내 순위는 기본 112, 좁은 시안 104의 큰 이탤릭 숫자로 강조한다. 시안의 127위는 샘플이다. 오른쪽의 상승 숫자 12 역시 실제 이전 주 순위와 현재 순위의 차이로 계산한다. 하락·동일·이전 주 미집계·신규 진입을 별도로 표시한다.

블루 영역은 바로 앞 러너의 이름과 순위, 누적 거리, 현재 거리 차이다. 차이는 같은 기간·같은 집계 시점·같은 순위 범위에서 계산한다. 시안의 0.8km는 33.4−32.6이다. 상대도 계속 달릴 수 있으므로 ‘더 달리면 반드시 추월’처럼 순위를 보장하는 문구를 넣지 않는다.

내 주변은 본인 앞 2명·본인·뒤 2명이다. 본인 행은 블루로 강조한다. 상위 러너 탭은 상위 목록으로 바꾼다. 탭 전환으로 큰 본인 순위나 실제 집계 범위를 임의 변경하지 않는다.

하단에는 본인 누적 거리와 러닝 횟수가 있다. 탭하면 해당 주의 기록 상세를 연다. 시안의 기록 12.8+4.8+8.6+6.4=32.6km와 4회는 데이터 일관성을 보여주는 fixture다.

6. 주간 포인트 화면

구조:
제목/기간 → 이번 주 적립 포인트와 순위 → 전체 러너/우리 크루 전환 → 순위 목록 → 바로 앞 순위와의 차이 및 내 주변 상세.

이번 주 적립량은 약 62 크기의 숫자, P는 약 23으로 구분한다. 내 순위는 옆 블루 영역이다. 시안은 2,680P와 전체 84위/크루 8위다. 범위를 전환하면 목록·본인 순위·앞뒤 순위·차이가 모두 같은 범위로 변경되어야 한다.

1위 행은 블루 표면과 더 큰 숫자로 강조한다. 크루 화면의 큰 시상대 구조를 그대로 복사하지 않는다. 2위 이후는 읽기 쉬운 정렬 목록이다.

포인트는 ‘이번 주 적립’을 의미한다. 잔액, 누적 생애 적립, 토큰 가격, 원화 가치, APR/APY, 예상 보상을 섞지 않는다. P와 $SUP의 관계는 이 시안으로 확정된 것이 아니다. 포인트 취소·정정·회수·이월 반영 방식은 기존 서비스 정책을 확인한다.

하단에는 바로 앞과의 차이를 표시하고 내 주변 상세로 연결한다. 시안의 80P는 2,760−2,680이다. 데이터가 갱신되면 비교 대상과 차이를 같이 갱신한다. 1위이면 가짜 0위 목표를 만들지 않는다.

7. 배경 애니메이션

같은 네이비 배경에서 푸른 빛이 고정된 러닝 트랙 3개를 따라 흐른다. 레이아웃·순위 숫자·프로필·버튼 자체는 움직이지 않는다.

레이어 아래→위:
네이비 베이스 → 부드러운 블루 빛 → 고정 트랙 및 회전 빛 → 콘텐츠 → 하단 내 기록 → 상세 시트.

트랙은 기본 560×336의 경기장 형태, 안쪽으로 20/40씩 들어간 3개 선이다. 외곽 모서리는 168, 안쪽 148/128. 선 두께 약 2. 각 선의 빛은 18초 linear 한 바퀴이며 시작 위상을 −1/−7/−13초로 나눈다. 트랙 자체를 빙빙 돌리지 않고 그 위의 빛이 이동하게 한다.

부드러운 빛은 430×430의 정적 radial gradient를 합성한다. 16초 동안 opacity .58→1, 위치 (0,0)→(−12,10)을 왕복한다. 곡선 cubic-bezier(.77,0,.175,1). 프레임마다 큰 블러나 그라디언트 픽셀을 다시 만드는 방식은 피한다.

크루 1위에는 폭 90의 빛 띠가 10초 동안 대각선으로 지나간다. 숫자 1과 실제 글자는 고정한다. 초기 위상 −3초, opacity 최대 .65다. 밝기가 올라갈 때도 작은 글자가 읽혀야 한다.

배경 기준 강도는 크루/포인트 80%, 개인 90%. 미리보기 조절 범위 35~100%는 검토용이다. 실제 앱에서 별도 슬라이더를 추가하라는 뜻이 아니다.

배경은 화면 높이 1% 지점에서는 투명, 13~51%에서는 보이며 73%에서 다시 투명해진다. 본문 목록은 네이비 표면으로 가려 읽기 쉽게 유지한다. 실제 화면 높이와 스크롤 위치에 맞게 적용한다.

화면별 트랙 위치/각도와 정확한 색·키프레임은 motion-spec.json 및 원본 CSS를 참고한다. 네이티브 앱에서는 같은 시각 결과를 현재 렌더링 기술로 구현한다. 영상/GIF/무거운 3D 라이브러리를 새로 넣지 않는다.

정지 조건:
- 해당 화면이 보이지 않거나 미리보기 기준 가시 비율 5% 미만.
- 앱 또는 문서가 백그라운드.
- 상세 시트가 열려 읽고 있는 동안.
- 기존 앱 설정에서 모션을 끈 경우.

시스템 모션 감소에서는 회전·이동·빛 띠를 빼고 정적인 트랙/블루 배경만 유지한다. API 갱신, 목록 필터 변경, 리컴포지션마다 배경을 처음부터 재생하지 않는다. 기존 앱의 전력 절약 정책이 있으면 함께 따른다.

8. 데이터 연결과 정책 확인

data-contract.json은 화면에 필요한 데이터 항목을 제안한 문서다. 이 이름의 API가 이미 있다는 뜻이 아니다. 기존 서비스/Repository/ViewModel 등 현재 경계에 맞춰 매핑한다.

- 세 화면의 주간 시작·종료·시간대·집계 시점 기준을 일치시킨다. 시안은 월요일~일요일 표시지만 서버 정책이 확정되었다고 간주하지 않는다.
- API가 제공하는 본인 순위와 인접 순위를 사용한다. 현재 로드된 일부 목록의 배열 인덱스로 전역 순위를 계산하지 않는다.
- 정렬은 실제 정밀도의 거리·포인트로, 표시는 km 소수 1자리와 포인트 정수로 한다. 표시상 같다고 임의로 동점 처리하지 않는다.
- 동점 순위, 탈퇴/비공개 계정, 신고/무효 러닝, 취소된 포인트의 반영은 현재 서버 정책을 따른다. 사용자 ID로 임의 우열을 정하지 않는다.
- 이전 주 순위가 없는 경우 상승을 꾸며내지 않는다. 전주 적립량이 없는 경우 0으로 간주해 증가량을 부풀리지 않는다.
- 빈 목록/미집계/미소속/통신 실패를 구분한다. 데이터가 없다고 0위, −1위, NaN, 가짜 포인트를 노출하지 않는다.
- 동점 차이 0은 동점으로, 다음 순위가 없는 1위 상태는 선두 상태로 처리한다.
- 서버 응답에 안정적인 사용자/크루 식별자를 사용한다. 순위 범위 전환 중 오래된 요청 결과가 새 범위의 본인 순위를 덮지 않게 한다.
- 보상·세션 기록·신발 소모·광고 수익 분배·토큰 수수료는 이번 리더보드 UI 때문에 바꾸지 않는다.

9. 완료 기준

[ ] 최신 3개 화면만 앱 내 리더보드 진입과 연결.
[ ] 크루 1위의 시각적 우선순위, 별도 2·3위, 하단 우리 크루 유지.
[ ] 개인의 큰 순위·전주 변화·다음 러너 격차·내 주변/상위 전환 연결.
[ ] 주간 적립과 잔액 구분. 전체/크루 범위에서 모든 관련 값 함께 갱신.
[ ] 크루/개인/포인트 상세 및 닫기/뒤로가기/초점 또는 네이티브 접근성 처리.
[ ] 실제 주간 기간, 프로필, 순위, 기록, 포인트에 연결. 샘플 값 하드코딩 제거.
[ ] 순위 동점·0차이·1위·빈 목록·신규 사용자·미소속·오류 상태 처리.
[ ] 배경은 같은 화면 내 상태 변경에서 재생성되지 않음.
[ ] 안 보이는 화면/백그라운드/상세 시트에서 정지, 복귀 시 정상 재개.
[ ] 시스템 모션 감소와 기존 전력 절약 정책 확인.
[ ] 작은 화면/긴 이름/큰 글꼴/노치에서 잘림 및 하단 목록 가림 없음.
