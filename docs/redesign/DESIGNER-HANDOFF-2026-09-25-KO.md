# StepUp 디자이너 인계서

기준일: 2026-09-25 · 작업 브랜치: `codex/stepup-cohesive-redesign` · 문서 작성 기준 HEAD: `9be699a`

## 1. 프로젝트를 한 문장으로

**StepUp은 오늘의 걸음과 러닝 기록을 보기 쉽게 만들고, 신발 수집·보상·함께 달리기를 연결하는 Android 러닝 앱이다.** 처음 보는 사용자는 Web3를 알아야 앱을 쓸 수 있다고 느끼지 않아야 한다. 첫 화면의 주 행동은 **러닝 시작**이다.

대상은 가볍게 운동을 시작하는 사람과 꾸준히 기록을 쌓는 러너다. 핵심 경험은 **오늘의 활동 확인 → 러닝 → 기록 확인 → 보상/신발/코스 확인 → 커뮤니티 참여**다. SUP는 앱 안에 표시되는 보상 단위다. 서버가 확정하지 않은 보상을 이미 받은 것처럼 표현하지 않는다.

이 문서의 화면 목록은 현재 소스의 **이동 경로 34개**를 모두 포함한다. `A-1`처럼 같은 경로 안에서 변하는 상태와 팝업은 따로 적었다. 경로 34개가 곧 디자인 시안 34장이나 전체 상태 34개라는 뜻은 아니다. 시작/로그인/첫 안내는 이동 경로 수 밖에 있다.

## 2. 지금 확정된 방향

- **캐릭터 없는 버전**이 현행 방향이다. 옛 RUNO/LUMI 캐릭터, 의상, 옷장 시안과 관련 자산 목록은 이전 실험의 기록이며 이번 디자인에 다시 넣지 않는다. 앱의 두 번째 탭은 옷장이 아니라 **신발 선택**이다.
- **신발 수집·착용, 신발 뽑기, 보관함, 도감, 마켓은 유지**한다. 신발의 등급·레벨·스탯·보유 여부는 실제 상태를 따라야 한다.
- 하단에는 **러닝 / 신발 / 뽑기 / 커뮤니티 / 내 정보**가 보인다. 기술적으로는 네 개의 기본 탭 사이에 독립된 **뽑기** 진입 버튼이 있다. 상세 화면에서는 부모 탭의 선택 상태를 유지한다.
- 푸른 밤/새벽 러닝 풍경, 짙은 남색 바탕, 파란 주 버튼과 차분한 보조 글자를 기본 톤으로 쓴다. 풍경은 **갈아 끼울 수 있는 별도 이미지**이고, 버튼·수치·탭·목록·선택 상태는 실제 Android UI다. 배경 한 장에 화면 전체를 합성하지 않는다.
- 한 화면에 중요한 다음 행동 하나를 먼저 보이게 한다. 다른 행동은 보조 버튼이나 상세 화면으로 보낸다. 보유하지 않은 신발, 확정 전 보상, 없는 모임을 예시 이미지로 실제 상태처럼 채우지 않는다.
- 지도는 실제 **2D 타일 지도**다. 3D 도시 시안으로 대체할 수 없고, 출처 표시와 로딩/오프라인/경로 없음 상태를 위한 공간이 필요하다. 현재 보이는 지도 밖에 있는 코스를 “지도에 보인다”고 안내하지 않는다.

## 3. 디자이너가 알아야 할 용어와 기능

| 용어/기능 | 실제 사용 흐름 | 화면 디자인에서 주의할 점 |
|---|---|---|
| 걸음·러닝 | 오늘 걸음, 목표, 시간·거리·페이스, GPS 경로, 결과와 기록 | 측정 중·일시정지·GPS 대기·권한 없음·저장 실패를 구분 |
| SUP | 러닝 보상과 지갑 잔액·내역, 일부 신발 강화 등에 사용 | 예정/확정/실패 상태를 색과 문구로 분리. 임의 잔액 금지 |
| 신발 | 보유한 신발 선택·착용, 상세 스탯·레벨·강화·판매 | 미리보기와 실제 착용 상태가 다를 수 있음. 상품 그림과 UI 분리 |
| 뽑기 | 신발 뽑기, 도감·지갑 연결 | 실제 연결 설정이 없으면 준비 안내와 비활성 버튼. 당첨 연출은 확정 결과일 때만 |
| 코스 | 내 코스 선택, 실제 기록에서 만들기, 공유 게시판과 코스 순위 | 경로 미리보기는 개략 그림. 선택/공유/삭제/좋아요는 실제 데이터 기준 |
| 챌린지 | 일일·주간 등 목표의 진행률과 보상 | 진행 중/완료/수령 가능을 구분. 가짜 대회 추가 금지 |
| 커뮤니티 | 자유글·팁·번개러닝, 좋아요·댓글·신고, 크루 | 게시물/모임이 없으면 빈 상태. 로그인·네트워크 문제를 빈 목록과 구분 |
| 지도·땅따먹기 | 주변 번개/코스 핀, 서버에서 받은 영역과 순위 | 실제 위치·가시 범위·타일 공급자 출처를 지킴 |
| 랭킹 | 걸음·거리 등 부문, 기간, 크루 순위 | 로그인 필요/기록 없음/불러오는 중을 실제 순위와 구분 |
| 개인 정보 | 프로필, 통계, 기록 지도, 업적, 알림, 설정 | 사용자 사진/이름/기록을 유지. 계정·지갑 연동 성공은 별도 검증 필요 |

기능 화면과 호출 코드는 존재하지만 **야외 GPS 정확도, 실제 계정/서버 보상 정산, 마켓 거래, 땅따먹기·랭킹 서버 응답, 외부 지갑과 뽑기 계약의 운영 성공은 이 디자인 인계서의 완료 판정이 아니다.** 디자인은 성공·로딩·실패·권한 없음·로그인 필요를 모두 수용해야 한다.

## 4. 전체 페이지 맵

표시: **검토** = 해당 경로의 대표 상태를 Android 14·15 실제 앱 화면으로 확인, **후속** = 화면 소스는 있으나 이 캐릭터 없는 버전에서 해당 경로를 집중적으로 캡처·검수하지 않음. 검토는 기능·모든 데이터 상태·밝은 테마까지 승인했다는 뜻이 아니다.

### 0. 시작 흐름 — 이동 경로 34개와 별도

| ID | 화면/상태 | 목적·보이는 요소 | 현재 |
|---|---|---|---|
| 0-1 | 시스템 시작·로딩 | 앱 준비, 로고/상태 표시. 오래 기다리게 하는 가짜 진행률 금지 | 후속 |
| 0-2 | 로고 전환 | 짧은 STEPUP 로고 연출. 원본 로고 자산 사용 | 후속 |
| 0-3 | 로그인 | 풍경, Google 로그인, 약관/안내. 기존 계정으로 들어갈 수 있어야 함 | 검토(대표 화면) |
| 0-4 | 첫 사용 안내 | 실제 홈·신발·프로필을 가리키는 3단계 가이드 | 검토(대표 화면) |

### A. 러닝 — 하단 `러닝`

| ID | 화면(이동 경로) | 디자이너가 설계할 정보·행동 | 현재 |
|---|---|---|---|
| A-0 | 메인 홈 `home` | 오늘 걸음/목표, 최근 7일 기록, 거리·시간, 바뀌는 별도 풍경 배너, 러닝 시작/재개. 상세 바텀시트에서 챌린지·소식 연결 | 검토 |
| A-1 | 러닝 준비·진행·일시정지·결과 `run?start={start}` | 큰 시간·거리·페이스, 실제 경로 지도, 시작/일시정지/재개/종료, 저장 결과와 보상 상태. 권한 없음/GPS 대기/저장 실패도 같은 흐름의 상태 | 검토(대표 상태) |
| A-2 | 코스 `courses` | `선택 / 만들기 / 게시판` 세 탭. 코스 이름·거리 → 경로 → 보상·기록 → 선택. 지난 GPS 기록으로 코스 만들기, 공유·검색·좋아요·순위 | 검토(세 탭) |
| A-3 | 챌린지 `events` | 목표 카드, 진행률, 참여/수령 조건과 러닝 연결. 실제 목표 데이터 사용 | 검토 |
| A-4 | 소식 `news` | 대회·러닝·건강 소식의 목록/필터/원문 이동 | 후속 |

**A-1의 상태 컷:** 준비, 활동 권한 거부, GPS 잡는 중, 러닝 중, 일시정지, 종료 확인, 결과, 보상 확정 대기/거절, 저장 실패/재시도. **A-2의 상태 컷:** 내 코스 없음, 코스 선택 확인/해제, 새 코스 기록·이름 입력, 게시판 검색 결과 없음, 코스 순위.

### B. 신발 — 하단 `신발` (구 옷장 대체)

| ID | 화면(이동 경로) | 디자이너가 설계할 정보·행동 | 현재 |
|---|---|---|---|
| B-0 | 내 신발 선택 `customize` | 실제 보유 신발의 미리보기·목록, 착용 중 표시, 선택 후 착용, 도감/보관함/마켓 연결. 선택 미리보기는 착용 확정과 다름 | 검토 |
| B-1 | **신발 상세·스탯** `sneaker/{id}` | 상품 이미지, 계열/등급/발행번호/레벨, 펼침형 스탯(적립 보너스·행운·편안함·에너지 절약·내구도), 강화 비용 확인, 판매 이동 | 후속 |
| B-2 | 신발 보관함 `items` | 보유 신발 묶음·개별 사본, 착용/강화/판매 진입, 필터·정렬, 사용 중인 부스트, 발행/결과 상태 | 후속 |
| B-3 | 신발 도감 `sneaker/dex` | 수집 목록·보유 여부와 각 신발 상세 진입 | 후속 |
| B-4 | 러너 마켓 `runner-market` | 신발 상품 목록·가격/상태, 보관함과 상품 장부 연결. 준비/데모 표기는 실제 판매로 오해되지 않게 | 후속 |
| B-5 | 상품별 거래 화면 `market/...` | 호가(판매/구매/최근 값), 판매·입찰 목록, 거래 기록, 구매/입찰/판매 등록 동작 | 후속 |

**B-1은 별도 스탯 이동 경로가 아니다.** 신발 상세 안의 펼침 영역이지만 디자이너가 독립 상태 컷으로 그려야 한다. 보유하지 않은 신발의 소유·강화·판매를 활성화해 보여주면 안 된다. 신발 상품 그림은 화면 배경/카드/버튼과 독립 자산이다.

### C. 뽑기 — 하단 중앙 진입 버튼

| ID | 화면(이동 경로) | 디자이너가 설계할 정보·행동 | 현재 |
|---|---|---|---|
| C-0 | 신발 뽑기 `mystery-box` | 상자 이미지, 비용·조건 안내, 뽑기 버튼, 도감·지갑 이동. 계약/웹 연결 설정이 없을 때는 준비 안내와 비활성 버튼 | 검토(대표 상태) |

의상 뽑기와 캐릭터 뽑기는 이번 버전의 흐름이 아니다. 앱 밖 웹/DApp에서 이어지는 거래와 소리는 성공이 확인된 뒤에만 결과로 표현한다.

### D. 커뮤니티 — 하단 `커뮤니티`

| ID | 화면(이동 경로) | 디자이너가 설계할 정보·행동 | 현재 |
|---|---|---|---|
| D-0 | 커뮤니티 홈 `community` | `함께 달리기 / 이야기` 내용, 번개 목록·글 피드·내 크루, 글쓰기, 지도/랭킹 입구. 크루 화면은 내부 전환 | 검토(대표 화면) |
| D-1 | 주변·영역 지도 `map` | `내 주변 / 땅따먹기` 탭, 실제 타일/위치/핀/영역, 확대·축소, 아래 정보 카드, 코스 목록 연결 | 검토(두 탭 배치) |
| D-2 | 랭킹 `ranking` | 걸음/거리/SUP/크루 등 부문, 일·주·월·전체 기간, 순위 목록/로그인 필요/기록 없음 | 검토(대표·주간·크루) |
| D-3 | 크루 만들기 `crew/create` | 이름·지역·소개 등 입력, 필수값/오류, 만들기 행동 | 검토 |
| D-4 | 크루 게시판 `crew/board/{crewId}` | 크루 정보·글·모임, 게시/대기실/번개 상세 진입 | 후속 |
| D-5 | 크루 대기실 `lobby/{crewId}` | 참가자·준비 상태·함께 달리기 진입 | 후속 |
| D-6 | 번개러닝 상세 `flash/{postId}` | 장소·시간·거리·인원·참가 상태, 채팅/대기실 진입, 별도 풍경 배너 | 검토 |
| D-7 | 번개러닝 대기실 `flash/lobby/{postId}` | 해당 번개의 참가/준비 상태와 러닝 이동 | 후속 |
| D-8 | 글쓰기 `post/compose/{crewId}` | 자유글·팁·번개러닝을 한 양식에서 구분. 번개 선택 시 장소·시간·인원 등 추가 입력 | 검토 |

**D-0의 내부 상태 컷:** 함께 달리기 첫 화면, 전체 번개 목록, 자유글/팁 피드, 내 크루, 글/모임 없음, 로그인 필요, 연결 오류. **D-1의 상태 컷:** 주변 핀 선택/화면 밖 목록, 영역 로딩/확대 필요/로그인/오류. 지금의 코스 수는 등록된 전체 목록 수이며 현재 보이는 핀 수와 다르다.

## 6. 실제 디자인 진행 상태와 우선순위

현재 **34개 이동 경로 중 25개는 대표 상태의 기기 캡처를 확인**했다. **9개 경로**(A-4, B-1~B-5, D-4·D-5·D-7)와 시작 화면 0-1·0-2, 팝업 18개는 집중 마감이 남았다. 숫자는 화면 수 기준이며 전체 디자인 완성률이나 출시 준비도로 환산하지 않는다.

1. **신발·마켓 5경로:** B-1 스탯 상태를 먼저 정하고 B-2~B-5의 상품 카드/가격/실패 상태를 통일한다. 캐릭터/의상 이미지는 되살리지 않는다.
2. **모임 3경로:** D-4·D-5·D-7을 D-0/D-6과 같은 정보 위계·버튼 규격으로 마감한다.
3. **소식·시작:** A-4, 0-1·0-2의 그림/로딩·긴 글씨를 확인한다.
4. **팝업 18개와 전체 통일:** P 목록, 작은 폰/1.6배 글씨, 밝은 테마·네 언어, 빈/오류/로그인 상태를 묶어 확인한다.

디자이너가 넘겨줄 것은 페이지마다 **기본 화면 + 필요한 내부 탭/팝업/빈·오류 상태**, 사용한 독립 이미지 목록, 실제 앱 캡처와 시안의 차이 목록이다. 임의 수치·사람·소유 신발이 들어간 홍보용 예시 화면은 실제 화면과 명확히 표시해 구분한다.
