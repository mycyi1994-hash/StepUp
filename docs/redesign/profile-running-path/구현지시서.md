# StepUp 내 정보 — 러닝 패스 구현 지시서

사용자가 선택한 시안은 `reference-running-path.png`의 **2번 러닝 패스**다. 이 이미지의 내 정보 화면을 기존 앱에 구현해줘. 다른 시안으로 재해석하지 말고, 기록 중심의 구성과 오른쪽 경로 그래픽을 그대로 살려줘.

## 1. 작업 목표와 기준 자료

내 정보 첫 화면에서 누적 러닝 기록이 가장 먼저 눈에 들어오게 한다. 짙은 남색 카드 안에는 큰 거리 숫자와 러닝 횟수를 넣고, 오른쪽에만 가는 경로 그래픽을 배치한다. 카드 아래에는 흰색 `내 러닝 기록 보기` 버튼, 그 아래에는 `챌린지 / 지갑 / 설정` 세 행을 둔다.

기준 파일:

- `reference-running-path.png`: 최종 모양의 기준 이미지. 1170 × 2532px, 390 × 844 기준의 3배 크기.
- `reference-running-path.svg`: 텍스트와 그래픽을 확인할 수 있는 편집용 원본. Pretendard 사용.
- `assets/running-path-card-background.svg`: 글자와 버튼을 제외한 **기록 카드 배경만** 분리한 파일. 342 × 168 기준.

기존 앱의 기술 구조와 기능을 활용해 구현한다. 별도 웹페이지나 데모 사이트를 만들지 않는다. 완성 화면 이미지를 통째로 화면에 붙이지 말고, 텍스트·수치·버튼·메뉴는 실제 UI로 구현한다.

## 2. 화면 구성

위에서 아래로 다음 순서를 유지한다.

```text

[프로필 사진]  닉네임                 프로필 수정

┌──────────────────────────────────────────┐
│ 지금까지 달린 거리                       │
│                                          │
│ 34.2 km                     경로 그래픽  │
│                                          │
│ 8번의 러닝을 기록했어요.                  │
└──────────────────────────────────────────┘

[             내 러닝 기록 보기            ]
```

34.2km, 8회, 83.07 SUP, 러너님은 **시안용 예시**다. 운영 화면에는 실제 사용자 데이터를 연결한다.

## 3. 레이아웃과 간격

기준 화면은 390 × 844다. 아래 좌표는 시안 대조용이며, 실제 앱에서는 dp/sp와 시스템 여백을 적용한다. 화면 전체를 절대 좌표로 고정하지 않는다.

| 요소 | 기준 위치와 크기 | 구현 기준 |
| --- | --- | --- |
| 본문 좌우 여백 | 24 | 기본 가로 여백 유지 |
| 화면 제목 | x24, 글자 기준선 y82 | 25sp, 600 |
| 프로필 이미지 | x24, y119, 40 × 40 | 원형, 사용자 사진 사용 |
| 닉네임 | x77, 기준선 y146 | 21sp, 600 |
| 프로필 수정 | 오른쪽 끝 x366, 기준선 y145 | 13sp, 실제 터치 영역은 최소 48dp |
| 기록 카드 | x24, y193, 342 × 168 | 가로는 화면 폭 − 48dp, 모서리 23dp |
| 카드 문구 | 왼쪽 안쪽 여백 20 | 숫자만 시각적으로 4dp 왼쪽 보정 가능 |
| 기록 보기 버튼 | x24, y386, 342 × 54 | 카드 아래 25dp, 모서리 17dp |
| 메뉴 행 | y475 / 549 / 623에서 시작 | 각 행 74dp, 행 전체 터치 |
| 메뉴 아이콘 받침 | 36 × 36 | 모서리 12dp, 행 왼쪽 |
| 메뉴 아이콘 | 21 × 21 | 얇은 선형 아이콘 |
| 메뉴 이름 | x74 | 17sp, 600 |
| 지갑 잔액 | 오른쪽 끝 x342 | 14sp, 화살표 앞 여백 확보 |

390 기준의 표준 글자 크기에서는 카드 높이 168dp를 맞춘다. 글자 확대나 좁은 화면에서는 카드 높이를 늘릴 수 있다. 하단 탭 위 본문은 세로 스크롤이 가능해야 한다. 상태 표시줄의 시각·배터리·통신 아이콘과 시스템 홈 바는 OS가 표시하도록 한다.

## 4. 색상과 타이포그래피

| 용도 | 값 |
| --- | --- |
| 화면 배경 | `#050912` |
| 주 텍스트 | `#F2F4FC` |
| 보조 텍스트 | `#98A8C0` |
| 프로필 수정 링크 | `#A3BFFE` |
| 카드 배경 | 좌하단 `#0D182A` → 우상단 `#182E4C` |
| 카드 제목 | `#B0C3E0` |
| 거리 단위 km | `#A6BCDD` |
| 러닝 횟수 문장 | `#A4B8D5` |
| 흰색 버튼 | 위 `#F7F8FF` → 아래 `#E8EDFA` |
| 버튼 텍스트 | `#081223` |
| 버튼 아래 얇은 깊이 표현 | `#26334B`, 2dp 아래 오프셋 |
| 메뉴 아이콘 받침 | `#101B2C` |
| 챌린지·지갑 아이콘 | `#B4CAFF` |
| 설정 아이콘 | `#A4B2CA` |

글꼴은 Pretendard를 사용한다. 제목과 닉네임은 600, 보조 문구는 400이다. 거리 숫자는 **72sp / 600**, 자간은 기준 크기에서 약 −2.7sp다. `km`는 **23sp / 400**으로 숫자 옆 아래쪽에 맞춘다. 단위의 위치는 숫자의 실제 너비를 따라가게 하고, `34.2` 너비에 맞춰 고정하지 않는다.

화면 우상단의 남색 기운은 기준 SVG의 약한 배경 그라데이션 정도로만 적용한다. 기본 배경과 자연스럽게 이어지게 한다.

## 5. 러닝 패스 카드 — 가장 중요한 부분

카드는 왼쪽의 정보와 오른쪽의 그래픽으로 나눈다. 거리 숫자가 그래픽보다 먼저 보여야 한다.

1. 첨부된 카드 배경 SVG의 색·곡선·배치를 재사용한다. 글자 없이 카드 배경만 들어 있으므로 그 위에 실제 데이터를 배치하면 된다.
2. 카드 오른쪽의 얇은 선들은 지도 등고선을 닮은 장식이다. 기본 선은 `#4C6787`, 두께 0.8, 투명도 25%다.
3. 중심 경로는 두께 2.8, 둥근 끝 처리다. 색은 `#5475A7 → #8CB6FF → #D9E7FF`로 이어진다. 아래쪽에 작은 시작점, 위쪽에 밝은 끝점이 있다.
4. 중심 경로 뒤의 넓은 선은 두께 9, `#497AC4`에 투명도 10%다. 밝은 네온광으로 키우지 않는다.
5. 모든 그래픽은 카드 모서리 안에 잘린다. 본문, 숫자, 버튼 위로 튀어나오지 않는다.
6. 이 그래픽은 **실제 위치나 실제 러닝 경로가 아니다.** 지도 SDK, 위치 권한, 지도 보기 버튼을 추가하지 않는다. 스크린리더에서도 장식으로 제외한다.
7. 정적인 배경으로 구현한다. 경로를 계속 그리는 애니메이션이나 움직이는 점을 추가하지 않는다.

배경 SVG는 카드 비율이 같은 경우 그대로 사용할 수 있다. 작은 화면이나 글자 확대에서는 배경을 오른쪽에 고정하고 잘라내며, 텍스트 공간을 우선 확보한다. 경로가 숫자와 겹치면 그래픽 영역을 줄인다. 장식 때문에 숫자나 단위를 잘라내지 않는다.

SVG를 바로 표시할 수 없는 환경에서는 첨부 벡터를 프로젝트에서 지원하는 이미지 벡터 또는 Canvas로 옮긴다. 기존 디자인 시스템 안에 재사용 가능한 컴포넌트로 구현한다.

## 6. 실제 데이터와 버튼 동작

| UI | 연결할 내용 |
| --- | --- |
| 프로필 사진·닉네임 | 기존 사용자 사진과 닉네임. 비어 있는 이름은 기존 기본 호칭 사용 |
| 프로필 수정 | 기존 사진·닉네임 편집 창 열기 |
| 지금까지 달린 거리 | 저장된 러닝 세션의 누적 거리, km 단위 소수 첫째 자리 |
| 러닝 횟수 | 같은 러닝 세션 집계의 총 횟수 |
| 내 러닝 기록 보기 | 기존 전체 러닝 기록/분석 진입 동작 |
| 챌린지 | 기존 챌린지 화면 |
| 지갑 | 기존 지갑 화면. 행 오른쪽에는 실제 SUP 잔액 |
| 설정 | 기존 설정 목록. 뒤로 가기로 내 정보 첫 화면 복귀 |

기록 카드 자체는 정보 영역이며, 아래 흰색 버튼이 기록 화면으로 들어가는 명확한 진입점이다. 메뉴는 작은 화살표만 누르는 방식이 아니라 행 전체가 눌려야 한다. 기본 터치 피드백은 기존 앱 컴포넌트를 활용한다.

### 현재 로컬 Android 코드에서 확인한 연결

확인한 프로젝트는 `stepup-stage9`이며, 실제 구현 시 현재 체크아웃에서 이름과 동작을 다시 확인한다.

| 대상 | 확인한 연결 |
| --- | --- |
| 화면 | `app/src/main/java/com/stepup/android/ui/screens/profile/ProfileScreen.kt` |
| 데이터 | 같은 폴더의 `ProfileViewModel.kt` |
| 거리·횟수 | `viewModel.runTotals`의 `meters`, `runs` |
| 닉네임 | `state.nickname` |
| 사진 | `state.avatarId`, `state.avatarRev` 및 기존 사진 로딩 흐름 |
| SUP 잔액 | `state.balance` |
| 프로필 수정 | `showProfileEdit = true`, 기존 `ProfileEditDialog` |
| 기록 보기 | 현재 `RecentRunsCard`의 전체 보기와 같은 `onOpenAnalytics` |
| 챌린지 | `onOpenChallenges` |
| 지갑 | `onOpenWallet` |
| 설정 | 현재 내부 설정 목록으로 전환하는 `tab = 1` 및 기존 뒤로 가기 처리 |

거리에는 걸음 수로 추정한 `lifetimeKm`나 최근 3회 합계를 대신 넣지 않는다. 기존 `runTotals` 집계를 재사용한다. 프로필 사진/닉네임 저장 방식과 계정 식별자, 데이터베이스, 보상 계산은 그대로 유지한다.

기존 첫 화면의 최근 기록 목록과 총 시간 표시 등은 이번 시안에 맞춰 첫 화면에서 정리한다. 해당 정보와 기능은 기록 보기 및 설정에서 계속 접근할 수 있게 한다. 기존 연결 화면에 필요한 정보가 있는지 확인하고, 기능 자체를 지우지 않는다.

## 7. 화면 상태와 작은 화면 대응

| 상태 | 표시와 동작 |
| --- | --- |
| 정상 | 실제 거리·횟수·잔액 표시 |
| 기록 없음이 확인됨 | `0.0 km`, `아직 기록한 러닝이 없어요.`. 기록 보기 버튼은 유지 |
| 기록 로딩 중 | 거리와 횟수에 자리를 유지하는 로딩 표시 또는 `—` 사용. 0회로 단정하지 않음 |
| 불러오기 실패 | 카드 안에 `기록을 불러오지 못했어요.`와 재시도 동작. 실패를 0km로 표시하지 않음 |
| 긴 닉네임 | 프로필 수정 터치 영역을 확보한 뒤 닉네임 한 줄 말줄임 |
| 큰 누적 거리 | 숫자와 km를 하나의 행으로 계산. 필요하면 장식을 줄이고, 숫자는 읽기 좋은 크기로 조정 |
| 긴 잔액·큰 글자 | 잔액이 이름이나 화살표와 겹치면 행 높이를 늘려 보조 줄로 표시 |

실제 데이터 소스의 로딩/오류 상태를 확인해 연결한다. 시안만 맞추기 위해 가상의 성공 상태나 잔액을 만들지 않는다. 확대 글꼴에서는 카드 문구 줄바꿈과 높이 증가를 허용하고, 본문 스크롤로 모든 메뉴에 접근할 수 있게 한다.

## 8. 범위와 구현 원칙

- 이번 변경 대상은 **내 정보 첫 화면**과 그 화면의 기존 진입 동작이다.
- 레벨 배지, 등급, 메달, 연속 출석, 추천 상품, 지갑 연결 배너, 랭킹 등 새 요소를 첫 화면에 추가하지 않는다.
- 메뉴 전체를 각각 큰 카드로 감싸거나 두꺼운 테두리를 추가하지 않는다. 작은 아이콘 받침과 여백으로 정리한다.
- 최근 기록을 길게 나열하거나 그래프를 추가해 첫 화면을 다시 복잡하게 만들지 않는다.
- 공통 헤더와 하단 내비게이션은 기존 디자인 시스템을 재사용한다. 화면 내부에 두 번째 헤더·하단 바를 만들지 않는다.
- 시안의 하단은 러닝 / 신발 / 커뮤니티 / 내 정보 4개 탭이다. 실제 앱에는 최신 승인된 공통 내비게이션 구성을 사용한다. 이 지시서는 별도 뽑기 탭 등 다른 경로를 임의로 삭제하라는 지시가 아니다.
- 프로젝트의 `AGENTS.md`와 최신 디자인 인수인계를 먼저 확인한다. 과거 시안과 외관이 충돌하면 이번에 사용자가 선택한 러닝 패스 이미지를 기준으로 삼는다.

## 9. 완료 기준

1. 첨부 PNG와 나란히 비교했을 때 프로필, 기록 카드, 흰색 버튼, 세 메뉴의 순서와 비중이 맞는다.
2. 카드 오른쪽에 기준 이미지의 경로 그래픽이 있고, 숫자의 가독성을 해치지 않는다.
3. 거리·횟수·잔액은 실제 데이터이며 프로필 수정, 기록 보기, 챌린지, 지갑, 설정과 뒤로 가기가 모두 동작한다.
4. 정상, 기록 없음, 로딩/오류, 긴 이름·큰 숫자 상태를 확인한다. 좁은 화면과 확대 글꼴에서 겹침이나 잘림이 없다.
5. 프로젝트가 요구하는 관련 검사와 빌드를 실행하고, 같은 수정본의 실제 앱 화면을 캡처한다. 시안 이미지를 실제 구현 캡처처럼 제출하지 않는다.
6. 결과는 변경 파일, 확인한 동작, 실제 화면 캡처, 남은 제한 사항으로 짧게 정리한다.

구현에 앞서 새로운 시안을 다시 만들지 말고, 첨부된 러닝 패스 디자인을 기존 앱에 충실하게 옮겨줘.
