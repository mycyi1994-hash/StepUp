## 1. 이번에 확정한 기준

사용자는 다음 두 화면을 선택했다.

- references/01-approved-my-shoes.webp: 내 신발. 큰 신발 + 등급 프레임/효과 + 능력치 바 + 보유 신발 가로 목록.
- references/02-approved-vault-grid.webp: 신발 보관함. 보유 수/정렬/필터 + 2열 신발 그리드.

위 화면을 바탕으로 **이름 끝의 등급을 작은 둥근 테두리 배지로 변경**한다. references/03-rounded-badge-reference.webp는 둥근 배지 모양만 참고한다. 3번째 그림의 옛 탭 구성, 이름 위의 배지 위치, 상세 보기 링크는 다시 가져오지 않는다.

현재 전달물은 디자인과 작업 지시서다. 실제 앱 구현·빌드·배포 결과가 아니다. 사용자는 이 대화에서 코드 작업을 중단하고 이미지와 Claude용 지시서를 요청했다.

## 2. 내비게이션 — 최신 사용자 지시가 이전 문서보다 우선

- 하단은 5개: **러닝 / 신발 / 뽑기 / 커뮤니티 / 내 정보**.
- 뽑기는 독립된 가운데 하단 탭이다. 기존 뽑기 기능을 연결한다.
- 신발 화면 상단은 2개: **내 신발 / 신발 보관함**.
- 신발 상단에 뽑기를 남기지 않는다. 하단에서 신발/뽑기를 눌렀을 때 선택 상태와 뒤로 가기가 일관되어야 한다.
- 기존 루트 셸의 공통 머리글·하단 내비게이션을 수정한다. 화면 안에 별도 로고나 하단바를 복제하지 않는다.
- 기존 AGENTS.md, DESIGN.md, S2 문서의 '4개 하단 탭·신발 내부 뽑기'는 이 최신 지시로 변경되는 부분이다.

## 3. 내 신발 화면

위에서부터:
1. 기존 STEPUP 로고와 실제 잔액.
2. 내 신발 / 신발 보관함.
3. 신발 이름 + 그 이름 끝의 작은 등급 배지. 다음 줄은 실제 레벨·번호·착용 상태.
4. 실제 신발 이미지와 대응하는 등급 프레임/앞뒤 효과.
5. 능력치 바.
6. 보유 신발 가로 목록.
7. 공통 하단 5개 탭.

### 꼭 지킬 것

- 내 신발에는 실제 보유한 신발만 보여준다. 도감의 미보유 모델, 마켓 상품, 구매·판매 광고를 섞지 않는다.
- **기본 휴대폰 화면에서 아래로 드래그하지 않아도 선택 신발·능력치 바·보유 목록을 함께 볼 수 있어야 한다.**
- 화면 높이가 줄면 큰 이미지·장식 여백부터 줄인다. 능력치나 보유 목록을 하단바 뒤로 밀지 않는다.
- '상세 보기', '신발 자세히 보기' 등의 별도 링크는 없앤다.
- 실제 그림 비율을 보존한다. 화면 전체 목업 PNG를 붙여 앱 화면으로 쓰지 않는다.
- 같은 모델의 여러 켤레도 고유 소유 id로 구분한다. 선택한 신발과 실제 착용 신발을 혼동하지 않는다. 구경/선택만으로 착용 상태를 바꾸지 않는다.
- 착용·강화·수리·판매 등 기존 동작을 임의 삭제하지 않는다. 그리드/썸네일 선택 후 기존 동작이나 작은 관리 메뉴로 연결하되, 첫 화면에 큰 상세 버튼이나 원형 착용 영역을 추가하지 않는다. 별도 착용 확인 없이 자동 장착하지 않는다.

## 4. 능력치

최신 서버 신발의 실제 항목 3종을 표시한다.

| 제목 | 짧은 효과 설명 | 실제 출처 |
|---|---|---|
| 효율 | SUP 적립 보너스 | efficiencyBps를 기존 화면과 동일하게 % 표시 |
| 착화감 | 에너지 절감 | 기존 energyEfficiency / energySavingPercent 계산 |
| 내구도 | 필요 시 현재 / 100 | 서버 durabilityPts 또는 기존 보유 데이터 |

- 왼쪽 제목/짧은 설명, 오른쪽 실제 값, 아래 가로 막대. 세 막대의 트랙 폭과 두께·정렬을 통일한다.
- 보상의 확정 금액과 능력치 %를 혼동하지 않는다.
- 목업의 +4.8%, 7.5%, 92/100, 잔액·수량·레벨은 예시이며 실제 사용자 값으로 하드코딩하지 않는다.
- 막대 기준은 실제 정의된 범위를 확인해서 정한다. 단위가 다른 값을 임의로 100점으로 바꾸거나, 4.8%를 근거 없이 48% 길이로 표시하지 않는다. 비교 기준을 사용하면 명확히 설명하고 모든 신발에 같은 기준을 쓴다.
- 구형 로컬 신발의 행운·착화감 원시값은 기존 데이터다. 새 서버 신발에 없는 행운을 만들어 넣지 않는다. 구형 항목은 기존 확인 경로를 보존한다.

## 5. 신발 보관함

references/02-approved-vault-grid.webp의 **2열 격자**가 선택된 안이다. 목록형/가로 갤러리형으로 바꾸지 않는다.

- 실제 보유 수, 정렬, 필터, 보유 신발 그리드 순서.
- 각 칸: 등급 프레임 속 실제 신발 → 이름 끝 둥근 배지 → 레벨·번호·착용 상태.
- 착용 체크는 실제 착용 중인 한 켤레에만. 선택 테두리와 착용 체크는 구분한다.
- 보유하지 않은 신발, 가짜 재고, 빈 칸 채우기용 상품을 넣지 않는다.
- 보유량이 많아지면 그리드는 세로 스크롤할 수 있다. '한 화면에 신발과 능력치' 요구는 내 신발 대표 화면에 적용된다.
- 상단 필터의 수량은 실제 데이터로 계산한다. 6종이 좁은 폭에 맞지 않으면 필터를 가로 이동시켜도 되며, 두꺼운 필터를 여러 줄 쌓지 않는다.
- 마켓/상점/도감 등 기존 경로의 삭제를 뜻하지 않는다. 이 화면의 보유 목록에 섞지 말고 기존 기능의 별도 진입을 보존한다.

## 6. 둥근 등급 배지 6종

사용자의 '버튼'은 신발 이름 옆 등급 표시 자산이다. 의미 없는 클릭 동작을 붙이지 않는다. 필터로 사용하는 경우만 상호작용 상태를 제공한다.

| 파일 | 표시 | 시각 구분 |
|---|---|---|
| badges/01-common.webp | 일반 | 카본·브러시드 실버, 짧은 각인 |
| badges/02-rare.webp | 레어 | 블루·아이스빛, 속도선·가속 눈금 |
| badges/03-epic.webp | 에픽 | 퍼플·라벤더, 프리즘 면·빗금 |
| badges/04-legendary.webp | 레전더리 | 골드·샴페인, 금속광·꺾쇠·작은 광점 |
| badges/05-redline.webp | 레드라인 | 코럴·앰버, 가속선·곡선 열기 파동 |
| badges/06-finish.webp | 피니시 | 민트·보라·아이스화이트, 곡선·체커 결승 테이프 |

- 6종 모두 개별 PNG, 2172 × 724, RGBA. 실제 알파 투명 영역을 확인했다. PNG 안에 한국어 글자가 포함된 디자인 원본이다.
- 기존 3번째 첨부의 둥근 테두리 방식에 각 등급의 특징을 더한 신규 디자인 자산이다. 앱용 최종 크기로 검증된 버튼이 아니다.
- **위치는 이름 끝, 같은 행. 별도의 등급 전용 행을 만들지 않는다.** 이름이 길면 최대 2줄 범위에서 마지막 이름 줄 끝에 배지를 배치한다. 배지 하나 때문에 별도 빈 행이 생기지 않게 한다.
- 작은 등급 배지로 사용한다. 시작 크기 제안은 실제 보이는 배지 높이 24–28dp, 라벨 11–12sp, 좌우 여백 8–10dp, 이름과 간격 6dp다. 이 수치는 사용자 지정값이 아니라 구현 시작점이며 실제 폰에서 읽히게 조정한다.
- 제공 PNG의 3:1 캔버스 폭을 모든 짧은 라벨에 강제해서 이름 공간을 과도하게 쓰지 않는다. 같은 보이는 높이/글자 크기를 유지하면서 라벨 길이에 맞춘 컴팩트 배지를 재현한다. 이미지를 찌그러뜨려 줄이지 않는다.
- 내 신발과 그리드 모두 같은 배지 컴포넌트를 쓴다. 다국어·글자 확대를 위해 테두리/효과와 네이티브 라벨을 분리해 재현하는 방법을 우선 검토한다. 제공 PNG는 디자인 기준과 한국어 시안 자산이다.
- 네이티브 재현 시 6종을 단순 색상 교체만으로 축소하지 말고 각각의 속도선·프리즘·금속광·열기·체커 특징을 작은 크기에서도 남긴다. 신발보다 큰 버튼으로 만들지 않는다.
- 정적인 자산이다. 새 애니메이션이나 무한 발광을 필수로 추가하지 않는다.

## 7. 6종 디자인과 현재 데이터 연결

저장소 확인 기준:
- 기존 도메인 Rarity는 COMMON / RARE / EPIC / LEGENDARY 네 가지다.
- design/shoes-2026-09/catalog.json의 새 70종은 레어 20, 에픽 20, LEGENDARY 30이다.
- LEGENDARY 30종 안에 series가 LEGENDARY / REDLINE / FINISH로 나뉜다.
- 따라서 레드라인·피니시 모델은 **기존 series에 따라 05·06 시각 배지와 프레임을 적용**할 수 있다. 보상·확률에 쓰는 rarity를 새 enum으로 바꿀 이유는 없다.
- 시각 선택은 알려진 series REDLINE/FINISH를 먼저 확인하고, 나머지는 실제 rarity에 대응한다. 보관함 표시/필터도 같은 시각 분류를 일관되게 따른다.
- 사용자는 6종을 서로 다른 디자인으로 보여달라고 했다. 이것을 드롭률·보상·NFT·DB 등급을 새로 늘리라는 승인으로 확대하지 않는다.
- 과거 프레임 안내의 '레드라인·피니시는 미리 보기만'은 그때의 상태 기록이다. 최신 카탈로그 series 및 이 시각 지시를 함께 적용한다. 이미 있는 05·06 레이어를 활용하고 새 서버 경제는 만들지 않는다.

## 10. 구현 후 완료 기준

- 확정한 2개 화면과 실제 앱 캡처를 나란히 비교해 제시.
- 내 신발의 신발·3개 능력치 바·보유 목록이 세로 스크롤 없이 보이는지 360×800 및 일반 크기에서 확인. 작은 화면/큰 글씨에서는 내용 잘림 없이 장식 크기를 우선 조정.
- 보관함 2열, 정렬·필터·보유 수·착용 체크가 실제 데이터에 연결.
- 등급이 이름 끝의 작은 둥근 배지로 표시되고, 6종 시각 분류가 큰 프레임/썸네일/배지에서 일치.
- '상세 보기' 링크 없음. 상단 내 신발/신발 보관함, 하단 5탭과 독립 뽑기 연결.
- 선택만으로 자동 착용되지 않으며 기존 기능과 계정·신발·잔액 데이터 보존.
- 대표 등급 6종과 긴 이름, 빈 목록·불러오기 실패, 큰 글씨, 밝은/어두운 테마를 확인.
- 저장소 지침에 따라 디자인 계약·문자열/리소스 검사·빌드와 관련 검증 수행. 같은 소스의 실제 캡처로 보고하며 목업을 앱 캡처로 보고하지 않는다.
