미정 정책 / 시안의 구현상 한계

확정 규칙과 미정 사항을 섞지 않는다. 아래는 원문에 세부 방식이 없거나 현재 저장소 확인이 필요한 항목이다. 기존 도메인 규칙을 먼저 확인하고, 답이 없으면 선택지·영향·권장안을 한 번에 정리한다. 그동안 확정된 화면과 자료구조 작업은 계속한다. 시안의 임시 버튼 연결이나 샘플 숫자를 정책 결정 근거로 삼지 않는다.

D01. 첫 2분 보상과 조기 종료
미정: 확인 후 처음 2분에도 가산을 소급할지, 이후만 적용할지, 2분 전에 종료하면 어떻게 정산할지.
확정: 출발 때와 2분 뒤 모두 500m 조건을 충족한 인증 인원만 집계한다. 확인 전에는 확정값으로 표현하지 않는다.
구현: 시작~확정 구간과 이후 구간을 식별하고 최종 정책에 맞춰 서버에서 정산한다. 확인 전 UI는 Pending이다. 샘플 74.88 SUP를 실제 초기 보상으로 사용하지 않는다.

D02. 확정 이후 인원 변화
미정: 2분 뒤 집계수를 러닝 내내 유지할지, 이후 이탈·종료 때 다시 계산할지.
확정: 다른 참가자가 모두 종료해 실제 한 명만 남으면 자동 종료한다. 보너스 집계 인원과 미종료 참가자 수는 별개다.
구현: 보너스 판정 버전과 적용 구간을 보관할 수 있게 한다. 화면은 서버가 반환한 적용값을 표시한다.

D03. 500m 기준점과 위치 증거
미정: 진행자 위치·모임 기준점·출발점·참가자 간 거리 중 무엇을 기준으로 할지, 위치 정확도·샘플 유효 시간·2분 시점의 허용 범위.
확정: 출발과 2분 뒤의 500m 조건, 같은 크루·같은 방·인증 조건은 유지한다.
구현: 기존 위치 검증 코드를 확인한다. 임의로 반경을 200m·250m로 바꾸지 않는다. 위치 미확인과 범위 밖을 구분하고, GPS가 없으면 확인 불가로 표시한다.

D04. 러닝 도중 레벨 업
미정: 오늘 풀 전체를 새 레벨 효과로 다시 계산할지, 신규 기여에만 적용할지, 다음 러닝·다음 날부터 적용할지. 진행 중 보상 효과도 적용 시점이 필요하다.
확정: 체력은 (Lv−1)×6%, 보상은 (Lv−1)×1%이며 레벨은 내려가지 않는다.
구현: 적용 레벨·정책 버전·변경 이력을 보관한다. 축하 화면과 실제 경제 효과의 적용 시점을 분리한다. 시안은 같은 레벨로 진행한 예시다.

D05. 한국 자정을 넘는 활성 세션
미정: 자정 전후 세션을 어떻게 구간 분할·귀속할지, 계속 달리는 사람의 새 날짜 기여와 하루 참여권을 어떻게 처리할지.
확정: 일일 풀은 한국 자정에 비워지고 참여 제한은 한국 날짜 기준이다. 누적 XP·레벨은 유지한다.
구현: 날짜별 풀과 시각별 원장을 보관하고 경계를 잃지 않는다. 자정의 풀 초기화를 무시하는 방식으로 결정하지 않는다. midnight 시안은 이미 종료한 사용자가 다음 날을 맞는 경우다.

D06. 체력 0 이후 새 참가자의 기여
미정: 신규 기여로 풀이 양수가 되면 기존 참가자도 적립을 재개할지, 이미 소진을 겪은 세션은 계속 중단할지.
확정: 신규 참가자는 출발 때 기여한다. 풀 0 구간은 적립 중단이며 개인 신발로 전환하지 않는다.
구현: 풀 소진과 세션 종료를 분리한다. 신규 기여 시각을 기록한다. 풀이 0이었던 구간의 걸음을 임의로 소급 적립하지 않는다.

D07. 무효 러닝과 체력·보상 정정
미정: 무효 확정 시 이미 기여·소비한 풀의 조정 여부, 지급 보상 취소·보류, 참여권 복구 여부.
확정: 무효 거리는 XP에서 제외하며 레벨은 내려가지 않는다. 모든 자원을 환불한다는 규칙은 없다.
구현: 기존 무효 판정과 원장 정책을 확인하고 별도 정정 이력으로 처리한다. 한 사람의 무효를 이유로 타인의 풀·보상을 조용히 다시 쓰지 않는다.

D08. 소수 사용량과 반올림
미정: 분당 5를 초 단위로 비례 정산할지, 완료한 분 단위로 정산할지. 서버 정밀도와 최종 반올림 방식도 확인한다.
확정: 달린 1분마다 5를 사용한다. 시안의 106.7은 21분 20초를 비례 계산해 소수 한 자리로 표시한 예시다.
권장: 내부 정밀도를 유지하고 기존 원장 단위에 맞춰 최종 반올림한다. 샘플 표시값을 새로운 회계 정책으로 취급하지 않는다.

D09. 연결 끊김·기록 유실·복구
미정: heartbeat 만료 후 언제 종료를 확정할지, 오프라인 구간과 2분 위치 확인을 어떻게 인정할지.
확정: 일시정지 가능, 명시적 종료 후 재입장 불가, 타인이 모두 종료하면 마지막 참가자 자동 종료.
구현: 기존 세션 복구·기록 서비스 정책을 재사용하고 서버 상태를 기준으로 한다. 일시적인 통신 실패를 즉시 종료로 처리하지 않는다.

D10. 방과 진행자 세부 동작
확인 필요: 진행자 이탈 시 역할 승계, 출발 직전 일부 참가자 검증 실패, 이미 출발한 방의 늦은 참가, 오늘 완료한 회원의 비참여 방 관리.
확정: 크루원 누구나 방 생성, 최대 20명, 같은 방에서 함께 출발, 사용자당 하루 1회.
구현: 중도 합류 기능을 임의로 추가하지 않는다. 방 생성과 실제 러닝 참여권을 구분한다. 진행자 종료가 전원 종료로 이어지는 기존 로직은 새 규칙과 대조한다.

D11. 진행 중 신발 자산 변경
확인 필요: 판매·업그레이드·장착 변경이 활성 세션에 미치는 기존 영향.
권장: 출발 시 선택한 신발·능력치·최대 내구도를 스냅샷으로 저장한다. 기존 소유권·경제 코드의 잠금 정책을 확인한다. 선택 변경으로 기여를 중복 적립하지 않는다.

D12. 인증 상태 출처
확인 필요: 현재 서버에 신뢰할 수 있는 전화번호 인증 정보가 실제로 있는지.
확정: SMS·OTP·번호 입력·인증 계정 화면은 이번 범위 밖이다. 미인증자도 참여 가능하다.
구현: 정보가 없으면 임의로 인증 처리하지 않는다. 개발용 fixture와 운영 상태를 분리한다. 유효한 인증 데이터가 없으면 보너스 집계 인원이 0일 수 있음을 보고한다. 별도의 인증 공급 기능을 몰래 추가하지 않는다.

D13. 0069 전환과 진행 중 세션
확인 필요: 0070 또는 후속 개편의 실제 적용 여부, 기존 에너지 풀과 활성 세션 존재 여부.
확정: 에너지 몫을 공용 내구도로 대체한다. 두 모델의 숫자 단위가 다를 수 있다.
구현: migration 번호·적용 이력·구버전 앱을 확인해 전환 계획을 세운다. 기존 원장을 삭제하거나 잔량을 임의 환산하지 않는다.

경제 관련 열린 질문
크루 보상 무제한의 영향은 출시 후 수치를 보고 조정한다는 사용자 계획이다. 현재 규칙을 구현하고 일일 기여·소모·보상·참가자·레벨별 발행량을 확인할 수 있게 한다. 임의 상한·APR·수익률을 추가하지 않는다.

시안 구현을 복사할 때 주의할 점
P01. reference.html은 HTML 검토용이며 Android·Supabase 구현체가 아니다. 39개 PNG 상태와 8개 연결 상태가 있다.
P02. 숫자·이름·신발 ID·시간·보상은 예시다. 화면 선택은 하나의 러닝을 연속 시뮬레이션하지 않는다. 이동할 때 12분·21분·2분 미만 등 예시 시점이 바뀔 수 있으므로 실제 러닝 시계에 복사하지 않는다.
P03. 2분 확인·위치 재확인을 버튼으로 넘기는 것은 상태 검토용 데모다. 실제 판정은 GPS 증거와 서버 결과로 한다.
P04. 6명·20명 명단, 620m 거리, 신발 #1248에 쓰인 이미지는 레이아웃 예시다. 실제 보유 자산·서버 목록으로 대체한다.
P05. 일부 채팅·모임 버튼은 관련 예시 화면으로 연결된다. 제품에서는 기존의 실제 채팅·모임·기록·목록 경로에 연결한다.
P06. 저장 완료·받은 보상은 정산 성공 예시다. 미정산·실패·조기 종료·데이터 없음은 화면 명세의 공통 상태 계약에 따라 구현한다.
P07. 지도는 기존 Android 테스트 fixture 좌표와 OpenStreetMap 타일을 합성한 예시다. 실제로 달린 길이나 검증된 러닝 코스가 아니다. 앱의 실제 지도·GPS 경로로 교체한다.
P08. 갤러리 상태 선택기는 제품 UI가 아니다. 전체 선택에서 상태를 초기화하는 JavaScript를 ViewModel 전환 로직으로 쓰지 않는다.
P09. 390×844 고정 프레임은 리뷰 기준이다. 실제 앱은 기기 인셋·가로폭·글꼴 배율을 반영한다.
P10. 메인 상태 39장은 PNG가 있고 연결 상태 8개는 같은 컴포넌트의 변형이다. SMS 화면은 없다. 시스템 권한·통신 오류 조합은 기존 부품으로 처리하고 실제 기기 검증 때 추가 캡처한다.
