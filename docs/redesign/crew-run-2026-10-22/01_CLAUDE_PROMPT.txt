첨부한 StepUp 크루 러닝 핸드오프를 기준으로 실제 Android 앱과 Supabase를 구현해줘.

StepUp은 Kotlin · Jetpack Compose 앱이고 서버는 Supabase(Postgres + RPC)야. 지금의 0069 '에너지 몫' 방식 대신, 크루원들이 출발할 때 고른 신발의 최대 내구도를 모아 함께 쓰는 공용 내구도 방식으로 개편하는 작업이야.

먼저 00_START_HERE.txt, 02_CONFIRMED_RULES.txt, 03_SCREEN_BEHAVIOR.txt를 모두 읽고 reference.html과 screenshots/를 직접 확인해. 기존 저장소의 AGENTS.md·CLAUDE.md·현재 브랜치·로컬 변경사항과 실제 관련 코드를 확인한 뒤 작업해. 이미 구현된 항목은 정합성을 검토하고 이어서 수정해.

반드시 지킬 것
1. 디자인은 이 ZIP의 남색 배경, 하늘색 강조, Pretendard, 흰색 버튼과 파란 하단 면을 유지해. 임의의 밝은 테마나 새로운 디자인으로 바꾸지 마.
2. 기본 글꼴 배율에서 실제 휴대폰 한 화면에 핵심 정보와 하단 행동이 들어와야 해. 390×844는 검토 기준이지 앱 전체에 고정할 dp 높이가 아니야. 실제 시스템바·내비게이션바·IME를 반영하고 작은 화면에서도 내용이 겹치거나 잘리지 않게 해. 큰 글꼴 접근성 모드에서는 상세 이동/스크롤을 허용하고 글자를 억지로 줄이지 마.
3. 하루 공용 체력 = 참여자가 출발하며 선택한 신발들의 최대 내구도 합 × 크루 레벨 효과. 남은 개인 내구도를 합산하거나 인원별 몫으로 나누지 마. 같은 크루의 같은 날짜에는 방이 달라도 하나의 풀을 공유해.
4. 달리는 사람마다 분당 5씩 공용 체력만 사용해. 개인 신발은 닳지 않아. 체력 0 이후에는 적립만 멈추고 기록은 계속되며, 개인 신발로 넘어가지 않아.
5. 보상은 각자 선택한 신발 능력치로 계산해. 인원 보너스와 레벨 보너스는 더하고, 각 인원 구간끼리는 중복 적용하지 마.
6. 크루 러닝은 사용자당 한국 시간 기준 하루 한 번이야. 크루를 옮겨도 동일하고, 일시정지는 가능하지만 종료 후 재입장은 불가능해. 다른 참가자가 모두 종료해 혼자 남으면 마지막 사람도 자동 종료해.
7. 보너스 집계 인원은 같은 크루이며 출발 때와 2분 뒤 모두 500m 안에 있고 휴대폰 인증 상태가 확인된 사람이야. 참여 인원·현재 달리는 인원·보너스 집계 인원을 분리해.
8. 문자 발송, SMS 업체 연동, OTP 요청/재전송, 번호 입력과 인증 화면은 이번에 구현하지 마. 기존 서버의 신뢰할 수 있는 인증 상태가 있으면 읽어서 사용해. 미인증자도 크루 러닝에 참여하고 자기 신발로 보상받을 수 있어. 인원 보너스 집계에서만 제외해. 클라이언트에서 임의로 인증 처리하거나 전원을 인증된 것으로 설정하지 마.
9. 레벨 1–20의 전체 경험치 표, 인원 2–20명의 전체 보너스 표, 600 SUP 개인 상한과 분리된 크루 보상 무제한 규칙을 02 문서 그대로 적용해.
10. 예시 숫자는 데모야. 실제 개인 신발 기본 보상 공식, GPS 검증, SUP 원장, 세션 저장·복구는 기존 검증된 구현을 이용하고 필요한 부분만 확장해.

구현 순서
A. 실제 소스와 0069/0070 적용 여부를 확인하고, 기존 구조와 새 규칙의 차이를 기록한다.
B. 공용 풀·일일 참여 기록·선택 신발 스냅샷·보너스 확인·경험치·정산의 서버 모델과 RPC 계약을 정리한다. 서버와 앱이 같은 계약을 보도록 맞춘다.
C. 서버 트랜잭션·동시성·중복 요청 방지를 먼저 구현하고 기존 자유 러닝 동작이 유지되는지 확인한다.
D. 홈 → 대기실 → 신발 선택 → 출발 확인 → 러닝 → 종료 → 결과의 전체 경로를 구현한다. 보조 상태 39개와 연결 상태 8개는 03 문서를 따른다.
E. 권한·GPS·오프라인·앱 재시작·저장 실패·자정 경계·2분 확인·마지막 1인 자동 종료를 연결한다. '서버 확인 중'과 '적립 완료'를 구분한다.
F. 06 문서의 검증을 실행하고 Android 실화면 캡처를 시안과 비교해 수정한다. DB 적용/배포 여부는 실제로 수행한 범위만 보고한다.

아직 정하지 않은 정책은 07 문서에 따로 표시했어. 먼저 현재 서버 규칙에서 답을 찾고, 없으면 해당 로직을 분리해 두고 필요한 결정만 한 번에 정리해줘. 그동안 확정된 UI·자료구조·테스트 작업은 계속 진행해. 임의로 보상 소급 방식이나 인증 면제를 확정하지 마.

금지
웹 시안을 WebView로 넣어서 앱 구현을 대신하지 마. 미리보기 분류 탭/선택기, 가짜 상태바, 데모 날짜·계정·좌표, window.openai, 테스트 버튼을 제품에 넣지 마. 예전 에너지 몫 코드, 개인 내구도 fallback, 미인증자 출발 차단을 남기지 마. 실제 현재 API를 확인하지 않고 제안 RPC 이름을 이미 있는 함수라고 가정하지 마.

완료 보고
수정한 앱/서버 파일과 migration 번호, 규칙별 구현 위치, 실행한 검증 결과, 실제 기기/에뮬레이터 캡처, 남은 결정 사항을 정리해. 화면만 만들고 서버가 완성됐다고 하거나, 웹 시안 검증을 Android 실기기 검증이라고 보고하지 마.
