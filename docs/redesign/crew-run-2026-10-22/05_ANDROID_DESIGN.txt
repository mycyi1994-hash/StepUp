Android / Jetpack Compose 구현 및 디자인

1. 구현 진입점
실제 저장소의 현재 구조를 먼저 확인한다. 과거 확인된 경로는 다음과 같으며 현재 파일명/분리는 달라질 수 있다.
app/src/main/java/com/stepup/android/ui/screens/community/home/CrewHomeScreen.kt
app/src/main/java/com/stepup/android/ui/screens/walk/CrewLobby.kt
app/src/main/java/com/stepup/android/ui/screens/walk/CrewRunScreens.kt
app/src/main/java/com/stepup/android/ui/screens/walk/CrewRunLive.kt
app/src/main/java/com/stepup/android/ui/screens/walk/CrewRunResult.kt
같은 폴더 또는 관련 패키지의 CrewRunKit, CrewBlueKit, CrewHomeParts, CrewStaminaParts, domain/CrewStamina.kt, Party/Run repository, Run service/ViewModel.
검색어: crew_stamina, crew_level, record_session, party_start/finish/leave, CREW_EMPTY, PERSONAL, energy_pool, run_km, '내 몫'.
새 화면이 동일 기능을 중복 구현하지 않게 기존 내비게이션·리포지터리·위치 서비스·기록 저장 흐름을 확장한다. 번개러닝/자유러닝에 크루 규칙이 섞이지 않게 한다.

3. 휴대폰 한 화면 기준
시안 프레임390×844, PNG780×1688. 기본 높이 배분: 상태바26 + 헤더56 + 본문674 + 하단88. 이 수치는 검토용 기준이며 실제 앱에 인위적 상태바26/전체height844를 고정하지 않는다.
가로 여백20, 주요 간격12~16, 카드 반경18~20, 주 버튼 높이60(파란 하단면4 포함), 보조 버튼48~60. 기존 네이티브 터치 영역48dp 이상을 우선한다.
실제 WindowInsets를 반영하고 gesture/3버튼 내비게이션 양쪽에서 CTA가 가리지 않게 한다. 가짜 상태바와 제스처 바를 Compose로 그리지 않는다.
기본 폰트에서 일반390×844급 기기와360×800급 기기를 검증한다. 핵심 홈/대기실/러닝/결과는 상세 목록을 별도 시트로 빼 한 화면에 유지한다.
큰 글꼴/매우 작은 높이/키보드에서는 접근 가능한 스크롤·페이지 분할을 허용한다. 전체 앱 화면을 통째 scale-down하거나 10sp 이하로 줄여 억지로 맞추지 않는다.
시트는 화면 안에 배치하고 최대 높이/인셋을 고려한다. 20명 명단은 시안처럼 10명씩 나누거나 기존 적절한 목록으로 제공한다. 레벨표는 모든20개가 접근 가능해야 한다.

4. 화면 구조
대기실: 크루/방 이름 → 준비 명단 → 선택 신발 → 예상 인원 보너스 → 내 체력 기여 → 500m/2분 안내 → 출발/준비 CTA.
러닝: 지도 → 거리·시간·페이스 → 공용 체력 → 보상/인원 상태 → 상태 띠 → 일시정지·끝내기.
결과: 거리·시간·페이스 → 경로 지도 → 보상 카드(기본/인원/레벨) → 레벨 기여/체력 사용 상세 진입 → 완료.
기존 승인 홈: 크루 정체성 → 오늘 체력 → 채팅/다음 러닝 → 모임 안내 → 기록/레벨 상세 진입 → 참여 CTA.
모든 상세를 기본 화면에 쌓지 않는다. 공용 체력의 잔량/총량과 참가 인원, 버튼을 우선한다.

5. 앱 상태 모델 권장
화면 모델은 서버 snapshot과 UI 조작 상태를 분리한다. 예시:
CrewHomeUiState(Loading/Ready/Error), LobbyUiState, CrewRunUiState, ResultUiState.
Run phase: NotStarted / Starting / Verifying / Running / Paused / Finishing / Saved / SaveFailed / EndedAutomatically.
Earning state: Pending / Accruing / PoolEmpty / Paused. Run phase와 독립이다. PoolEmpty를Ended로 바꾸지 않는다.
Bonus state: Preview / Pending(checkAt) / Confirmed(count,pct) / Unavailable(reason).
Daily eligibility: Available / Active(runId) / Completed(nextEligibleAt) / Unknown. Unknown은Available이나Completed가 아니다.
Pool state: Ready(total,remaining,day,asOf,version) / Loading / Unavailable. null을0으로 바꾸지 않는다.

서버에서 같은 스냅샷에 계산된 잔량·레벨·인원 값을 전달받는다. UI 여기저기서 독립적으로 추측 계산해 서로 다른 숫자를 표시하지 않는다.
출발 버튼 연타 방지, 요청 중 버튼 비활성, 성공 확인 후 화면 이동. Timeout이면 기존 요청/세션을 조회하여 복구하고 무조건 다시 새 start를 호출하지 않는다.
내가진행자인 경우 '준비한 N명과 출발'. 일반 참가자는 '준비 완료' 후 '출발 대기 중'과 준비 취소. 방 생성은 모든 크루원에게 열어둔다.
시트 Back/닫기/바깥 탭은 원래 부모 화면의 선택 신발·역할·준비 상태를 보존한다. 사용자 완료 확인 없이 자동 start/finish하지 않는다.
실제 서버 상태가 변경되면 시트의 예상치도 갱신하거나 확인 버튼에서 재검증한다. 5→6명 변경이 인원+20→+50임을 보여준다.

6. 데이터/로직 경계
신발 변경: 출발 전 자신의 보유 신발만 선택. 화면에는 최대/현재 개인 내구도를 구분. 선택한 최대치×레벨 체력 효과를 미리보기로 표시. 출발 승인 때 서버 스냅샷 고정. 진행 중 신발 교체로 보상/기여를 다시 얻지 않는다.
위치: 기존 앱의 위치 권한·정확도·백그라운드 수집을 재사용. 500m 판정은 서버 기준/정책에 맞춘다. 위치를 못 읽는 상태를500m 밖이라고 거짓 확정하지 않는다.
지도: 기존 SDK/공급자와 실제 GPS 데이터를 사용한다. 미리보기의 타일·샘플 경로는 레이아웃 예시이며 실코스가 아니다. 저작자 표기와 현재 위치 정확도/권한 상태를 유지한다.
공용 체력: 서버 값의 부드러운 표시용 보간은 가능하지만, 로컬 애니메이션0 도달만으로 지급 원장을 확정하지 않는다. 재동기화 시 변경 이유와 최신 snapshot을 반영한다.
러닝 시간: monotonic time과 기존 세션 저장 기준을 사용하고 Wall clock 변경에 영향을 받지 않게 한다. 서버 확인용 사건 시각을 구분한다.
보상: 확인 전 '예상/확인 중', 서버 정산 후 '받은 보상'. 미확인/실패를0원 성공으로 표시하지 않는다. 결과의 기본+인원+레벨합과 원장 금액이 일치해야 한다.
거리: 기존 검증된 거리 산정/무효판정 사용. 시안 좌표/거리값을 하드코딩하지 않는다. 경험치에는 각 개인의 유효 거리를 1회만 반영한다.

7. 예외 상태의 공통 규칙
로딩: 필요한 자리/CTA를 유지하고 아직 읽지 못한 값은 — 또는 확인 중. 잘못된 빈 풀/재입장 제한을 만들어내지 않는다.
오프라인: 로컬 기록을 기존 서비스 규칙에 맞게 보존하고 서버 값에는 갱신 지연 상태를 표시. 네트워크 복귀 시 동일run_id로 재동기화. 새 출발의 일일권 검증은 서버 승인이 필요하다.
GPS 불량/권한 없음: 기존 권한 안내를 연결. start와2분 판정에 필요한 위치가 없으면 확인 중/권한 복구 동작을 제시한다.
저장 실패: 기록 보존, 재시도, 중복 지급 금지. 서버 확인 전 크루 경험치/레벨 업을 확정 표시하지 않는다.
무효 러닝: 원인 표시가 서버에 있으면 사용자 문구로 매핑. 경험치0, 레벨 하락 없음. 보상/내구도 환불 정책을 UI에서 새로 만들지 않는다.
동시 종료/혼자 남음: 서버의terminal_reason으로 결과 화면 연결. 남은 '보너스 인원'이 아니라 실제 미종료 참가 상태로 판단한다.

8. 백그라운드·잠금 알림·복구
기존 foreground running service를 사용하고 백그라운드에서도 필요한 기록을 지속한다. UI화면이 사라졌다고 종료하지 않는다.
알림에 공용 체력 remaining/total, 러닝 상태, 거리/시간, 적립 중단 상태를 반영한다. 공용 풀 조회 실패는0으로 덮어쓰지 않는다.
일시정지해도 다른 사람이 뛰면 풀은 줄 수 있다. pause 화면에서 풀 값을 동결하지 않는다.
잠금 알림을 탭하면 동일한 활성run_id로 돌아온다. 알림해제는러닝 종료가 아니다. 잠금 위 화면표시 기능은 실제 프로젝트 설정과 사용자 권한에 맞춘다.
프로세스 종료/재시작 시 마지막 run_id, 선택 신발 스냅샷 참조, 업로드하지 못한 구간, 사용자 상태를 복구한다. 서버에서 이미 종료된 세션이면 결과로 연결한다.
현재 시안의 가짜 시계19:30, Android 알림 외곽은 앱 화면으로 복사하지 않는다. 실제 시스템 알림 템플릿은 OS가 소유한다.

9. 접근성·모션
색만으로 상태를 구분하지 말고 준비/미인증/적립 멈춤/일시정지를 텍스트로 제공한다.
공용 체력에는 현재값/최대값, 보너스에는 예상/확정 상태를 읽어줄 semantics를 제공한다. 매초마다 전체 보상/타이머를 강제 낭독하지 않는다.
시트가 뜨면 포커스를 시트로 이동하고 닫히면 트리거로 복귀한다. 하드웨어 Back 지원.
경고는 일회성/상태 전환에 맞춰 표시하고 매 heartbeat마다 반복하지 않는다.
레벨 업 모션은 값/효과를 가리지 않게 짧게. 화려한 배경·루프 애니메이션을 새로 추가하지 않는다. 모션 감소 설정을 존중한다.

10. 제품에 넣지 않을 시안 요소
웹 갤러리의 홈·성장/대기실/러닝 중 분류 탭, 이전/다음 버튼, 화면 선택기, 휴대폰 외곽 그림자, 가짜 상태바, 예시 계정/인원/신발 ID, 고정 지도 경로, window.openai, 미리보기의 날짜 변경/상태 선택은 제품 UI가 아니다.
reference.html의 JavaScript는 화면 검토용이다. 실제 권한·서버·실시간 GPS·타이머·경제 로직이 들어 있는 구현체가 아니다.
