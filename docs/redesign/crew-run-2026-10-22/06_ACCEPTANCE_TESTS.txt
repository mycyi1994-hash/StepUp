구현 완료 기준 및 검증 시나리오

이 문서의 테스트는 앞으로 Claude가 실제 앱/서버에서 수행할 항목이다. qa/의 결과는 웹 시안 검증이며 아래 서버/Android 테스트를 대신하지 않는다.
미정 정책과 관련된 테스트는 07의 결정이 정리된 후 기대값을 고정한다. 실패를 숨기거나 보상 규칙을 테스트에 맞춰 임의 변경하지 않는다.

A. 수치 규칙 — 단위/DB 테스트
T01 최대 내구도 사용: 개인 75/100, Lv7 출발→공용 기여 136. 잔여 75에 1.36을곱한 102가아님.
T02 다른 신발: 최대 150, Lv7→204. 출발전변경은최종선택만기여하고미리보기조회는기여하지않음.
T03 동일 출발 재시도: 동일키 10회→run_id1개, 일일 참여권 1개, 공용 기여 1회.
T04 서로 다른 방: 같은 크루·같은날 두방의기여/소비가 같은풀에반영. 다른 크루/다른날은분리.
T05 소비율: 6명이 60초달림→30사용, 각 5. 20명이 60초→100사용.
T06 휴식: 6명중 1명정지, 다음 60초→5명×5=25. 휴식자소모 0,공용 풀은감소.
T07 표준 예시: 기존 612/816에 6명×100×1.36추가→1428/1632. 21분 20초 전원달림→640사용,788남음. 개인약 106.7표시.
T08 총량/잔량 구분: 소모해도분모는증가된기여총량유지. 잔량을분모로사용하지않음.
T09 개인 보호: 크루 러닝전후개인 내구도동일. 같은날자유 러닝은개인 내구도만기존규칙대로감소.
T10 정확한 소진: 풀 15,동시 6명→30/분이므로 30초에 0. 앞 30초의유효걸음만적립대상,이후기록계속. 개인 소모 0.
T11 구간별 기록: 소진전후걸음분포가치우친세션도시간경계에맞게걸음보상분리. 전체보상단순 잔량비율분배금지.
T12 소수/반올림: 짧은구간반복처리와한번에동일시간처리의원장합이정의된정밀도안에서동일. 매heartbeat반올림누적손실방지.
T13 인원표: 2..20전체expected=[5,10,15,20,50,52,54,56,58,60,62,64,66,68,70,72,74,76,150]와일치. 0/1은가산 0.
T14 5→6 불연속: 20%→50%. 인원 가산구간누적금지.
T15 레벨표: 모든 threshold의 바로 아래/정확히 같은 값/바로 위를 확인. 누적 449.999km는 Lv6,450km는 Lv7. 내부 단위가meters라면 449999m와 450000m 경계를 검증한다.
T16 Lv1:체력/보상 0%; Lv7:36/6; Lv20:114/19. Lv21없음.
T17 보상결합: B48,6명,Lv7→기본 48+인원 24+레벨 2.88=74.88.
T18 최대구간: B100,20명,Lv20→269.00. 297.50으로곱하지않음.
T19 개인별 속성: 두사람신발기본보상이서로다르면같은인원·레벨에도각자 다른합계. 평균내거나총합/N금지.
T20 크루 무제한: 개인 상한 600을이미채운사용자도남은공용 체력으로크루보상가능. 크루보상>600시잘라내지않음.
T21 XP 개인 합산: 6명각 3km 유효정산→크루누적+18km. 같은run재저장→추가 0.
T22 무효 XP: invalid run→기여 0. 기존최고레벨을내리지않음. 무효관련보상/체력정책은D07별도.

B. 참여·인원·인증
T23 모든 크루원 생성: 크루장아닌회원도대기실생성. 생성/준비만으로하루 참여권소비없음.
T24 최대 20: 20명성공,21번째입장/동시마지막좌석경합중초과실패. 크루전체정원 30과혼동없음.
T25 같은 크루: 다른 크루회원이방/크루 ID를변조해참여·보너스·풀기여를만들지못함.
T26 하루 1회: 오늘종료후다른방/다른 크루/재로그인/앱재설치에서도새출발불가.
T27 동시출발 요청: 같은사용자가 2방동시start→정확히 1개만성공. 실패한방에기여잔여물없음.
T28 일시정지/재개: 같은 run_id, 일일 참여권/신발기여재사용없음.
T29 범위: 결정된거리기준에서 500m포함/500m초과경계. GPS정확도정책과샘플신선도반영.
T30 2분: 서버출발+120초를사용. 폰 시간변조/클라이언트타이머완료만으로확정불가.
T31 두시점: 출발통과/2분통과만포함. 출발밖→2분안인사람을자동소급포함하지않음.
T32 미인증 허용: 실제참가 6명·인증 5명→출발 6,공용 기여 6,보너스집계 5/20%. 미인증사용자의자기신발보상도가능.
T33 보너스 0~1명: 실제러너여러명인데미인증때문에eligible0/1이어도'혼자남음'으로종료하지않음.
T34 인증 변조: 일반사용자가verified필드나타인번호식별자를써서통과못함. 기존인증번호중복계정방지.
T35 SMS 제외: 새 SMS업체 SDK/키/Edge Function/OTP/번호 입력 UI/발송요청없음. 인증상태읽기와보너스분기만존재.
T36 풀 0 출발: 새로운유효참가자는신발기여후출발가능. 오늘완료인사람은 0여부와별개로출발불가.
T37 마지막 1명: 다른모든사람의명시적종료후남은 1명도서버종료. PAUSED참가자는미종료로계산.
T38 비정상 끊김: 화면닫기·백그라운드·일시적통신끊김을명시적종료로오판하지않음. timeout은D09정책검증.

C. 서버 원자성·재시도·경계
T39 중복 progress: 같은 구간/sequence를반복전송해소모·보상·XP가증가하지않음. 순서역전/지연도검증.
T40 소진 경합: 거의빈풀에여러방동시소모/새기여. 음수없음,소진시각/정산원장일치,어느방도개인fallback없음.
T41 종료 경합: 수동finish와마지막 1인자동finish동시도정산 1회. 늦은resume/progress가 ENDED를살리지않음.
T42 보상 저장 재시도: 네트워크응답유실후동일run조회/재시도→같은settlement,새지급없음.
T43 레벨 경합: 두사람동시기여로threshold넘음→누적합정확,레벨하락없음,동일레벨 업이벤트중복없음.
T44 한국 자정: UTC15:00경계에한국날짜변경. 클라이언트타임존과무관. 새 날짜풀 0/0,일일 참여권새 날짜,XP유지. 진행중세션은D05결정대로.
T45 데이터 조회 실패: null/timeout을잔량 0·참여 완료로변환하지않음.
T46 권한: 다른사용자의원장·전화번호·비공개좌표읽기/변경불가. 앱에서service_role사용없음.
T47 migration: 빈 DB전부적용,0069실제이전스키마에서업그레이드,기존데이터보존,번호충돌대응. 잘못된옛단위그대로변환없음.
T48 구버전 호환: 옛클라이언트가새크루정산을개인에너지/개인 상한경로로돌리지못함. 지원불가상태정직한표시.

필수 실제 기기 시나리오
• 서로 다른 2계정 이상으로같은 방출발→2분확인→한사람휴식→재개→한사람끝내기→마지막자동 종료.
• 테스트서버fixture로 20명/5→6명/0풀경합/미인증상태/다른 크루일일 참여권을재현. 운영데이터를가짜인증시키지않음.
• GPS를쓰는외부기기경로검증과지도레이아웃캡처를구분. 모의위치로검증했다면그사실을표시.

완료 증거
1. 변경파일·실제migration번호·RPC계약.
2. 실행한명령/환경/실패와수정내역,안돌린검증목록.
3. 규칙R01~R13과테스트T01~T64의통과/보류/해당없음매핑.
4. 실제네이티브핵심/보조화면캡처,기기크기·OS·글꼴배율.

6. 07의미정정책결정기록과미해결항목. 미해결부분이있으면전체기능완성으로보고하지않음.
