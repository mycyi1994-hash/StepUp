화면별 동작 명세
39개 PNG 시안 + 미리보기에서 이어지는 8개 상태 = 47개 화면/상태 정의.
추가 8개는 새로운 디자인이 아니라 같은 화면의 데이터/역할/종료 상태 변형이다.

공통 규칙
• 상태·숫자는 서버 snapshot의 동일 버전을 사용한다. 샘플 숫자와 클릭으로 강제 변경하는 데모를 제품 로직으로 복사하지 않는다.
• API 로딩/오류/재시도/데이터 없음은 모두 처리한다. 응답 누락을 0·미인증 확정·참여 완료·범위 밖으로 임의 변환하지 않는다.
• 출발·종료·준비의 요청 중 중복 제출을 막는다. timeout은 상태 조회로 해소하고 같은 idempotency key로 재시도한다.
• 화면 전환/Back/시트 닫기는 서버의 러닝 상태를 임의로 바꾸지 않는다. 선택값·역할·동일 run_id를 보존한다.
• 좌표 확인은 실제 위치/서버 판정이 필요하다. 시안의 '위치 다시 확인' 버튼은 성공 예시로 연결되어 있지만 제품에서는 검증 결과를 기다린다.
• 미인증자는 참여 가능하다. SMS/OTP/번호 입력/계정 인증 화면을 추가하지 않는다.
• 보상 확인 중/저장 실패 상태는 실제 확인 전 숫자를 '받은 보상'으로 표시하지 않는다.
• 시스템 권한·GPS 불량·오프라인·저장 재시도 화면은 기존 앱 부품을 같은 톤으로 연결한다. PNG 39장에 모든 네트워크 오류 조합이 따로 그려져 있다는 뜻은 아니다.
• 기본 폰트에서 390×844 기준 한 화면. 작은 화면/큰 글꼴에서는 상세 분리·접근 가능한 페이지/스크롤을 허용한다. 버튼 겹침·잘림 금지.
• 하단 주요 행동은 하나를 중심으로, 러닝의 일시정지/끝내기는 중요도 차이를 유지한다.

01. 크루 홈 [home]
참고: screenshots/home.png
진입: 크루 상세 진입 또는 크루 러닝 완료 후 돌아옴.
표시: 크루 이름·이미지·레벨·정원, 오늘 공용 체력 잔량/총량, 오늘 기여 참가자 수, 자정 리셋, 레벨 효과, 기존 채팅·모임 진입.
동작: 체력→rules, 레벨→level. 러닝 참여는 서버의 오늘 참여 상태를 확인한 뒤 활성 세션 복구 / 대기실 목록·lobby / used로 연결한다. 기록→history. 채팅은 기존 실제 채팅으로 연결한다.
상태/예외: 로딩·null과 0/0을 구분한다. 날짜가 바뀌면 서버의 현재 날짜를 다시 읽는다. 오늘 종료한 사람에게 재출발 버튼을 제공하지 않는다. 오늘 참가자 수와 특정 방의 보너스 인원은 다르다.
규칙: R01, R05, R09, R13

02. 크루 러닝 이용 안내 [rules]
참고: screenshots/rules.png
진입: 홈 체력/러닝 안내 아이콘에서 열림.
표시: 최대 내구도 기여, 분당 5 사용, 개인 소모 0, 소진 후 기록 계속, 하루 1번, 혼자 남으면 종료, 500m·2분·인증 조건, 자정 초기화.
동작: 확인·닫기·뒤로가기→열었던 부모 화면. 설명을 읽는 동안 러닝을 자동 정지하거나 종료하지 않는다. 전체 인원표→bonus, 레벨표→ladder.
상태/예외: 같은 안내를 화면마다 다르게 쓰지 않는다. 부모 화면의 데이터·역할·선택값을 보존한다.
규칙: R01, R02, R03, R05, R06, R07, R12

03. 크루 레벨과 성장 [level]
참고: screenshots/level.png
진입: 홈의 레벨 칩 또는 레벨 메뉴.
표시: 현재 레벨, 누적 유효 거리, 다음 레벨 임계값, 현재 레벨 구간 진행률, 공용 체력·보상 효과.
동작: 전체 기준 보기→ladder. 뒤로가기→부모 화면. Lv20은 다음 레벨 대신 최고 레벨을 표시한다.
상태/예외: Lv7·520km라면 450→650 구간의 70/200=35%다. 520/650을 현재 레벨 진행률로 쓰지 않는다. 무효 거리를 제외하며 자정에도 누적값을 유지한다.
규칙: R09, R10

04. 레벨 1–20 전체 기준 [ladder]
참고: screenshots/ladder.png
진입: level에서 전체 기준 탭.
표시: Lv1~20의 누적 거리, 체력 보너스, 보상 보너스 전체 표와 현재 레벨 강조.
동작: 확인·닫기→level. 작은 화면이나 큰 글꼴에서는 페이지 분할 또는 접근 가능한 목록을 사용한다.
상태/예외: 19개 승급 기준을 생략하지 않는다. Lv1은 0km·0%·0%, Lv20은 10,000km·114%·19%다.
규칙: R09, R10

05. 레벨 업 축하 [levelup]
참고: screenshots/levelup.png
진입: 서버의 새 레벨 업 이벤트 확인 후.
표시: 크루명, 이전→새 레벨, 달성 누적 거리, 체력·보상 효과 변화. 예: Lv7→8, 체력 36→42%, 보상 6→7%.
동작: 성장한 크루 보기→실제 새 레벨 상세. 시안 연결은 level-eight다. 닫기→이벤트가 발생한 부모 화면.
상태/예외: 동일 event_id를 새로고침마다 다시 재생하지 않는다. 클라이언트 예상 거리만으로 승급을 확정하지 않는다. 러닝 도중 효과 적용 시점은 D04를 따른다.
규칙: R09, R10

06. 대기실 · 5명 준비 [lobby]
참고: screenshots/lobby.png
진입: 크루 대기실 입장, 진행자 관점의 준비 중 상태.
표시: 예시 6명 중 5명 준비, 각자의 역할·준비 상태, 선택 신발 최대 내구도, 개인 소모 0, 예상 인원 보너스 20%, 한 명 더 포함되면 50%, 내 체력 기여량.
동작: 신발→shoes, 보너스→bonus, 명단→roster. 진행자 출발→실제 준비·자격 인원으로 start를 연다. 뒤로가기는 기존 대기실 나가기 정책을 따른다.
상태/예외: 입장·준비만으로 일일 참여권이나 공용 체력을 사용하지 않는다. 준비하지 않은 사람을 출발 명단에 자동 포함하지 않는다. 미인증자도 참가할 수 있으며 보너스 집계만 분리한다.
규칙: R01, R05, R07, R08, R12, R13

07. 대기실 · 6명 준비 완료 [ready]
참고: screenshots/ready.png
진입: 6명의 준비 완료가 서버에서 확인됨.
표시: 서버가 확인한 준비 인원, 보너스 대상 인원, 인원 보너스, 레벨 보상, 선택 신발의 기여량. 대상 6명·Lv7 예시는 50%+6%다.
동작: 진행자: 준비한 인원과 출발→start. 신발 변경·준비 상태 변경 시 출발 조건을 다시 검증한다.
상태/예외: 참가자 6명이 모두 보너스 대상이라는 뜻은 아니다. 미인증·위치 미확인을 반영한다. 준비 취소·이탈 이벤트를 받으면 값과 버튼을 갱신한다.
규칙: R01, R07, R08, R13

08. 참가자 · 준비하기 [member]
참고: screenshots/member.png
진입: 일반 크루원이 대기실에 입장.
표시: 본인의 미준비 상태, 실제 진행자, 선택 신발, 예상 보너스.
동작: 준비 완료 요청이 성공하면 member-ready로 이동한다. 신발·보너스·명단 상세를 열 수 있다. 일반 참가자에게 방 전체 출발 버튼을 제공하지 않는다.
상태/예외: 준비 요청 중 중복 탭을 막는다. 미인증은 준비 차단 사유가 아니다. 신발 소유 등 실제 준비 조건은 서버가 검증한다.
규칙: R05, R12, R13

09. 대기실 · 첫 참가자 [solo]
참고: screenshots/solo.png
진입: 생성 직후 등 방에 1명만 있음.
표시: 현재 참가자 1명, 크루원 대기 안내, 선택 신발과 예상 기여량, 인원 보너스 없음.
동작: 출발 버튼은 비활성 상태다. 초대·모집은 기존 기능에 연결한다. 참가자가 들어오면 실제 대기실 상태로 갱신한다.
상태/예외: 준비만으로 공용 풀이 늘지 않는다. 실제 참가자 1명과 보너스 대상 1명을 혼동하지 않는다. 여러 사람이 있으면 미인증 때문에 혼자인 상태로 처리하지 않는다.
규칙: R05, R06, R07, R13

10. 대기실 만들기 [create]
참고: screenshots/create.png
진입: 크루 홈에서 대기실 만들기 선택.
표시: 방 이름 입력, 소속 크루, 최대 20명, 500m·2분·하루 1번 안내.
동작: 대기실 열기→생성 RPC→solo 또는 실제 대기실. 취소·뒤로가기는 생성 요청을 보내지 않는다.
상태/예외: 크루원 누구나 만들 수 있다. 크루장 전용으로 제한하지 않는다. 입력 검증, 중복 제출 방지, 오류·재시도를 처리하고 입력한 방 이름을 실제로 저장한다. SMS 작업은 없다.
규칙: R05, R13

11. 함께 달릴 신발 선택 [shoes]
참고: screenshots/shoes.png
진입: 대기실의 선택 신발 줄.
표시: 보유 신발의 이름·실제 이미지·효율·착화감·현재/최대 개인 내구도·출발 시 공용 기여량과 선택 상태.
동작: 신발 탭은 임시 선택만 바꾼다. 이 신발로 준비하기→기존 선택·준비 API에 반영한 후 대기실로 돌아간다. 닫으면 임시 선택을 버리고 이전 확정값을 유지한다.
상태/예외: 현재 75/100이라도 최대 100을 사용한다. Lv7이면 136, 최대 150이면 204 기여다. 출발 시 소유·유효성을 다시 검증한다. 출발 후 신발을 바꿔 기여를 중복 적립하지 않는다.
규칙: R01, R04, R13

12. 인원 보너스 전체 표 [bonus]
참고: screenshots/bonus.png
진입: 대기실 보너스 카드 또는 상세안내.
표시: 2~20명 전체 보너스 표, 구간 중복 없음, 같은 크루·출발 500m·2분 뒤 500m·인증 조건, 20명·Lv20의 총 가산 169%.
동작: 확인·닫기→부모 화면. 표를 탭해서 실제 참가 인원이나 보너스를 바꾸지 않는다.
상태/예외: 인원 50%와 레벨 6%는 합계 56%다. UI가 인원·보상을 확정하는 도구가 되어서는 안 된다.
규칙: R07, R08, R10, R12

13. 전체 명단 · 20명 [roster]
참고: screenshots/roster.png
진입: 대기실 전체명단.
표시: 해당 방의 실제 참가자 수/정원 20명, 진행자·본인·준비 상태·보너스 집계 상태. 시안은 10명씩 두 페이지다.
동작: 이전·다음으로 전원을 확인한다. 닫기→같은 대기실. 실제 인원이 6명이면 6명만 표시한다.
상태/예외: 전체 참가 인원과 보너스 인원을 구분한다. 전화번호 자체를 공개하지 않는다. 참가자 변경 시 같은 서버 버전의 목록으로 갱신한다.
규칙: R07, R12, R13

14. 출발 전 최종 확인 [start]
참고: screenshots/start.png
진입: 진행자가 출발 선택 후 최종확인.
표시: 본인 선택 신발, 실제 출발 예정 인원, 예상 인원 보너스·레벨 보상, 내 공용 기여량, 2분 뒤 확정 안내, 하루 1번 최종 확인.
동작: 시작→원자적 start RPC 성공→기존 출발 연출→checking. 닫기·뒤로가기→원래 대기실. 서버 성공 전 러닝 상태로 이동하지 않는다.
상태/예외: 조건이 바뀌면 확인 내용을 갱신한다. 참여권 사용·신발 스냅샷·기여는 같은 트랜잭션이다. 응답 유실은 같은 키로 조회·복구한다. 미인증·현재 풀 0만으로 출발을 막지 않는다.
규칙: R01, R05, R07, R13

15. 500m 밖 · 위치 확인 [far]
참고: screenshots/far.png
진입: 출발 준비/확인에서 유효한 위치가 500m밖으로 판정됨.
표시: 범위 밖 안내, 서버 기준 거리(시안 620m), 허용 범위 500m. GPS 미확인은 별도 상태다.
동작: 위치 다시 확인→새 위치 수집→서버 재판정. 통과하면 대기실로 돌아가 출발을 다시 확인하고, 실패하면 안내를 유지한다.
상태/예외: 버튼을 누르자마자 성공으로 바꾸지 않는다. 아직 출발 전이므로 참여권·체력 기여를 소비하지 않는다. 거리 기준점은 D03에서 결정한다.
규칙: R05, R07

16. 미인증자 참여 안내 [unverified]
참고: screenshots/unverified.png
진입: 참가자 본인의 미인증 상태 또는 보너스 집계 설명.
표시: 참여 가능·보너스 인원에서만 제외 안내. 실제 참가 6명/인증 대상 5명이라면 예상 20%. 본인의 신발 보상과 체력 기여는 유지한다.
동작: 함께 달리기 준비→unverified-lobby. 닫기→부모 화면. 인증받기·문자 보내기 버튼은 만들지 않는다.
