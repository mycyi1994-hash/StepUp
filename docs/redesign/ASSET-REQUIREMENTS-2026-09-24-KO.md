# StepUp 디자인 100%를 위한 자산 전수 목록

> 후속 제작 현황(2026-09-24): 아래는 **제작 전 요구량의 기준표**다. 이후 상품 고해상도 후보 62개를 모두 모았고 기존 5개는 재사용 후보로 확인했다. 앱 적용·네이티브 시각 승인은 아직이다. 실제 제작/검사 결과는 [상품 원본 제작과 달리기 애니메이션 시험](PRODUCT-ASSET-PRODUCTION-2026-09-24-KO.md)을 본다.

기준: 2026-09-24 현재 로컬 소스와 86개 화면·상태 작업표. **이 문서는 제작 명세와 남은 일 목록이다. 제작 완료 표시가 아니다.** 사용자가 요청한 화면 우선순위와 PNG를 버튼·문구·지도로 쓰지 않는 원칙을 따른다. APK를 생성하지 않았다.

## 숫자를 먼저 바로잡기

이전에 말한 `8장`은 두 캐릭터의 한 착장 시험 분량이었고 전체 필요량이 아니다. `464개`라는 계산에는 기본 의상·기본 신발·체험용 의상·모자가 빠져 있었다. 이 값을 전체 제작량으로 사용하지 않는다.

| 구분 | 현재 확인된 범위 | 제작/확인 상태 |
|---|---:|---|
| 화면·상태 시안 | 작업표 86개 모두 초안 매핑, **현행 초안 90장** + 교체 전 참고본 13장 + 공통 부품 보드 1장 | 승인·최신 앱 비교는 86개 모두 대기. 미제작으로 확인된 **새 화면 종류는 0개** |
| 캐릭터 분리형 **논리 자산** | **556개**: 몸체 8 + 의상 72 + 모자 원본 52 + 착용 신발 424 | 등록·합성 완료 **0개**. 기존 전신과 시험본은 이 개수에 합격품으로 세지 않음 |
| 의상→모자 연결 | 72개(성별 2 × 자세 4 × 의상 9) | 위 모자 원본 52개를 참조하는 연결표. **새 그림 72개가 아님** |
| 상품 그림 | 67개 기존 후보: 신발 52 + 일반 의상 10 + 기본/체험 의상 5 | 작은 기존 원본 **62개 고해상도 재작업**; 나머지 5개는 일치·테마 검수 |
| 장면·벤치 | 장면 7개 사용 중 + 테라스 장면 후보 1개 + 프로필 벤치 1개 | 이미 있음. 사용 중인 장면의 크롭·발/좌석 접점·빛·밝은/어두운 테마 검수 대기 |
| 원본 워드마크·앱/알림 아이콘·로그인 마크·공유 로고·공통 삽화·글꼴·벡터 아이콘 | 기존 파일/코드 재사용 | 새 브랜드/버튼 PNG **0개**; 최종 화면에서 품질 확인 대기 |

`556 + 62 = 618`은 **새로 완성하거나 다시 만들어야 하는 논리 자산과 상품 컷의 현재 작업 단위**다. **618개의 PNG라는 뜻은 아니다.** 앞뒤 조각·가림 마스크·편집 원본이 한 논리 자산에 여러 파일로 붙을 수 있다. 실제 출력 파일 수는 기준 포즈의 합성 규격을 통과한 뒤에만 고정할 수 있다. 기존 전신의 활용이나 새 상품/포즈 추가가 범위를 바꿀 수 있다.

완전한 착장 표시가 필요한 상태 조합은 **성별 2 × 자세 4 × 의상 9 × 신발 53 = 3,816**이다. 3,816장의 전신 그림을 제작하자는 뜻이 아니다. 아래의 분리 자산을 합성하고, 실제 소유/체험 상태가 화면에 맞게 표시되는지 확인할 조합 수다.

## 1. 캐릭터 원본 — 556개 논리 자산의 전 행

각 파일/ID는 [ASSET-CHARACTER-REQUIREMENTS.csv](ASSET-CHARACTER-REQUIREMENTS.csv)에 **한 행씩** 있고, `NEW` 551개와 정렬이 실패한 초안을 다시 만들어야 하는 `REWORK_PILOT` 5개로 구분한다. 아래 접힘 범위까지 CSV에 모두 펼쳤다. ID는 저장 데이터 ID를 바꾸는 지시가 아니라 제작/검수 키다.

| 자산군 | 빠짐없이 포함할 변형 | 고유 원본 수 | 파일마다 필요한 표현 |
|---|---|---:|---|
| 몸체 | RUNO·LUMI × `IDLE`, `RUN`, `CHEER`, `SIT` | **8** | 얼굴·파란 눈·피부·머리·팔다리. 옷/모자/신발이 박혀 있지 않은 기준 몸체, 뒤쪽 머리/팔 및 앞쪽 머리/손의 가림 순서 |
| 착용 의상 | 두 캐릭터 × 네 자세 × `starter_hoodie`, `CLO-001`~`005`, `STUDIO-PINK`, `STUDIO-LAVENDER`, `STUDIO-OLIVE` | **72** | 상의·하의·양말 한 벌. 몸체/손 앞뒤에 지나가는 소매와 옷자락을 분리하거나 정확한 마스크 제공. 모자·신발은 포함하지 않음 |
| 모자 | RUNO는 자세마다 기본/일반 상품 공용 1종 + 체험색 3종. LUMI는 자세마다 기본 1종 + 상품별 5종 + 체험색 3종 | **52** | 챙·UP 로고·포니테일/앞머리 가림. 모자는 별도 구매 슬롯이 아니고 **선택 의상에 따라** 바뀜. [72개 연결표](ASSET-CAP-BINDINGS.csv) 참조 |
| 착용 신발 | 두 캐릭터 × 네 자세 × 기본 `SHOES-BASE` + `FIR-001`~`013`, `WAT-001`~`013`, `LIT-001`~`013`, `WND-001`~`013` | **424** | 좌우 한 켤레, 신발 형태·밑창·실제 발/양말 접점. 상품 카드용 단독 신발 컷을 발에 그대로 붙이지 않음 |

한 논리 자산은 **같은 자세의 1024×1536 기준 캔버스, 원점과 발 기준점, 투명 알파, 광원 방향, 레이어 순서**를 공유해야 한다. 필요한 앞/뒤 조각·가림 마스크·팔/머리카락/모자/양말 접합부를 자산 패키지의 필수 구성으로 검수한다. 실제로 가림이 없는 변형에는 빈 PNG를 억지로 만들지 않는다. 레이어 구성과 누락 여부를 메타정보에 기록한다. 캐릭터 그림 안에 배경·벤치·글자·버튼·발광 UI를 합치지 않는다.

기존 서기 전신 변형 100여 장과 고해상도 핑크 앉기 2장은 **현재 앱의 대체 표시/참고 원본**이다. 몸·옷·신발을 독립 교체할 수 없어 위 556개를 충족하지 않는다. `design/redesign-2026-09/assets/modular/`의 LUMI 몸체/의상/모자/신발 시험본 및 러닝 뒷모습은 정렬·가림 합성 미승인이다. 별도 `sneakers/` 32개도 앱에 등록되지 않은 초안이다. 기존 파일을 삭제하거나 새 원본으로 간주하지 않는다.

## 2. 상품 그림 — 정확한 67개 ID

[ASSET-PRODUCT-REQUIREMENTS.csv](ASSET-PRODUCT-REQUIREMENTS.csv)에 현재 경로와 조치를 모두 적었다.

- **52개 신발 카드/도감 컷:** 위 네 속성의 `001`~`013` 전부. 현재 52장 모두 **340×209px**이므로 상세·고밀도 화면용 원본 해상도 1024px 이상 투명 컷으로 다시 만든다. 단순 확대는 품질 개선으로 인정하지 않는다. 실루엣·상대 크기·테마별 알파 경계가 카탈로그와 일치해야 한다. 위 424개 착용 신발과 **다른 용도**다.
- **10개 상품 의상 컷:** RUNO `CLO-001`~`005` 5개, LUMI `LUM-CLO-001`~`005` 5개. 현재 가로 **284~308px**로, 상세/카드 확대에 맞는 원본으로 다시 만든다. LUMI 의상 컷과 모자 색은 착용 레이어와 동일해야 한다.
- **재사용 검수 5개:** RUNO/LUMI 기본 의상 상품 컷 2개, 체험용 핑크·라벤더·올리브 컷 3개(모두 1254×1254). 몸에 입힌 모습과 색/재단이 일치하고 흰/남색 바탕에서 외곽이 깨끗하면 신규 제작하지 않는다. 불일치하면 해당 ID를 재작업으로 변경한다.

## 3. 교체 배경·전경·화면별 사용처

[ASSET-SCENE-REVIEW.csv](ASSET-SCENE-REVIEW.csv)는 현재 사용하는 일곱 장면, **현재 쓰이지 않는** 테라스 장면 후보 하나와 벤치를 **파일명별**로 기록한다. 홈/프로필은 푸른 밤·새벽, 옷장은 테라스·노을, 러닝은 밤·노을, 커뮤니티는 새벽을 쓰며 보조 화면은 기존 장면 또는 색/벡터 바탕을 공유한다. 장면은 조작할 때 바뀌되 착장/텍스트 재구성으로 임의 교체되지 않아야 한다. 각 장면의 지면·발 기준점, 주요 피사체 크롭, 명암, 상단 제목/하단 버튼 가독성을 확인한다. 벤치는 프로필 배경 및 두 성별의 앉기 자세와 접점을 확인하고, 앞판이 캐릭터를 가려야 하는 구도라면 벤치 전경 조각을 분리한다. 현재 구도에는 새 전경이 확정 요구사항은 아니다.

[ASSET-SCREEN-COVERAGE.csv](ASSET-SCREEN-COVERAGE.csv)에 **86개 항목 전부**를 한 줄씩 넣고 장면/캐릭터/상품/지도/기존 삽화 사용군을 표시했다. 작업표의 장면 15개, 캐릭터 11개, 상품 15개, 실제 지도 11개 계획 행에 더해, 현재 소스에서 장면·캐릭터를 사용하는 마켓과 번개 모임 상세도 반영했다. 화면별 시안이 있다고 실제 앱의 조명·크롭·상태가 승인됐다는 뜻은 아니다.

[ASSET-MOCKUP-REVIEW.csv](ASSET-MOCKUP-REVIEW.csv)는 **현행 화면 초안 90장**, 이전 버전 13장, 공통 부품 보드 1장을 파일별로 구분한다. 이전 버전 13장은 새 화면 요구가 아니며 최종 납품에도 쓰지 않는다. 현행 초안 90장과 작업표 86항목의 수가 다른 것은 일부 항목을 여러 실제 상태로 그렸기 때문이다. 현행 초안은 모두 앱 캡처와 대조하기 전이다.

## 4. 새 비트맵을 만들지 않는 디자인 자산

- **기존 파일 전수 대조:** [ASSET-EXISTING-RESOURCES.csv](ASSET-EXISTING-RESOURCES.csv)에 앱에 포장된 이미지·벡터·글꼴 **229개 전부**를 경로별로 분류했다. 기존 전신 127, 신발 상품 52, 의상 상품 15, 장면 8, 벤치 1, 워드마크 2, 공유 로고 1, 커뮤니티 삽화 1, Google 로그인 마크 1, 런처 아이콘/설정 13, 알림 아이콘 1, 글꼴 7이다. 한 파일도 미분류 상태로 남기지 않았다. 기존 파일 수는 새 제작 수와 별개다.
- **원본 STEPUP 로고:** 앱의 투명 `logo_wordmark.png`, `logo_wordmark_on_dark.png`를 유지. `brand_logo_white_on_blue.webp`와 브랜드 원본은 다른 바탕 용도로 재사용한다. 새 로고를 생성하거나 글자로 흉내 내지 않는다.
- **앱/알림 아이콘:** 기존 `ic_launcher_foreground.png`, 적응형/밀도별 `ic_launcher` 리소스와 `ic_stat_walk.xml`을 재사용한다. [브랜드 원본](../../design/brand/stepup-app-icon.webp)과 대조하고 런처 안전 영역·밝은/어두운 바탕·알림 상태 표시 크기에서 잘림/판독성을 확인한다.
- **커뮤니티/로그인 삽화:** 기존 `community_warmup.webp`를 재사용하고 배경과 독립 배치. 게시글/모임의 인물·사진은 실제 데이터가 있을 때만 표시한다.
- **Google 로그인/러닝 공유:** 로그인 버튼의 `google_g.png`와 러닝 공유 카드의 `brand_logo_white_on_blue.webp`를 기존대로 사용한다. 둘 다 실제 결과 화면에서 대비·크롭을 확인한다.
- **글꼴과 아이콘:** 기존 Pretendard 5종·Barlow 2종, `StepUpIcons`/Material/기존 벡터·알림 아이콘을 쓴다. 86개 화면의 새 아이콘 PNG 제작은 확정 요구가 없다.
- **M01–M14, M17–M18의 버튼·탭·카드·배지·입력·팝업·피드 UI:** 색/크기/그림자/상태를 Compose와 벡터로 그린다. 기본·선택·눌림·포커스·비활성·처리 중·빈/오류/로딩·밝은/어두운 테마를 구현/검수해야 하나, 상태마다 PNG를 자르는 목록에 넣지 않는다.
- **지도:** 실제 2D 지도 타일과 GPS 경로·핀·영역의 벡터 오버레이. 시안 속 가짜 도로·마커·소유 영역을 배경 PNG로 만들지 않는다. 외부 지도 타일은 앱에 납품할 고정 이미지 원본이 아니다.

## 5. 완성 판정과 범위의 경계

이 목록은 **현재 앱 카탈로그·86개 작업표에 정의된 모든 디자인 자산 요구 ID**를 닫는다. [생성 스크립트](../../tools/build_design_asset_inventory.py)는 성별/자세/의상/신발 원본을 읽어 행을 생성하고, 카탈로그/작업표 수가 바뀌면 실패하게 했다. 포장된 시각·글꼴 파일 229개를 전부 분류했고, 현재 앱 UI 코드가 참조하는 drawable 이름 208개도 별도 대조했으며 누락 참조는 0개다.

다만 **'하나도 빠짐없음'을 새 PNG의 최종 물리적 장수로 보장할 수는 없다.** 앞/뒤 가림과 접점 조각의 수는 실제 분리 합성에서 결정된다. 이미 있는 배경·벤치·상품 5개·로고도 네이티브 화면에서 크롭/품질 검수를 통과해야 재사용 완료다. 86개 시안은 초안이며 실제 작은 화면·큰 글씨·키보드·두 테마·모든 장면/성별/착장/자세에서 검수 전이다. 검수에서 확인된 차이는 해당 행의 `NEW`/`REWORK` 상태에 추가하고, 마지막 합격 전까지 디자인 100%라고 표시하지 않는다.

스토어 제출용 실제 앱 스크린샷/홍보 이미지는 **앱 내 디자인 자산과 다른 배포 산출물**이다. 지금의 시안 PNG를 실제 앱 캡처로 대체하지 않는다. 출시 범위가 확정되면 배포 자료 목록을 별도로 닫는다.
