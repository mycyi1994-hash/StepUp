# 보유 신발 상세 v1 (2026-09-28 전달본)

사용자 전달본 "StepUp 보유 신발 상세 v1"(`design/shoe-detail-v1/` — 구현 지시서 · 먼저 보기 · 보낼말 · 흐름 · 토큰 · 장면 목록 · 예시 보유 목록,
시안 18장면 — 비교 보드 9장은 이 폴더의 `reference-*.webp`)을 앱에 적용했다. 신발 → 주요 능력치 → "이 신발 신기" 순서로 읽고,
능력치 전체와 신발 정보는 누른 뒤에 연다. 경로는 그대로다 — 신발 탭(`customize`)과 상세(`sneaker/{id}`, 신발 탭 하위 · 하단 탭 있음).

화면은 모두 Compose 로 그렸다(시안 PNG · SVG 를 붙이지 않았다). 받침 · 조명은 시안 `03-components/shoe-stage.svg` 의 도형을
그대로 옮긴 `ShoeStage`(`ui/components/ShoeDisplay.kt`)이고, 그 위의 신발은 앱에 든 실제 신발 그림이다 — 새 도감 70종은 모델 번호로,
예전 52종은 속성 × 변형으로(`sneakerArtRes`). 그림에서 보이는 부분(알파) 경계를 재어 신발 바닥을 접촉 그림자에 맞춘다.

## 장면 → 구현

| 08 다른 켤레의 상세 | 구현 | 같은 모델이라도 그 켤레(소유 id)의 번호 · 능력치 · 날짜 |

## 데이터 — 기존 값 그대로, 읽기만

| 화면 표시 | 출처 |
|---|---|
| 이름 | `Sneaker.variantLabel()` — 새 도감은 모델 번호 이름, 예전 52종은 속성 × 변형 이름. 이 앱이 모르는 모델 번호면 다른 신발 이름 대신 "신발 모델 N" |
| 신발 번호 | `mintNumber`(`#%04d`) — DB id · 체인 토큰 번호와 섞지 않는다 |
| Lv. | `level` |
| 보유 중 · 지금 신고 있어요 · 아직 없음 | `equipped` 와 목록의 착용 켤레 |
| SUP 적립 보너스 | 기존 상세와 같은 출처 — 서버 신발은 효율(`efficiency_bps ÷ 100`), 폰에만 있던 예전 신발은 `Sneaker.boostPercent`(도감 값 + (레벨 − 1) × 0.5). "+0.45%" 형식(배율 1.0045 · SUP 수량으로 쓰지 않음) |
| 에너지 절감 | `(1 − energyEfficiency) × 100` — 서버 신발은 착화감 bps, 예전 신발은 착화감 기준 최대 15%. 화면에서 새로 계산하지 않는다 |
| 행운 · 착화감 | 예전 신발의 `luck` · `comfort`(두 자리) |
| 내구도 | 예전 `durability`, 서버 `durability_pts`(내려서) — "100 / 100" |
| 등급 · 속성 | 기존 현지화 `Rarity.label()` · `Faction.label()`(속성은 예전 52종만) |
| 받은 날짜 | `acquiredAt`, 사용자 시간대, `yyyy.MM.dd` |
| 체인(추가) | `tokenId` — 없으면 "아직 체인에 없음"(발행 대기일 수 있다 — 내 정보 › 지갑 › 체인 기록), 1,000,001 이상은 "StepUp 금고에 발행됨 · 토큰 #N"(v3 금고 — `StepUpSneakersV3.FIRST_TOKEN_ID`), 그 밖은 "체인 NFT · 토큰 #N". 번호를 꾸미지 않는다 |
| 보유 켤레 수 | 목록의 켤레 수(모델 종류 수가 아니다) |
| 같은 모델 | `Sneaker.slotKey`(새 도감 "M:1101", 예전 "FIRE:EPIC:1"). 칸 대표는 신고 있는 켤레, 없으면 보관함과 같은 규칙(레벨 · 번호가 가장 큰 켤레) |

값은 `ui/screens/items/ShoeDetailModel.kt` 의 순수 함수가 정한다(`shoeStats` · `formatBonus` · `energySavingPercent` · `chainMarkOf` ·
`ownedGroups` · `resolveSelection` · `detailStateOf` · `classifyEquip`). 고르기는 늘 소유 id 로 한다 — 목록 순서(인덱스)로 고르지 않는다.

## 착용 — 기존 길 그대로

- "이 신발 신기"는 기존 `ItemsViewModel.equip(id)` → `SneakerRepository.equipOnServer(id)` 를 그대로 탄다: 서버 경제 · 서버 신발이면
  서버 `sneaker_equip` 뒤 서버 값을 다시 받고, 폰에만 있던 신발이면 `SneakerDao.equipExclusively(id)` 한 번의 UPDATE(없는 id 면 0건 —
  기존 착용 유지). 저장소 · DAO · 서버 함수는 바꾸지 않았다.
- 누르는 동안 `equipping` 으로 막아 두 번 보내지 않는다. 보내기 전에 최신 목록에서 아직 내 신발인지 다시 본다(다시 신기 포함).
- 성공 신호만으로 "신었어요"라고 하지 않는다 — 화면이 보는 목록(`owned`)에서 착용이 그 id 로 바뀔 때까지(최대 3초) 기다린 뒤 저장된
  착용을 읽어 결말을 정한다(`classifyEquip`). 기다려도 바뀌지 않으면 "확인하지 못했어요"와 함께 서버 값을 한 번 더 맞춘다 —
  시간이 지났다고 성공이나 실패로 넘기지 않는다. 11 을 띄운 뒤 목록이 그 켤레로 바뀌면 완료로 바꾼다.
- 결말은 그 상세 화면의 ViewModel(탐색 항목마다 하나)이 한 번 보여 주고 지운다 — 다시 들어오거나 앱을 다시 켜도 되풀이하지 않고,
  표시는 저장된 값을 따른다.
- 착용 변경은 SUP 를 쓰지 않고 보상을 주지 않는다. 러닝 중 변경 금지 · "다음 러닝부터" 같은 새 규칙, 지난 기록 재계산은 넣지 않았다.

| 무대 크기 | 시안은 신발 탭에서 화면 폭(390), 상세 0.88배. 앱은 신발 탭에서 목록 창 높이에 맞춰 줄이고(220dp 아래로는 줄이지 않고 스크롤), 상세는 본문 폭 |
| 신발 탭 · 상세의 등급 프레임 v8 → 받침 무대 | 시안의 낮은 받침 · 은은한 조명(사용자 보낼말 "받침 · 조명 유지"). 등급 프레임은 보관함 착용 카드 · 컬렉션 칸 · 마켓 모델 · 뽑기 결과에 그대로 있고, 등급은 신발 정보에 글자로 |
| 좌우 여백 20dp(시안 24) · 글꼴 크기 그대로 | 앱 공통 여백(`StepUpDesign.Gutter`) — 다른 화면과 맞춘다 |
| 밝은 테마 | 받침 · 칸 · 버튼 · 시트를 설정 v1 의 밝은 값으로(어두운 색으로 덮지 않음). 어두운 테마는 시안 값 |
| 보너스 · 절감 숫자 | 소수 둘째 자리까지, 끝의 0 은 한 자리만("+0.45%", "+0.4%", "7.5%", "6.0%") |
| 보유 칸 순서 | 등급 높은 순 → 최근에 받은 순. 착용을 바꿔도 칸 순서가 바뀌지 않아 돌아왔을 때 가로 목록 자리가 맞는다(시안 예시는 번호 순) |
| 시트를 닫은 뒤 포커스 | 시트는 기존 `SettingsSheet`(따로 뜨는 창)라 열리면 뒤 화면을 누를 수 없고 포커스가 시트로 옮겨 간다. 닫으면 플랫폼이 이전 창으로 돌려준다 — 특정 버튼으로 옮기는 코드는 넣지 않았다 |
| 첫 신발 · 동기화 대기 | 첫 신발은 스플래시의 `ensureStarter` 가 먼저 준비한다. 다른 계정으로 바꿔 서버 사본을 새로 받는 동안(기존 `clearCopy` 뒤)에는 빈 목록이 잠깐 보일 수 있다 — 동기화 동작은 바꾸지 않았다 |

## 미확정 — 그림 매핑

시안 일러스트 세 켤레(시티 스프린트 · 새벽 강변 · 나이트 트랙)와 앱 도감(새 70종 · 예전 52종)의 대응은 정해지지 않았다. 그 그림 · 이름을
앱에 넣지 않았고, 기존 식별자(`slotKey` · `modelId`)와 기존 그림을 그대로 쓴다. 시안의 예시 이름 · 번호 · 능력치(`sample-inventory.json`)도
앱 데이터 · DB 에 넣지 않았다 — `ShoeDetailDesignTest` 의 장면 캡처 안에만 예시 번호(#0001 ~ #0004) · 능력치가 있다(신발 그림 · 이름은 실제 도감).
