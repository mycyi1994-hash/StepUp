# 앱 UI 피드백 4건 (2026-11-07)

클라이언트 피드백:
1. 흰색 덧 붙히기 — 사용자 확인: 흰 테두리 · 덧칠
2. 함께 뛰기 쪽 다시 플로우짜기, 디자인 점검 — 특히 이야기탭
3. 신발 수리하는 버튼 앞으로
4. 아이템칸이 생긴다는 가정하에 디자인

## 1. 흰 테두리

공통 장치: `ui/components/StepUpUi.kt`

- `Modifier.stepUpRim(shape, kind, enabled, darkOnly)` — 테두리 종류 `RimKind` 다섯
- 색: `StepUpUiColors.rim` · `rimControl` · `rimPrimary` · `rimPhoto` · `rimGlass`
- 굵기: `RimWidth` 1dp · `PhotoRimWidth` 1.5dp
- 앱 전체 켜고 끄기: `StepUpUi.RimOn`

| 종류 | 다크 | 화이트블루 |
|---|---|---|
| Surface(카드 · 묶음 목록) | 흰색 14%, 1dp | 남색 10%, 1dp — 흰 카드 위 흰 선은 안 보임 |
| Control(회색 버튼 · 원 버튼) | 흰색 18%, 1dp | 흰색 100%, 1dp |
| Primary(파란 주 버튼) | 흰색 35%, 1.5dp | 흰색 60%, 1.5dp · 안쪽으로 2dp 들임 |
| Photo(사진 카드 · 썸네일) | 흰색 85%, 1.5dp | 흰색 90%, 1.5dp · 안쪽으로 1.5dp 들임 |
| Glass(사진 위 유리 원) | 흰색 50%, 1dp | 같음 |

넣은 곳:
- 주 · 보조 · 위험 · 작은 버튼
- 원 버튼 — 윗부분 호 대신 원 전체
- StepUpTabs — 색만 바꿈
- 사진 카드 · 주간 카드 · 장소 썸네일(다크만)
- 묶음 목록 · 입력칸(포커스 · 오류 링이 없을 때만) · 시트 면(다크만)
- 숫자 스테퍼 · 러닝 원 버튼
- 러닝 쪽: RunCard(선택 안 됐을 때) · RunModeCard · 링크 줄 · 고르기 줄 · 입력칸 · 지도 크게 보기
- 하단 탭 위 선 — 다크만 흰색 12%
- 화면에서 직접 그린 카드 — 크루 상세 · 크루 만들기 · 함께 뛰기 고르기 시트 · 베타 코드 · 지도 판 · 자유 러닝 칩 · 버튼

규칙:
- 비활성은 선 없음.
- 이미 테두리가 있던 곳은 덧대지 않고 바꾼다.
- 구분선은 예전 색을 지킨다(`hairline`, Material `outlineVariant`).

## 2. 함께 뛰기

- 세그먼트: 모집 중 · **이야기** · 크루 (예전: 모집 중 · 크루 · 이야기)
- 머리:
  - 연필을 뺐다.
  - 지도 원은 세그먼트에 맞는 지도를 연다(이야기는 이야기 지도).
  - 크루 채팅 원은 가입 · 운영 중인 크루가 있을 때만 보인다.
- 쓰기는 세그먼트마다 아래 주 버튼 하나:
  - 모집 중 「함께 뛰기 만들기」
  - 이야기 「이야기 쓰기」 — 글이 있어도 늘 있다. 빈 목록이면 「첫 이야기 남기기」, 실패면 「다시 불러오기」.
  - 크루 「크루 모집하기」
- 이야기 목록 위:
  - 지역 줄을 누르면 범위 시트가 열린다(예전엔 끊겨 있었다). 시트 안에 「지역 변경」이 있다.
  - 겹치던 「지도 보기」 링크는 뺐다.
- 크루 밖 글쓰기는 번개러닝만 된다. 자유 · 꿀팁은 크루 게시판에서 쓴다.
  - 예전에는 장소 없는 자유 글이 이야기 탭 맨 아래로 떨어졌다.
  - 「모두 보기」 아래 버튼은 「번개러닝 모집」이다.
- 크루 칸:
  - 맨 위 「내 크루」, 그 아래 「크루 찾기」 — 내 크루는 찾기 목록에 다시 넣지 않는다.
  - 목록 끝 「번개 모임 · 같이 달리기 보기」 줄을 뺐다.
  - 명함은 카드 전체 하나만 누른다.
- 「모두 보기」:
  - 번개 카드는 모집 중과 같은 줄이다. 참가는 상세에서만 한다.
  - 지도 카드는 머리 지도 원으로 바꿨다.
  - 이니셜 원은 뺐다.

안 한 것:
- 이야기 목록 위 「어제 5.2km — 이야기로 남기기」 줄 — 목록에서 러닝 기록을 새로 읽어야 해서 작은 수정이 아니다. 글쓰기 화면은 지금도 최근 러닝을 붙인다.
- 쓰이지 않는 `CommunityTab.CREW` 갈래와 `TogetherTab.kt`는 지우지 않았다.

## 3. 신발 수리

- 기준 함수 (`ShoeDetailModel.kt`):
  - `repairUrgent` — 다 닳음, 또는 보상 받을 시간이 10분보다 적음. 출발 전 점검과 같은 기준.
  - `repairable` — 남은 내구도가 최대보다 적음.
- 신발 탭:
  - 보조 버튼 「보관함」을 「수리하기」로 바꿨다. 그 화면에서 바로 수리 시트가 열린다.
  - 급하면 파랗게 강조한다.
  - 결과 모르는 강화가 이 신발을 잡고 있으면 막는다.
  - 보관함은 위 글자 탭으로 간다.
- 신발 상세:
  - 내구도 칸 옆에 「수리하기」(`shoe-durability-repair`)를 두었다.
  - 신고 있는 신발이 닳았으면, 눌리지 않던 「지금 신고 있어요」 대신 주 버튼이 「수리하기」(`detail-primary-repair`)다. 신고 있다는 표시는 이름 아래 한 줄로 옮겼다.
  - 「신발 관리」 묶음의 수리 줄은 뺐다. ⋯ 시트의 수리는 그대로다.

## 4. 아이템칸

- 위치: 신발 상세 — 능력치 · 수리 → **아이템칸** → 신발 관리(포인트 · 판매 · 기록)
- 부품: `ui/screens/items/ShoeItemSlots.kt` — `ItemSlots.OPEN = false`, 칸 셋
- 모양:
  - 제목 「아이템칸」 + 보조 글자 「곧 열려요」(배지 아님)
  - 정사각 칸 셋 — 점선 테두리 · 자물쇠 · 흐림
  - 설명 한 줄. 누르면 안내 토스트만 뜬다.
- 서버에 칸 · 아이템 개념이 없어 아이템 · 숫자를 그리지 않는다. 데모 모드도 같다.
- 열 때: 서버 계약(칸 수 · 해금 · 장착)을 정하고 `OPEN` 을 켜서 값을 받아 그린다. 신발 탭 · 출발 전 점검에는 그때 한 줄만 더한다.
- 문구는 `res/values*/item_slots.xml` 네 언어.
