# StepUp 화면 디자인 검수 — 1차

기준: 2026-09-24 로컬 작업 트리. 이번 검수는 **화면·공통 UI와 기존 배경**에 한정한다. 사용자가 후순위로 정한 캐릭터 부위·의상·신발의 전체 조합 제작은 제외한다. APK/에뮬레이터 캡처를 만들지 않았으므로 이 문서는 **시안 대 소스 검수**이며 실제 앱 화면 합격 판정이 아니다.

## 검수 범위와 통과한 대조

- [화면별 대조표](ASSET-SCREEN-COVERAGE.csv)의 86개 작업 ID 전부가 [현행 시안 목록](ASSET-MOCKUP-REVIEW.csv)의 실제 PNG 행에 연결된다. 현행 시안 90장, 교체 전 참고본 13장, 공통 부품 보드 1장을 구별했다. `ASSET-SCREEN-COVERAGE.csv`의 `mockup_files` 열에서 각 ID가 참조하는 실제 파일을 바로 찾을 수 있다.
- 직접 열어 본 대표 시안 8개: [홈](../../design/redesign-2026-09/concepts/03-home.png), [러닝 중](../../design/redesign-2026-09/concepts/04-running.png), [커뮤니티](../../design/redesign-2026-09/concepts/05-community.png), [옷장](../../design/redesign-2026-09/concepts/06-wardrobe.png), [내 정보](../../design/redesign-2026-09/concepts/08-profile.png), [러닝 결과](../../design/redesign-2026-09/screens/11-running-result.png), [로그인](../../design/redesign-2026-09/screens/59-login.png), [코스 지도](../../design/redesign-2026-09/screens/76-courses-select-map.png).
- 홈은 캐릭터 무대와 고정된 러닝 시작 버튼을 분리하고, 옷장은 배경/캐릭터/실제 선택 UI 및 3열 목록을 분리한다. 커뮤니티는 예시 모임을 실제 데이터로 표시하지 않으며 빈 상태가 있다. 코스 선택은 실제 `LiveRouteMap`을 사용한다. 이 항목들은 **소스 구조 확인**이며 크롭·가독성·터치 품질의 네이티브 합격은 아니다.
- 디자인 계약 검사: **33개 라우트**, 공통 헤더/탭/로고 역할 통과. 문자열 검사 통과. 기존 경험 자산 검사 통과. 현재 UI에서 참조하는 drawable 208개 중 누락 0개.

## 발견 사항 — 중요도순

| 중요도 | 화면 | 확인한 차이·위험 | 완료 조건 |
|---|---|---|---|
| 차단 | 전체 | 이 작업 트리로 컴파일·실행한 화면 캡처가 없다. 로컬 Android SDK/JDK도 확인되지 않았다. 시안이나 과거 버전 캡처로 지금의 크롭, 테마, 큰 글씨, 버튼 겹침을 합격 처리할 수 없다. | 사용자가 요청한 통합 확인 시점에 **같은 소스 revision**의 320dp/보통 폰, 두 테마, 큰 글씨 캡처와 버튼 동작을 대조한다. 그 전까지 86개 `native_visual_review`는 `PENDING`이다. |
| 중요 | 러닝 결과 `screen-35` | [시안](../../design/redesign-2026-09/screens/11-running-result.png)은 큰 캐릭터 뒤에 거리·시간·페이스 한 패널을 두고 완료/공유를 함께 보여 준다. 현재 `FinishCard`는 보상 상태 카드 → 작은 캐릭터 → 기록 카드 → 잔액 카드 → 공유 순서이고 완료 버튼은 화면 아래에 고정된다. 실제 첫 화면에서 **운동 기록이 아래로 밀리는지** 확인이 필요하다. 보상 미확정 문구 자체는 진실하게 유지해야 한다. | 네이티브 첫 화면에서 거리·시간·페이스가 읽히는지 확인하고, 필요하면 기록을 앞당기거나 패널을 합친다. 완료 버튼 고정과 SUP 확인 중/거절 상태는 유지한다. |
| 중요 | 로그인 `screen-24` | [시안](../../design/redesign-2026-09/screens/59-login.png)은 인간 러너 둘을 크게 보여 주지만, 현재 로그인 화면은 세 RUNO/LUMI 캐릭터의 `community_warmup.webp`를 사용한다. 두 원본이 다른 브랜드 인상을 주므로 현행 시안이 앱의 RUNO/LUMI 방향과 어긋난다. | 기존 캐릭터 원본을 재사용해 로그인 시안을 앱의 RUNO/LUMI 방향으로 교정하고, 실제 캡처에서 로고/인물/버튼 크롭을 대조한다. 새 캐릭터 이미지 생성은 필요하지 않다. |
| 확인 | 장면 7개 | 실제 사용 중인 배경은 모두 약 851–853×1844–1847px이다. 1080×2400 화면에서 전체 화면에 맞추면 대략 1.3배 확대될 수 있다. 현재 해상도만으로 품질 불합격이라고 단정할 수 없지만 큰 기기에서 선명도를 확인해야 한다. | 홈·옷장·러닝·프로필 배경 전환별 실제 캡처에서 흐림, 발 접점, 상단 로고와 하단 조작 대비를 확인한다. 문제가 보인 자산만 고해상도 재작업 목록에 추가한다. |

러닝 시안의 뒤에서 본 포즈와 현재 장비에 맞는 캐릭터 그림의 차이는 사용자가 **후속 단계로 미룬 캐릭터 자산 범위**에 기록되어 있다. 이번 화면 UI 검수의 합격 수에 포함하지 않는다. 지도 시안의 타일과 좌표·핀은 표시 예시이고 실제 앱에서는 지도 데이터가 달라질 수 있으므로 픽셀 일치 대상으로 보지 않는다.

## 다음 검수 묶음

1. 앱 캡처 없이 진행 가능한 범위: 90개 현행 시안의 상태/문구와 실제 화면 코드 연결, 86개 작업 항목의 공통 버튼·시트·빈/오류 상태 대조. 차이를 화면별로 남긴다.
2. 통합 확인 시점: 동일 revision을 컴파일한 뒤 홈→러닝→옷장→커뮤니티→내 정보, 시작/로그인/지도/결과, 작은 화면·큰 글씨·두 테마를 실제 캡처와 터치로 확인한다. 이때까지 디자인 100%나 APK 최종본으로 표시하지 않는다.

검증 명령은 `py tools/check_design_contract.py`, `py scripts/check-strings.py`, `py tools/check_experience_assets.py`, `py tools/build_design_asset_inventory.py`를 사용했다. 모두 통과했다. APK/AAB·CI 빌드·푸시·새 이미지 생성은 하지 않았다.
