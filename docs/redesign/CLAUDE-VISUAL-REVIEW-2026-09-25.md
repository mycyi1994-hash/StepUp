# StepUp 캐릭터 제거 Android 리디자인 시각 리뷰

**판정: 변경 요청.** 해결이 필요한 문제는 네 가지로 좁혀집니다. 대형 글꼴에서 하단 메뉴 이름이 단어 중간에서 줄바꿈되는 문제, 360dp 러닝 화면의 통계 세로 배치 문제, 프로필 상단 영역의 높이, 비로그인 안내가 모임 콘텐츠를 가리는 문제입니다. 모두 레이아웃만 고치면 되고 방향 전환은 필요 없습니다. 기록 중심 홈, 배경 이미지와 네이티브 컨트롤 분리, 실제 GPS 지도, 캐릭터·옷장 제거는 캡처에서 잘 지켜졌습니다.

이전 체크포인트의 홈 배너 글자·컨트롤 겹침은 이번 원본(`ref-390-normal-00-home.png`, `ref-390-large-00-home.png`)에서 **해결된 것을 확인**했습니다. 문구는 좌하단에 있고 화살표는 상단 모서리에 있어 서로 겹치지 않습니다.

## 발견 사항

### P1-1. 대형 글꼴에서 하단 메뉴 "커뮤니티"가 "커뮤니 / 티"로 끊김 (사용성 결함)
- **캡처:** `captures/api35/ref-390-large-00-home.png`, `-05-community.png`, `-06-profile.png`
- **보이는 것:** 390dp·대형 글꼴에서 "커뮤니티"가 음절 중간에서 두 줄로 나뉩니다. 모든 탭의 이름 높이가 두 줄 기준으로 맞춰져 메뉴 바가 높아지고 본문 영역이 줄어듭니다.
- **원인 (소스로 확인):** `source/ui/StepUpRoot.kt:785` 탭 너비는 `maxWidth / 6 - 8dp`(약 57dp)입니다. `StepUpRoot.kt:786-792`는 가장 높은 이름을 기준으로 모든 탭 이름 높이를 맞추고, `StepUpRoot.kt:924`는 `softWrap = true`입니다. 가운데 뽑기 이름만 `maxLines = 1`(`StepUpRoot.kt:881`)입니다.
- **최소 수정:** `NavTab` 이름을 `maxLines = 1`로 바꿉니다. 이미 있는 `measurer`로 한 줄에 맞는 글자 크기를 구하고, 하한(예: 11sp)을 둔 채 줄여서 적용합니다. 탭 구성, 라우트, 선택 표시는 그대로 둡니다.
- **통과 기준:** 390dp·대형 글꼴에서 다섯 탭 이름이 모두 한 줄이고, 메뉴 바 높이가 기본 글꼴 대비 크게 늘지 않아야 합니다.

### P1-2. 360dp 러닝 중 화면에서 통계가 세로로 쌓여 지도가 가려짐 (사용성 결함)
- **캡처:** `captures/api35/ref-360-normal-03-run_active.png`. 비교용: `ref-390-normal-03-run_active.png`
- **보이는 것:**
  - 390dp에서는 거리와 평균 페이스가 2열로 나옵니다.
  - 360dp에서는 "거리 / 3.20 / km / 평균 페이스 / 7'35"" 다섯 줄로 쌓입니다.
  - 지도는 아래쪽이 일시정지 버튼 위에서 평평하게 잘리고, 아래 둥근 모서리와 지도 출처 표기(© MapTiler)가 보이지 않습니다.
- **원인 (소스로 확인):** `source/ui/screens/walk/WalkScreen.kt:1220` 조건이 `maxWidth < 340.dp`입니다. 화면 폭 360dp에서 좌우 여백을 빼면 약 320dp라서 기본 글꼴에서도 세로 배치가 됩니다. 여기에 고정 높이 `WalkScreen.kt:345` `height(280.dp)`가 스크롤 영역 안에 있어 지도가 잘립니다.
- **최소 수정:** 폭 기준을 낮춥니다(예: 300dp). 세로 배치는 글꼴 배율이 클 때(`fontScale > 1.25f`)만 유지합니다. 같은 조건이 러닝 완료 카드(`WalkScreen.kt:1100`)에도 있으니 함께 맞춥니다. 대형 글꼴에서 세로로 쌓이는 것은 허용된 반응형 동작으로 봅니다.
- **통과 기준:** 360dp·기본 글꼴에서 거리와 페이스가 2열이고, 지도 네 모서리와 출처 표기가 스크롤 없이 보여야 합니다.

### P2-1. 프로필 상단 신원 영역이 너무 높아 기록이 뒤로 밀림 (시안과 다름 + 사용성)
- **캡처:** `captures/api35/ref-390-normal-06-profile.png`, `ref-390-large-06-profile.png`. 시안: `references/07-profile.png`
- **보이는 것:**
  - 설정 버튼, 아바타(76dp), 이름 줄, 인사말이 세로로 이어져 390dp 화면 높이의 약 40%를 차지합니다.
  - "최근 러닝 기록" 카드는 화면 약 2/3 지점에서 시작합니다.
  - 대형 글꼴에서는 카드 본문이 하단 메뉴 아래로 잘립니다.
  - 시안은 아바타와 이름을 가로 한 줄에 둔 좁은 헤더입니다.
- **원인 (소스로 확인):** `source/ui/screens/profile/ProfileScreen.kt:1053-1060`에서 설정 버튼이 한 줄을 통째로 차지합니다. `ProfileScreen.kt:1048-1077`은 모든 요소를 가운데 세로로 쌓습니다.
- **최소 수정:** 설정 버튼을 아바타·이름 줄과 같은 행 오른쪽에 둡니다. 가능하면 아바타·이름을 가로로 배치합니다(`ProfileHeader`, `ProfileScreen.kt:378`에 이미 가로 배치 패턴이 있음). 편집·설정의 이동 대상은 바꾸지 않습니다.
- **통과 기준:** 390dp·기본 글꼴에서 "최근 러닝 기록" 카드의 제목과 첫 줄이 스크롤 없이 화면 절반 부근 안에 보여야 합니다.

### P2-2. "최근 러닝 기록"이 카드 제목과 아래 목록 행에 두 번 나옴 (사용성, 소스로 확인)
- **캡처:** `captures/api35/ref-390-normal-06-profile.png`
- **보이는 것:** 카드 제목과 바로 아래 목록 행이 같은 문구이고, 둘 다 같은 분석 화면으로 이동합니다.
- **원인:** `ProfileScreen.kt:306`(`RecentRunsCard`, 제목은 `:1195` `me_recent_runs`)과 `ProfileScreen.kt:311`(`QuietListRow` 이름 `me_recent_runs`, `onOpenAnalytics`)이 겹칩니다.
- **최소 수정:** 목록 행 이름을 역할에 맞게 바꿉니다(예: "활동 기록"). 또는 카드의 "전체 보기"가 같은 곳으로 가므로 행을 뺍니다. 이동 대상은 유지합니다. 행을 뺄지는 제품 판단이 필요합니다.
- **통과 기준:** 프로필 한 화면 안에 같은 문구의 이동 항목이 하나만 있어야 합니다.

### P2-3. 비로그인 안내 카드가 모임 콘텐츠를 밀어내고, 고정 버튼이 보이지 않는 모임을 가리킴 (사용성)
- **캡처:** `captures/api35/ref-390-normal-05-community.png`, `ref-390-large-05-community.png`
- **보이는 것:**
  - **390dp·기본 글꼴:** 안내 카드(아이콘 + 문구 + 버튼)가 모임 카드 위에서 큰 면적을 차지하고, 모임 카드 아래쪽은 고정 버튼 뒤로 잘립니다.
  - **대형 글꼴:** 모임 제목 "Tonight 7PM · 5K by the"가 위쪽 절반만 보이는 채 잘립니다. 그 상태에서 "모임 자세히 보기" 버튼만 크게 보여, 버튼이 무엇을 여는지 알 수 없습니다.
- **원인:** `source/ui/screens/community/TogetherTab.kt:62-63`에서 `BoardSyncCard`가 목록 맨 위에 옵니다. `TogetherTab.kt:99-105`의 대표 모임 버튼은 목록 밖에 고정됩니다. `BoardSyncCard` 정의는 스냅샷에 없어 크기 원인은 확인하지 못했습니다.
- **최소 수정:** 비로그인 상태의 안내를 한 줄 인라인 배너(아이콘 + 짧은 문구 + 텍스트 버튼)로 줄이거나 모임 목록 아래로 옮깁니다. 로그인 처리 동작은 그대로 둡니다.
- **통과 기준:** 390dp 기본·대형 글꼴 모두에서 첫 모임 카드의 제목 전체가 고정 버튼 위에 보여야 합니다.
- **불확실:** 처음부터 로그인하지 않은 사용자에게 "다시 로그인" 문구가 맞는지는 `BoardSyncState`가 비로그인과 세션 만료를 구분하는지에 달려 있어 확인하지 못했습니다. 이 캡처는 비로그인 상태와 테스트 게시물을 합친 것이라 로그인 흐름 검증으로 보지 않습니다.

### P3-1. 홈 배너 화살표가 이미지 모서리에 맞붙어 있음 (다듬기, 불확실)
- **캡처:** `captures/api35/ref-390-normal-00-home.png`
- **보이는 것:** 좌우 화살표 원이 배너 위쪽 모서리에 바짝 붙어 둥근 모서리를 덮습니다. 글자와 겹치지는 않습니다.
- **최소 수정:** 화살표를 배너 안쪽으로 약 8~12dp 들이거나, 세로로 가운데 정렬합니다.
- **통과 기준:** 화살표 원과 배너 가장자리 사이에 여백이 보여야 합니다.
- **불확실:** 소스 줄 번호는 확인하지 않았고 시각적 판단만 있습니다.

## 허용된 반응형 동작 / 결함 아님
- 대형 글꼴 러닝 화면의 세로 통계 배치 (`fontScale > 1.25f`)
- 대형 글꼴 홈의 거리·운동 시간 줄이 스크롤 아래로 내려감
- 뽑기 설정이 없어서 비활성화된 뽑기 버튼
- 러닝 집중 화면에 공통 헤더와 하단 메뉴가 없음
- 목업 수치 불일치와 테스트용 기록·경로·게시물 (홈의 "9.8 km / 00:00" 조합 포함)
- 가운데 뽑기 이름이 다른 탭보다 낮게 놓이는 것은 시안과 같습니다
