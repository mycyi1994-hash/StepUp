# 쉬운 글쓰기 — 상황별 추가 지시

사용자가 고른 이전 2번 이미지의 코스 첨부·장소·문구·본문 구성을 유지한다. 이번 시안은 그 구조를 사용자 상태에 따라 바꾼 것이다. 크루 모집은 작업 범위에 다시 넣지 않는다.

기본 원칙은 **코스 첨부의 가능 여부와 일반 글쓰기 가능 여부를 분리**하는 것이다. 최근 코스가 없거나 기록 조회가 실패해도 공개 장소와 본문이 있으면 일반 글을 쓸 수 있다. 불가능한 버튼을 늘어놓는 대신 해당 상황에 쓸 수 있는 행동을 보여준다.

## 상태별 동작

| 상태 | 판별 근거 | 코스·기록 영역 | 다음 행동 |
|---|---|---|---|
| 앱에 완료 기록이 한 번도 없음 | 서버 조회 성공, 전체 완료 수 0, 진행 중 세션 없음 | 아직 러닝 기록이 없어요 | 일반 글 작성 유지, 선택적으로 첫 러닝 시작 |
| 오래된 기록만 있음 | 전체 완료 수 > 0, 첨부 가능한 기록 수 0 | 마지막 완료 날짜와 기간 제한 | 지난 기록 보기 / 새 러닝 시작 / 일반 글 작성 |
| 오늘~3일 전 완료 기록 있음 | 소유권·완료 상태·날짜 조건 충족 | 코스·거리·시간 표시 | 코스 첨부 후 게시 |
| 초안의 첨부가 기간을 넘김 | 초안 재개 또는 게시 시 첨부 재검증 | 기존 글·장소 보존, 첨부 해결 안내 | 다른 기록 고르기 / 코스만 빼기 |
| 유효한 기록에 GPS 경로 없음 | 기록 데이터 정상, 경로 없음 | 실제 거리·시간만 공유 | 장소 직접 선택 후 기록 요약으로 게시 |
| 기록 조회 실패 | API 실패·오프라인 | 실패 안내와 재시도 | 일반 글은 작성 가능 |
| 현재 위치 사용 불가 | 위치 권한 거부·위치 기능 꺼짐을 확인 | 수동 장소 선택 경로 | 장소 이름 검색 / 지도에서 선택 / 설정 열기 |
| 게시 실패 | 게시 요청 실패 | 첨부·장소·본문을 보존 | 다시 올리기 |

위 8개가 개별 이미지로 제공된다. 아래 추가 상태는 동작 정의이며 이번 패키지에서 별도 화면으로 그리지는 않았다.

- **최초 기록 조회 중:** 조회 중 표시나 작은 로딩 상태를 사용한다. 아직 결과가 없다는 이유로 처음 사용자 또는 오래된 기록 사용자로 분류하지 않는다. 기존 유효 첨부·본문을 지우지 않는다.
- **러닝 진행 중:** 진행 중인 코스는 아직 첨부할 수 없다. 러닝 화면으로 돌아가 완료할 수 있게 하고, 글쓰기 초안을 보존한다.
- **최근 장소가 없음:** 최근 장소 버튼을 빼고 내 주변 / 직접 검색을 제공한다. 빈 목록을 먼저 열게 만들지 않는다.
- **필터를 고른 날짜만 비어 있음:** 해당 날짜의 기록 없음과 전체 기간의 기록 없음을 구분한다. 전체 버튼으로 되돌아갈 수 있다.

## 올리기 활성화 규칙

공개 장소가 선택되어 있고 공백이 아닌 본문 또는 유효한 공유 기록이 있어야 한다. 유효한 기록만 선택한 경우에는 실제 기록에 근거한 기본 문장을 만들어 사용자가 직접 길게 쓰지 않아도 된다.

첨부가 만료되어 해결되지 않은 상태, 다른 계정 기록, 유효하지 않은 기록은 게시 전에 교체 또는 첨부 제거가 필요하다. 코스가 아예 없는 일반 글까지 막지 않는다. 게시 중에는 중복 요청을 차단한다.

처음 사용자와 오래된 기록 사용자 시안에서 올리기가 활성화된 이유는 **이미 사용자가 장소와 문구를 고른 상태**이기 때문이다. 위치를 동의 없이 자동으로 선택하거나 예시 질문을 동의 없이 게시하지 않는다. 입력이 비었으면 올리기를 비활성화하고 입력 필요 항목을 분명하게 표시한다.

## 기간과 초안

- 사용자가 요청한 기준은 오늘·어제·2일 전·3일 전이다. 달력 날짜와 앱 기준 시간대를 사용한다. 9월 28일에는 9월 25일 기록까지 가능하고, 9월 29일에는 같은 기록이 4일 전이 되어 새 첨부로 게시할 수 없다.
- 날짜 판정은 실제 완료 시각을 기준으로 한다. 제목 수정·데이터 동기화·업로드 시각으로 기간을 갱신하지 않는다. 미래 기록과 미완료 기록을 제외한다.
- 예시의 만료 초안은 9월 25일의 2.10km 기록, 장소 마포대교 남단, 본문을 그대로 보존한다. `코스만 빼기`는 초안 첨부 연결만 제거하고 원본 러닝 기록·장소·작성 문장은 삭제하지 않는다. 이후 일반 글로 올릴 수 있다.
- 기간 초과로 이미 올라간 게시글을 숨기거나 삭제하지 않는다. 3일 제한은 새 코스 첨부 규칙이다.
- 자동 생성 문장에 날짜가 필요하면 9월 25일처럼 고정 날짜를 사용해 초안을 나중에 열어도 사실이 달라지지 않게 한다. 사용자가 쓴 문장을 다시 쓰거나 상대 날짜를 조용히 변경하지 않는다.

## 문구와 장소 버튼

- 처음 사용자: 러닝을 시작해요 / 어디서 뛸까요? / 신발이 궁금해요 / 궁금한 게 있어요.
- 오래 쉰 사용자: 다시 달려보려고요 / 지난 러닝 이야기 / 추천하고 싶어요 / 궁금한 게 있어요.
- 최근 기록 사용자: 완주했어요! / 천천히 달렸어요 / 이 코스 추천해요 / 러닝이 궁금해요.
- 문구는 편집 가능한 시작점이다. 계정 기록이 없다는 사실을 실제 평생 러닝 경험이 없다는 단정으로 사용하지 않는다. 사용자 작성 문장은 항상 우선하며 문구를 중복 삽입하거나 덮어쓰지 않는다.
- 코스 주변은 사용할 수 있는 경로가 있을 때만 표시한다. 최근 장소는 저장된 최근 공개 장소가 있을 때만 표시한다. 경로가 없는 경우 현재 위치 또는 직접 장소 검색으로 선택할 수 있다.
- 기록 요약 공유에는 가짜 코스 그림을 만들지 않는다. 장소까지의 거리와 실제 러닝 거리를 구분한다.

## 데이터 판단과 실패 복구

현재 조회 기간에 결과가 없다는 사실만으로 전체 기록이 한 번도 없다고 판단하지 않는다. 전체 완료 수 또는 마지막 완료 시각 등 실제 판별 가능한 데이터가 필요하다. 그 정보가 없으면 중립적으로 최근 첨부 가능한 기록이 없다는 상태만 보여준다.

기록을 가져오는 요청이 실패했을 때 기존 첨부를 삭제하거나, 새로 선택한 다른 계정의 기록으로 대체하지 않는다. 사용자가 작성한 본문·장소는 항상 별도로 보존한다. 첫 러닝 시작과 지난 기록 보기를 누르면 초안을 저장한 후 해당 기존 앱 화면으로 이동하고 돌아왔을 때 복원한다.

GPS가 없는 러닝의 거리·시간 공유는 실제 서버 데이터에 값이 있을 때만 가능하다. 원본 필드가 없으면 통계를 만들어내지 않는다. 커뮤니티 API의 요약 기록 첨부 지원 여부를 확인한다.

게시 실패는 실제 실패와 결과 불확실을 구분한다. 결과 불확실 시 재조회 또는 멱등 요청 키를 사용해 중복 글 생성을 피한다. 서버 성공 후에만 작성 내용을 정리하고 목록으로 이동한다.

## 구현·파일 범위

앞선 `StepUp-러닝이야기-코스첨부-쉬운글쓰기.zip`의 기본 흐름에 이 상황 분기를 추가한다. 이번 자료가 충돌하는 경우 이번 상태 정의가 우선이다. 제공 파일은 PNG·편집 SVG·상태 명세이며 실제 앱 동작을 구현한 결과가 아니다. Figma Auto Layout과 프로토타입 연결은 별도 작업이다.

390×844를 기준으로 그렸으며 안전 영역·키보드·스크롤·큰 글꼴을 실제 앱에서 확인해야 한다. 날짜 경계와 초안 보존, 게시 조건, 기록 없음과 조회 실패 구분, 권한 없는 장소 선택을 우선 검증한다.
