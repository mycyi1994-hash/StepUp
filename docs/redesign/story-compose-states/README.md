# 러닝 이야기 글쓰기 — 쉬운 글쓰기 상황별 (2026-09-28)

사용자 전달본 **"StepUp — 쉬운 글쓰기 상황별 시안"**(8개 상황 · 비교 보드 4장 · 분리 부품 8개 · 지시서 · 상태 명세)을
동네 이야기 글쓰기(`StoryComposeScreen`)에 구현했다. 지시서 · 명세 원문은 `handoff/`, 시안은 `reference/`(390px로 줄임).

- 기본 원칙 그대로 **코스 첨부의 가능 여부와 일반 글쓰기 가능 여부를 나눴다.** 최근 코스가 없거나 기록 조회가 실패해도
  공개 장소와 본문이 있으면 올릴 수 있다. 크루 모집은 넣지 않았다.
- 지시서가 기본 흐름으로 가리키는 `StepUp-러닝이야기-코스첨부-쉬운글쓰기.zip`(사용자가 고른 이전 2번 화면)은 이번에 전달되지
  않았다. 여덟 시안이 2번 화면의 구성(기록 칸 · 장소 · 한 줄 이야기 · 본문 · 올리기)을 모두 보여 주므로 그 구성을 그대로 따랐고,
  시안에 그려지지 않은 조각(기록 고르기 시트 · 상세와 목록의 러닝 표시)은 같은 색 · 크기로 만들었다. 원본이 오면 맞춰 고친다.

## 서버 계약 (`supabase/migrations/0046_story_runs.sql`)

| 항목 | 내용 |
|---|---|

| 쓰기 | `story_create(…, p_run, p_client_key)` — 거리 · 시간 · 코스 그림(64점)은 서버 기록에서 옮겨 적는다(앱 숫자를 믿지 않는다). 경로 없는 러닝은 거리 · 시간만 |

## 지킨 규칙

- **3일**: 오늘 · 어제 · 2일 전 · 3일 전, 한국 날짜(서버의 하루와 같다), 실제 완료 시각 기준. 제목 수정 · 동기화 · 업로드 시각으로 늘리지 않는다.
  기간 초과로 이미 올라간 글을 숨기거나 지우지 않는다 — 고칠 때도 같은 기록이면 그대로.
- **올리기**: 공개 장소 + (공백 아닌 본문 또는 유효한 기록). 기록만 붙였으면 기록 문장으로 올린다. 만료 · 붙일 수 없는 첨부는 바꾸거나
  빼야 한다. 올리는 동안 다시 누를 수 없다. 서버 성공 뒤에만 임시저장을 지우고 목록으로 간다.
- **문구**: 편집 가능한 시작점이다. 본문이 비었거나 앱이 넣은 글 그대로일 때만 바꾸고, 사용자가 쓴 글은 덮어쓰지 않고 한 줄 아래 붙인다.
  같은 문구는 두 번 넣지 않는다. 계정 기록이 없다는 것으로 "평생 처음"이라 단정하지 않는다 — 서버가 0이어도 이 폰에 러닝이 있으면 "처음" 카드를 쓰지 않는다.
- **기록 문장**: 날짜는 "9월 25일"처럼 고정 날짜로 만든다(나중에 열어도 사실이 바뀌지 않게). 장소 이름은 앞 낱말만("마포대교 남단" → "마포대교").
  사용자가 고친 뒤로는 장소 · 기록을 바꿔도 문장을 조용히 바꾸지 않는다.
- **장소**: 위치를 동의 없이 고르지 않는다 — 목록이 새 글에 "300m 안 글 장소"를 미리 붙이던 것을 없앴다(목록에서 직접 고른 장소를 보고 있을 때만 그곳).
  코스 주변은 유효한 경로가 붙었을 때만(코스의 처음 · 가운데 · 끝 자리 이름 + 곁 400m 의 글 장소), 최근 장소는 이 계정이 글에 붙였던 공개 장소가 있을 때만.
- **이동**: 첫 러닝 시작 · 러닝 시작 · 지난 기록 보기는 쓰던 글을 먼저 저장하고 기존 화면(러닝 시작 메뉴 · 내 러닝 기록)으로 간다. 뒤로 오면 그대로,
  새로 열면 "작성하던 글이 있어요"로 이어 쓴다.
- **조회 실패 ≠ 기록 없음**: 실패 카드와 다시 불러오기를 두고, 붙여 둔 첨부 · 본문 · 장소를 지우지 않는다. 다시 받기에 실패해도 앞서 받은 결과를 둔다.

## 시안과 다르게 한 것

1. 05 시안의 본문 "오늘 3.24km 달렸어요." — 지시서 규칙(자동 문장은 고정 날짜)을 따라 "9월 28일 3.24km 달렸어요."로 만든다. 카드의 "오늘 · 3.24km · 24분 18초"는 화면 표시라 상대 날짜 그대로다.
2. 08 시안의 "삭제" — 03 과 같은 "첨부 삭제"로 맞췄다.
3. 40dp 버튼(장소 버튼 · 한 줄 이야기 · 카드 안 버튼)은 보이는 크기 40dp, 누르는 곳은 위아래 4dp 를 더한 48dp(시안 간격에서 그만큼 뺐다).
4. 머리는 앱 공통 하위 화면 머리(뒤로 · 가운데 제목)를 쓴다. 제목은 "이야기 쓰기", 고칠 때 "이야기 고치기".
5. 본문 칸의 글자 수는 900자를 넘으면 보인다(시안에는 없음, 1,000자 제한은 그대로).

## 남은 것 · 확인할 것

- **서버 적용**: 0046 은 main 에 합치면 deploy-sql 이 올린다. 그 전 서버에서는 기록 칸이 "기록을 불러오지 못했어요"로 보이고, 러닝 없는 글은
  예전 모양으로 한 번 더 보내 올라간다.
- **코스 그림 공개**: 붙인 코스는 64점으로 줄여 누구나 본다(시작 · 끝 자리 포함). 집 근처를 가리는 구역 같은 것은 정책 결정이라 넣지 않았다.
- **원본 2번 패키지**: 목록 · 상세의 러닝 표시(지금은 상세의 러닝 카드 · 목록 한 줄의 "2.10km 러닝")는 원본 시안이 오면 맞춘다.
