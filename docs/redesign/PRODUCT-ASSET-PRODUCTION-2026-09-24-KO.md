## 2026-09-25 앱 적용 준비

52개 신발과 10개 의상 후보를 640×640 투명 WebP로 변환해 기존 `drawable-nodpi` 상품 리소스에 교체했다. 기존 상품 ID·카드 컴포넌트 매핑을 그대로 사용한다. 기본/체험 의상 5개는 기존 원본을 유지한다. 기본 착장에 NFT 신발이 **없을 때만** 러닝 화면에서 RUNO/LUMI 2프레임을 380ms 간격으로 재생하고, 일시정지·화면 비활성·모션 줄이기에서는 멈춘다. 기본 지급되는 WND-010을 신고 있으면 외형이 다른 이 프레임을 사용하지 않는다. 다른 장비의 달리기 합성은 아직 없다. 커밋 `c129bef`의 APK 빌드와 Android 14/15 꾸미기 화면 캡처는 통과했으나, 러닝 움직임은 기기 캡처로 검증하지 않았다.

아래 제작/시험 기록의 기준: 2026-09-24, 현행 앱 상품 카탈로그 67개. 앱 적용 변경은 위 2026-09-25 항목에 따로 적었다.

## 캐릭터 달리기 시험

[2프레임 재생 보드](../../design/redesign-2026-09/assets/modular/running-preview.html)와 `running/` 폴더에 기본 착장의 RUNO/LUMI 프레임 후보를 두었다. 이번에 만든 새 캐릭터 파일은 LUMI 두 프레임과 RUNO 반대 보폭 한 프레임 **3개**다. RUNO 첫 프레임은 기존 `avatar_male_running.webp`의 복사본이다. 모두 배경과 분리된 전신 후보이며 캐릭터 몸/의상/신발의 독립 장착 레이어는 아니다.

**구현 가능 여부: 가능.** Compose에서 동일 기준 캔버스의 프레임을 러닝 상태일 때만 바꾸면 팔다리가 실제로 달리는 연출을 만들 수 있다. 현재 `CharacterStage.kt`는 한 장의 그림에 최대 5dp 수직 움직임만 주므로 이 요구를 충족하지 않는다. `AvatarArtCatalog`의 RUN 포즈도 RUNO 기본 착장 한 장뿐이며 LUMI에는 RUN 그림이 등록되지 않았다.

2026-09-24 시험 당시 앱 연결은 **보류**였다. RUNO A/B는 1060×1484와 1024×1536으로 크기가 다르고, LUMI A/B도 불투명 실루엣의 발 하단이 16px 차이 난다. 2026-09-25에 동일 출력 캔버스로 정규화해 기본 착장 한정으로 연결했지만 머리·발 접점의 튐과 외곽 빛 번짐은 실제 화면 검수가 필요하다. 2프레임은 가능성 검증이며 자연스러운 출시 품질의 달리기 주기를 입증하지 않는다. 분리 착장/신발이 없는 현재 구조에서는 기본 착장 외의 장비를 프레임에 정확히 표시할 수 없다.

앱에 연결할 조건은 같은 1024×1536 캔버스의 동일 머리/발 기준점, 최소 4개 이상의 일관된 보폭 프레임 또는 검증된 뼈대/레이어 원본, 실제 장착 의상·신발과 맞는 합성, 러닝 일시정지·종료 시 정지, 시스템 모션 줄이기 대응, 장면과 독립된 알파, 실제 기기 프레임률/메모리 확인이다. 조건을 만족할 때 `CharacterStage`의 RUN 렌더 경로에 프레임 교체를 붙이고, 정확한 착장 그림이 없는 조합은 현재처럼 안내를 유지해야 한다.
