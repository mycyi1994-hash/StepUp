확정된 크루 러닝 규칙
기준: 사용자 작업 정의서 + 이후 문자 발송 제외 + 2026-10-24 대기실 배경 한정.

R01. 공용 풀의 단위
크루 체력은 공용 내구도 바 하나다. 같은 crew_id와 한국 날짜에 하나이며 여러 대기실이 같은 풀을 사용한다.
오늘 기여 총량 = 오늘 실제 출발한 참가자의 선택 신발 최대 내구도 합 × (1 + 크루 레벨 체력 보너스).
레벨이 중간에 바뀌는 경우 기존 풀 재평가 시점은 미정이므로 별도 정책을 확인한다.
pool_total은 누적 기여 총량, pool_remaining은 아직 쓰지 않은 잔량이다. 소비한다고 분모를 줄이지 않는다.

R02. 기여와 초기화
참가자가 실제 출발할 때 자신의 기여가 한 번 반영된다. 방 입장·신발 선택·미리보기·준비 완료만으로 기여하지 않는다.
선택 신발의 MAX 내구도를 사용한다. 현재 개인 내구도가 75/100이어도 최대치는 100이다.
한국 시간 매일 00:00에 새 날짜 풀은 0에서 시작한다. 수리는 없다. 지난 날짜 원장과 기록은 보존한다.
0/0 상태에서 새 참가자의 기여로 출발할 수 있으므로 기존 풀 0만으로 차단하지 않는다.

R03. 소비와 적립
RUNNING인 사람마다 달린 1분에 공용 내구도 5를 쓴다. PAUSED 사람의 소비는 0이다.
내가 쉬는 동안에도 다른 크루원이 달리면 공용 바는 줄어든다.
크루 러닝에서는 개인 신발 내구도가 줄지 않는다. 자유 러닝의 개인 신발 사용 경로와 분리한다.
공용 바가 0이 된 시점부터 해당 구간의 걸음은 적립하지 않는다. 거리·시간·경로 기록은 계속된다.
개인 신발로 자동 전환하지 않는다. 적립 중단과 러닝 종료를 다른 상태로 다룬다.
분 미만 정산/반올림, 다른 참가자의 새 기여 이후 재적립은 08의 정책 확인 대상이다.

R04. 개인별 보상
기본 보상 B는 해당 사용자가 출발 때 선택한 자기 신발 능력치와 기존 유효 러닝 보상 함수를 사용한다.
효율·착화감·내구도 등 실제 앱 속성의 의미와 기존 기본 산식을 확인한다. 시안이 새로운 기본 산식을 정의하지 않는다.
총 보상 = B × [1 + 인원 가산율 + 레벨 가산율].
기본분, 인원 추가분, 레벨 추가분을 각각 서버에서 반환한다.
신발을 평균 내거나, 참가자 총 보상을 인원으로 나누거나, (1+인원)×(1+레벨)로 곱하지 않는다.

R05. 하루 1번과 종료
같은 user_id의 실제 출발은 한국 날짜별 하루 1번. unique 기준에 crew_id/party_id를 넣지 않는다.
다른 크루로 옮기거나 다른 방에 들어가도 참여 기록은 유지된다.
일시정지와 재개는 동일 run_id를 유지하며 새 기여·새 참여권을 만들지 않는다.
끝내기를 확정하면 그날 다시 들어올 수 없다.
같이 뛰던 다른 사람이 모두 종료해 마지막 한 명만 미종료로 남으면 그 사람의 크루 러닝도 종료한다.
PAUSED는 종료가 아니다. 일시적 통신 끊김도 즉시 종료로 해석하지 않는다.
앱 Back, 화면 닫기, 잠금, 프로세스 재시작은 명시적 종료 요청이 아니다.

R06. 역할과 정원
크루원 누구나 대기실을 연다. 최대 20명이다.
크루 소유자(owner)와 해당 대기실 진행자(host)는 다르다.
진행자는 기존 권한에 따라 코스 변경·참가자 관리·출발을 담당한다. 참가자는 자기 신발 선택·준비·취소를 한다.
모든 참가자는 크루원 목록, 공용 내구도, 크루 목표, 코스를 볼 수 있다. 내 신발은 본인 선택 자산이다.
진행자 나가기의 승계/방 종료, 늦은 합류 등 미정 권한 정책은 08 참조.

R07. 보너스 인원
같은 크루, 같은 대기실에서 함께 출발하고, 출발 시점과 120초 뒤에도 500m 조건을 만족하며, 신뢰된 번호 인증을 가진 사람만 센다.
500m의 기준점·위치 정확도·샘플 신선도는 기존 정책을 확인한다. 시안의 '출발 지점' 문구만으로 새 위치 정책을 정하지 않는다.
서버 출발 시각을 기준으로 2분 확인한다. 클라이언트 타이머가 끝났다고 검증 성공으로 처리하지 않는다.
actual_participants, active_runners, non_ended_participants, bonus_eligible_count를 구분한다.
미인증자는 달리기·보상·기여가 가능하고 보너스 집계 인원에서만 제외한다.
실제 6명 / 인증 조건 충족 5명 → 6명이 기여·러닝, 보너스는 5명 구간 +20%.
실제 여러 명인데 bonus_eligible_count가 0 또는 1이어도 혼자 남은 것으로 종료하지 않는다.

R10. 레벨 효과
공용 내구도 가산율 = 0.06 × (Lv−1).
크루 보상 가산율 = 0.01 × (Lv−1).
Lv.1: 0% / 0%. Lv.8: +42% / +7%. Lv.20: +114% / +19%.
20명, Lv.20 → +150% +19% = +169%, 최종 보상 2.69 × B.
효과 적용 시점과 진행 중 레벨 업의 정산은 08에서 확인한다.

R11. 상한
크루 러닝 보상은 개인 러닝 하루 600 SUP와 분리한다. 현재 크루 일일 상한은 없다.
공용 내구도가 적립 가능한 구간을 제한한다. 임의로 600 SUP를 잘라내거나 별도 캡을 추가하지 않는다.
무제한 발행 영향은 이후 관찰·조정할 사항이며 이번 구현에서 미리 정책을 바꾸지 않는다.

R12. 인증 범위
번호 하나 = 계정 하나라는 악용 방지 목표는 유지한다.
이번에는 문자 공급자·문자 발송·OTP·번호 입력·인증 안내/설정 화면을 만들지 않는다.
서버의 기존 신뢰된 인증 정보가 있으면 읽는다. 없으면 임의로 모두 인증 처리하지 않는다.
인증 출처가 없는 환경에서는 보너스 집계가 0일 수 있음을 구현 보고에 남긴다.
인증 상태를 일반 클라이언트가 마음대로 갱신하지 못하게 하고 번호 원문을 크루원에게 공개하지 않는다.

R13. 기본 시안 예시 — 실제 서비스 수치가 아님
Lv.8, 기존 오늘 풀 720 / 1,200, 6명 각각 최대 내구도 100.
각 기여 142, 합계 852. 출발 직후 1,572 / 2,052.
6명 모두 21분 20초 뛰면 비례 정산 가정상 640 사용 → 932 / 2,052.
개인 사용 약 106.7, 개인 신발 사용 0. 초 단위 비례 여부는 미정 정책 D08을 확인한다.
개인 기본 보상 예시 B=120, 인원 +50%, Lv.8 +7% → 188.4 SUP = 120 + 60 + 8.4.
크루 누적 859 km에서 6명이 각 3.2 km 기여 → 878.2 km, 다음 Lv.9까지 21.8 km.
레벨 업 화면은 별도 fixture로 900 km 임계값을 넘은 장면이다. 모든 갤러리 장면을 동일 세션의 연속 실적으로 해석하지 않는다.
