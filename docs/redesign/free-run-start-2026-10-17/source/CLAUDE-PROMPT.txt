StepUp 자유러닝 시작 플로를 실제 앱에 구현해줘.

첨부한 HANDOFF.txt, motion-spec.json, reference.html, source/preview.html을 먼저 읽어. reference.html은 최신 승인 디자인을 반영한 동작 참고 시안이고, 실제 앱 코드는 아니다. 앱 저장소의 지침과 기술 스택을 확인하고 기존 자유러닝 시작 코드, 장착 신발 데이터, 러닝 세션 생성, 위치 수집, 지도 화면을 찾아 연결해. 확인하지 않은 파일명이나 프레임워크를 가정하지 마.

구현할 흐름:
자유러닝 시작 → 장착 신발 최종 점검 → 사용자가 출발 확인 → 3 → 2 → 1 → 0 → StepUP! → 중앙에서 지도가 펼쳐짐 → 기존 러닝 진행 화면.

확정 디자인:
- 배경은 StepUp 딥 네이비 #061B30. 숫자는 흰색, 회전 원호는 #1450FF 계열.
- 회전 원호 두께는 기준 8px 상당. 초마다 회전을 재시작하지 말고 0과 로고 전환까지 계속 회전시켜.
- 카운트다운에는 숫자와 원호만. ‘자유러닝’, ‘곧 러닝을 시작해요’, 취소 버튼을 넣지 마.
- StepUP!은 assets/logo.png의 실제 로고 글자 형태를 사용해. 일반 글꼴로 로고를 다시 타이핑하지 마. !는 로고 옆에 굵은 이탤릭으로 배치한 시안을 참고해.
- 0에서 새 불투명 화면으로 갈아 끼우지 마. 같은 네이비 배경 위에서 숫자·원호가 사라지는 300ms 동안 로고가 동시에 들어와야 한다. 둘 다 보이지 않는 중간 프레임이 없어야 해.
- 지도 펼침을 시작할 때 로고를 즉시 없애지 마. 120ms 유지한 뒤 300ms 동안 빠지게 하고, 지도가 중앙에서 커지며 로고를 자연스럽게 덮도록 연결해.
- 최종 러닝 화면의 레이아웃은 현재 앱 것을 유지해. 시안의 지도와 수치를 실서비스에 복사하지 마.

수치, 곡선, 레이어 구조, 상태 전이는 HANDOFF.txt와 motion-spec.json을 기준으로 해. 전체 재생 버튼이 신발 점검을 1.1초 뒤 자동 통과하는 것은 시연 기능일 뿐이며 앱에서는 반드시 사용자가 출발을 확인해야 한다.

성능과 연결 조건:
1. 로고 디코딩, 지도 화면 준비, 기존 권한·신발 상태 검증을 시작 전에 처리해. 전환 중 네트워크 응답이나 지도 첫 마운트를 기다리지 마. 지도 타일 다운로드 완료를 무기한 기다리는 구조도 만들지 마.
2. 한 시퀀스 소유자와 단조 증가 시간 기준으로 전체 흐름을 제어해. 버튼 연타·리컴포지션·재진입으로 타이머, 위치 수집, 세션 생성이 중복되지 않게 해.
3. 정상 흐름의 기록 시작 이벤트는 지도 펼침 진입 시점이다. 실제 세션 시작 성공을 확인한 뒤 펼침을 진행하고, 시작 실패 시 기존 오류 처리로 복귀해. 리워드·수수료·신발 차감 규칙은 이번 작업에서 바꾸지 마.
4. 시스템 뒤로가기·백그라운드·화면 재생성 때의 정리는 기존 앱 정책과 연결해. 이미 기록이 시작된 REVEAL 단계도 운동 중으로 취급해. 활성 세션 복귀에 카운트다운을 다시 재생하지 마.
5. 모션 감소 설정에서는 회전·이동·확대를 빼고 200ms 페이드로 같은 흐름을 전달해.

실제 앱을 수정하고 관련 빌드·검증을 수행해. 특히 0→StepUP! 구간을 느린 재생으로 확인하고 실제 기기에서 첫 실행과 반복 실행을 확인해. 수행하지 못한 검증은 완료했다고 쓰지 마.

완료 보고에는 수정 파일, 실제 데이터 연결 위치, 세션 시작 이벤트의 정확한 위치, 빌드·검증 결과, 첫 실행/반복 실행의 전환 영상 또는 캡처, 남은 제한을 적어줘. 승인된 톤과 구성을 임의로 재디자인하지 마.
