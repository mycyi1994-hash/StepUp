StepUp 자유러닝 시작 플로 — 개발 핸드오프
작성일: 2026-10-17
기준: 이 패키지에 포함된 최신 시안

1. 전달 범위와 현재 상태

이 패키지는 사용자가 검토한 UI 시안과 실제 앱 구현 지시서다. 이번에 수정한 것은 웹 시안이다. 이 작업 폴더에는 실제 Android/iOS 앱 소스가 없으므로 앱의 클래스명, 화면 파일명, 지도 SDK, 프레임워크를 확인한 것으로 간주하면 안 된다.

클로드는 실제 StepUp 저장소에서 자유러닝 진입, 장착 신발, 세션 생성, 위치 수집, 기존 러닝 지도 화면을 찾아 연결한다. 해당 저장소의 지침과 현재 기술 스택을 따른다. 시안의 HTML을 앱 전체 UI로 교체하는 작업이 아니다.

전달 파일:
- CLAUDE-PROMPT.txt: 클로드에게 그대로 전달할 작업 지시.
- HANDOFF.txt: 디자인 확정사항, 타이밍, 연결 조건, 완료 기준.
- motion-spec.json: 동일 내용을 구현에 사용할 수 있는 수치로 정리한 명세.
- reference.html: 브라우저에서 실행할 수 있는 동작 참고 시안.
- reference-fragment.html: 이미지가 포함된 인라인 시안 원본.
- source/preview.html: 읽고 수정하기 쉬운 CSS·HTML·JavaScript 원본. __LOGO__, __SHOE__는 자산 자리 표시자다.
- source/build.mjs: assets/의 이미지를 삽입해 reference-fragment.html을 재생성하는 선택적 빌더. Node 기본 모듈만 사용한다.
- assets/logo.png: 실제 StepUp 흰색 워드마크, 원본 900×156.
- assets/shoe_1201.webp: 실제 StepUp 신발 이미지. 시안에서만 이 신발이 고정되어 있다.
- VALIDATION.txt: 이번 시안에서 실제로 수행한 검증과 미수행 검증.

reference.html의 이미지 데이터는 파일에 포함되어 있다. 글꼴과 미리보기 스타일 등 외부 CDN 리소스는 인터넷 연결이 필요할 수 있다. source/build.mjs는 fragment만 갱신하며 reference.html 래퍼는 자동 갱신하지 않는다. 실제 앱에는 CDN이나 미리보기 도구 코드를 이식하지 않는다.

2. 사용자 확정 사항

자유러닝을 누르면 바로 기록을 시작하지 않고 장착 신발 점검창을 먼저 보여준다. 점검창에서 사용자가 출발을 확인하면 카운트다운을 시작한다.

카운트다운 배경은 딥 네이비다. 중앙의 흰색 숫자와 두꺼운 파란 회전 원호를 유지한다. 처음의 영화 필름 십자선과 보조 링은 사용하지 않는다. ‘자유러닝’, ‘곧 러닝을 시작해요’ 문구와 화면 안의 취소 버튼은 제거된 최종안이다. 다시 추가하지 않는다. 신발 점검창의 돌아가기와 닫기는 유지한다.

순서는 3 → 2 → 1 → 0 → StepUP! → 중앙 지도 펼침이다. 0을 생략하지 않는다. StepUP!은 힘 있게 등장하되 숫자와 사이가 비거나 화면이 뚝 바뀌면 안 된다. 앱 전체 지도 화면은 중앙의 원형 마스크가 커지면서 드러난다.

StepUP!에는 실제 로고 이미지를 쓴다. 정확한 로고 폰트 파일은 제공되지 않았다. 일반 글꼴을 비슷하게 골라 로고 폰트라고 주장하지 않는다. 시안은 원본 워드마크와 별도의 굵은 이탤릭 !를 함께 배치했다. 프로젝트에 원본 벡터 로고가 있다면 같은 형태의 자산을 우선 사용한다.

3. 시각 기준

배경: #061B30
강조 파랑: #1450FF
숫자·로고: #FFFFFF
원호 끝 강조: #72A6FF
얇은 원형 트랙: #A9C2E4, 알파 약 13%

기준 시안은 360×748 CSSpx이며 좁은 미리보기에서는 높이 724px, 원 지름 224px을 사용한다. 기본 원 지름은 244px, 회전 원호 두께는 8px이다. 앱에서는 안전 영역과 dp/pt에 맞춰 중앙 정렬하고 원 지름을 224~244 상당으로 조절한다. 회전 원호가 숫자를 가리거나 화면 가장자리에서 잘리지 않아야 한다.

숫자는 굵고 기울어진 형태, 크기는 기준 154px/좁은 화면 142px이다. 시안의 Bahnschrift는 웹/Windows 참고 글꼴이므로 앱에 해당 글꼴이 있다고 가정하지 않는다. 기존 프로젝트 숫자 서체를 확인하고 시안의 굵기·기울기·간격을 맞춘다. 실제 로고 글자 형태는 이미지로 보존한다.

로고 그룹은 화면 폭에서 좌우 24px 이상을 확보하며 최대 너비 296px이다. 워드마크와 ! 사이 간격은 8px이다. 로고에 기본 버튼 스타일, 테두리, 별도 카드 배경을 추가하지 않는다.

4. 정상 모션 타임라인

아래 t=0은 필요한 준비를 마친 뒤 카운트다운이 실제로 시작한 순간이다. 신발 점검창에서 사용자가 머무는 시간과 사전 준비 시간은 포함하지 않는다. 프레임과 스케줄러에 따라 수 ms의 오차는 있을 수 있다.

0ms       숫자 3
1,000ms   숫자 2
2,000ms   숫자 1
3,000ms   숫자 0
3,180ms   숫자·원호 퇴장과 StepUP! 진입을 동시에 시작
3,480ms   숫자·원호 퇴장 완료, 로고 정착 완료
3,760ms   지도 펼침 시작, 러닝 세션 기록 시작 이벤트
3,880ms   로고 퇴장 시작 — 지도 펼침 시작보다 120ms 늦음
4,180ms   로고 퇴장 완료
4,410ms   지도 화면 전체 노출, RUNNING 표시 상태

숫자 변화:
- 3·2·1은 각각 1,000ms. 0은 로고 교차 전환 전 180ms 보여준다.
- 각 숫자 진입은 160ms, opacity .6→1, translateY 6→0, scale .96→1.

회전 원호:
- 0→1260도, 3,500ms, linear. 1초에 한 바퀴를 유지한다.
- 숫자가 바뀔 때 원호 회전을 재시작하지 않는다.
- 원호는 0과 로고 교차 전환 중에도 계속 움직이고, 전체 원 그룹의 퇴장에 함께 사라진다.

숫자·원호 → 로고:
- 원 그룹 퇴장과 로고 진입은 정확히 같은 타임라인 시작점을 사용한다.
- 원 그룹: 300ms, opacity 1→0, translateY 0→-10, scale 1→1.04.
- 로고: 300ms. 시작 opacity 0, translateX -18, scale .96.
- 로고 진행 72% 지점: opacity 1, translateX 3, scale 1.025.
- 로고 완료: opacity 1, translateX 0, scale 1.
- 로고 정착 후 280ms 동안 읽을 시간을 준 뒤 지도 펼침으로 연결한다.
- 곡선: cubic-bezier(.23,1,.32,1).

지도 펼침:
- 공통 중심은 전체 러닝 화면의 중앙(50%, 50%)이다.
- 마스크 최대 반경: ceil(hypot(width/2, height/2)) + 12. 둥근 모서리까지 완전히 덮는다.
- #5287FF 선행 색면: 지연 0ms, 500ms 동안 반경 0→최대.
- #1450FF 색면: 지연 35ms, 540ms 동안 반경 0→최대.
- 실제 지도·러닝 화면: 지연 70ms, 580ms 동안 반경 0→최대.
- 곡선: cubic-bezier(.77,0,.175,1).
- 지도 펼침 시작 후 120ms까지 로고를 유지한다. 이후 300ms 동안 opacity 1→0, scale 1→1.045로 퇴장한다.
- 세 색면/지도 마스크와 로고 퇴장은 공통 시작점에 정렬한다. 펼침 완료 전 배경 레이어를 제거하지 않는다.

5. 끊김을 없애기 위한 구조

이전 시안은 0을 보여준 뒤 불투명한 로고 화면을 즉시 올려 숫자를 가렸고, 로고는 opacity 0부터 시작했다. 그 결과 숫자가 사라지고 로고가 충분히 보이기 전까지 연결이 끊겨 보일 수 있었다. 성능 계측 없이 모든 끊김을 렉으로 단정한 것은 아니다.

수정안은 네이비 배경과 상태 표시 영역을 유지한다. 로고 레이어는 투명한 오버레이다. 원 그룹과 로고가 300ms 동안 겹쳐 보이고, 로고에서 지도까지도 동작이 겹친다. 두 내용을 모두 숨긴 뒤 새 내용을 마운트하는 구조는 사용하지 않는다.

레이어 아래→위:
기존 자유러닝 진입 화면 / 네이비 카운트다운 배경·숫자 / 투명 StepUP! 로고 / 선행 파란 색면 / 강조 파란 색면 / 실제 러닝 지도 화면.

시안은 로고·신발 이미지 decode를 미리 요청하고, 준비가 끝난 뒤 카운트다운을 시작한다. 원호는 한 번의 연속 회전으로 재생한다. 교차 전환과 지도 마스크의 WAAPI 애니메이션에는 공통 startTime을 적용했다.

6. 실제 앱 연결 기준

상태 흐름:
IDLE → SHOE_CHECK → PREPARING → COUNTDOWN → LAUNCH → REVEAL → RUNNING

PREPARING은 개발 상태명이지 새 화면을 추가하라는 뜻이 아니다. 기존 점검창/기존 로딩 표현 안에서 권한과 데이터 준비를 처리한다.

- SHOE_CHECK에는 실제 장착 신발 이미지·등급·레벨·내구도를 연결한다. 시안의 레어, Lv.3, 92%를 하드코딩하지 않는다.
- 점검 취소는 세션을 만들지 않고 기존 화면으로 돌아간다.
- 출발 버튼 연타는 한 번의 시작 요청으로 처리한다.
- 신발 사용 가능 여부, 위치 권한, GPS 준비 등은 현재 앱의 검증 정책을 유지한다. 검증 실패는 카운트다운 전에 기존 방식으로 안내한다.
- 지도 View와 로고 자산을 시작 전에 준비한다. 지도 타일 준비 지연 때문에 0이나 로고에서 멈추지 않는다. 타일 로딩은 현재 지도 SDK의 기존 표시/재시도 동작을 따른다.
- 세션 기록 시작은 REVEAL 진입 이벤트에서 1회 실행한다. 실제 세션 생성/시작이 성공하면 펼침을 진행한다. 실패하면 준비된 시퀀스를 정리하고 기존 오류 화면/안내로 복귀한다.
- 카운트다운과 로고 노출 시간을 운동 경과 시간에 포함하지 않는다. 위치 준비와 실제 기록 시작을 구분한다.
- 시간, 거리, 페이스, 위치 수집, 일시정지, 종료, 신발 소모, 보상은 기존 앱 로직을 사용한다. 지도 펼침이 세션 생성이나 리워드 규칙을 다시 실행하는 트리거가 되어서는 안 된다.
- REVEAL부터는 기록이 시작된 상태다. 이때 시스템 뒤로가기를 단순 카운트다운 취소로 처리하지 않고 기존 운동 중 뒤로가기 정책을 따른다.
- 세션 시작 전 화면 이탈 시 타이머·애니메이션·준비용 구독을 정리한다. 기록 시작 후에는 기존 세션 유지/종료 정책을 따른다.
- 백그라운드/화면 재생성/활성 세션 복귀에서 카운트다운을 중복 재생하지 않는다. 화면의 임시 애니메이션 상태가 영속 세션 상태를 덮어쓰지 않게 한다.
- 기존 내비게이션으로 COUNTDOWN, LAUNCH, REVEAL을 별도 화면처럼 연속 push하지 않는다. 같은 루트의 레이어와 하나의 시퀀스 소유자로 구현한다.

앱의 비동기 세션 시작이 필요한 경우 3,760ms는 정상 경로의 목표값이다. 실제 시작 성공 전 RUNNING을 보여주거나 실패한 세션을 성공한 것처럼 표시하면 안 된다. 기존 서비스의 준비 API를 사용해 지연을 앞당겨 처리하고, 불가피한 오류·지연은 기존 상태 처리와 연결한다.

7. 모션 감소

카운트다운 숫자와 순서는 유지한다. 원호 회전, 숫자 이동/확대, 로고 이동/확대, 원형 지도 확장은 사용하지 않는다. 숫자·원호와 로고는 같은 시작점에서 200ms 페이드로 교체한다. 지도도 200ms 교차 페이드로 드러낸다. 같은 상태 전이와 세션 시작 기준을 유지한다.

8. 앱 완료 기준

[ ] 자유러닝 클릭 → 신발 점검, 실제 신발 데이터 표시.
[ ] 점검창을 닫으면 기록 미생성. 출발 확인 시에만 카운트다운 시작.
[ ] 네이비 배경, 굵은 파란 원호, 흰 숫자. 삭제한 문구·취소 버튼 없음.
[ ] 3·2·1·0 순서와 StepUP!이 유지됨. 회전 원호가 숫자마다 멈추지 않음.
[ ] 0→로고 사이 빈 화면, 불투명 화면 교체, 흰/검은 플래시 없음.
[ ] 지도 펼침을 시작할 때 로고가 갑자기 사라지지 않음.
[ ] 실제 지도와 기존 러닝 화면으로 연결됨. 시안용 지도/고정 수치가 앱에 들어가지 않음.
[ ] 빠른 연타와 재진입에도 세션·타이머·위치 구독이 중복 생성되지 않음.
[ ] 세션 시작 실패, 권한 거부, 화면 이탈, 백그라운드 복귀 처리 확인.
[ ] 이미 진행 중인 세션에 복귀할 때 카운트다운을 다시 보이지 않음.
[ ] 모션 감소 설정 확인. 작은 기기/노치/글꼴 배율에서 잘림 없음.
[ ] 첫 실행과 반복 실행을 실제 기기에서 확인하고 전환 구간을 느린 재생으로 점검.
[ ] 관련 빌드·기존 세션 검증 통과. 수행하지 못한 검증을 별도로 보고.

최종 보고에는 수정 파일과 데이터 연결, 세션 시작 지점, 검증 결과, 전환 영상/캡처, 미해결 제한을 포함한다.
