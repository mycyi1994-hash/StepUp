# 0118 ~ 0123 나눠 켜기 (2026-11-23)

사용자 "#210 을 나눠서 내보내요 — 진행해". PR #210(파일 301개 · 서버 0118 ~ 0123 · 새 판 30 · 1.21.0)을 한 번에 내보내지 않고
**서버를 먼저, 예전 셈으로 올린 뒤 스위치를 하나씩 켠다.** 앱 30 은 마지막이다.

## 왜 번호로 자르지 않나

0122 · 0123 의 고침 가운데 여럿이 0118 ~ 0121 이 새로 연 구멍을 막는다(예: 0121 러너 레벨을 가짜 지난 기록으로 Lv30 → 0123 의 3번,
0121 의 러너 레벨 상자가 섞이던 것 → 0122 의 12번). 0118 만 먼저 내보내면 그 사이 구멍이 열린 채 운영된다.
게다가 0122 · 0123 은 "마지막 정의를 복사"해 만들어서(tools/build_0122.py · build_0123.py) 순서를 바꿀 수도 없다.

대신 0118 ~ 0121 의 새 셈은 모두 **설정 스위치**로 되돌릴 수 있다(각 파일 머리말의 "되돌리기"). 마이그레이션은 설정을
`on conflict (key) do nothing` 으로 넣으므로, 그 키를 배포 **전에** 예전 값으로 넣어 두면 배포해도 셈은 지금과 같다.

## 단계

각 단계는 SQL 창에서 한다(몇몇 키는 운영자 페이지 "경제" 탭에 없다). 켠 뒤 하루쯤 운영자 페이지 "경제" 현황
(하루 적립 · 수리 · 상자)과 `security-alert` 이슈를 본다. 이상하면 그 단계의 "되돌리기".

### 1단계 — 서버를 예전 셈으로 올린다

2. 이 브랜치(서버 몫만 — `app/` 은 그대로 29 · 1.20.1)의 PR 을 합친다 → `Deploy server schema` 가 0118 ~ 0123 을 올린다(5 ~ 6분).
3. push-send 를 손으로 다시 올린다(새 푸시 `REWARD_RULES` 문구) — 아직 보내지는 않는다.
4. 확인: `Deploy server schema` 초록 · 테스트 앱(29)으로 러닝 하나 → 적립 · 기록 · 체인 기록(2 ~ 6분 뒤 탐색기)이 예전처럼.

### 2단계 — 0118 보상 걸음 · 0119 경제의 뿌리

```sql
update public.economy_settings set value = v.value::jsonb, updated_at = now()
  from (values ('reward_steps_rule', '"REWARD"'), ('worn_rate', '0.30'), ('eff_wear_exp', '1'), ('eff_energy_exp', '1'),
               ('dur_repair_exp', '1'), ('energy_per_level', '0'), ('forge_xp_curve', '"LINEAR"')) v(key, value)
 where economy_settings.key = v.key;
```

닳은 신발도 걸음을 다 세고 적립 30%, 상자 · 목표는 경로로 확인된 걸음, 하루 에너지는 레벨과 떼고(착화감으로), 강화 통 굽이.
바뀐 셈은 `select admin_notice_send('REWARD_RULES');` 로 알린다(문구가 "4,000보부터 · 닳은 신발도 걸음은 다 센다"라 이 단계 뒤에 보낸다).

되돌리기: 위 값을 `"OLD"` · `0` · `0` · `0` · `0` · `2` · `"CLASSIC"` 으로.

### 3단계 — 0120 함께 달리기 보너스 고침

```sql
update public.economy_settings set value = v.value::jsonb, updated_at = now()
  from (values ('crew_bonus_rule', '"ACTIVE"'), ('party_bonus_rule', '"ACTIVE"'), ('daily_max_rule', '"HOUR"'),
               ('crew_blend_share', '0.2')) v(key, value)
 where economy_settings.key = v.key;
```

함께 달린 사람만 인원 보너스(10분 · 1,500보 · 목표 거리 50% · 가입 24시간), 탈주한 사람의 공용 체력은 묶임,
하루 최대 SUP = 그 신발 1시간 값 × 4, 크루 효율 8 : 2. 20명 출발 · 18명 바로 종료로 2,639.7 SUP 를 받던 구멍(docs/점검-2026-11-21-보너스.md)을 막는 단계라
**2단계와 같은 날이나 바로 다음 날** 켠다.

되돌리기: `"ALL"` · `"ALL"` · `"CAP"` · `0`(0122 의 9번 — ALL 로 되돌렸다 다시 켜도 인원 보너스를 두 번 주지 않는다).
