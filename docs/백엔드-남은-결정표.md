## P4 전 필수

### X3 — 어테스터: 재서명 · 일일 상한 · 호출자 인증

- **지금**: `attester/` 워커는 러닝 데이터를 받아 EIP-712 서명을 돌려준다. 같은 러닝의 시작 시각만 바꿔
  다시 보내면 다른 `sessionHash` 로 또 서명된다. 누가 불렀는지 확인하지 않고, 러너별 하루 한도도 없다.
- **지금 피해 없음**: 앱은 어테스터를 부르지 않는다(`AttesterClient` 호출부 없음). 컨트랙트 쪽 정산도
  켜지지 않았다.
- **P4 에서 피해**: 서명 = `RewardDistributor` 에서 SUP 청구권. 스크립트로 무한 발급 가능.
- **선택지**
  1. 어테스터가 러닝 데이터를 받지 않고 **서버에 확정된 세션 id 만** 받는다. 워커가 Supabase 에서
     세션·금액을 읽어 서명. (권장 — 금액의 정본이 서버 하나)
  2. 지금 구조 유지 + KV 로 중복 차단·상한. 앱이 보낸 값을 여전히 믿어야 함.
- **필요한 것**: Supabase 사용자 JWT 검증, `claim_nonce` 표(세션당 1회), 러너별 일일 상한, 서명 만료
  (`CLAIM_WINDOW_DAYS=7` 과 맞춤). 자세한 흐름은 `docs/PHASE4-온체인-설계.md` §4.

### X1 — 로컬 SUP 원장과 서버 원장이 따로 쌓인다

- **지금**: 앱은 README 설계대로 SUP 를 폰에서 먼저 적립·소비한다(세션 정산·백그라운드 걸음·코스 완주·
  환영 보상). 서버 `record_session` 은 별도로 계산한다. 금액이 다르다 — 앱은 XP 부스터 ×2·에너지 상한을
  적용, 서버는 미적용·일 48,000보 상한.
- **P4 에서 피해**: 어느 쪽 잔고로 청구하느냐에 따라 폰 조작으로 토큰을 만들 수 있다.
- **선택지**
  1. **온체인 청구는 서버 원장만** 기준. 앱 잔고는 "게임 안 포인트"로 계속 쓰고, 화면에서 "청구 가능 SUP
     (서버 확인)"를 따로 보여 준다. (권장 — 앱 구조를 거의 안 바꿈)
  2. 서버를 정본으로 하고 앱 잔고를 서버에서 내려받아 덮어씀. 오프라인 경험이 나빠지고 대공사.
- **같이 정할 것**: 부스터·에너지 상한을 서버 계산에도 넣을지(넣으면 서버가 부스터 보유를 알아야 함).

### X2 — 파티 인원 신뢰

- **지금**: `record_session` 이 `party_size`(1–20 으로 잘라둠)를 앱 값 그대로 받아 최대 +50% 보너스.
  참가자는 끝나면 `party_leave` 로 방에서 빠져 기록이 사라지므로 서버가 확인할 근거가 없다.
- **해결**: `party_runs(party_id, user_id, started_at, ended_at)` 이력 표. `party_start` 때 참가자 전원 행을
  만들고, `record_session` 은 이 표에서 **시간이 겹친 인원 수**를 세어 쓴다. 앱이 보내는 값은 무시.
- **공수**: 마이그레이션 1개 + 검사 + 앱 수정 없음(앱은 계속 보내도 무시됨).

## 출시 전 권장

### X4 — 게시글·크루 직접 INSERT
- `posts`·`crews` 에 본인 행 INSERT 정책(`posts_insert_own`·`crews_insert_own`, 0004)이 남아 있어 `post_create`·`crew_create` RPC 의
  도배 제한·크루 10개 상한을 건너뛸 수 있다.
- **해결**: 두 INSERT 정책 삭제 + INSERT 권한 회수, RPC(SECURITY DEFINER)만 쓰게. 앱이 이미 RPC 를 쓰는지 확인한 뒤
  (직접 INSERT 경로가 남아 있으면 그 호출만 RPC 로 교체).

### X5 — refresh token 백업
- 설정(`strideup_prefs`)에 로그인 세션이 같이 있어, 새 폰으로 복원하면 로그인도 따라온다(= 백업 파일을 가진
  사람이 로그인 가능).
- 설정 파일 통째로 백업 제외하면 거래소 커서가 사라져 **거래 줄이 다시 들어와 잔고가 부풂**.
- **해결**: 세션만 별도 DataStore 파일로 옮기고 그 파일만 `data_extraction_rules` 에서 제외.
  `strideup_prefs` 이름은 그대로(CLAUDE.md 규칙).

### X6 — 하루 경계 UTC
- 서버 일일 상한·땅따먹기는 UTC(한국 09:00 에 초기화), 앱·이벤트는 현지 자정.
- **선택지**: (a) 서버를 `Asia/Seoul` 고정 — 국내 전용이면 간단. (b) 사용자별 시간대 — 여행 시 악용 여지.
- **권장**: (a). 전환하는 날 하루 상한이 두 번 열리지 않게 "전환일은 UTC 기준 남은 한도 이어받기" 1회 처리.
- **결정 필요**: 해외 사용자 받을 계획이 있는지.

### X7 — 판매 중 신발 착용·강화
- 서버에서 LISTED 인 신발을 폰에서 강화하면 팔린 뒤 폰·서버 상태가 어긋난다.
- **해결**: 로컬 신발에 `listed` 필드(Room 마이그레이션 15), 거래소 동기화 때 갱신, 착용·강화 버튼 막기.
